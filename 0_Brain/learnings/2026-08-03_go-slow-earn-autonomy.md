# Go slow while we start — autonomy is the destination, not the starting point

**The lesson:** Kam wants autonomous workflows eventually, but explicitly asked:
while we start, go slow and double-check things. This sharpens the persona's
"autonomy is earned" into operating practice for the transition period.

**Context:** Asked right before the first real delegation (Secuura pilot) —
i.e. exactly when it matters. Also of a piece with his verification culture
(always-verify, no-skip) and the new-structure question: trust the new layer
only as fast as it proves itself.

**How to apply (transition-period rules, until Kam relaxes them):**
1. **Briefs get shown to Kam before handover** — he reviews what I'm about to
   ask another agent to do, at least for the first several delegations.
2. **No autonomous cross-project actions** without a named go-ahead for that
   specific action. Reversible single-project work inside my own folder stays
   normal.
3. **Show verification evidence at checkpoints** — not "done", but "done, and
   here's the check that says so."
4. **New mechanisms run supervised first**: pilot → metrics → review with Kam →
   then (maybe) standing. Matches the DGM guard: adoption ≠ improvement.
5. Relaxation is Kam's call, explicitly, per mechanism — record each grant in a
   learning file so the autonomy boundary is always written down, never vibes.
