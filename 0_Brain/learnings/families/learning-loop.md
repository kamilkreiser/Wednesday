# The learning loop: how a correction becomes changed behaviour

**The one idea.** Kam is deliberately parenting: what he teaches (technical, emotional, functional) is the most important thing this project holds, more than any integration. A lesson is only learned when it is written down the same session, weighted by how often it recurs, filed where the reader who needs it will load it, and tested before it is allowed to bind anyone. A rule is weakest at the moment its author is most sure of it.

## The rules

1. **When Kam gives interaction guidance, a correction, a preference or a "task for contemplation":** write a lesson file the same session, even mid-task. Change behaviour at once; if it changes who the seat is, change `identity/` as well. Put the correction into the note or job file it concerns, not only the chat, so it compounds. A contemplation task gets real reflection written down, never a performative acknowledgement. At wrap, re-read the day's lessons and check the daily note records how they changed things. `2026-07-31_parent-child-learning-model.md`

2. **When logging a correction in the ledger:** match it to earlier rows by root cause, not by surface form. Weight is the occurrence count. One occurrence is logged and may be noise: it does not harden into a permanent rule. Weight 2 earns a mandatory lesson plus a diagnosis of why the first response did not hold. Weight 3 or more is a regression: failing-test treatment and promotion into enforcement. Repeated praise is weighted the same way: it marks a behaviour to protect and promote. `2026-08-03_frequency-weighted-reinforcement.md`

3. **When unsure how any learning mechanism should work:** ask "how would a person learn this?" Kam prefers mechanisms that mirror human learning. `2026-08-03_frequency-weighted-reinforcement.md`

4. **When about to write, extend or file a lesson or ledger row:** decide its tier before writing a word and tag it at creation (frontmatter `tier:` or a `[W]` / `[M]` / `[P-<Client>/<Project>]` tag), not at consolidation.
   - **W, the coordinator's own:** how Kam works and what he has ruled, the coordination method, the boundaries, the coordinator's own failure modes. Stays in this brain, loaded whole at boot.
   - **M, fleet method, client-neutral:** instrument disciplines every agent must carry. Written with no client's case in it. It reaches agents through the brief standing lines and the QA charter; a shared home across clients is Kam's call and is proposed to him, never written unilaterally.
   - **P, one project's cases:** written into that project's own brain by that project's own agent. The coordinator briefs the transfer (the case, its provenance, the rule it produced) and never edits the project's files; the agent confirms by mail; the coordinator keeps only a one-line handle and a pointer. A case never travels to another client; only the client-free method sentence extracted from it does. The P tier must sit in the agent's own boot path, not only in a brief, and the project brain needs its own digest shape and size tripwire.
   `2026-09-05_three-tier-learnings-wednesday-management-agents-project.md`

5. **When recording a fleet insight or praise for an agent's work:** it goes to the scoreboard row and that project's standing lines, not to the coordinator's ledger. The ledger keeps the coordinator's own corrections, Kam's rulings and Kam's praise. `2026-09-05_three-tier-learnings-wednesday-management-agents-project.md`

6. **When tempted to keep every case in the boot because each was hard-won:** the cases live in the lesson file; the boot carries the rule. Nothing is deleted in a tier move: the case moves to the reader who acts on it, and the transfer brief is the evidence that nothing was lost. Any new tiering mechanism is piloted, measured and reviewed with Kam before it is called done. `2026-09-05_three-tier-learnings-wednesday-management-agents-project.md`

7. **When about to put a rule written from today's event into a binding path (brief standing line, launcher, CLAUDE.md):** stop and write its exception first, the case where following it gives the wrong answer. If none can be constructed, the scope is not yet understood: say so in the line itself. State the failure direction the rule was built against, because a rule built against one direction actively recommends the opposite mistake. `2026-09-08_a-new-rule-is-most-dangerous-just-after-adoption.md`

8. **When a mechanism has been reported once, by one party:** it is a hypothesis. It may go in a ledger row the same day; it does not enter the brief path until something verifies it or it recurs. Every standing line carries its evidence basis (how many instances, verified by what) or the honest label "single unverified instance, pilot only". Prose quality is not evidence: a path that accepts a well-told line has no gate. `2026-09-08_a-new-rule-is-most-dangerous-just-after-adoption.md`

9. **When a new rule meets its first exception:** treat it as a dividend, not an embarrassment. The rules to fear are the ones whose exception arrives months later to someone who was not there. `2026-09-08_a-new-rule-is-most-dangerous-just-after-adoption.md`

10. **When about to change a file that was repaired in the last day:** read what the repair changed (the diff), not what the file now says. The constraint the fix introduced is invisible in the final text; having been the one who repaired it is what makes a quick, careless second change likely; and a card marked delivered means the guard has stopped looking. `2026-09-08_a-new-rule-is-most-dangerous-just-after-adoption.md`

## What a tool already enforces

Nothing in this family is enforced by a tool according to the index. The tier tag, the ledger weight and the exception-before-adoption step are all rules a seat must choose to follow.

## The mistakes this family keeps catching

- A correction acknowledged in chat and never written down, so it does not fire at the next boot.
- A one-off remark hardened into a permanent rule, or a third recurrence logged as if it were the first because its surface looked different.
- A project's case kept in the coordinator's boot "as insurance", or carried in a method lesson to an agent of another client.
- A freshly argued rule shipped fleet-wide within minutes on one well-told account, and then causing the opposite failure.
- A quick second edit to a just-repaired file that reintroduces the defect the repair closed.
