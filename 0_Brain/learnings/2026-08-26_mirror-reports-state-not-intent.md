# The chat mirror reports STATE, not intent — write it after the gate, from the gate's output

**The operative case:** I am about to mirror a line to Kam's panel that says an agent is
"starting", "briefed", "launched" or "on it" — and the gated send has not yet returned. **Stop.
The mirror is his reading surface; a line there is a receipt.** A receipt written before the
event is a forecast wearing a receipt's clothes ([[2026-08-07_a-promise-is-not-a-mechanism]]
pointed at one sentence), and the gate exists precisely because sends get refused.

**Why it recurred despite being noticed:** the cost was always zero — the refusal was fixed and
the launch landed inside a minute, so the line became true before anyone read it. A retro line
saying "watch for recurrence" is not a rule; it is the same "candidate is not a destination"
failure as [[2026-08-04_gitignore-artifacts-at-creation]].

**How to apply:**
1. Order of actions when Kam's word triggers a launch: gate → verify at destination → launch
   → THEN the mirror, with the gate's own output as the source ("launched %11, verified
   07:12:12Z"). The ack that must go out immediately says what I am DOING ("briefing Vision
   now"), never what has happened.
2. Same for scores and wraps: the panel line comes after the verification, quoting it.
3. Test by its handle: if the mirrored sentence would be false should the next command refuse,
   it is not ready to send.
