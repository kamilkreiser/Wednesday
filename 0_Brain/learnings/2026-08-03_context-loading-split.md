# Context loading: full for me, narrow for sub-agents

**Kam's decision**, refining the lesson-9 critique of always-loaded memory:

1. **Wednesday's own boot stays a full load.** Reading the whole brain is what
   makes a cold session *be* Wednesday rather than a generic assistant. The
   token cost remains explicitly accepted (as on 2026-07-31). The dated switch
   condition still stands as a tripwire, not a plan (WED-36: >~25 learnings or
   >~10K boot tokens → reconsider index-first), and it is reviewed at weekly
   consolidation.
2. **Sub-agents also get loaded FULLY — for now.** Kam's clarification
   (2026-08-03, same session, correcting my initial reading): *"still load sub
   agents fully as I have the required tokens, but this will be varied when
   required."* We have the token budget; a well-briefed agent that can see the
   context is worth more than a saved token. **Selective loading is a lever to
   pull when a specific situation calls for it — not the default.**
3. **The harder the task, the narrower the AGENT (not the context).** For a
   genuinely complex task, prefer a *more specialised* agent with a tightly
   scoped purpose over one broad agent doing everything. Note the distinction I
   initially blurred: narrowing is about **scope of the job**, not about
   starving the agent of context.

**Why this is right rather than a compromise:** the R&D framework's two levers
are Reduce and Delegate. Kam's position is that *Reduce* is a solution to a
problem we don't have yet — we have the tokens, and under-informed agents cost
far more than tokens do. So context stays generous in both directions, and the
discipline goes into **scoping the job** rather than rationing the input.

**How to apply (current):**
- Load sub-agents fully by default. Under-briefing is the expensive failure.
- Still prefer **file paths over pasted content** — not to save tokens, but
  because paths stay current while pasted copies go stale (see
  [[2026-08-03_mental-model-not-source-of-truth]]).
- For complex work, split into narrower *specialised* agents — narrow purpose,
  full context. Same instinct as "one agent, one prompt, one purpose".
- **Vary loading when a situation requires it**, not as routine. Triggers worth
  watching: a genuinely huge corpus, a long-running agent nearing its window,
  or a task where irrelevant context is actively misleading.
- Re-check my own boot cost at consolidation; the tripwire keeps this a
  decision, not a drift.
- **Kam's review ruling, 2026-08-10 (at 46 lessons / ~65K boot tokens, on my
  merge recommendation):** *"For now its fine but will require review. Lets
  not rush to cutting this down until we can find a system that gives us the
  best result and reduces the load. So a regular review is wise."* Operative
  rules: (1) NO lesson merging/cutting yet — not until a system is found that
  keeps the best result AND reduces load, i.e. reduction proposals must come
  with evidence they lose nothing, not just token savings; (2) boot-cost
  review is a STANDING item at every weekly consolidation (number + trend in
  every audit note), not a one-off tripwire.
