## What the tooling or checklist should change
1. spark_gate.sh: a docs-only PR (all touched files .md/.html/.txt) has nothing to run; today the operator must invent a test file, and the runner reports a green "9 passed" that means nothing. Add a `--docs-only` mode (no test file required, facts.json `deterministic_checks: "diff only"`, `targeted_*` = null) or refuse with a message naming the mode. Otherwise a docs gate looks more verified than it is.
2. For docs PRs the useful deterministic facts are exactly the ones this Claude gate computed by hand: the hunk list (`git diff -U0`), a sorted-marker-line compare, `git diff --check`, a token-existence pass over backticked paths/symbols (the seat's docs_check_y11.py), and docs-fragments check. Wiring those into facts.json would give the Spark something to be measured against; today its Notes #6 ("byte-identical not in facts.json") are the Spark pointing at the same hole.
3. spark_review.py: for a docs PR, the ticket slot should take the actual ticket; a proxy (S 45th's draft) pushes the Spark to restate the proxy. Add the cited CODE files as inputs when a docs line cites `route:` / `file:` (it could not check one sentence against code, which is the whole value of a docs gate). Without code, recall on a docs gate is structurally 0 for truth-of-sentence findings.
4. spark_review.py: reject Notes whose evidence is "PR says docs only / PR says not run" (7 of 12 here) and the `comment_sentences_overstated` entries that only say "this is a code reading" when the sentence already says "code read".
5. Verdict label: when every Note is a restatement the label should be GO (PR 2136 got it, PR 2135 got GO WITH NOTES on identical-kind Notes), so the label is not stable across two same-kind PRs.
