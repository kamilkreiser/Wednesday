## 1. BLUF for the owner
1. When our gate says "allow", Claude Code did not ask, for a file write and a simple terminal command, in the manual mode and in the auto mode. So ALLOW needs no new Claude Code trick for these calls. Whether Anthropic's own server-side reviewer can still stop such a call was not measured.
2. When our gate says "ask", Claude Code shows its dialog and waits for your key, also in the auto mode a new session starts in here. But for a file write the dialog did not show our reason. So the product must show its reasons in its own window, not rely on Claude Code's dialog.
3. Claude Code hides a terminal command's text about a second after it runs. Your activity view is the only place it stays.
4. A confirmation typed into a terminal is not safe from the agent: a command the agent ran could type into and read from another terminal window of yours. With Claude Code's sandbox on, that one route was blocked; other routes were not tried. So the switch to ALLOW needs a different place to confirm.
5. The mode Claude Code is in must be read from what it tells our hook each time, never assumed: a new session here started in "auto" with no setting asking for it.
6. Still open: the server-side reviewer; where exactly to confirm the switch to ALLOW; and whether a line shown to you by Claude Code is ever replayed to the agent later.

## 4. What the product must now do that the note did not say
1. **Its own surface for the gate's reason (M8; also M2, M3).** In an auto session the Write dialog showed none of our reason, while the Bash dialog did (MEASURED M8, reproduced r2 §6). On an allow, `permissionDecisionReason` is never shown (MEASURED M3). So the owner cannot count on Claude Code to show why CoAgent asked or allowed. LOCAL ACTIVITY must show the gate's reason, in full, for every asked call, file edits included, and must never depend on Claude Code's dialog text. REASONED from M8 and M3.
2. **The mode is read, never assumed (M1 fresh rows; RESULT.md:71).** The product reads Claude Code's mode from the hook's own `permission_mode` at each call and shows that value. If the field is absent it says so; it never fills in "default". REASONED. Also: in an auto session Claude Code asked nothing for these calls without our hook (MEASURED M1-fresh-ctl), so APPROVE there rests wholly on the gate's `ask`, which M8 shows works.
3. **A typed confirmation in a terminal is not agent-proof (M7+, M10).** The agent's own Bash has no terminal, but one command it ran could write onto another same-user pty and take the next line typed there (MEASURED M7+, sandbox off, path given, after one allowed command). With the sandbox on, that one route was refused (MEASURED M10); other routes were not tried. Consequences, REASONED: (a) the switch to ALLOW cannot be confirmed by typing into any terminal while that is so, including the viewer's own window; (b) the owner's C-5 puts terminal commands in ALLOW outside the sandbox condition, and a reader left running from an ALLOW period can sit on a terminal later (M7+ limit as worded by the first check, F3); (c) so the confirmation surface is outside the terminals (candidates in P2 above), chosen by Friday. LOCAL ACTIVITY, which only displays, is not affected: it accepts no input.
4. **What a hook `systemMessage` may carry (M3).** It is shown to the owner and was not sent to the model at that turn; it is kept in Claude Code's transcript on disk (display, not secrets) and sent to SDK/stream-json hosts; "never sent later" is unmeasured. So it may carry only fixed product text that may sit in the agent's session files (for example a pointer to the activity view). Never peer text, never a secret, never the content of LOCAL ACTIVITY. `additionalContext` reaches the model and is never used for owner-only text. `terminalSequence` lasts under 0.71 s and is not a channel. REASONED from M3.
5. **Results need both events (M6).** Any result column registers `PostToolUse` and `PostToolUseFailure`. REASONED.
6. **Show the gate's decision, not "what ran" (M9).** Until results are captured, LOCAL ACTIVITY says "CoAgent allowed / asked / refused", never "ran". REASONED from the M9 limit.
