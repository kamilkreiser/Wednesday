## 12. Findings
**M-1 (Major). With the mode on, a search whose root is the EMPTY path is allowed, and that root can hold credentials, gate files or excluded files.**
- What: `Grep`/`Glob` with `"path": ""` is classified as `SearchRoot { recursive: true }` on `NormPath::Uncertain { why: "empty path" }` (`src/action.rs:336-355` -> `src/path/mod.rs:113-115`). An uncertain root matches no rooted pattern, so it carries no `CredentialFolder`, no `gate_read`, no `may_read_excluded`; today it is a T2 card (`UnresolvablePath`), and in the mode [7d] turns that into `Allow(Bypass)`. Probes (`zz_qa_probes.rs`, mode live, either shell setting): `Grep {"path": ""}` from a home `cwd` -> ALLOW (the same call with NO path, which the classifier roots at `cwd`, is refused as a credential folder); `Glob {"path": ""}` from home -> ALLOW; `Grep {"path": ""}` from the workspace with `**/.env*` excluded -> ALLOW (with no path, or `"."`: refused as may-read-excluded). My generated run found the same 20 times.
- Why it matters: the classifier itself treats a missing `path` as "search the working directory"; whether the host also treats an EMPTY `path` that way is UNVERIFIED here (no host run was allowed). If it does, the agent searches the credential folders (owner ruling D1: credentials still refused), the gate's own folders (F-7) or the owner's excluded files (F-3, the Q-4 safe reading) with no card, by changing one character of its call. Even if it does not, the policy is deciding to allow a search whose target it says it cannot resolve, the one place where the mode turns "unknown" into "yes": everywhere else an unknown (untaught tool, odd spelling, unknown URL host for a grant) is never auto-allowed.
- Not the builder's fault in the narrow sense: R5 is a CLOSED list and defines the class as `a.may_read_excluded`, which the build honours exactly; the gap is that the pre-existing flag (and the rooted credential/hard-deny "below" matches) is never set for an unresolvable root, harmless before because steps [9]-[11] never auto-allow such a root.
- Smallest fix (needs the coordinator's ruling, since R5 is closed): in [7c], refuse a READ or SEARCH-ROOT target whose path is not `NormPath::Certain` (a new class "a path the gate could not resolve"), or at least a recursive search root that is not `Certain`; a `t21` row and a red control for it; one line in docs §2/§11. With the mode absent nothing changes (the new check sits inside [7c]).
