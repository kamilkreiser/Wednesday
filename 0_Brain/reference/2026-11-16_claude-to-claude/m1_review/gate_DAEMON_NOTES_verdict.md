## Findings

**F1 — Minor (borderline; read the last paragraph). The relay guard's new stderr lines can end the guard by a panic when the daemon is gone.**
- Where: `crates/coagent-daemon/src/relay_child.rs:672-675` (`eprintln!("relay-guard: end of input; …")`) and `:659` (`eprintln!("relay-guard: the relay exited by itself …")`), both in `guard_main`. Same class, daemon side: `:412` logs (via `crate::log!` = `eprintln!`) BEFORE `exited.send(RelayExited …)`.
- What: `eprintln!` panics when stderr cannot be written. The guard's stderr is a pipe whose reader is the daemon (`:326`, `:349-355`). When the daemon dies (crash, SIGKILL), the guard sees end of input, kills and reaps the relay, then writes the new line into a pipe with no reader → `EPIPE` → panic → exit status 101. Before the lane the guard returned 0 there.
- Reproduction (one command, needs an identity blob from any `--keep-relay-identity` data folder): `python3 -B gate_daemon_notes_tests/qa_guard_epipe.py <head bin dir> <relay-identity.key>` → `guard exit status: 101`, relay gone; with the base bin dir → `guard exit status: 0`; with `--keep-reader` (normal stop) both 0.
- Why only Minor: the relay is stopped and reaped BEFORE the line in both arms, so the property the rule protects (no relay left, no change to the stop/kill/reap path, the daemon's behaviour) holds in every path I ran; the guard is an orphan by then and nobody reads its status; Rust's default unwinding panic writes no crash report (none appeared). The daemon-side line at `:412` can only bite a daemon whose own stderr is broken, which the daemon's existing log lines already cannot survive.
- Suggested fix: write the diagnosis lines with `let _ = writeln!(std::io::stderr(), …)` (ignore the error) in `guard_main`, and in the daemon move the `:412` line after the `exited.send(…)` (or make `log::line` ignore write errors).
- Borderline: the brief lists "a diagnosis line that changes behaviour (the relay child's stderr aid must be lines only)" among the NO GO grounds. This line does change the guard's exit path in one circumstance. I grade it Minor because nothing that anyone or anything observes changes; if Friday reads the rule literally, this one item turns the verdict into NO GO, and the fix is two lines.

**N1 — Note. `timeout_s` wording vs clamping.** `crates/coagent-mcp/src/main.rs:288` (`WAIT_TIMEOUT_TYPE_TEXT`) and `:294-303`. The text says "a whole number from 1 to 300", but `0` → 1 and `1000` → 300 are accepted while `-1` and `30.0` are refused with that text.
