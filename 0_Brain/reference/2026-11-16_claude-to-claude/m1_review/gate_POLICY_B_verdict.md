## The two paragraphs for the owner (plain words)
**(A) What changed for you.** When an agent in a linked session writes a long search, a long instruction to another agent or tool, or the instruction text of a web fetch, the gate now checks every word of the first 1 200 characters against your list of files that must not be touched, not only the first 160 or so words. A file on your list named late in such a text is now refused, as an early one already was. The commonest example: a search or a web fetch that says "summarise the file .env for me" is now refused when `.env` is on your list; before, it asked you, and with your ALLOW setting a web fetch ran without asking. A file name written on its own line (after a line break or a tab) is now caught too. Commands run through the terminal tools (`Bash`, `PowerShell`, `Monitor`) answer exactly as before. One small extra: a tool the gate does not know, carrying a command together with other text, may now be refused when that other text names a file on your list.

**(B) What is not checked, and what is now refused.** Text after the first 1 200 characters of a prompt, search or tool input is still not checked against your list. A file name glued to other characters is still not caught, as before: with a full stop or question mark right after an exactly listed name (`.env.`), in brackets or stars (`[.env]`, `*.env*`), in curly quotes or a long dash, or inside Chinese or Japanese text written without spaces. New: a text whose first 1 200 characters hold too many short distinct words is refused as "too large to check" instead of being checked in part. Built texts (a 1 300-character chain like `a@b@c@…`, long option words like `-/a/a/a…`) are refused through every tool. One kind of ordinary text is refused too: a web fetch instruction holding 471 or more different single characters or very short words separated by spaces (for example a list of Chinese characters, emoji or kana to look up) is refused, where before it was asked; through a search or an agent instruction the same list is admitted, just under the limit. Every other ordinary text measured (logs, code, diffs, mail, tables, prose in eight languages, and 28 404 slices of this project's own files and history) is admitted, the largest at about half the limit. How long a decision takes in the build you run: at most about 40 to 60 thousandths of a second for the slowest text measured (about half a second only in the slower test build); for ordinary texts the new reading adds at most about 13 thousandths of a second with the default list.
