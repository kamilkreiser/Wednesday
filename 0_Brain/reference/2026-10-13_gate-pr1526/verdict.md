## Findings

**Majors: none.**

**Minor 1 - demo-service CORS website origin is unguarded.** `scripts/check-compose-stack-safety.mjs` section 6: for `demo-service.CORS_ORIGINS` the check only requires the value to differ between slots and to contain slot 2's *gateway* port; slot 2's *website* port is asserted for api-gateway only. Repro: in `docker-compose.yml:2185` change `${WEBSITE_PORT:-6881}` to `6881`; all guards and suites stay green (T3). Oracle: Product consistency (spot 3 says both origins move). Fix-shape: assert `web2` is in demo-service's value too (loop the includes check over the api-gateway and demo-service CORS values). Regression test: that T3 tamper.

**Minor 2 - the ".env then stack_env" ordering the code comments call load-bearing is untested.** `scripts/start-local.sh:103` vs `:130`. Repro: swap so `.env` is sourced after the stack_env block (T7); every guard and all three new suites stay green, while a stale `GATEWAY_PORT=6882` in `.env` would then beat the slot. Fix-shape: a cell in `ks1355_slot_blind_launchers.test.sh` that runs start-local with a stub docker, a `.env` holding `GATEWAY_PORT=6882`, slot 2, and asserts banner `6982` / `COMPOSE_PROJECT_NAME=secuura_slot2` (I did this by hand and it passes at head).

**Minor 3 - launcher census has named blind shapes.** `scripts/check-stack-safety.sh` (`_launcher_candidates`, ~lines 183-197): the detector needs `docker compose|docker-compose` and `up|run|restart|down` on one line, so a backslash-continued `docker compose \` + `up`, `$DC up` and `${compose_cmd} up` launchers are invisible (probes P3c v1, v2, v6), and a not-yet-`git add`ed file is invisible (P3a; fine in CI, matters only for a local pre-commit run). The comment promises "A NEW script that brings the platform stack up must fail HERE". Fix-shape: join continuation lines before matching, and either flag any script that defines a variable as `docker compose` or document the limit in the census comment. Regression test: the three shapes planted tracked.

**Minor 4 - exception list lacks a ticket on two entries; the check does not look for one.** `LAUNCHER_EXCEPTIONS` in `check-stack-safety.sh`: the two Akto entries have reasons only; the reasonless check (`*"|"?*`) accepts any non-empty text. Commit message and brief say "a reason and a ticket". Fix-shape: require a `KS-[0-9]+` or `PS-[0-9]+` token and add one to each entry.

**Minor 5 - narrow literal guard omits several slot-offset ports.** `check-compose-stack-safety.mjs` `SLOT1_HOST_PORTS` = 11434, 8881, 6882, 6881, 6433, 6432, 6379. `stack_env.sh` also offsets 6090-6094 (cardano mock/n2n/yaci/admin/submit). Repro: an env value `http://localhost:6090` on any service renders identically on all slots and the guard stays green (P2b). Not an instance today (my independent census found only the 6 listed), and `scripts/start-local.sh:276` still prints a literal `localhost:6092` "Cardano Devnet" line in the banner on every slot; the PR says KS-1381 widens it. Recorded so the widening has the list.

**Info 1 - stale/adjacent text.** `scripts/preflight/preflight.sh:12,16,37` still say "only when the local stack is up on :6882"; now true only when no slot is named. `Blockchain/Dev/Makefile:93` (production preflight) greps `^CORS_ORIGINS=` in `.env`; since `env.example` no longer carries the line, a fresh `cp env.example .env` now reports "WARNING: CORS_ORIGINS not set", where previously it reported "set" with localhost dev origins. The warning is arguably more honest for production, but it is a visible change.
