420: note cannot crash it**: the scan that feeds the note reads only regular files under a size cap, and the
421: whole note is wrapped so that any throw costs the note and nothing else. Round 1 of this change tried to
422: decide it BEFORE tsc ran, by resolving `typesVersions` the way TypeScript does; two gates found six shapes
423: where that differs (first-match versus longest-prefix keys, a version range other than `*`, a redirected
424: `types` field, extensionless and wildcard targets, a mixed array) and each exited 2 on a build tsc accepts.
425: Emulating a resolver was the wrong shape of answer. **Where tsc is NOT happy the resolver still matters**,
426: and it is not TypeScript's (it takes the first matching key, and reads only the `*` version range). So in
427: contrived shapes it can name the wrong file, or call a permanently-absent target "stale, rebuild it" — and
428: had such a `TS2307`/`TS7016` been **baselined**, that would refuse a push develop accepts. Both committed

431: admit one whose target is on disk at the time. The residue is ticketed.

433: type-checks cleanly and prints a note; and a subpath the package declares **no** declaration target for,
434: which is an import of something that does not exist and so is the author's own error, left to tsc.

460:   dev-only `fs.watch` hot-reload, and whether it fires **depends on how the spec
461:   was written** — an in-place rewrite (what `npm run generate-openapi` does) is
462:   picked up; a replacement (`mv`, `rsync`, an image rebuild) is not.
463:   **`api-gateway/src/index.ts` is the authority on that split — read the comment
464:   above `fsWatch(specPath, …)` rather than trusting a restatement here** (measured
465:   by Peter 2026-08-31; KS-659 tracks making the reload unconditional). Restarting is
466:   still the reliable move, because it works for both write shapes. Worse, after a
467:   `git checkout` the single-file bind mount keeps pointing at the **dead inode**
468:   the old file had: the container path becomes unreadable while
469:   `/api/docs/openapi.yaml` keeps answering **200 with the previous branch's
470:   spec**. Kamil hit exactly this — 1,152,555 bytes served against the branch's
471:   1,232,278. So compare `md5sum` of the served bytes against the host file
472:   rather than trusting a 200. **If the checksums differ the mount is dead, and a
473:   restart will NOT clear it** — a bind resolves at container *create*, so the fix
474:   is `docker compose -f docker-compose.local.yml up -d --force-recreate --no-deps
475:   api-gateway`. (Measured again 2026-09-02: after checking out a branch whose
476:   spec differs, `md5sum` inside the container answered *"No such file or
477:   directory"*; one `--force-recreate` and host and container agreed, healthy in
478:   ~6 s.)

516: ## Date/time standards — UTC everywhere (KS-201)
517: Every timestamp is a legally-significant artefact (on-chain anchoring, audit,
518: eIDAS/UETA), so date/time handling must be unambiguous and region-independent.
519: - **Containers run `TZ=UTC`.** Set on every backend service in
520:   `Blockchain/Dev/docker-compose.yml` and in the Azure bicep `commonEnvVars`
521:   (`deployment/azure/services.bicep`). Add it for any new service.
522: - **Don't rely on local-time Date methods or local-time date-fns.** Use
523:   `getUTCFullYear()/getUTCMonth()/getUTCDate()` (not `getFullYear()/getMonth()`),
524:   and UTC-explicit boundaries (`services/analytics/src/utils/utcDate.ts`:
525:   `startOfUtcDay`/`endOfUtcDay`/`startOfUtcMonth`/`endOfUtcMonth`) rather than
526:   date-fns `startOfDay`/`endOfMonth`, which operate in the process TZ.
527: - **Persisted/on-chain date strings must be deterministic.** Never build an
528:   NFT/VC/anchor date with `toLocaleDateString`/`toLocaleString` (locale + TZ
529:   dependent, and on-chain data is immutable) — format from UTC getters with
530:   fixed month names. UI-only display formatting may still use `toLocale*`.
531: - API responses keep `.toISOString()`; Postgres/Prisma already store `Date` as UTC.
