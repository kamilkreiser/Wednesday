## Plain answer for Kam
This round fixed what the last gate found. The script now refuses when the database pooler is pointed at another machine, in every way the last gate and this one tried for that setting, and it refuses whenever docker compose cannot be asked. It never showed a password in any of the 70 test variants or hundreds of runs, and a second run changes nothing. But the pooler takes five more settings (its connection limits) from the same files, and its start-up script copies them into its configuration file unchecked. A specially written value in one of them can add a second line that sends the pooler to a remote database, and the script does not look at those five settings, so it switches on the test accounts anyway. That needs a crafted value, nobody types it by accident, and whether the pooler obeys the second line was not tested. But it is the same kind of gap this round was meant to close, so it needs one more check before merging. Two smaller points can be ticketed: the check's sandbox can still run other programs on this Mac's old bash, and the test that lists the database settings only catches about half of the new ones it should.
