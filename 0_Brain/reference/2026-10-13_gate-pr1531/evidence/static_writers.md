## Conclusions

1. **No writer lets a caller make a FORGED row pass C1-C5 except the two named, not-closed paths** (both stated in the PR body):
   - **Parent belongs to someone else (deterministic, same tenant).** Request shape, as any write-role user or `certifications:write` connector in the victim's tenant:
     `POST /api/certifications/issue` `{"type":"verification_certificate","holderId":"<any existing user uuid>","parentDocumentId":"<victim document external_id>","data":{"contentHash":"<victim document content_hash>","issuerName":"<any display string, e.g. the victim's org>"}}`
     Result: derived row `doc-<ms>-<certId8>`, parent = victim doc, hash = victim hash, owner = caller = cert issuer. `verify(<victim hash>)` -> `isCertified: true`, `certificationId` = the caller's real cert, `certifiedBy` = the caller's string. Closed only by the write-side parent access check.
   - **32-bit external-id residual** via /version, /sign-cert, /sign-wallet: probability about N*M/2^32 for N genuine certs and M such rows; C5 confines it to an attacker who owns the source, or to **connector principals, where C5 is vacuous (NULL == NULL)**: any connector-registered (NULL-owner) source in the tenant and ANY connector-issued certification in the tenant pair up, regardless of which connector issued it. So for connectors, C5 does not bind actor to actor; the only binding left is C3.
2. **Connector cross-citation:** yes in principle, both NULL compare equal (`String(null ?? '') === ''`), so C5 never distinguishes connector A from connector B. It is reachable only through C3, i.e. through the certify route itself (which binds to its OWN new cert id) or the 32-bit residual. Not deterministic.
3. Checked and DISCARDED: an earlier draft of this file suspected a genuine certification without `type` would fail C4. It cannot happen on `/issue`: `body('type').isIn([...])` (`certifications.ts:118-133`) rejects a missing type.
4. The legacy `'certified'` sibling path is still trusted unconditionally by `siblingCertification` (`verification.ts:333`) and is the PR 1525 / KS-1561 surface.
