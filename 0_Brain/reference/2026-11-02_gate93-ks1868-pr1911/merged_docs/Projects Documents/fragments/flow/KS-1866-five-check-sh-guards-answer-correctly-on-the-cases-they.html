. Five check-*.sh guards answer correctly on the cases they exist to catch: root and no-USER Dockerfiles, node_modules walks, the untracked PII leg, Akto names behind docker flags (KS-1866)

What this changes. Five one- or two-line changes in Blockchain/Dev/scripts/ and one new shell suite for each. check-dockerfile-non-root.sh (line 27): \s, which BSD grep and sed (macOS) do not know, becomes [[:space:]], and || true keeps a Dockerfile with no USER from ending the script silently under pipefail. check-no-strictness-patches.sh (46) and check-connector-xss.sh (23): --exclude-dir=node_modules. check-no-pii-store.sh (56 and 64): --exclude-standard=false, which is not a valid option and hid its failure behind || true, becomes --exclude-standard, and the warning block no longer ends non-zero. check-akto-container-names.sh (82): docker exec -it akto-mongo and docker logs --tail=50 akto-testing are now flagged (option flags between the verb and the container name).
Five new suites in Blockchain/Dev/scripts/__tests__/ (check_dockerfile_non_root_reports_root, check_no_strictness_patches_skips_node_modules, check_connector_xss_skips_node_modules, check_no_pii_store_untracked_leg, check_akto_container_names_flags), each with controls that pass before and after. Four product hunks and four suites are Spark output applied strictly; the Akto line and its suite are a hand-applied golden whose escaping I checked byte for byte. One hand edit: the strictness suite spelled the banned flip in two printf fixtures, so the repo guard that scans scripts/*.sh failed on the suite itself; those two lines now write the same bytes through a %s argument (asserted equal), and the literal no longer occurs in the file.
