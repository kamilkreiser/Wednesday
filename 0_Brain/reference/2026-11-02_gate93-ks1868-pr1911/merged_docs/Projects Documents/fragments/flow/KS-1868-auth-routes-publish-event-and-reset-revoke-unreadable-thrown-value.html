. The auth routes log a constant reason when a thrown value cannot be read: register and login event publish, reset-password session revocation (KS-1868)

What this changes. In Blockchain/Dev/services/auth/src/routes/auth.ts, three catch blocks read the thrown value with err instanceof Error ? err.message : String(err) inside their logger.error call (lines 306, 612 and 880 of the base): the .catch on the fire-and-forget publishEvent of POST /register and of POST /login, and the session-revocation catch of POST /reset-password. A thrown value that cannot be read (a revoked Proxy throws on instanceof; an Error whose message getter throws) made that read throw. Each read now sits in its own try and falls back to the constant unreadable thrown value. 1 product file, +25/-3.
Register and login. Before: the log call threw inside the .catch handler, so the promise it returns rejected with nothing to handle it, an unhandled rejection after the 201 or 200 had already been sent (the red cells count 1). The auth service installs no unhandledRejection handler (only the gateway and originate do; the gateway also sets UNHANDLED_REJECTION_MODE=survive in compose) and its image is node:24-alpine, where Node's default would end the process (read from the source and the Dockerfile, not run). After: the constant is logged, 0 unhandled rejections, and the response is unchanged. Today publishEvent swallows its own errors (a bare catch in events.ts), so this .catch is not reached with a real value: defence in depth.
Reset password (tier 1: a public pre-auth route). Before: an unreadable throw from revokeAllUserSessions escaped the catch as a TypeError and the route answered 500 INTERNAL_ERROR, with the new password already written, the other sessions not revoked and the reset link not burned. After: the 503 SERVICE_UNAVAILABLE (Your password WAS reset, but your other sessions could not be ended ...) that an ordinary revocation Error already gets, with the same persisted state: password written once, link not burned (the cells assert the status, the code, the message and both counters).
What does not change: an ordinary Error is logged with its own message and gets the same answers as before; the 503 text; the err?.message reads at lines 372, 547, 587 and 768; and the same-shape reads elsewhere in the service (routes/users.ts change-password at line 1030, issuerCerts.ts, issuerCert.ts, issuerCertSweep.ts, oauthState.ts). Three new test files, 12 cells. Two product hunks apply only under git apply -C1 (see Proof).
