. analytics export and scheduled-job loaders keep logging when the thrown value is unreadable (KS-1868, analytics)

What this changes. Two startup loaders in Blockchain/Dev/services/analytics: ExportService.loadFromDb (src/services/exportService.ts) and loadScheduledJobsFromDb (src/services/scheduledJobs.ts). Each catch read the thrown value with err instanceof Error ? err.message : String(err) and no guard. If the value is a revoked Proxy, or an Error whose message getter throws, that read throws inside the catch: the WARN is never logged and the loader rejects instead of starting with its empty or default store. Each read now sits in an inner try with the fallback unreadable thrown value; the WARN texts, the error key and the value logged for any readable thrown value are unchanged. Product bytes: +7/-1 in each file. exportService.ts line 160 (the message stored on the export record returned to clients) and the dbSaveExport, dbSaveAlertRule and dbSaveAlert catches are different sites and are not touched.
Six new cells in two new files (ks1868-export-service-load-unreadable-throw.test.ts and ks1868-scheduled-jobs-load-unreadable-throw.test.ts, 3 cells and +60 lines each): a control that an ordinary Error still logs its message (C1), and red cells for a revoked Proxy (R1) and a throwing message getter (R2). Both product edits are held Spark passes (O40-P1, O40-P2) applied with strict git apply --check -p1 (rc 0 on all four sections, rc 1 on a copy with one context line's content corrupted); there is no hand edit.
