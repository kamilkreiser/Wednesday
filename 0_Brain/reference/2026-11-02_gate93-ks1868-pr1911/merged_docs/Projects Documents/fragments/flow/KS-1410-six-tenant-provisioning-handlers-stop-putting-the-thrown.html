. Six tenant-provisioning handlers stop putting the thrown text in their 500 answer (KS-1410)

What this changes. Blockchain/Dev/services/tenant-provisioning/src/index.ts (+12/-6, six catch blocks). A response-shape text change: the 500 answer of GET /api/tenants, GET /api/tenants/:id, PATCH /api/tenants/:id/status, PATCH /api/tenants/:id, DELETE /api/tenants/:id and GET /api/audit-log used to carry the thrown text in error.message; each now logs it with console.error('[provisioning] <method> <path> failed:', message) and answers the constant An unexpected error occurred. The key set of the body is unchanged (success, error.code, error.message). POST /api/tenants (the key-generation path) is not changed: its 500 still carries message: message, and the new test pins that.
New test ks1410-provisioning-500-never-echoes-the-thrown-text.test.ts, 6 cells, a source-text guard (the module starts a server and a pool on import): P1 to P3 are RED (no 500 outside POST /api/tenants names a caught value; each of the six answers the constant; each of the six logs the thrown text just before it answers); C1 to C3 are controls (the scanner flags a leaking answer and passes the constant one; the file has exactly seven 500 answers and the POST one is untouched; the three 400 validation answers keep their details).
