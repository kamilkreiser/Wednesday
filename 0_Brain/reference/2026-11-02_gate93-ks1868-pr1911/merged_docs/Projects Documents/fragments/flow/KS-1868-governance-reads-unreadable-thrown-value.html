. governance DB read helpers log and return their empty value when the thrown value is unreadable (KS-1868, governance)

What this changes. Five helpers in Blockchain/Dev/services/governance/src/services/governanceService.ts: dbGetProposal (reached through getProposal), dbGetAllProposals (getProposals), dbGetAllParticipants (getParticipants), dbGetActiveDelegations (revokeDelegation) and the exported getTotalVotePower. On a failed database read each logs an ERROR line and returns its empty value (undefined, [], [], [], 0). Each read the thrown value with err instanceof Error ? err.message : String(err) and no guard, which itself throws for a revoked Proxy (instanceof throws) or for an Error whose message getter throws; the helper then rejected without logging. Each read is now in an inner try with the fallback 'unreadable thrown value'. The log text, the level and the value each helper returns are unchanged (+35/-5 lines, +7/-1 per site, in the one product file).
Five new test files, 54 lines and 3 cells each (15 cells): each takes the helper through the real exported function against a ../db stand-in whose query rejects with the value under test. Per file, a control that an ordinary Error still logs its message and returns the empty value (C1), and two red cells, a revoked Proxy (R1) and an Error whose message getter throws (R2), that must resolve the empty value and must log the constant reason. dbGetActiveDelegations is not exported, so its cells go through revokeDelegation('d-1') and also depend on that function resolving undefined for an empty list. The product file and the test bodies are the held Spark passes O43-P2 and O44-P1 to P4, applied in old-line order with strict git apply --check -p1 at the base. One hand edit, approved by the coordinator at 22:03 AEDT on 1 Nov: each of the five test files carries one added line, export {};, after its header comment. It makes the file a module so a whole-program tsc does not see a redeclared global; it changes no behaviour.

.3 What this does not prove

Five sites, not the ticket; and what the one-line edit does and does not do. KS-1868 stays open: it lists 253 catch and log sites that read a thrown value unguarded; this change covers five, in governance. Seven more unguarded reads remain in the same file (the three save helpers, which rethrow; dbGetParticipant; dbGetParticipantByAddress; verifyDbReady; processExpiredProposals). KS 1732 names the same five catch lines for a different defect (a failed read answers as empty and the active-proposal cap fails open): this change keeps that behaviour exactly, and a later KS 1732 change must rebase over it. The guard protects a read that throws, not one that returns a non-string (the class KS 1904 tracks for the sites already merged).
The one-line edit: as the operators wrote them, the five new test files each declared top-level mockHolder and ERRORS and had no import or export, so tsc over a program that held all five reported 10 TS2451 (cannot redeclare block-scoped variable), 2 per file; the untouched tree reports 0. Each pass alone declares each name once, so the single-pass proofs could not show it. export {}; in each file removes it. It is not what keeps the push green: jest compiles each file alone and passed 15 of 15 before and after, and no push gate type-checks governance tests as one program (the test-types ratchet covers auth, api-gateway, vc-issuer, security and m365-integration only). Not run: a booted governance service, the four platform suites (Schemathesis, Akto, Playwright, Performance/k6), Node 24 or any LTS Node, any deploy.
