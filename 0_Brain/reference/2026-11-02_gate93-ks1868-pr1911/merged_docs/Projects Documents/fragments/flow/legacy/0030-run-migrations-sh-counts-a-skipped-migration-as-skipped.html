41. run-migrations.sh counts a skipped migration as skipped, not applied (KS-808)

41.1 What this row is, and what it is not

The deploy-path migration runner Blockchain/Dev/scripts/run-migrations.sh printed Summary: applied=N failed=N, where applied counted every file apply_one returned 0 for. It returns 0 for an already applied skip as well as for a real apply, so a re-run over an up-to-date database reported every migration as applied. Only the summary counter moves. A skipped_count is counted on the skip path (built :122), initialised before the loop (:148) and subtracted from applied_count before the summary (:175); the summary line gains skipped=N (:176). apply_one's return codes, the loop, the KS 1031 exit 3 block (built :197) and all SQL are unchanged. This is defect (2) of KS-808 only: the exit code (defect 1) is handled under KS 1031, and the tracker citation (defect 3) was PR #1229. KS-808 stays open; a live run is owed (41.4).

41.3 Who reads the summary line

The only code consumer is run_migrations_failure_exit_code.test.sh:82, which matches Summary: applied=2 failed=0 as a prefix. The added skipped=N keeps it green (7/7 above). The closing line Migration runner finished (applied=…, failed=…) keeps its format; its number is now the true apply count. Runbook and guide prose that still describes the old line is listed in the PR and is not edited here.

41.4 What is NOT proven

A runtime-behaviour change is not done on offline green. The runner ran only against stubbed psql under macOS sh. The migrations container's own /bin/sh against a real PostgreSQL with a skip present is a live run owed, and because the runner ships inside the migrations image (built from services/originate/Dockerfile) that run needs the image rebuilt. The four platform suites (Schemathesis, Akto, Playwright, Performance/k6) are unmeasured here. Timings: this change alters no timing this document carries.
