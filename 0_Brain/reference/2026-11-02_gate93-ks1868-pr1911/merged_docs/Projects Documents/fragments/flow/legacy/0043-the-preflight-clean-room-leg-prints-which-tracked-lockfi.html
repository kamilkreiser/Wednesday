53. The preflight clean-room leg prints which tracked lockfiles it did not install (KS-1426)

What this adds. Blockchain/Dev/scripts/preflight/lockfile-cleanroom.sh (preflight leg 2) prints All N standalone lock(s) pass clean-room npm ci.. The N counts the locks that a find over four directories (services packages frontend scripts) reaches. A new function, report_surface, runs after that line when the leg was started with no arguments. It asks git for the tracked package-lock.json files, prints how many of them the leg installed, and lists the paths of the rest. It runs with git’s own list of repository-local variables unset (git rev-parse --local-env-vars), in a subshell. A pre-push hook that runs in a linked worktree has GIT_DIR exported to it, and with GIT_DIR set git rev-parse --show-prefix prints an empty string at rc 0 while ls-files still lists repository-relative paths, so no lock matched and the line read 0 of N on those pushes.
It reports. The wrapper ends in return 0 whatever its subshell does, and the leg’s own exit-code lines are not edited. It does not change what the leg installs: the find line still names the same four directories, so the install-widening the ticket discusses is a later change.
The ticket’s own “Not claimed” section declines a fix and does not claim any lock is broken. This change refs the ticket and does not close it. A live run on a developer machine and on CI is owed.
