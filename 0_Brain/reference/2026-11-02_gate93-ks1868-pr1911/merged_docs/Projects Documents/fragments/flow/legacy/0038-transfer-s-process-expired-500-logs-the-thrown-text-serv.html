47. transfer's process-expired 500 logs the thrown text server-side instead of returning it (KS-1410)

47.1 What this row is, and what it is not

POST /api/delegations/admin/process-expired answered 500 with message: error.message, so the thrown error's own text reached the client's body, with no NODE_ENV guard on that route. The handler now calls logger.error with the route named and answers the constant Internal server error in an unchanged INTERNAL_ERROR envelope. The log call sits inside the handler's if (error instanceof Error) branch, so it is that branch which logs error.message; a non-Error throw still falls through to next(error) and does not reach this line. This row therefore makes no claim about how a thrown non-Error is rendered anywhere else. Scope is services/transfer/src/routes/delegations.ts at the single 500 site; the four 4xx error.message sites in the same file are untouched by this pass and are a separate decision. The api-gateway slice of this ticket is row 36.; the audit-export slice is a separate pass in lane R.

47.2 The cells, and the numbers that back the row

Six new cells in src/__tests__/ks1410-delegations-process-expired-500.test.ts. T1 runs in three NODE_ENV values (production, development, test) and asserts the thrown message is absent from the 500 body. T2 asserts the message is logged once, server-side, with the route named. TC1 and TC2 are controls: a success still answers 200 with the expired count and logs nothing, and the revoke route still answers 404 NOT_FOUND with its business message. Measured by Seat G 7th on develop 613070f29112, by npm test (vitest 4.1.11, read from node_modules) in services/transfer on node v24.7.0 with npm 11.5.1: the suite reads 79 cells passing at the base and 85 passing after. With the test file applied and the product change withheld, 4 of the 6 new cells fail (T1 in all three environments, and T2) and the two controls pass; with the product change, 6 of 6 pass, each enumerated by name from vitest's JSON reporter rather than inferred from the suite total. tsc --noEmit (TypeScript 5.9.3) reads rc 0 for the package and, through a pinned-typeRoots config that lists the test file, for the test file too; a planted TS2322 in a copy inside rootDir fires, so that rc 0 is not a vacuous pass. A live run is owed: this is a runtime behaviour change proved offline only, so the ticket does not move to Done.
