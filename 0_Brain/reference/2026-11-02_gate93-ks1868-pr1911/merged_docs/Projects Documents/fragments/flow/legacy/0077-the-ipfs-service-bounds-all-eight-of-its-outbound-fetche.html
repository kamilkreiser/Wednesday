88. The IPFS service bounds all eight of its outbound fetches, and a gateway body that stalls answers 503 (KS-1240 part 3)

What this changes. KS-1240 part 3, services/nft-certificate/src/services/ipfs.service.ts: eight outbound fetch calls (Pinata upload, pin and unpin; Infura add, pin/add and pin/rm; Web3.Storage upload; the gateway read in IPFSService.fetch) carried no timeout, so a provider or gateway that accepted the connection and then went quiet held the caller for as long as the socket lived. Each call now passes AbortSignal.timeout: 60 s for the three uploads, 15 s for the four pin and unpin calls, 30 s for the gateway read. On expiry the handling each call already had answers: an upload returns { success: false }, pin and unpin return false, the gateway read throws ServiceUnavailableError (503).
The gateway body read moved inside a try. response.arrayBuffer() sat outside the try that maps a failed connect to 503, so a gateway that sent its headers and then stalled the body, or dropped the connection part-way through it, surfaced as the raw error (TimeoutError or TypeError: terminated, neither carrying a status) and not as the 503 the method’s own comment promises. The read now maps any body failure to the same 503 and logs IPFS gateway body read failed.
Scope, and a trade-off. The ticket text names only the api-gateway key-validate fetch; this part was added by the coordinator’s brief, not by the ticket. An object the gateway needs more than 30 s to deliver now answers 503 where it used to wait.

Measured at base bd6697e079fc, 2026-10-28 (UTC), Kamil’s MacBook Pro (Mac14,5, Apple M2 Max, 32 GB), shared with other sessions. The new test file (15 cells: five gateway-read cells over a real local http server, seven provider cells over a stubbed fetch that honours init.signal, one bounds cell, one source scan and one scanner control) against the UNFIXED service: 12 failed / 3 passed, the three passes being the controls.

The seven provider calls each hang against an endpoint that never answers, and the source scan lists all eight call sites as unbounded (lines 70, 105, 123, 166, 195, 208, 239 and 463).

88.3 What the cells prove, and what they do not

The status mapping and the requested bounds, not production timings. The gateway cells drive the real fetch (the undici built into Node) against a real local server with the bound shortened to 150 ms by wrapping AbortSignal.timeout; the bounds cell pins the lengths the service actually asks for (3 x 60 s, 4 x 15 s, 1 x 30 s). The provider cells prove each call carries a signal and keeps its existing failure answer.
Not covered. A real provider endpoint; a real network connect timeout (the silent-gateway cell is connected and then silent, not an unroutable address); the routes that call this service, and how they present success: false after 60 s; Node 24; a running stack; the four platform suites (Schemathesis, Akto, Playwright, Performance/k6). The change is not deployed.
The other nft-certificate files are untouched.
