55. Six POST request bodies are declared required in the published contract (KS-591)

What this fixes. Six POST operations in three services published a request body that was not marked required: POST /api/anchors and POST /api/anchors/thread-mint (anchoring), POST /api/stake/complete-unstake (staking), and POST /api/transfers, POST /api/delegations and POST /api/delegations/validate (transfer). A spec-driven caller such as Schemathesis may therefore send no body at all. These six belong to the KS-591 positive_data_acceptance register.
Each request body now carries required: true in its *.openapi.ts file (anchoring.openapi.ts, staking.openapi.ts, transfer.openapi.ts), with one comment line above each changed line that carries the key. docs/openapi/secuura-api.yaml is regenerated by npm run generate-openapi, never hand-edited: 6 insertions, 0 removals, each a required: true under one of the six operations.

55.1 Scope: the published contract only

What is and is not carried. A declaration and nothing else: the only change to the three *.openapi.ts files is the required flag on those six bodies plus the comment line above each. No handler or route file is touched. This declares the body required in the published contract; it does not make any handler refuse anything.
UNMEASURED: what each of the six handlers does today when the body is absent, and whether any runtime path reads the regenerated spec. git grep over service and package source finds no OpenAPI request-validation library and no reader of the yaml other than comments; the api-gateway depends on swagger-ui-express, which was not traced.
