111. Platform S’s signature hash is accepted on the sign verb, anchored verbatim and read back (KS-1454)

What this changes. In anchorSchema.ts the anchor request’s metadata gains an optional signatureHash: the plain SHA-256 of Platform S’s detached .p7s, exactly 64 lowercase hex characters. A refinement answers 400 when it arrives on any verb but sign, or with no verb, so a stray hash is never anchored as if it named a signature. On a sign anchor it is written into the anchored metadata payload verbatim, beside documentType.
In anchorReadback.ts a new pure function anchorSignatureHashView reads the string back from secuura.signatureHash; a value that is not a string, or no key at all (every anchor that predates the field), reads null. The verify-by-hash response builder includes it, and in index.ts the GET /api/anchors/:id handler spreads the same view (one import and one spread line). Product diff: +12 -0 in anchorSchema.ts, +12 -0 in anchorReadback.ts, +3 -1 in index.ts.
New test file ks1454-signature-hash-is-accepted-and-anchored-on-the-sign-verb.test.ts (+80 lines, 14 cells). R1: a sign anchor carrying the hash is accepted and anchored verbatim. R2: the same hash on an upload anchor is refused. R3: a hash with no documentType is refused. R4: six malformed values are refused (uppercase, 63 characters, 65 characters, non-hex, a number, an array). R5: the anchored hash reaches the Cardano metadatum as one string, not an array. C1 to C4 are controls: a sign anchor with no hash, an upload anchor with no hash, a body with no metadata, and a hash beside an identityCommitment all behave as before.
New test file ks1454-signature-hash-is-read-back-on-the-verify-and-by-id-reads.test.ts (+81 lines, 9 cells). B1 and B2: the view returns the hash from a database-form payload and from one that went through the chain codec. B3 and B4: verify-by-hash carries it under metadata.signatureHash beside documentType, from the database source and from the chain source. B5: the by-id handler imports and spreads the view. C1 to C4 are controls: no hash reads null, a value that is not a string is not surfaced, the identity read-back is unchanged, and the block located in index.ts is the one by-id handler.
