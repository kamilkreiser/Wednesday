56. Five POST request bodies are declared required in the published contract (KS-1364)

What this fixes. Five POST operations in three services published a request body that was not marked required: POST /api/analytics/exports (analytics), POST /api/teams/webhook-config and POST /api/teams/notify (m365-integration), and POST /api/batch/certifications and POST /api/batch/delegations (api-gateway). A spec-driven caller such as Schemathesis may therefore send no body at all. These five belong to the KS-1364 class, request bodies that are not marked required: true.
Each request body now carries required: true in its *.openapi.ts file (analytics.openapi.ts, m365-integration.openapi.ts, api-gateway.openapi.ts), with one comment line above each of the five changed lines that carries the key. docs/openapi/secuura-api.yaml is regenerated by npm run generate-openapi, never hand-edited: 5 insertions, 0 removals, each a required: true under one of the five operations.

56.1 Scope: the published contract only

What is and is not carried. A declaration and nothing else: the only non-test source files that change are the three *.openapi.ts files and the regenerated yaml. No handler or route file is touched. This declares the body required in the published contract; it does not make any handler refuse anything.
UNMEASURED: what each of the five handlers does today when the body is absent, and whether any runtime path reads the regenerated spec.
