12. GET /api/anchors/:id reports blockNumber as a number (KS-1333)

What this pins.services/originate/src/services/anchorStateSync.ts has four writers that persist blockHeight: anchor.blockNumber || 0 without shaping the value, and anchor.blockNumber arrives from GET /api/anchors/:id.
KS-1333's first step is to measure whether that route can hand them a raw pg int8 string.
Measured at source: it cannot. rowToAnchor converts block_number through Number() (services/anchoring/src/index.ts:1317), and the handler answers the mapped anchor.blockNumber || null rather than the raw row.
So the route answers a number or null, and the ticket's own rule applies — a recorded reason and a cell pinning it, not a coercion. This block is that cell.

12.1 The cells, and why the guard is source-text

Three cells in services/anchoring/src/__tests__/ks1333-get-by-id-blocknumber-is-a-number.test.ts. index.ts calls app.listen at import, so no test imports it; the guard therefore reads index.ts as text over the two lines that make the answer a number. B1 pins the Number() conversion in rowToAnchor. C1 pins that the handler answers the mapped value and never row.block_number. C2 pins that the by-id lookup maps its row through rowToAnchor at all — without C2, B1 could pass while the handler read a different row path entirely.
