What this changes. Akto 2.41.6 → 2.42.6: both 2.42.6_local tags were pushed to Docker Hub on 2026-10-30; 2.42.3 and 2.42.5 are dashboard-only. At v2.42.6 the dashboard’s login.jsp still carries the plan-gate line at line 120 and apps/testing is still git tree 9de6d35d, so the TEMPORARY plan-gate workaround and the service-log note carry over, re-verified rather than relabelled. akto-puppeteer-replay 1.51.2 → 1.51.3; mongo:7.0.45 stays (Akto v2.42.6 still pins mongo:7.0.4). npm: knip 6.44.0, fast-uri 4.2.3, and oxlint 1.90.0 / oxlint-tsgolint 7.0.2005 in all five systemTest packages that pin them, with @oxlint/plugins 1.90.0 in systemTest/oxlint (missed in the first pass, caught by the docs audit, now inside the lockstep test). observability/, a standalone package outside systemTest, moved to oxlint 1.90.0 as well (Peter, 2026-10-30; its 77 tests and lint pass), and the lockstep test now holds it to the same version. Akto released v2.42.7 at 09:29Z the same day, but at 10:59Z only the dashboard had 2.42.7_local (testing: 404), so 2.42.6 is still the latest matched pair; Peter ruled to stay on 2.42.6 for this change.
The minimum. Every npm range’s floor is the version installed (dependencyFloors.test.ts), and npm run start refuses an AKTO_IMAGE_VERSION / AKTO_DASHBOARD_VERSION / AKTO_TESTING_VERSION below the pin, from the shell or .env (scripts/assert-akto-version-floor.sh). A newer override is still allowed.
The tooling. update-akto-images.sh reads up to five pages of tags per image (a note when it stopped early but still found the pair; a warning when it did not) and names package.json as the pin; aktoPinDocMirrors.test.ts checks the 14 prose copies of the pin; systemTest/CLAUDE.md names the right test for each copy; and the harness re-uses one dashboard login per process and keeps a per-slot ledger of login times (no token), refusing at once, with docker restart <dashboard> as the remedy, when Akto’s 10-per-hour budget is spent. The ledger follows Akto’s own refill: Refill.intervally(10, Duration.ofHours(1)) in its RateLimitFilter (v2.42.6, identical at v2.41.6) puts all 10 back at once on each full hour from the first login after the dashboard starts, so the ledger counts those hours, not a sliding 60 minutes.
New templates and categories are scanned. A stale template catalog now blocks scanning: test:pr, test:pre-merge and test:security run check-test-ids first, and npm run start exits 1 at its end. It used to warn only, because CI blocked staleness, and CI is retired. test:security selects every catalogued template, so a regenerated catalog is all a new template or category needs. At 2.42.6 the catalog is byte-identical to 2.41.6’s: 213 ids, 21 categories.
