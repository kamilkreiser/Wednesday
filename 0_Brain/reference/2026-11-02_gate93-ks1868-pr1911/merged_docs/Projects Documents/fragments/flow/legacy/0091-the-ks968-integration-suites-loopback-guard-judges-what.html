102. The ks968 integration suite’s loopback guard judges what the pg client will dial, and the file type-checks (KS-1494)

What this changes. KS-1494 items 1 and 4, test-only. The guard in services/auth/integration/ks968-platform-admin-seed-with-both-rows.integration.ts asked new URL(RAW) for the host and the database name. The pg client resolves the same string differently: a ?host= or ?port= in the query string overrides the authority, a DSN that names no port dials 5432, a unix-socket ?host=/path makes new URL throw, and hostaddr is ignored by pg but honoured by libpq. The suite truncates users and pii_subject_keys, so a guard that reads the wrong host is a guard that does not guard.
The guard now builds a pg Client from the DSN (no socket opens until connect()) and judges what it reports: a loopback host, a usable port that is not a shared-stack port (5432, 6432 and 6433, plus whatever docker-compose.yml publishes for Postgres and pgbouncer), and a database whose name starts with ks_. A DSN that names a hostaddr, in any case or percent-encoding, is refused, and so is one the client cannot parse. It never calls new URL, so no DSN shape escapes as a bare TypeError.
Same decision as KS 1340 (pull request 1790, head 3a9b1c121f6d), minus the two gaps its gate 8 found (KS 1795): 6433, the shared stack’s pgbouncer port, is refused, and the hostaddr test matches its key without regard to case or percent-encoding.
Item 4: the file’s 4 tsc errors (TS2493 x3 and TS2352 x1 on the err.mock.calls destructurings) are cleared by one named type, errorCalls, with no @ts-ignore. The four hooks moved into the describe of the six real-Postgres cells so the new guard cells run without a database. Items 2, 3 and 5 of KS-1494 and userRepo.ts are not touched.

102.3 What this does not prove

A host, port and name check, not proof the database is disposable. Not run: the four platform suites (Schemathesis, Akto, Playwright, Performance/k6), a running stack, Node 24 (this host has only Node v26.8.1), and the 36-cell file as a whole against a real Postgres.
The shared-stack list holds the default ports. A stack started on another slot publishes other ports (KS 390), and a DSN aimed at one of those with a ks_ database name is accepted, as it was before. integration/README.md still says the suite refuses “any host other than loopback and any database whose name does not start with ks_”; it now also refuses shared-stack ports, a hostaddr and an unparseable DSN. The README is not edited here.
A ?port= naming a free loopback port is accepted and judged on THAT port, not the authority’s, as in KS 1340. Gate 11 measured that its mutant U16 (adding 0.0.0.0 and 127.0.0.2 to the loopback list) still passes every cell; it is an Info finding and this change does not pin it.
