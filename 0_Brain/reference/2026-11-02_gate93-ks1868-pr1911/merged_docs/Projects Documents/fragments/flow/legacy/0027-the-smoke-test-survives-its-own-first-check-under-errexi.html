37. The smoke test survives its own first check under errexit (KS-1139)

37.1 The defect, and why it hid on this machine

pass(), fail() and warn() in Blockchain/Dev/scripts/smoke-test.sh counted with ((PASS++)). A post-increment from 0 evaluates to 0, so the arithmetic command returns status 1. The script runs under set -euo pipefail, and bash 4.1 and later apply errexit to (( )) — so on a Linux runner or the Ubuntu demo VM the script died at its FIRST check and printed nothing after it. macOS /bin/bash 3.2.57, which is what this host ships, ignores that status, which is exactly why it passed locally and was unusable as a deploy check. All three helpers now use X=$((X + 1)), which never returns non-zero.

37.2 Red-first, and what the surviving cells mean

The new suite reads each helper's counter statement out of smoke-test.sh and drives the script under errexit. At the base: 3 passed, 3 failed, rc 1. With the fix: 6 passed, 0 failed, rc 0. The three that pass in BOTH states are the controls — a degraded run still counts, a down service still fails — and the total staying at 6 across both arms is what shows the cells executed rather than the suite failing to load. The sibling smoke_test_degraded_warns.test.sh reads 5 passed, 0 failed, unchanged.

37.3 What this row does NOT prove

The defect only bites on bash >= 4.1. This host has no such shell — /bin/bash is 3.2.57 — so the failing-before behaviour was never reproduced here; it is read from the shell's documented errexit semantics and corroborated by a reviewer's own rc-1 measurement on bash 5.2, which is his figure, not mine. A run on bash >= 4.1 is owed, and the ticket does not move to Done. The three scripts/validate-env.sh sites named in review are out of scope here and still OPEN: they need their own ticket and their own pass.
