13. A failed webhooks list query answers 500, not 200 with an empty list (KS-1345)

What this pins.GET /api/webhooks chained .catch() onto its list query and returned 200 { success: true, webhooks: [] } on failure, so a database error was indistinguishable from "this organisation has no webhooks" — to the client, and on this route to the log as well.
That .catch is gone.
A rejected query now reaches the route's existing fail500: a constant 500 body, the error logged once server-side, never a 200 with an empty list.
Numbering. This block is 13 and the document has no 12 yet.
That is deliberate, not a gap to be closed: block numbers belong to tickets, not to merge order.
12 is reserved for KS-1333, which is raised separately; whichever lands first, each block sits in number order and nothing is renumbered.
