61. Leg 14’s comment filter is pinned by a fixture hook carrying a commented control (KS-1746)

What this pins. Blockchain/Dev/scripts/preflight/preflight.sh:722 is the filter — grep -vE '^[[:space:]]*#' "$hook_src" — feeding :723, which extracts ${NAME:- reads from the pre-push hook so leg 14 can strip them before running the shell suites. A control named only inside a comment must not be derived and must not be stripped. No product file changes. The ticket is a missing cell, not a wrong filter: the code’s own comment at :709-713 states the hardening has no behaviour change on today’s hook, and that statement was re-measured here and is accurate. preflight.sh hashes bae62e73e2b087142b0c1fec1a9fedb155259d53907db5459e806e3d756a99f5 before and after this change.
The whole change is one file, Blockchain/Dev/scripts/__tests__/preflight_deps.test.sh: a third hook-stub mode on the existing preflight_fixture_run fixture, one extra reporting line in the fixture stub suite, and seven cells. .dockerignore:14 is **/__tests__, so the file reaches no image; of 35 Dockerfiles the only COPY lines naming scripts are originate’s run-migrations.sh (:47, :67) and auth’s own services/auth/scripts (:67), with 286 COPY lines across those Dockerfiles as the positive control that the matcher works.

61.1 Why no cell was possible against the real hook

The behaviour is unobservable on the shipped hook. On .githooks/pre-push the only ${NAME:- match is live code at :77 (if [ "${ALLOW_FORCE:-0}" = "1" ]; then), so excluding comment lines yields the identical derived set [ALLOW_FORCE]. With the filter present or absent the output is the same, which is exactly why G2 survived every one of the 68 cells. A cell therefore cannot be written against the real hook at all; it needs a hook that carries a commented control, and no fixture mode wrote one.
The new commented mode writes a hook with both: a comment line beginning with # that names a control the hook never reads, and the live ALLOW_FORCE read. The derived set must stay [ALLOW_FORCE]; with the filter gone it becomes [ALLOW_FORCE FAKE], because the derivation ends in sort -u and FAKE sorts second. The commented line must start with #: that is what the filter keys on, and a ${NAME:- inside a trailing comment is not excluded.

61.2 Two oracles, and why the behavioural one needs FAKE set

The announcement alone would not have been enough. Oracle (a) is the line leg 14 prints: the derived set must read exactly ALLOW_FORCE, asserted as a whole line so an extra name, a missing name or a reworded line all fail. But this is leg 14 describing its own work, and that is precisely what the earlier mutant M3 (announce the controls, strip nothing) was able to fake while surviving the gate at 61/61.
Oracle (b) is read from the stripped side, in the shape KS 1643’s Minor 2 established for ALLOW_FORCE: FAKE=1 is placed in the caller’s environment and the fixture stub suite must still see it, because a commented control is never added to env_clear. The stub reports its own environment, so this does not read leg 14’s words.
Why (b) needs FAKE SET. env -u on a variable that is already unset is indistinguishable from not stripping it, so an unset probe reads <unset> on the real tree and under G2 and discriminates nothing. One cell asserts that vacuity directly — with FAKE unset the probe reads <unset> either way — so a later edit cannot quietly simplify the FAKE=1 out of the arm above it and leave a dead test behind.
