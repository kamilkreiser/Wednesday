113. Another tenant’s anchor reads exactly as an absent one on GET /api/anchors/:id and /document/:documentId (KS-1822)

What this changes. The two anchor reads had no tenant check: behind jwtAuthenticate() only, with unscoped row reads, so any authenticated caller read another tenant’s anchor (content hash, transaction, anchored identity and signature hash) by anchor id, through the document-id fallback, or by document id. A new anchorReadGate.ts (+147 lines) applies the write side’s ruled decision table (KS 1603) to the reads: it refuses only a row whose document is held by a documents row in another tenant, and allows, by name, the caller’s own tenant, a flat anchor no document holds, a caller with no usable tenant claim, and a probe fault (fail-open, one warn line). It imports readIdOwners and isUuidShaped rather than copying them.
A refusal answers the 404 the same request gets when no row exists, status and body byte for byte, never a 403, so it tells the caller nothing about whether the anchor exists. The server log line names the document id and both tenants; the response names neither. index.ts: one import and one gated early return per handler, each with a one-line comment (+6 -0); on the by-id route the gate sits after both lookup paths, so the fallback is covered.
New test file ks1822-a-foreign-tenants-anchor-reads-as-absent.test.ts (+340 lines, 12 cells) drives the real app with a real RS256 bearer and the database boundary mocked (the real readIdOwners runs against a fake client). R1 to R3: the foreign row is refused on the anchor id, the document-id fallback and the document route, each byte-identical (status, content type, length, ETag, body) to the same request with no row. R7 and R8: a tenantless caller and a probe fault are still allowed, with one warn line each. R9: the refusal body names no tenant or organisation and the log line names the document and both tenants. R11: an organisation id equal to the owner tenant does not pass. Controls R4, R5, R6, R10, R12: own-tenant bodies unchanged (identity fields and signature hash included), flat anchors readable, a case-only tenant difference is the same tenant, and a read that found no rows makes no probe and no log line.
New test file ks1822-a-foreign-tenants-anchor-reads-as-absent.integration.test.ts (+169 lines, 1 cell) runs both routes on a migrated Postgres with the app connected as secuura_app: tenant B reads its anchor, tenant A gets the absent 404 on both routes, byte-identical to the same requests after the row is deleted.

113.3 What this does not prove

One rule on two routes, with named gaps. Known gaps, deliberate: a flat anchor stays readable by any authenticated caller (no owner recorded); a caller with no usable tenant claim is allowed (platform admins and connector keys without a tenant); a probe fault is allowed; two organisations in one tenant are not separated; /thread-state/:documentId, /tx/:txHash and /queue are not gated; and an admin reading another tenant’s document through originate with X-Tenant-Override no longer has that view heal a stale anchor (the document is still served).
Not run: the four platform suites (Schemathesis, Akto, Playwright, Performance/k6), a running stack, Node 24, any deploy. The pre-push hook’s own leg count is stated in the pull request.
Not measured: whether the admin registry-fallback view’s anchor heal persists today, and whether Platform S’s live connector key carries a tenant.
