83.1 What publishing changes at runtime

Documenting a path is not inert. The gateway reads the yaml at boot (index.ts line 612) and answers 405 with Allow: GET to any method the spec does not declare on a documented path (index.ts lines 1064 to 1081). After a deploy and a gateway restart (the yaml is bind-mounted locally and baked into the image on a deployed target), every non-GET method on this path, HEAD included, is a 405 with Allow: GET. POST, PUT and DELETE were the fall-through 404; HEAD was answered by the GET handler. The coordinator accepted this as a direct consequence of “publish it”. Cell R1 pins it for POST, DELETE and HEAD.
It does not move authentication. The operation declares no bearerAuth, and specRouteMap.ts line 47 arms the edge auth gate for bearerAuth only, so an anonymous GET still reaches the handler and gets its own 400. Cells U2 and R2 pin that; declaring bearerAuth reds both.

83.2 Where each answer comes from

Read from the handler and the init DDL, with line numbers in the comment above the registration. 400: neither hash nor documentId, an empty value counting as absent (platform.ts 1110 to 1111). 503: PLATFORM_DATABASE_URL unset (1114 to 1116). 200: { success: true, results: [...] }, up to five rows, seven fields (1125 to 1148); hash is tested first, so documentId is ignored when both are sent. 500: any other failure, a constant body (1152 to 1170).
429 is the gateway’s global per-minute limiter (index.ts line 479); this path is not in its exempt list (middleware/rateLimitSkip.ts line 23), so it applies here as to every other /api route. It is not the handler’s answer and is not exercised by cells W1 to W8.
Column types are read from the init DDL (docker/init-platform/01-platform-schema.sql lines 209 to 221): tenant_slug, document_type, title, status and certified_at are nullable there, so they are nullable in the schema. The live platform database was not queried.
