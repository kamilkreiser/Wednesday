92.1 What each combination does

One block, byte for byte, in all five scripts (a suite cell pins them equal). No TARGET_BASE, a slot named: that slot’s gateway, read from stack_env.sh in a subshell so nothing it exports reaches the script or its docker jobs.
No TARGET_BASE, no slot: refused with rc 2 and the example command, in KS-1016’s wording. It never falls back to any slot.
TARGET_BASE, no slot: used unchanged. This is the CI path. It is looser than KS-1016’s rule for the harnesses, because CI passes the variable and names no slot, and two existing suites (ks1405, orchestrate_jobs) run the scripts the same way.
TARGET_BASE and a slot: used unchanged, unless it is a LOCAL url on ANOTHER slot’s gateway, which is refused (the KS-1373 split-target shape). A remote host, or a local port that is no slot’s gateway (a stub), is left alone.
SECUURA_TARGET_RESOLVE_ONLY=1 prints the resolved TARGET_BASE and exits 0 before any job, curl, docker or tsx starts. None of the scripts had such a mode; it is the suite’s seam.

92.2 The static guard

check-stack-safety.sh section 3d extends the slot-derivation group’s single guard (3c) over Blockchain/Testing. A published port of any slot, typed as a standalone number in a tracked file under Blockchain/Testing, fails. The port set is derived from stack_env.sh under env -i (48 numbers across slots 1 to 4), never typed. The pattern matches a bare number, not only :PORT, so copying the port arithmetic with slot 1’s number typed is caught; a number that merely contains a port, or sits in a version, is not.
Four exceptions, each with a reason and a ticket, each excusing a real hit (an exception that excuses nothing fails as stale): the USER SIMULATED TEST run records, the baselines, the reconfirm-5xx URL fixtures, and the CI snippet (KS-1162). The guard reads green on the tree: 110 invariants hold.
