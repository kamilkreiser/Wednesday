73.1 Why the m1 cells need no Docker

A stub docker on PATH and a canned render. The checker needs the docker compose CLI but not a daemon: config only parses. It resolves docker from PATH and consumes only config --format json, so the REAL .mjs and the REAL stack_env.sh run in a fixture repo while the stub answers compose version and prints a canned render. The render models only what the checker reads: ownership labels, published ports, project and container names, the three MUST_MOVE values and the six KNOWN_SLOT_BLIND ones. It is not the real compose file, so these cells prove the checker’s logic and say nothing about what docker-compose.yml renders.
A control makes the canned render trustworthy: with every website half moved the checker is green (rc=0, OK —) and the stub logged exactly the bare, slot 1 and slot 2 renders, so a red below is attributable to the one reverted half. A second control keeps api-gateway’s own check honest: reverting its website half still fails the checker and names it.
