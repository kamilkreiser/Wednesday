10. API contract — the delegation GET spec declares its own envelope (KS-1015)

10a. KS-1015 — GET /api/delegations/{id} publishes the envelope its handler returns
What it pins. The published contract for GET /api/delegations/{id} declared a bare Delegation record as its 200 body, while the handler (routes/delegations.ts, GET /:id) answers { success, data: { delegation, chain } } — the chain being whatever buildDelegationChain() returns.
Schemathesis flagged the 200 as response_schema_conformance in the sweep of 2026-09-29. The spec now follows the runtime, not the other way round: the 200 content is a successEnvelope(...) whose data carries the unchanged Delegation component by $ref alongside the chain object. invalidReason is declared optional because the chain only carries it when isValid is false.
It NARROWS KS-1015, it does not close it. The ticket is a sweep finding covering 28 check/operation pairs with no live owner; this change owns one of them.
The remaining pairs stay open on the ticket.
