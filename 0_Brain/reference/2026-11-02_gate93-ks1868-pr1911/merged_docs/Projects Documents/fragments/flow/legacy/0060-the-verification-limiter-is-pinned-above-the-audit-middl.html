71. The verification limiter is pinned above the audit middleware (KS-1493)

What this fixes. Nothing pinned the order of two blocks in services/api-gateway/src/index.ts: the per-IP verification limiter (mounted on /api/verification and /api/v2/verification) and the audit middleware. Moved below the audit middleware, the limiter still answers 429 exactly as before, but the audit middleware has by then registered its finish listener on the response, so every throttled verification request would write one audit_logs row with status 429. The gate on pull request 1483 moved the block and 0 cells turned red. This is item N1 of KS-1493.
One new test file, ks1493-verification-limiter-sits-above-the-audit-middleware.test.ts, three cells. It drives the real gateway app with the db module stubbed (the audit middleware’s query is a recorder and isDbAvailable is true), sets the limit to 2 through VERIFICATION_RATE_LIMIT_MAX before the import, and sends four POST /api/verification/verify requests. No product file changes: index.ts is edited only as a throwaway copy for the red-first proof.

71.1 Scope: N1 only

What is and is not carried. A test and nothing else. The limiter and audit blocks, their order and their configuration are exactly as they were.
Not touched: item N2 of KS-1493, an owner decision. In production the unversioned /api/verification* redirects are counted by no limiter, and whether that unbounded redirect flood is acceptable is still open.

71.3 What the cells prove, and what they do not

The order, not the limit. They show the relative order of the two blocks in the real app: a request past the limit is answered 429 and no audit row carries status 429, while the requests that passed the limiter were audited with the status each one answered. The two control cells are what keep the RED cell from passing for want of a throttle or for want of a recorder.
UNMEASURED: the production-only redirect path (NODE_ENV is test here), the default limit of 60 (it is set to 2), a real database write, the four platform suites (Schemathesis, Akto, Playwright, Performance/k6), which are not claimed as passing, and any runtime other than node v26.8.1.
