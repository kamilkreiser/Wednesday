. Each PR adds its own docs fragment and one build step renders the two pages, so two PRs no longer conflict on them (KS-1887)

What this changes. Projects Documents/fragments/flow/ and Projects Documents/fragments/cheat/ hold head.html, tail.html, a frozen legacy/ directory (the 117 Flow entries and 112 Cheat Sheet entries on the pages at develop 9e1eb55fde53, with their literal numbers, in the pages’ own order) and one KS-NNNN-slug.html per new entry. A new Flow entry writes <!--n--> where its section number goes and <!--ref:NAME--> for another new entry’s number; the Cheat Sheet is unnumbered, so its fragments are plain HTML.
Blockchain/Dev/scripts/docs-fragments.mjs (no dependencies, no timestamps): check is the hard fragment lint (name, one entry per file, tag balance, tokens, no literal number in a new Flow entry, no token in a legacy file), the render passed through systemTest/__tests__/support/html_docs_check.mjs, and an advisory on how each committed page relates to the render; check --committed also needs both pages current; build --base <develop sha> rewrites the pages (refused unless that sha is an ancestor of HEAD, and never over content the fragments do not hold); build --out DIR is a preview; adopt [--from-ref REF [--against SHA]] turns an entry written by hand into a fragment; legacy-hash prints the pin.
Numbers: a new entry is numbered by the commit that first added it (git rev-list --first-parent order, ties by file name, an uncommitted file last), counting up from the highest literal number in the head and the legacy files; the build refuses a shallow clone. No PR rebuilds the committed pages: one separate docs-only push refreshes them after a batch of merges, so they may lag the fragments, and a hand edit of a page is an advisory with exit 0, never a stopped push.
Blockchain/Dev/scripts/__tests__/docs_fragments.test.sh sits in a root that run-shell-suites.sh already globs, so leg 12 finds it and leg 14 runs it. Not edited: .githooks/pre-push, any preflight leg, html_docs_check.mjs, html_docs_matrix.test.sh, check-stack-safety.sh. .claude/skills/secuura-test-discipline/SKILL.md: section 4 only.

.1 What proves it

Byte-identical, with controls that can fail. The render equals the committed pages at develop 9e1eb55fde53: Flow sha256 62990735186b4659dccc5676e7b5261da43d45ba70adc2997e22accf87fdcd9c (904074 bytes) and Cheat Sheet c89d4c382a76678fa16697ce1c55c0ccbaccc4363da67b59858e466594c8ea19 (599851 bytes), each computed three ways: git show of that sha, build --out, and the file on disk. 117 Flow and 112 Cheat fragments equal the per-PR entries (124 − 7 head sections, and 112 − 0).
Planted change: one changed character in one legacy fragment makes the rendered hash differ from the committed page and check --committed exit 1; restored by content (a unique anchor, count 1) the file’s sha256 equals the original and check --committed exits 0 again. html_docs_check.mjs on both renders exits 0, and exits 1 with “prose outside a table” on a planted paragraph. html_docs_matrix.test.sh 18 of 18.
The collision is gone: two scratch branches each adding a different fragment merge with 0 conflict files and are numbered 129 and 130 by merge order; the same two edits made the old way (a section appended to each page) conflict in both pages (2 files).
Cells: docs_fragments.test.sh 81 cells, all passing, 14 s standalone. Mutants: 41 single-edit mutants of the script (each parsed first, its anchor counted once), every one killed by at least one cell. Sweeps left three alive along the way, rev-list without --first-parent under clock skew, a same-length edit of the head, and no stem check in adopt --against (a same-length edit of old text plus an appended entry would have been half-adopted), and they became cells B10, C5 and E15. The first run of the cells (61 of 64) also caught the tool calling an edited entry “hand-appended” and adopt writing a fragment from it; cells C3, E4 and E7c now hold that.
The transition, on real open PRs in detached scratch worktrees, nothing pushed: #1837 (1 Flow and 1 Cheat entry) 8 of 8 steps, #1857 (a stack: 4 and 4) 8 of 8, with every adopted entry equal byte for byte to the text in the PR’s own page; #1383 (rewrites page text) is refused as a hand step, as predicted. The first try on #1837 was refused too, because its page was stale; --against (cells E10 to E14) is the fix.

.3 What this does not prove

The numbering and the process, not every history. Ordering by the first-add commit is proved on throwaway repos (squash shape, tie, merge-in shape, clock skew, delete and re-add, shallow clone), not on a long-lived develop. Two stacked PRs both converting the same base entry were not tested together (one stack member was tested alone); the names derive from the heading, so the files should be identical.
The committed pages lag the fragments until the first refresh; who runs it, and how often, is a process decision in SKILL.md, not code. A PR that edits existing page text, such as #1383, needs a hand step.
A push that touches only Projects Documents/ skips the pre-push gate, as a docs-only push does today, so a bad fragment merged that way fails leg 14 for the next code push until it is fixed.
Not run: the four platform suites (Schemathesis, Akto, Playwright, Performance/k6), a running stack, Node 24, any deploy. The pre-push hook’s leg count is stated in the pull request.
