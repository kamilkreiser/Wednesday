. nft-certificate fetchProtocolParams logs and returns null when the thrown value is unreadable (KS-1868, nft-certificate)

What this changes. The Blockfrost protocol-parameters read in Blockchain/Dev/services/nft-certificate/src/cardano/provider.ts: fetchProtocolParams() catches a failed read, logs Failed to fetch protocol parameters and returns null. The catch read the thrown value with err instanceof Error ? err.message : String(err), which itself throws for a revoked Proxy (instanceof throws) or for an Error whose message getter throws; the exception then left the function instead of returning null. The read is now in an inner try with the fallback 'unreadable thrown value'. The log message text and return null are unchanged (+7/-1 lines in provider.ts).
Three cells in the new ks1868-provider-fetch-protocol-params-unreadable-throw.test.ts (+70 lines): a control that an ordinary Error still logs its message and returns null (C1), and two red cells, a revoked Proxy (R1) and an Error whose message getter throws (R2), that must log the constant reason and return null. Both files are the held Spark pass O41-P1 applied with strict git apply --check -p1 at the base, with no hand edit.

.3 What this does not prove

One catch, not the ticket. KS-1868 stays open: it lists 253 catch and log sites that read a thrown value unguarded; this change fixes one, in nft-certificate. One behaviour changes beyond the log line (read from the code, not exercised): ensureFreshParams() in cardano/index.ts calls the function with no try/catch, so an unreadable value on the 5-minute refresh used to reject; it now yields null and the cached parameters are kept, as they already were for an ordinary Error. initCardanoNFT() wraps its call and returns false either way. The other catch sites in cardano/provider.ts and cardano/index.ts are not touched. nft-certificate mints on Cardano, so nothing deploys from this change and a later deploy needs its own gate.
Not run: a real Blockfrost call or a booted service, the four platform suites (Schemathesis, Akto, Playwright, Performance/k6), Node 24 or any LTS Node, npm ci, any deploy.
