. The non-root Dockerfile check reads USER root:root, 0:0 and ROOT as root (KS-1903)

What this changes. Blockchain/Dev/scripts/check-dockerfile-non-root.sh compared the last USER value to root and 0 exactly, so USER root:root, USER 0:0 and USER ROOT printed OK. A comment and two lines after the value is read now drop everything from the first colon on (the group) and lowercase what is left. Those three, and USER root:app, USER 0:1000 and USER Root:Root, are reported as root and exit 1.
Seven new cells (5 to 11) in the existing suite Blockchain/Dev/scripts/__tests__/check_dockerfile_non_root_reports_root.test.sh: four that fail at develop (root:root, 0:0, ROOT, root:app) and three controls that pass before and after (app:app, 1000:1000, app:root). The suite’s count guard moves from 4 cells to 11.

.1 What proves it

Red first, then green, and what the suite cannot see. Red first, by assertion: at develop 8126b22bd5aa with only the new cells applied the suite is 7 passed, 4 failed. Each failure is the script exiting 0 and printing “OK — all 1 Dockerfile(s) drop root for runtime.” for a root user. With the product lines it is 11 passed, 0 failed.
Mutants (scratch copies of the script run through the suite’s CHECK_DOCKERFILE_NON_ROOT_SH override, each parsed with bash -n, the real script’s sha256 unchanged): 4 of 6 killed — delete the group strip (cells 5, 6 and 10 fail), delete the lowercase (cell 7 fails), uppercase instead of lowercase (4 cells fail), keep the group instead of the user (cells 10 and 11 fail; the two cells that kill it were added after the coordinator’s review). 2 survived, both equivalent: stripping at the last colon (the same for a value with one colon) and swapping the two lines.
Twelve one-Dockerfile fixtures, develop’s script against this one: root:app (cell 10), 0:1000 and Root:Root (no cell) go from exit 0 to exit 1; app:root (cell 11) stays 0; root and 0 stay 1; app, app:app and 1000:1000 stay 0.
The real tree and the runners: 35 Dockerfiles; final USER values secuura 16, nodejs 11, app 4, nginx 2, postgres 1, migrate 1. Develop’s script and this one both print “OK — all 35 Dockerfile(s) drop root for runtime” and exit 0, so the guard that run-code-guards.sh runs does not turn red. run-code-guards.sh: 13 guards pass on develop’s tree and on this one. Every shell suite (run-shell-suites.sh, run before cells 10 and 11 were added to the same file): develop 106 passed, 0 failed, 1 skipped of 107 (the skip is ks949_main_seed_idempotence.test.sh, no PostgreSQL on this host); with the change 106 passed, 0 failed, 1 skipped of 107 (the skip is ks949_main_seed_idempotence.test.sh, no PostgreSQL on this host).

.2 Environment and figures

Measured 2026-11-02 (AEDT) on an Apple Silicon (arm64) Mac, macOS 27.0.1, shared with other seats. Develop 8126b22bd5aa with the change on top. /bin/bash 3.2.57, BSD grep and sed, Node v26.8.1 (used only by docs-fragments.mjs; not an LTS line). Machine load average was 9 to 15 during the runs.

.3 What this does not prove

One host, one userland; a gap in the suite. Nothing ran on a GNU/Linux userland. Two shapes that this change flips from exit 0 to exit 1, 0:1000 and Root:Root, have no cell of their own. A USER written with a variable, such as USER ${APP_USER}, was not examined. The four platform suites and any deploy were not run.
