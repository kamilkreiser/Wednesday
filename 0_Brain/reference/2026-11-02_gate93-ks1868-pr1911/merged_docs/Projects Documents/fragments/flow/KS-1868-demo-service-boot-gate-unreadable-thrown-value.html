. demo-service boot gate logs FATAL and exits when the thrown value is unreadable (KS-1868, demo-service)

What this changes. The fail-closed boot gate in Blockchain/Dev/services/demo-service/src/index.ts: assertDemoServiceEnabled() runs before the app is built, and its catch logs FATAL: <message> then calls process.exit(1). The catch read the thrown value with err instanceof Error ? err.message : String(err) and no guard. If the value is a revoked Proxy, or an Error whose message getter throws, that read throws inside the catch: the FATAL line is never logged and process.exit(1) never runs. The read now sits in an inner try with the fallback unreadable thrown value. The FATAL text and the exit code are unchanged for every readable value; the catch is log-only and nothing is returned to a client. Product bytes: +6/-1.
Two new cells in ks1868-boot-gate-unreadable-throw.test.ts (+57 lines): a control that an ordinary Error still logs its message and exits 1 (C1) and a red cell for a revoked Proxy (R1) that must log the constant FATAL line and exit 1. The edit is the held Spark pass O34-P1 applied with strict git apply --check -p1 (rc 0 on both sections, rc 1 on a copy with one context line's content corrupted); there is no hand edit.
