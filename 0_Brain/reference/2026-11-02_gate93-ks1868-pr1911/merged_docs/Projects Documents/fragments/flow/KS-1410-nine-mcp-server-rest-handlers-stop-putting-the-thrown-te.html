. Nine mcp-server REST handlers stop putting the thrown text in their 500 answer, and POST /verify’s error string becomes a constant (KS-1410)

What this changes. Blockchain/Dev/services/mcp-server/src/http-server.ts (+18/-9, nine catch blocks). A response-shape change, and a client-visible string: the 500 answer of POST /register, POST /register-batch, POST /verify, POST /verify-batch, GET /documents, GET /workflow/:id, GET /connector, GET /policy and POST /generate-package carried the thrown text. Each now logs it with console.error('[mcp-http] <method> <path> failed:', message) and answers the constant An unexpected error occurred. POST /verify’s body changes from { verified: false, error: <thrown text> } to { verified: false, error: 'An unexpected error occurred' }: the error string is now constant. ChatGPT Actions clients (and any other client of this REST mirror) were not checked. In POST /generate-package the log now runs before the headersSent test, so the thrown text is logged also when the answer was already started. POST /hash is not changed (its route belongs to another ticket) and the tests pin that.
Two new source-text tests (the module binds a port on import), 7 cells each: ks1410-mcp-http-500-part-a-never-echoes-the-thrown-text.test.ts covers the first five handlers, ks1410-mcp-http-500-part-b-never-echoes-the-thrown-text.test.ts the last four. In each, P1 to P3 are RED (no 500 answer of these handlers names a caught value; each answers the constant; each logs the thrown text just before it answers) and C1 to C4 are controls (the scanner flags leaks and passes the constant; the file has exactly ten 500 answers and POST /hash keeps message: message; the two per-item results of the batch routes, which are 200 answers, are not touched; the 400 refusals keep their messages).

.1 What proves it

Red with only the two new tests, green with the nine hunks, and no other cell moves. Tests alone at develop a8c554659cb3: 6 of 14 fail (3 of 7 in each file: P1, P2, P3), the 8 controls pass. With the nine hunks: 14 of 14 pass.
Whole mcp-server unit suite (vitest): develop 6 files / 30 cells, 30 pass; with the change 8 files / 44 cells, 44 pass, 0 failed, 0 skipped. tsc --noEmit with the test files in the program (18 source files, 8 under __tests__): 0 errors, and a planted type error was reported once as TS2322. eslint on both tests and http-server.ts: 0 errors, 0 warnings, and a planted file raised @typescript-eslint/no-unused-vars and no-debugger.
Clients, grepped at develop (not run): the repo holds a ChatGPT Actions deployment guide and an OpenAPI source for this mirror (src/mcp-server.openapi.ts, openapi.yaml). The source declares every 500 as the shared commonErrorResponses[500] and the passthrough envelope’s error as an optional string, so a constant string still satisfies the declared shape; no document under MCP Deployment names an error string. The only code outside the service that calls a changed route is the api-gateway’s /api/mcp/generate-package in routes/proxy.ts, which forwards a non-OK upstream body verbatim (res.status(r.status).json(err)) and does not read the message, so the constant now reaches its callers. What a ChatGPT Actions client does with the error string is not measured.
