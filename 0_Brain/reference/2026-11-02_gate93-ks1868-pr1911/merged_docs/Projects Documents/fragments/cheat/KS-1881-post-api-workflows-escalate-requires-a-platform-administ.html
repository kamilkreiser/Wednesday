POST /api/workflows/escalate requires a platform administrator — KS-1881

What to know. The transfer service’s escalation sweep (POST /api/workflows/escalate) now answers 403 FORBIDDEN “Admin role required” unless the caller’s role passes the shared isPlatformRole. That admits SYSTEM_ADMIN and SUPER_ADMIN, and also system_admin through the helper’s ASCII fold; an array or a Unicode look-alike is refused. On a refusal the sweep does not run. Before, any signed-in caller could escalate or time out every overdue approval step in every tenant.
Red at develop: 13 of 16. Green after: 16 of 16. Nine mutants, nine killed; three of them, added after QA gate 53, strip whitespace before the check (trim(), trimStart(), trimEnd()), and the padded-role cells E14 to E16 kill them.
Not measured here. A running stack, the four platform suites and any deploy. Nothing in the repo calls this route. The gateway does not proxy /api/workflows to transfer and compose publishes no transfer port, so it is reachable only inside the network (QA gate 53).
