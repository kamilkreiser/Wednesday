A credential is revoked only by the principal that may read it — KS-1851

What to know. POST /api/credentials/:id/revoke is bound by the same rule as GET /api/credentials/:id, mayReadCredential (since KS 1906): the creating principal (same userId and tenant), or, for a row with no recorded owner, a platform administrator of its tenant. Anyone else gets the same 404 “Credential not found” as an unknown id. Nothing is written, and the reason is not logged. The shared error handler still writes one error-level line for the refusal, the same line an unknown id gets, and it never contains the reason. A test that revoked as a different principal now gets 404.
