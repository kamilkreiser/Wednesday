The security service's rotate catches log a constant reason when the thrown value cannot be read — KS-1868

What to know. Two catches in the security service (revokePriorConnectorKeys and the rotate transaction of saveKeyAndRetirePriors) read the thrown value unguarded. An unreadable one (a revoked Proxy, an Error whose message getter throws) made the revoke function reject and made the rotate transaction roll back whole, so the register-connector route refused the rotate (500 or 503, no key issued). Both now log the constant reason unreadable thrown value and return null; the rotate commits the new key, the prior keys stay live and the route answers 201 with priorKeysRevoked: null, exactly what an ordinary retire error already did. TIER 1 for that change.
Not measured here. A real PostgreSQL, the route itself, Node 24 (the host has v26.8.1 only), the four platform suites. The thrown values are test-authored.
