Docs fragments: each PR adds two small files and one step builds the two pages — KS-1887

What to know. Do not edit the two pages. Add Projects Documents/fragments/flow/KS-NNNN-slug.html (it starts <h2><!--n-->. Title (KS-NNNN)</h2>; never type a section number, and write <!--n-->.1 in a sub-heading) and Projects Documents/fragments/cheat/KS-NNNN-slug.html (a plain entry, no tokens). One <h2> per file; the name is the ticket key plus a lowercase slug, unique in its directory; a PR with two entries adds two files per page.
Before you push run node Blockchain/Dev/scripts/docs-fragments.mjs check; it must end in OK, and the line goes in the PR’s Test Evidence. Leg 14 runs the same check for any push that changes Blockchain/Dev; a push that touches only Projects Documents/ skips the gate, so run it yourself.
To read the result: build --out "$TMPDIR/preview" writes both pages to a scratch directory. A section number is provisional until the PR merges (it follows merge order). Whoever merges runs the refresh after a batch of merges (build --base <ls-remote develop sha>, commit just the two pages), so the committed pages may lag; check says by how many entries.
A PR that still carries a hand-written entry brings it across once with adopt --from-ref "$OLD" --against "$D" after merging develop in and taking develop’s two pages (the commands are in SKILL.md section 4). A page edited by hand is only an advisory: the next refresh runs adopt first.
Not measured here. The four platform suites, a running stack, Node 24 and any deploy were not run. Two stacked PRs converting the same base entry were not tested together. A PR that edits existing page text (#1383) needs a hand step.
