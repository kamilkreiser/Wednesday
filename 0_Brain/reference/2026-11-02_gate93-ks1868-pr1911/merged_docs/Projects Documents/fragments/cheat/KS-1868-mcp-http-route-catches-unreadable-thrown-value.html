The mcp-server HTTP routes log a constant reason when the thrown value cannot be read — KS-1868

What to know. Nine route catches in mcp-server/src/http-server.ts read the thrown value unguarded for a log line. An unreadable one (a revoked Proxy, an Error whose message getter throws) made the handler reject and the request go unanswered. Each now logs through describeThrown and answers its same constant 500. An ordinary Error logs its message as before; a thrown string is now logged by kind only. 1 product file (+9/−18), 45 new cells in 3 files.
Not measured here. Node 24 (the host has v26.8.1 only), a real HTTP request, the api-gateway hop, the four platform suites. The /hash catch is not part of this change.
