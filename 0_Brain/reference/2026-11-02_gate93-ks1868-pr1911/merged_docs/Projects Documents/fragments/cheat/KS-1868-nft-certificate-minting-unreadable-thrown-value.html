nft-certificate DB catches log and carry on when the thrown value is unreadable — KS-1868, minting

What to know. Four nft-certificate catches (dbSaveNFTCertificate, loadFromDb, getNFTCertificate, getUserNFTCertificates) read the thrown value unguarded; a revoked Proxy or a throwing message getter made that read throw, so the function rejected instead of logging and carrying on. Each read is now in an inner try with the fallback unreadable thrown value. For an ordinary Error nothing changes. For an unreadable value the function now behaves like an ordinary database error, which also changes the answer of GET /certificates/:id (404, was 500) and of a mint whose last save fails (success, was MINT_FAILED).
Not measured here. KS-1868 stays open (four of its 253 sites). The red cells assert the log line only. KS 1843 touches the same functions for a different defect. The four new test files carry one approved hand-edited import line each. The route and caller behaviour above is read from the source, not exercised against a running service.
