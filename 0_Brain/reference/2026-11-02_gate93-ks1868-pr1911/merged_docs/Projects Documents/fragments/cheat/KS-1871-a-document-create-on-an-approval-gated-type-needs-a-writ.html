A document create on an approval-gated type needs a write role or the documents:write scope — KS-1871

What to know. POST /api/documents through the gateway now answers 403 FORBIDDEN, “Forbidden: your role does not permit document creation”, before any approval workflow is created, unless the caller has a document-write role (ISSUER_ADMIN, ORG_ADMIN, SYSTEM_ADMIN, SUPER_ADMIN; lower case is fine) or the documents:write scope. That is the rule originate already applies. An OWNER login token carries documents:write, so OWNER still gets 201 pending_approval. On a non-gated type a refused caller gets the same 403 as before, now from the gateway rather than from originate. A connector set to bypass the workflow (workflowPolicy: 'bypass') skips this check too: it writes no workflow and originate’s own create rule decides (QA gate 56).
