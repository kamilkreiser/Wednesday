KS-1384 F-a: row counts, payloadTimestamp, originate stops writing anchor_store, and the reconciler’s give-up

What to know.Anchoring’s status UPDATE can expect a status (or a list) and a hash (or no hash), and the runner says how many rows matched, or null when the write did not run. The reconciler reads it; the submitter does not yet.
POST /api/anchors answers payloadTimestamp (the stored payload’s anchoring time; the kept payload’s time when a repeat request did not replace it), and GET /api/anchors/:id answers it too. Additive.
originate’s POST /api/anchoring/anchor and /submit no longer write anchor_store; anchoring persists its own row.
The reconciler fails a row only 24 h after its last write and after two consecutive passes in which the chain answered “not found”; a provider outage never fails a row. Each of its writes expects the status and hash it read.
Not measured here.A real provider outage, the four platform suites, a running stack, Node 24 (LTS), any box.
