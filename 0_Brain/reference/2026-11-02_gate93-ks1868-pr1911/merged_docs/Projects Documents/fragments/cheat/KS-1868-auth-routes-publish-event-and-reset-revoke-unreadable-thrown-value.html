The auth routes log a constant reason when the thrown value cannot be read — KS-1868

What to know. Three catches in routes/auth.ts read the thrown value unguarded: the event publish of register and login, and the session revocation of reset-password. An unreadable one (a revoked Proxy, an Error whose message getter throws) now logs the constant reason unreadable thrown value. Register and login leave no unhandled rejection; reset-password answers the 503 an ordinary revocation error already gets, where it used to answer 500. 1 product file (+25/-3), 12 new cells. Two hunks need git apply -C1.
Not measured here. Node 24 (the host has v26.8.1 only), a real Redis or PostgreSQL, a real HTTP request, the four platform suites. The thrown values are test-authored. The whole auth suite has two ks949 cells that time out at 5 s under load, at the base too.
