MFA disable NULLs the seed and the backup codes — KS-938

What to know. “MFA disabled” used to answer 200 while leaving the TOTP seed and the hashed backup codes in the row — and the seed could then be re-armed without a new one being minted. updateUser skips any field whose value is undefined, so all three clearing sites emitted a partial UPDATE.
They now pass null, which writes SQL NULL. The undefined skip itself is unchanged — other callers rely on it to mean “leave this column alone”.
One site (POST /me/mfa/disable) did not pass mfaBackupCodes at all, so the key had to be added: the fix is per-site, not one shared edit.
