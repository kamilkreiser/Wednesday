The ks968 integration suite’s loopback guard judges what the pg client will dial — KS-1494

What to know. Test-only. ks968-platform-admin-seed-with-both-rows.integration.ts refuses a DSN unless the host, port and database the pg client will use are a loopback host, a port that is not a shared-stack port (5432, 6432, 6433 and the compose defaults) and a ks_ database. A ?host=, a ?port=, a missing port, a unix-socket host, a hostaddr in any case, and a DSN the client cannot parse are all refused at module load, before anything connects.
The file’s 4 tsc errors are cleared (0 now). A second describe holds the 30 guard cells and needs no database, because the four hooks moved into the describe of the six real-Postgres cells. Same decision as KS 1340, with the two KS 1795 gaps closed.
Not measured here. The four platform suites, a running stack, any deploy, and Node 24 (this host has only Node v26.8.1, not an LTS line). Another slot’s published ports are not in the shared-stack list.
