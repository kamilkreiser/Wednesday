adminConfig.ts: fifteen catch conditions survive a hostile thrown value — KS-1780

What to know. The fifteen catch conditions in services/originate/src/routes/adminConfig.ts that read err?.message?.includes(...) or err?.code before fail500 now do the read inside a try (helpers errorMessageIncludes and isMissingTableError). A revoked Proxy or a throwing message getter used to make that read throw and leave the request with no answer; it now gets the constant 500. Readable errors are answered exactly as before.
Four GET routes are driven by cells; the other eleven sites are pinned by a source-text cell (S1), which proves the text, not the behaviour. A local model wrote the patch; it is applied unchanged and strict. Parts 1 and 3 of KS-1780 are a separate, merged change.
Not measured here. A running stack, a thrown object whose code getter throws, a mutant analysis of the fifteen sites, and a Node 24 LTS run (the host is Node 26.8.1).
The four platform suites (Schemathesis, Akto, Playwright, Performance/k6) are not claimed as passing. The change is not deployed.
