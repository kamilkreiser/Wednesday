The format gate’s “in this push” label is literal — KS-998

What to know. check-package-format.sh asked whether a red file was in the current push with grep -qx "$full". -x anchors the match but still treats the path as a regex.
So a red src/a.b.ts that was NOT in the push matched a src/aXb.ts that was, and the gate printed the red as “(in this push)” — the bill landed on the wrong author.
A genuine src/[id].ts IN the push matched nothing and was labelled inherited.
The predicate is now grep -qxF. Only the label changes — the pass/fail verdict, the exit code and the failure count are all unchanged, and three of the eight cells are CONTROLs that assert so.
Gotcha when you run this locally. The new suite is 100644, not 100755, because the payload carries no new file mode line — and that is fine here.
run-shell-suites.sh globs *.test.sh and invokes bash <file>, so it needs no executable bit; package_format_gate.test.sh beside it is 100644 as well. Do not chmod it to match the other 15 suites in that directory — that would be a mode change nothing asks for.
Expect the shell-suite denominator to read 71 at this head, not 70: any older count quoted in a CI triage line does not describe it.
