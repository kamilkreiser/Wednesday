The verification limiter is pinned above the audit middleware — KS-1493

What to know. In services/api-gateway/src/index.ts the per-IP verification limiter must sit above the audit middleware. Below it, every throttled verification request (429) would write an audit_logs row. A new test, ks1493-verification-limiter-sits-above-the-audit-middleware.test.ts, pins the order with three cells.
It drives the real app with the db module stubbed and the limit set to 2 through VERIFICATION_RATE_LIMIT_MAX, sends four POST /api/verification/verify requests, and asserts that no audit row carries status 429. Two control cells assert that the requests past the limit really were throttled and that the requests that passed were audited.
No product file changes. To see it fail, copy index.ts under another name, move the limiter block below the audit block, and point a copy of the test at the copy; do not edit index.ts itself.
Not measured here. The production-only redirect path, the default limit of 60, and a real database write.
Item N2 of KS-1493, an owner decision about the unversioned redirects that no limiter counts, is still open.
