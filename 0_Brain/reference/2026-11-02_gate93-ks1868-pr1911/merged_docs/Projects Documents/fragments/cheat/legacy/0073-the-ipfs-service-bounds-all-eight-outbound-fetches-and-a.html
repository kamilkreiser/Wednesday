The IPFS service bounds all eight outbound fetches, and a stalled gateway body answers 503 — KS-1240 part 3

What to know. Eight outbound fetch calls in services/nft-certificate/src/services/ipfs.service.ts had no timeout. Each now passes AbortSignal.timeout: 60 s for the three uploads, 15 s for the four pin and unpin calls, 30 s for the gateway read. On expiry an upload answers { success: false }, pin and unpin answer false, and the gateway read answers 503.
A behaviour change on a read path. The gateway body read now sits inside the try that maps a failure to 503, so a gateway that sends its headers and then stalls (or drops the connection mid-body) answers 503 instead of the raw error. An object the gateway needs more than 30 s to deliver now answers 503 where it used to wait.
Scope. The ticket text names only the api-gateway key-validate fetch; this part was added by the coordinator’s brief, not by the ticket.
Not measured here. A real provider endpoint, a real network connect timeout, the routes that call the service, and a running stack. The four platform suites (Schemathesis, Akto, Playwright, Performance/k6) are UNMEASURED and not claimed as a pass. The change is not deployed.
Node v26.8.1, not the repository’s stated LTS line of Node 24 (none is installed on this host). The figures are declared as measured on v26.8.1, not claimed as LTS.
