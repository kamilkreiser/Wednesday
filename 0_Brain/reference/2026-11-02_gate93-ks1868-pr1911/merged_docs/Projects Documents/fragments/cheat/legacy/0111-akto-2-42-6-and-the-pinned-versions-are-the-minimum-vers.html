Akto 2.42.6, and the pinned versions are the minimum versions — KS-1609

What to know. Akto pin 2.42.6 (both 2.42.6_local tags, 2026-10-30; dashboard-only 2.42.3 and 2.42.5 skipped). akto-puppeteer-replay 1.51.3; mongo:7.0.45 unchanged. oxlint 1.90.0 / oxlint-tsgolint 7.0.2005 in all five systemTest packages that pin them, and @oxlint/plugins 1.90.0; observability moved to oxlint 1.90.0 too. v2.42.7 exists for the dashboard only (testing has no tag yet), so 2.42.6 is the latest pair.
Minimum versions. npm run start refuses an AKTO_IMAGE_VERSION, AKTO_DASHBOARD_VERSION or AKTO_TESTING_VERSION below the pin (shell or .env); a newer one is allowed. Every npm range’s floor is the installed version.
Login refused before trying? The harness counts its Akto dashboard logins per slot. When 10 have been made in Akto’s current hour (Akto refills all 10 at once on each full hour from the first login after the dashboard starts), it refuses at once, names when Akto refills and docker restart <dashboard>, which resets Akto’s limiter. npm run update-images now reads five pages of tags and names package.json as the pin.
Review .txt. An Akto run’s runs/<hexId>.txt now states the verdict, with Akto’s raw count on a labelled line.
Catalog STALE? The tiers and npm run start now stop on it. Run npm run generate-test-ids && npm run format, read the id diff (a new id is a new Akto test, a missing one is coverage Akto removed), and commit.
