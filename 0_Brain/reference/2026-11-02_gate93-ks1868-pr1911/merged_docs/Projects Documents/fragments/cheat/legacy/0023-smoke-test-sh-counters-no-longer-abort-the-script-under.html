smoke-test.sh counters no longer abort the script under errexit — KS-1139

What to know. pass(), fail() and warn() counted with ((PASS++)). A post-increment from 0 returns status 1, and under set -euo pipefail bash >= 4.1 applies errexit to (( )) — so the script died at its FIRST check on Linux runners and the Ubuntu demo VM. Now X=$((X + 1)).
It passed on macOS because /bin/bash 3.2.57 ignores that status. A green local run was never evidence here — that is the whole trap.
Evidence: base 3 passed, 3 failed -> 6 passed, 0 failed; sibling smoke_test_degraded_warns.test.sh 5 passed, 0 failed. The three cells passing in both arms are the controls.
Gotcha. Unreproducible on this host: no bash >= 4.1 exists here, so the red-before-fix behaviour is read from documented errexit semantics plus a reviewer's rc-1 figure on bash 5.2. A run on bash >= 4.1 is owed and the ticket does not move to Done.
Scope: the three helpers in smoke-test.sh only. The scripts/validate-env.sh sites of the same shape are still OPEN and deliberately not in this change.
