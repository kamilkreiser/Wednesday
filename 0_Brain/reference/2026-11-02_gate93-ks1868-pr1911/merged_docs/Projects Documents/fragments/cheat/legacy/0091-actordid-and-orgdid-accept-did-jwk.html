actorDid and orgDid accept did:jwk — KS-1175

What to know. The anchoring service’s identity block now accepts did:jwk as the third method on actorDid and orgDid (pattern ^did:(key|web|jwk):[A-Za-z0-9._:%-]+$, was ^did:(key|web):[A-Za-z0-9._:%-]+$; 512-character cap unchanged), on Stuart’s ruling on PS 1324. Before, Platform S’s Entra-verified did:jwk got a 400. The check is shape only: it never decodes the JWK. The refusal message names all three methods and still starts Invalid DID.
The generated spec (secuura-api.yaml) changed by its two pattern lines and two description lines; regenerate it with npm run generate-openapi, never by hand. The Schemathesis and Akto files hold no did:key, did:web or did:jwk value, so no example there changed.
Not measured here. The four platform suites, any stack or database, any live anchor of a did:jwk, and a Node 24 LTS run (the host is Node 26.8.1). Not deployed.
