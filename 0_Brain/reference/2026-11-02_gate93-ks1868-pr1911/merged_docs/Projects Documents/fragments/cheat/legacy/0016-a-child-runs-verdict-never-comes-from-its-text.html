A child run’s verdict never comes from its text — KS-1313

What to know. childSuiteCounts used to regex the child vitest’s human output for Tests N failed | M passed (T). The pattern requires the word “passed”, so fail-only, skip-only and todo-only runs matched nothing and it threw.
And a child killed by its 180 s spawnSync timeout prints no summary, so the read depended on whatever else was in its output — that is the KS 1326 half.
It now passes --reporter=json --outputFile.json=<tmp> and reads numPassedTests / numFailedTests.
endedNormally refuses a spawn error, a signal, or any exit status other than 0 or 1 before the report is read, so a killed child cannot read as a pass even beside a passing report.
Gotcha when you run this locally. The R6 fixtures say “captured from real vitest 4.1.9” and the runner you will resolve is 5.0.3. Check, do not assume: capture a report with the same flags and confirm the fields are still there.
They are — all five the fixtures use are present and numeric in 5.0.3 — but read the version out of node_modules/vitest/package.json, not out of the manifest: ^5.0.3 is a range, not a resolution.
Type-check with tsconfig.node.json. tsconfig.json does not include this file, so a green from it says nothing about this change — confirm with tsc --listFilesOnly if you doubt it.
