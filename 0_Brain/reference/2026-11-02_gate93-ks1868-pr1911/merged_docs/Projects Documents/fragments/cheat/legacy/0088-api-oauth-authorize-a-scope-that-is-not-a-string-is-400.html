/api/oauth/authorize: a scope that is not a string is 400 invalid_request — KS-1219

What to know. Behaviour change: GET and POST /api/oauth/authorize now refuse a scope that is present and is not a string with 400 invalid_request. An array (a repeated ?scope= or a JSON array) used to be a 500 server_error; a JSON null, 0 or false used to be read as an absent scope (the default allow-list) and is now a 400. No published message changes.
Wednesday accepted the tightening on 2026-10-28. The cells cover the array carriers and the null, 0 and false edge. Authentication surface. A local model wrote the patch; it is applied unchanged.
Not measured here. A running stack, real clients, tokens or a database, and a Node 24 LTS run (the host is Node 26.8.1). The other authorize parameters are not covered: a repeated state or code_challenge on GET still answers 500, and scope is neither deduplicated nor bounded (separate ticket, KS 1797).
The four platform suites (Schemathesis, Akto, Playwright, Performance/k6) are not claimed as passing. The change is not deployed.
