run-migrations.sh reports skipped migrations as skipped, not applied — KS-808

What to know. The summary of Blockchain/Dev/scripts/run-migrations.sh is now Summary: applied=A failed=F skipped=S. Before, apply_one returned 0 for an already applied skip as well as for a real apply, so applied= counted skips: a re-run over an up-to-date database reported every migration as applied.
Only the counter moved. Exit codes are unchanged (any failed migration still exits 3, KS 1031), and Migration runner finished (applied=…, failed=…) keeps its format with the true apply count. KS-808 stays open: a live run against a real database is owed.
Gotcha when you run this locally. (1) No database needed. The suite stubs psql and pg_isready and runs the runner as sh scripts/run-migrations.sh in a temp tree: bash Blockchain/Dev/scripts/__tests__/ks808_run_migrations_counts_skips_apart.test.sh gives 5 passed, 0 failed. Point RUN_MIGRATIONS_SH at a copy of the pre-change runner to see the old behaviour: 3 passed, 2 failed.
(2) Match applied= as a prefix. Anything that greps the summary must not expect the line to end after failed=N: it now ends skipped=N.
(3) The runner is baked into the migrations image. A local stack only picks this change up after migrations is rebuilt; rsyncing the script alone changes nothing.
