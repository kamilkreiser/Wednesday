countUsers classifies a database fault the way listUsers does — KS-1769

What to know. countUsersInner in Blockchain/Dev/services/auth/src/repositories/userRepo.ts now has the catch listUsersInner got in KS 1484. A database fault at the COUNT query is a 503 (SERVICE_UNAVAILABLE) when isInfrastructureDbError says it is an availability fault, anything else is rethrown as the very same error (toBe, not a message match), and every failure is logged once as DB countUsers failed with the error and its code. Before this, GET /api/users and GET /api/users/admin/list answered a raw 500 whenever the list answered and the count faulted, because both routes call the list and then the count.
The twelve new cells sit at the end of services/auth/src/__tests__/ks1186-userrepo-fromrow-sites-are-awaited.test.ts and use its helpers (loadRepo, rejection, INFRA). Four are red against the code before the catch; three pin the result path; five pin that the tenant, search and role filters reach the query as the same SQL and the same bound values, so the catch cannot have moved the WHERE builder.
This is a behaviour change on the user-listing path and it is not deployed: under the Done rule the ticket cannot move to Done until auth is.
Gotchas when you run this locally. The ks949 tree-walking cells time out at the default 5 s in a full run under load. ks949-platform-admin-seed-identity.test.ts read 2 failures on the cold first run in a fresh worktree and 1 on a later run (Test timed out in 5000ms); alone it passes in well under a second. For a load-proof full run pass --testTimeout=120000 --hookTimeout=120000. It is the flake KS 1053 tracks, not a defect of the count.
A route-level driver on tsx cannot assign onto a module. tsx compiles through esbuild, whose CommonJS exports are getter-only, so db.query = fake is silently ignored (the first run of the driver answered 401 on both routes). Replace the cached module’s exports instead (require.cache[path].exports = Object.assign({}, real, { query: fake })), and install the database seam before anything loads that could capture the real one.
A mutant’s test copy must still end in .test.ts. A copy named …test.M1.ts is outside vitest’s include glob, so every mutant would read “no tests ran”. Parse each mutant before running it: a syntax-broken mutant reds every cell and reads as a kill.
Run tsx with a short TMPDIR. It opens a unix socket under it and macOS caps that path near 104 bytes; a TMPDIR under a long scratch path dies with listen EINVAL, which reads like a repo defect. This round used /tmp/xk1769.
Not measured here. Every database call in the cells and in the route run is a mock; a real pg fault was not produced. The four platform suites (Schemathesis, Akto, Playwright, Performance) were not run, nothing was run on Node 24, and the Node v26.8.1 used here was not checked against the vendor’s LTS schedule.
KS 1168 (the encrypted-column search) will rewrite the two search clauses the filter controls pin; it has to update those cells in the same change.
