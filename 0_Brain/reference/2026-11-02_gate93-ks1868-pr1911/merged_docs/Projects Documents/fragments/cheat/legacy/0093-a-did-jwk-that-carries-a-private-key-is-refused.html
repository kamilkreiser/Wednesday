A did:jwk that carries a private key is refused — KS-1175

What to know. Kam’s ruling of 2026-10-29: the anchoring service decodes a did:jwk on actorDid and orgDid only to refuse private-key members (d, p, q, dp, dq, qi, k) with a 400 whose message starts Invalid DID and names the members, never a value. A payload that is not unpadded base64url of a JSON object is refused too.
did:key and did:web are unchanged. Nothing else about the JWK is checked: no kty, no curve, no key length.
Not measured here. The four platform suites, any stack or database, any live anchor of a did:jwk, and a Node 24 LTS run (the host is Node 26.8.1).
A Schemathesis case generated from the unchanged spec pattern can meet this 400. Not deployed.
