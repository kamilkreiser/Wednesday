The NFT certificate list answers only the verified caller’s rows — KS-1836

What to know. GET /api/nft/certificates now takes the owner from the verified token (req.user.userId), never from ?userId=, and returns only rows whose userId equals it; ?walletAddress= and ?userId= can only narrow that set. A foreign selector gets the empty 200 a caller with no rows gets; a caller with no usable identity (absent, not a string, blank, or the legacy 'user-id') gets 403. Every record written today carries 'user-id', so real callers list nothing until the mint paths record the caller. New nftReadGate.ts (+95), nft.routes.ts +22 -9; 31 new cells in 2 files.
