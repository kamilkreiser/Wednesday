GET /api/platform/document-lookup is in the published contract, as a public route — KS-1773

What to know. The route was live and missing from the published spec. It is now published as a deliberate public endpoint (security: []; Kam, 2026-10-28: “Keep it public and publish it”) with query parameters hash and documentId and the answers 200, 400, 429, 500 and 503. There is no 404: a lookup that matches nothing is a 200 with an empty results list.
Publishing arms the gateway’s method gate: after a deploy and a gateway restart, every non-GET method on this path, HEAD included, is a 405 with Allow: GET; POST and DELETE were the fall-through 404 and HEAD was answered by the GET handler. Authentication does not move: an anonymous GET still gets the handler’s own 400.
No handler change; the cells compare the handler’s answers with what the yaml declares.
Not measured here. A live platform database (the 200 and 500 bodies come from a stubbed pool; column types are from the init DDL), a running stack, and the gateway’s 429.
The four platform suites (Schemathesis, Akto, Playwright, Performance/k6) are not claimed as passing. The change is not deployed.
