Gotcha when you run this locally. (1) Never invoke vitest bare in this package. The config is vitest.unit.config.ts, which vitest does not auto-detect, so node_modules/.bin/vitest run <file> silently runs on vitest's defaults: a 5000 ms timeout instead of 15,000, different include globs, and no setupFiles — which means clearSlotEnv.setup.ts never strips the shell's slot family. Measured on one tree: bare gave 456 tests with 1 failure (unitSuiteSlotIndependence.test.ts timing out at 5000 ms), while npm run test:unit gave 1363 passed, 0 failed. The failure was the harness. Use npm run test:unit (vitest run --config vitest.unit.config.ts).
(2) The red proof here is a TAMPER, not a base run. A test-only payload covers behaviour that is already correct, so it cannot be red at the base. Remove .toLocaleString() from both counts at report.ts:104, re-run, and restore. A real red reports 3 total / 1 failed; a 0 total / 0 failed reading is a load failure and proves nothing.
