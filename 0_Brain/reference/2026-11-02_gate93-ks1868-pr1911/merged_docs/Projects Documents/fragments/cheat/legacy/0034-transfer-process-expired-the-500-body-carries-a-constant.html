transfer process-expired: the 500 body carries a constant and the thrown text goes to the log — KS-1410

What to know. POST /api/delegations/admin/process-expired used to answer 500 with message: error.message. It now answers message: 'Internal server error' inside the same INTERNAL_ERROR envelope, and logger.error records the thrown text server-side with the route named. If you were reading the response body to find out what broke, read the service log instead.
Which branch logs. The log call is inside the handler's if (error instanceof Error) branch, so that branch is what logs error.message. A non-Error throw takes next(error) and never reaches the line, so do not read this row as a statement about non-Error throws elsewhere in the service.
What did not change. The envelope shape and the INTERNAL_ERROR code are the same, a success still answers 200 with the expired count, and the revoke route still answers 404 NOT_FOUND with its business message — the last two are pinned by controls TC1 and TC2. The four 4xx error.message sites in the same file were not touched by this pass.
