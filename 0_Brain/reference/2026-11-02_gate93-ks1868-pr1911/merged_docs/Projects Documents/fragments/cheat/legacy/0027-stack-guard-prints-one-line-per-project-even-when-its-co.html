stack_guard prints one line per project, even when its containers disagree about the owner — KS-1355

What to know. stack_guard.sh grouped foreign stacks by (project, owner), so a project whose containers carried different owner labels was listed once per owner. It now prints one line per project.
Where some containers have a real owner and others are owner=unknown, the line names the real owner and appends (+N container(s) with owner unknown). That wording is this change's choice, not the ticket's.
Behaviour change: a project with two different real owners now prints ONE line — the first tuple in docker ps order — so the second real owner is no longer shown. NARROWING: spot 1 only; KS-1355 does NOT close.
Gotcha when you run this locally. (1) The exec bit. This repo sets core.filemode=false, so git apply on a 100755 script leaves it 644 on disk while recording no mode change. The tree keeps 100755; the working copy does not. Read the mode back from the index for the named paths — never checkout-index -a -f.
(2) Run it with /bin/bash (3.2.57 on macOS), from Blockchain/Dev: bash scripts/__tests__/stack_guard.test.sh. Expect 27 passed, 0 failed. The two-owner case is fixture-proved only — a live Docker host run is still owed.
