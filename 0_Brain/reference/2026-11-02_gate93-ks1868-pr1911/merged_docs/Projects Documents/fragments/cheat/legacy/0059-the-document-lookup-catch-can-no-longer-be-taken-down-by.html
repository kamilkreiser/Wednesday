The document-lookup catch can no longer be taken down by its own log line — KS-1524

What to know. Two things changed on GET /api/platform/document-lookup. A thrown null is now pinned (cell L6): typeof null is 'object', and the err !== null guard was the only thing stopping Object.getPrototypeOf(null) from throwing inside the catch. The old file passed 9 of 9 with that guard removed; the new file fails L6 alone, 3 of 3 runs.
A behaviour change on a request path: building the log line and writing it are now each guarded. A thrown value that cannot be described (a throwing message getter, a Proxy whose getPrototypeOf or ownKeys trap throws, a revoked Proxy) or a logger that throws used to reject the handler from its own catch and leave the request with no response. The route now sends the constant 500 in all five cases and logs thrown value that could not be described for the first four.
Behaviour for every value that could be described before is unchanged: the original nine cells pass 9 of 9 against the fixed route. Each guard is pinned by its own cells (describe guard removed: 4 failed; logger guard removed: 1 failed).
Not measured here. What an unhandled rejection does to a running gateway (the process posture, KS-1427); the log-line cap and the live-ingress measurement (items d and e of KS-1524, held); and the same describing expression on 11 other lines (the audit-log catch in the same file and 8 other files), which this change does not touch. The four platform suites are UNMEASURED and not claimed as a pass.
