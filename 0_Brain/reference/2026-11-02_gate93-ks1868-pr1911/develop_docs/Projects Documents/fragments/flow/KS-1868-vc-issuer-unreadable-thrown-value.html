. vc-issuer catch blocks keep logging when the thrown value is unreadable (KS-1868, vc-issuer)

What this changes. Three catch blocks in Blockchain/Dev/services/vc-issuer: credentialRepo.loadFromDb, presentations.loadPresentationsFromDb and credentialRepo.ensureTable. Each read the thrown value with no guard (err instanceof Error ? err.message : String(err), or err?.message). If the thrown value is a revoked Proxy, or an Error whose message getter throws, that read throws inside the catch: the WARN is never logged and the caller gets a TypeError instead. Each read now sits in an inner try with the fallback 'unreadable thrown value'; the WARN text, its key and the value logged for any readable thrown value are unchanged. Product bytes: credentialRepo.ts +14/-2, presentations.ts +7/-1.
Eight new cells in two new test files (ks1868-credentialrepo-loadfromdb-unreadable-throw.test.ts, 5 cells, +93 lines; ks1868-presentations-load-unreadable-throw.test.ts, 3 cells, +60 lines). Per site: a control that an ordinary Error still logs its message (C1; C2 for the table check), and red cells that a revoked Proxy (R1; R3 for the table check) and an Error with a throwing message getter (R2) log the constant reason. loadFromDb and loadPresentationsFromDb are two held Spark passes (O35-P1, O35-P2) applied with strict git apply --check -p1 (rc 0 on both, and rc 1 on a copy with one context line's content corrupted). ensureTable is the same shape written by hand, the one hand edit; it keeps err?.message semantics, so a thrown string or undefined still logs undefined.

.3 What this does not prove

Three catch blocks, not the ticket. KS-1868 stays open: it lists 253 catch and log sites that read a thrown value unguarded; this change fixes three of them, in vc-issuer. The other catch sites that read a thrown value, in these two files and in other services, are not touched. Nothing else in vc-issuer changes behaviour for a readable thrown value.
Not run: the four platform suites (Schemathesis, Akto, Playwright, Performance/k6), a running stack, Node 24 or any LTS Node, npm ci on the merged lockfile, any deploy.
