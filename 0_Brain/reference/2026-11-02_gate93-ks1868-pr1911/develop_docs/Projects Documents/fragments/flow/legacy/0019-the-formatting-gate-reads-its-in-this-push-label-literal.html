29. The formatting gate reads its “in this push” label literally, not as a regex (KS-998)

What this fixes. check-package-format.sh decided whether a red file belonged to the current push with printf '%s\n' "$changed_paths" | grep -qx "$full".
-x anchors the match but still treats $full as a basic regular expression, so a path containing . or a bracket expression matches a different file.
A red src/a.b.ts absent from the push matched src/aXb.ts that was present, and the gate billed the red to the wrong author; a real src/[id].ts in the push matched nothing and was labelled inherited.
The predicate is now grep -qxF: the path is compared as a literal string, which is what a path is.

29.1 The mechanism, and what is deliberately NOT changed

The product change is one line — grep -qx to grep -qxF at systemTest/scripts/check-package-format.sh:180, inside the hunk the payload opens at :177. It changes only which label a red file is printed with. The gate's verdict is untouched: a red package still fails, the exit code is unchanged, and the trailer still counts the same number of failures — three of the suite's eight cells are CONTROLs asserting exactly that. No threshold, no baseline, no manifest, no package list and no exit-code path is touched.

29.2 Red-first, and the figures

Measured at base 147ae442074c, not carried forward. With the new suite present and the product file still at its blob at the base, the suite gives rc 1, 5 passed / 3 failed. The three reds are exactly the dotted-path and bracket-path label cells.
All five CONTROL cells stay green in that red arm, so the red is attributable to the defect and not to a broken harness. With the one-line fix applied the same suite gives 8 passed, 0 failed, rc 0. bash -n is rc 0 on both touched files, so neither red was a load failure. Named siblings at the same head: package_format_gate.test.sh 33 passed / 0 failed, pre_push_hook_base.test.sh 28 passed / 0 failed, pre_push_hook_current_develop.test.sh 4 passed / 0 failed.

29.3 The new suite is 100644, and that is correct here

systemTest/__tests__/ks998_format_gate_push_label_is_literal.test.sh lands 100644, because the payload carries no new file mode line. That is not a defect to repair: run-shell-suites.sh discovers by globbing *.test.sh and invokes with bash <file>, so no executable bit is required, and the suite's nearest neighbour package_format_gate.test.sh is 100644 too.
Stated because it is a real asymmetry: 15 of the 17 shell suites in that directory are 100755. Nothing in systemTest discovers a suite by its exec bit — measured, with the only two -x tests in the tree being a Schemathesis runner path and a prettier binary, neither a suite. Discovery moves 70 → 71, measured by moving the file aside and back and listed 1 time after against 0 before; the file was restored sha256-identical (7a6c8313ae687339, 4,707 B). For CI triage: any quoted shell-suite denominator below 71 does not describe this head.
