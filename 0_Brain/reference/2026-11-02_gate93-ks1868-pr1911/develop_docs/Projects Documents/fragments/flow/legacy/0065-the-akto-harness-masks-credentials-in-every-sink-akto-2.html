76. The Akto harness masks credentials in every sink; Akto 2.38.5 → 2.41.6 (KS-1608)

What this fixes. The harness masked four header names and nothing else, so the run artifact <hexId>.report.json stored Akto’s raw testResults[0].message for every flagged row (the role JWT the HAR replay feeds Akto, cookies, the CSRF secret, login tokens), and the HTML cards, curl reproducers, service-log rows, <hexId>.threads.txt and exception messages showed bodies, query strings and error text raw. One module, systemTest/akto/src/core/redact.ts, now decides what a credential is, and every sink calls it: the capture (flagged messages, error patterns, skip and N/A reasons), the message parser (headers, URL, bodies), the curl builder, finding errors and workflow-step errors, service logs (at capture and at render), the diagnostic files and Akto error bodies in exceptions.
Kept on purpose: ids, document hashes, UUIDs, wallet addresses, paths, status codes and non-credential headers such as Server. A JSON body that holds no credential is returned byte-for-byte. Masking changes no count, bucket, severity or exit code: a test checks that every masked engine error still lands in the same skip bucket. The Schemathesis setup no longer prints the first 12 characters of the minted API key.
