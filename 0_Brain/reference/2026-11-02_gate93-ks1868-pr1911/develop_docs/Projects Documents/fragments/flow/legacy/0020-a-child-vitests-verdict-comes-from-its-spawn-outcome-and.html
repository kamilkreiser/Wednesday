25. A child vitest’s verdict comes from its spawn outcome and its JSON report, never from its text (KS-1313)

What this fixes. childSuiteCounts read the child run’s totals by matching /Tests\s+(?:(\d+) failed \| )?(\d+) passed \((\d+)\)/ against the child’s human-readable stdout and stderr.
That pattern requires the word “passed”, so a real fail-only, skip-only or todo-only run matched nothing and the helper threw — the KS 1226 residue this ticket records.
Worse, a child killed by its own 180 s spawnSync timeout writes no summary at all, so whether it was read as a pass depended on what else happened to be in its output (KS 1326).
The helper now runs the child with --reporter=json --outputFile.json=<tmp> and reads numPassedTests / numFailedTests from the report.
Before the report is read at all, endedNormally refuses any child that did not end on its own — a spawn error, a signal, or an exit status other than 0 or 1 — so a killed child cannot read as a pass even beside a passing report.

Measured at base 147ae442074c. Hunk 3 alone — the seven new cells without the new reader — gives rc 1, 7 failed | 3 passed (10), and all seven reds are R1–R7.
The cells red by assertion, not by a load error: each calls a reader() helper whose first act is expect(typeof countsFromSpawn).toBe('function'), and typeof on an undeclared identifier is the one JavaScript form that does not throw. Proved rather than assumed by reading the JSON report’s own totals: passed + failed = 10, so cells ran. 0 passed and 0 failed would have been a load failure and is explicitly not what happened. 25.5 Not covered, and one hole named as a follow-up

A follow-up, not a regression: endedNormally accepts exit status 1, which vitest also uses for an unhandled error rather than ordinary test failures. So a child that died of an unhandled error while still writing a report with numFailedTests: 0 would be accepted. That is strictly narrower than the behaviour being replaced and is not made worse by this change, but it is a real remaining gap and is named here rather than discovered later.
This is a test-harness change: no service, no runtime, no migration, no deploy, and therefore no live sweep is owed.
