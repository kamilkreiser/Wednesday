51. The migration runner’s failed-run message no longer calls a closed defect open (KS-1456)

What this fixes. run-migrations.sh ends a run in which a migration failed by printing why it exits 3. That text said the remaining applied=N-counts-skips defect is KS-808, on every failed run.
Commit ae9bf6828f88 (KS-808 item 2) made the runner count skipped migrations apart from applied ones, so the sentence named a defect the runner no longer has.
The two echo lines that carried it are now one, ending were changed under KS-1031. Exit 3 …. Cells 2–4 of the new suite assert the exit code, the Summary: line and the clean-run path, and they pass at the base and after the change.

51.1 Scope: the printed message, and one comment line

What changes and what does not. The product change is one echo line replacing two, plus one shell comment line after the last echo of the message, at Blockchain/Dev/scripts/run-migrations.sh:189. The comment carries the ticket key and states the prior behaviour; it is not part of the printed text.
With the stub setup of the suite, the failed-run output of the script with and without the comment line is byte-identical (897 bytes each, rc 3 each). No SQL, counting, threshold or exit-code path is touched, and the ticket does not move to Done.
