66.1 Why the old arm is kept, not replaced

Replacing nocontrol outright would have lost a kill. Before this change the non-empty arm was exercised by accident, through the misnamed fixture, and four existing cells depended on it. Making nocontrol truly empty and nothing else would have left a mutant that deletes the second half of the condition (M_2nd, leaving only -z) alive, because an empty set is refused either way. The old line is therefore kept verbatim as trailingcomment and given its own cells, which also pins a boundary of the filter that had no cell: a ${NAME:- in a trailing comment is not excluded.
The three existing call sites of nocontrol (HOOKCTL-REFUSED/1, the short-circuit, and the KS-1643 withheld-run cells) now run on the arm their comments describe — “the derivation has stopped working” — and stay green at 82/0.

66.2 The -z disjunct cannot be pinned, and why

It is redundant, so deleting it is an equivalent mutant. For an empty set the second half of the condition is also true: printf '%s\n' "" | grep -qx 'ALLOW_FORCE' fails, and the ! makes that a refusal. So [ -z "$hook_controls" ] || … and the same condition with the first half removed refuse on exactly the same inputs. A truth table over five derived sets ([], [NAME], [ALLOW_FORCE], [ALLOW_FORCE FAKE], [FAKE]) under bash 3.2 with pipefail, which is preflight.sh:91’s own setting, gives identical columns for the original and the deletion.
Driven through the real suite as a matched pair, the deletion arm reads 82 passed, 0 failed and a cell-by-cell verdict diff against the control moves zero cells. No cell can distinguish the disjunct’s presence, so a cell that “goes red when it is deleted” cannot exist. What a cell can do is make the branch execute, which the empty arm now does, and pin the two mutants that are not equivalent.
The two killable mutants separate cleanly by arm. M_accept (an empty set is accepted: [ -n "$hook_controls" ] && ! …) proceeds only on the empty set, and is killed by the empty arm. M_2nd (only -z remains) proceeds on [NAME] and [FAKE], and is killed by the trailing-comment arm. Whether to delete the redundant disjunct from preflight.sh is a product-file question and is not decided here.
