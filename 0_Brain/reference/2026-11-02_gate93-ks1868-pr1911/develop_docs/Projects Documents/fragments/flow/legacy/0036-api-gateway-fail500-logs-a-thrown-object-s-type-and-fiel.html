45. api-gateway fail500 logs a thrown object's type and field names, not [object Object] (KS-1346)

45.1 What this row is, and what it is not

Three api-gateway routers share one fail500() helper: routes/notifications.ts, routes/batch.ts and routes/audit-export.ts. Its log expression was String(err), so a thrown non-Error object rendered as "[object Object]" and the throw's content was lost from the log. It now logs a thrown object's type and field names only. Kam's ruling (card secuura-ks1346-logging-thrown-objects-leaks-secrets, choice a): "log a thrown object's TYPE and FIELD NAMES only." The expression is byte-for-byte the one already live in services/originate/src/routes/adminConfig.ts (263 bytes, cmp rc 0 against all three sites after the change; a cmp against the pre-ruling text differs, as the control). The 500 response body is unchanged — it was already the constant INTERNAL_ERROR body, so the response tells a reader nothing about this row.

45.2 What it deliberately does NOT change, because the expression's own branches decide it

A thrown Error still logs its .message. Thrown text is still logged verbatim (typeof err === 'string' ? err). An empty Error("") logs "". Only objects, class instances and numbers are reduced to type plus field names. QA gate77 threw a credential-shaped URL at these routes and it reached logger.error intact. That case is recorded on this ticket and is not closed by this row, so nothing here should be read as "the log no longer carries secrets". The three sites were added on 2026-10-09 with blobs 5ae6c0788dfd, 75e84b3aa06c and 893669657db0; the same three paths at this row's base 613070f29112 carry those identical blobs, so the change lands on exactly the sites QA measured.
