105. originate adminConfig.ts: fifteen catch conditions can no longer be hung by a hostile thrown value (KS-1780, part 2)

What this changes. KS-1780, part 2: fifteen catch blocks in services/originate/src/routes/adminConfig.ts tested err?.message?.includes(...) or err?.code BEFORE they reached fail500. That read touches the thrown value itself, so a revoked Proxy, or an object whose message getter throws, made the read throw from inside the catch: the handler’s promise rejected and the request got no answer at all (the KS 1772 shape, one step earlier; fail500 already survives such a value). Two small helpers, errorMessageIncludes and isMissingTableError, now do those reads inside a try and return false when the value cannot be inspected, so such a value is not a “table missing” or “unique constraint” error and falls through to fail500, which answers the constant 500. Thirteen of the fifteen sites are the missing-table check (does not exist or code 42P01); the other two are one message check on POST /document-types (unique constraint) and one on GET /rights-holders/:id/documents (does not exist only). For a readable value nothing changes, with one strictness: the helpers compare with === true. A local model (the Spark, DeepSeek V4 Flash, pass ks_1780_p2_admin) wrote the patch; its checker passed 7 of 7 and it is byte-identical to the drafter’s golden. It was applied here strictly and unchanged.
adminConfig.ts changes +36 / −15 (the two helpers and the fifteen replaced conditions). The new test is ks1780-admin-config-catches-cannot-hang-on-a-hostile-throw.test.ts (jest, 21 cells): A1 and A2 on four GET routes (eight cells), C1 to C3 on the same four routes (twelve controls) and S1, a source-text pin.
