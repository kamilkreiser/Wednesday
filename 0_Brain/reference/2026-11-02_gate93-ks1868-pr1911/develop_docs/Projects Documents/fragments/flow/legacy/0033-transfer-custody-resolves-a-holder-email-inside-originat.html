44. transfer-custody resolves a holder email inside originate, not through auth's lookup (KS-1402)

44.1 What this row is, and what it is not

POST /api/documents/:id/transfer-custody with newHolderEmail no longer calls auth's GET /api/users/lookup. That call forwarded the caller's credential, and Platform S's connector key is minted without users:read on purpose, so every S custody transfer by email answered 403 (Stuart measured 7 of 7 on 2026-10-05). Originate now computes the email's lookup HMAC and reads users itself, on the request's db, with the tenant bound in the query. Kam's ruling (card secuura-ks1402-s-key-cannot-carry-users-read-1006, choice a): "Originate resolves the holder with its own service credential (Stuart's option 2)." Reading "its own service credential" as originate's own database role, rather than a new service token, is a reading of that sentence, confirmed by Wednesday on 2026-10-09. No token is minted, stored or sent, auth is not changed, and no scope moves. The act is still authorised on the caller, first, by the unchanged documents:transfer-custody gate; only resolution moved. Section 9a (KS-1402's first half, auth's /lookup accepting a connector token) still describes auth correctly; this route simply no longer goes there.

44.2 The headline for the gate: the tenant guard is newly load-bearing for connectors

Before KS-1402 auth refused the connector before its tenant compare ever ran, so for a connector the cross-tenant guard was unreachable. Now the connector resolves, and the bound tenant predicate is the only thing between it and another tenant's user. Cell C2 pins it: a tenant-A connector naming an email whose only user is in tenant B gets 404 RECIPIENT_NOT_FOUND, byte-equal to a true miss, nothing written, and the tenant value bound is tenant A (asserted as a value, not as SQL text). C2b pins the same guard for an interactive caller, which did reach auth's compare at base: green at base and head. The bound predicate is also stricter than the path it replaces: auth's /lookup skipped its tenant compare whenever the caller's credential carried no tenant (the KS 1406 class, filed, unchanged here).

44.6 What is NOT proven

A runtime-behaviour change is not done on offline green. A live sweep is owed (no stack was built). No S-to-K pair run: Stuart's cell turns green only after a deploy. Legacy rows: a user whose email is still plaintext, with no lookup hash, resolved at base through auth's legacy fallback and is 404 here; how many exist was not measured. Deploy requirement: originate must have PII_LOOKUP_HMAC_KEY (docker-compose declares it for originate), or every email transfer answers the labelled 502. A database failure during resolution now lands in the route's existing 500, as the id path's users read already does; before, the only failure here was auth being unreachable (502). The KS 1406 class on auth's /lookup itself is not addressed, and /lookup is unchanged.
