127. The Schemathesis post-run gates run on a failed sweep (KS-752)

What this changes. Report reconciliation, console vs verdict and the triaged baseline now run on every valid run, a failed sweep included, as Kamil directed on KS-752 (2026-09-02): “evaluate … eagerly rather than behind success, and combine the verdicts afterwards”, with an invalid-run rehearsal. Before, they read NOT EVALUATED on every failing sweep (every run, since the sweep always finds something) and were run by hand. They are still skipped, with the reason printed, when the run is invalid or its NDJSON incomplete, because their inputs cannot be trusted then. A gate can turn a run red, never green: each is AND-ed onto the verdict so far (scripts/runner/post_run_verdict.py).
Live. On the 2026-10-30 pre-merge sweep (slot 1, seed 3447773427, run pre-merge-2026-10-30T11-20-16Z-slot1), which failed, no gate read NOT EVALUATED: reconciliation agreed (87 unique failures, 11,387 cases), console vs verdict agreed, and the baseline gate named its 4 untriaged pairs itself (80 failing pairs, 76 baselined).
