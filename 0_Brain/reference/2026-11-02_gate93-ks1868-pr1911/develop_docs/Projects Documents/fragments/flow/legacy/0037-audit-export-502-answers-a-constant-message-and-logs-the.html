46. audit-export 502 answers a constant message, and logs the failed fetch by the ruled expression (KS-1410)

46.1 What this row is, and what it is not

GET /api/admin/audit/export in api-gateway (routes/audit-export.ts): when the fetch to the security service throws, the 502 body was `Failed to reach security service: ${err.message}` with no NODE_ENV guard, so the thrown text reached the client in every environment. It now answers the constant Failed to reach security service, and the catch logs the failure server-side, naming the route. Before, that catch logged nothing. This is one site of KS-1410's scope (the ticket counts 28 across six services), and the ticket stays open. Raised from a Wednesday-held Spark pass and re-proved on develop 613070f29112. The file's own fail500 at :24-25 is not changed here: PR 1443 (KS 1346) carries that line, about 145 lines away from this hunk.

46.2 The log line uses the ruled expression, and what it still logs

The new log line's error value is the expression Kam ruled on 2026-09-27 (card secuura-ks1346-logging-thrown-objects-leaks-secrets, choice a: log a thrown object's type and field names only). It is byte-identical to the ruled line in originate/src/routes/adminConfig.ts:104: 262 bytes, sha256/16 4623660d465c942a, compared with cmp. What it reduces and what it does not: an Error is logged as its .message and a thrown string as it is; a plain object or class instance is logged as thrown <Type> with fields [a, b]; any other value as thrown <typeof>. So at this site the 502 body no longer carries the thrown text, while the log still carries an Error's message. The Spark's payload logged err instanceof Error ? err.message : String(err), which writes a plain object as [object Object] (node v24.7.0); replacing it is the one deviation from that payload.
