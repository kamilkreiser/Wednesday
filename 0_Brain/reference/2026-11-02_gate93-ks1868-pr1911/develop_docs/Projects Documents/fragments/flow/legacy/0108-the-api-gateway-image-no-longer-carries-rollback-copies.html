119. The api-gateway image no longer carries rollback copies of the OpenAPI spec that sit in the host directory (KS-1823)

What this changes. One product file: the builder stage of Blockchain/Dev/services/api-gateway/Dockerfile gains two lines straight after COPY docs/openapi/ ./docs/openapi/ and before the TypeScript build: a comment and RUN rm -f ./docs/openapi/*.pre-* ./docs/openapi/*.rollback-*. The runtime stage copies /app/docs/openapi from the builder, so what the builder no longer holds the image no longer ships. This alters the content of the image, so it is a deploy surface.
Why: the builder copies the whole docs/openapi directory. The demo host’s copy of that directory holds two rollback copies of the spec, secuura-api.yaml.pre-ks508 and secuura-api.yaml.rollback-2026-08-27-ks661, that are not in git, and a build there baked both into the image. The gateway reads secuura-api.yaml only. Whether anything served the copies is not measured.
New test ks1823-dockerfile-drops-spec-backups.test.ts, 8 cells, reading the Dockerfile and the gateway src/index.ts as text: R1 to R3 are RED (the rm line exists for each of the two name shapes, and sits after the spec COPY, before the build and before the runtime stage); C1 to C5 are controls (the spec COPY and the runtime COPY are still there, no line removes the spec or the directory, the gateway still reads docs/openapi/secuura-api.yaml, and the instrument reads real files).

119.1 What proves it

Red without the Dockerfile line, green with it, and the effect shown in a real image build. Test only, at develop 7152ac669d2d: 3 of 8 cells fail (R1, R2, R3) and the 5 controls pass. With the Dockerfile line: 8 of 8 pass.
Whole api-gateway suite, vitest with --maxWorkers=3, warm, at develop 84ddbd63c008: untouched develop 129 files / 1313 of 1313 pass; with the change 130 files / 1321 of 1321 pass, 0 failed, 0 skipped (+8 cells). tsc with the test files in the program (166 files, 130 under __tests__): 27 errors, the same 27 as untouched develop and as the recorded ratchet baseline (test-types-ratchet.sh: 27 in the baseline, 0 new, 0 stale), none in the new file; a planted type error was reported by file name. eslint on the new file: 0 errors, 0 warnings, and a planted file raised @typescript-eslint/no-unused-vars and no-debugger.
Three local docker builds (Docker Desktop 29.7.2 client and server, linux/arm64; context Blockchain/Dev, -f services/api-gateway/Dockerfile, as docker-compose.yml and deploy-all.sh use it). Two decoy files named like the two backups were planted untracked in docs/openapi of the build tree, then moved to a dated quarantine folder. (1) Develop’s Dockerfile, kept outside the context: ls /app/docs/openapi in the image lists both decoys, secuura-api.yaml and two markdown files. (2) The patched Dockerfile, same tree: the listing has no decoy, and secuura-api.yaml and the two markdown files are still there. (3) The patched Dockerfile in a tree without decoys: the build succeeds (the new rm -f exits 0 when nothing matches) and its image has the same image ID as (2).
Nothing was pushed to a registry and nothing was deployed.

119.2 Environment and figures

Measured 2026-10-29 (UTC) on an Apple Silicon (arm64) Mac, macOS 27.0.1, shared with other seats. Node v26.8.1 (not an LTS line), TypeScript 5.9.3, vitest 4.1.12, eslint 10.7.0. The whole-suite runs took 77 s (untouched develop) and 83 s (with the change).
A busy host changes the whole-suite result. With default parallelism, or on the first run in a fresh worktree, up to three api-gateway test files failed here under load, on untouched develop as well as with this change: ks815-verification-router-guards-its-own-body (hook timed out in 10000 ms; 12 cells skipped), ks1543-document-types-catch-logs-the-error (the same hook timeout, or a cell that lints a real file through the ESLint Node API) and ks1543-five-pre-existing-eslint-warnings-in (the same kind of cell). Each passes when run alone (12 of 12, 10 of 10, 6 of 6). The figures above are from warm runs with the worker cap.

119.3 What this does not prove

An image content change, not a host change. Not done: any deploy of the image, any az acr build (the cloud build; this host built with a local Docker), and any removal of the two backups from the demo host. They stay on the host; only the image stops carrying them.
The line removes two name shapes only (*.pre-* and *.rollback-*). A backup the host later gains under another name would still enter the image.
Not run: the four platform suites (Schemathesis, Akto, Playwright, Performance/k6), Node 24, a running gateway container. The pre-push hook’s leg count is stated in the pull request.
