84. AppError subclasses in packages/shared keep their own prototype, so instanceof on them is no longer always false (KS-1467)

What this changes. KS-1467, the packages/shared half (the services/auth half is a separate change): the constructor of AppError in packages/shared/src/errors/index.ts ended with Object.setPrototypeOf(this, AppError.prototype), which reset every subclass instance to the base prototype. So err instanceof NotFoundError, and the same test on the other eight subclasses and on DocumentNotFoundError, was always false. The line now reads Object.setPrototypeOf(this, new.target.prototype). A local model (the Spark, DeepSeek V4 Flash) wrote the patch; its checker passed 7 of 7 and the patch is byte-identical to the drafter’s golden. It was applied here strictly and unchanged.
One product line changes (+1 / −1). The new test is packages/shared/src/__tests__/ks1467-shared-app-error-subclasses-keep-their-own-prototype.test.ts (vitest, 29 cells). A search of non-test source in services/ and packages/ finds one code use of instanceof on one of these subclass names, in services/auth/src/middleware/errorHandler.ts, which defines its own classes and does not import these (plus one comment in passwordLoginGate.ts). No tier timing or budget in these documents moves.
