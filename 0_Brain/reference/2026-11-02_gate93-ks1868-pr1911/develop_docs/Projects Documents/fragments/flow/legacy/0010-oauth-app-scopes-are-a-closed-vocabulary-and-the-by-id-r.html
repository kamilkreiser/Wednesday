18. OAuth app scopes are a closed vocabulary, and the by-id routes are owner-or-admin (KS-1210)

What this fixes. Any authenticated user, whatever their role, could register an OAuth app — or change another user's app — with any scope list at all, including the wildcard *, the privileged subjects:erase, and strings that are not scopes (made:up).
Both request schemas took z.array(pgSafeStringSchema), i.e. any NUL-free string, and neither POST /apps nor PATCH /apps/:id carried a role or ownership check.
Measured again at this change's base: updateApp(id, updates) and getAppById(id) are keyed on the id ALONE, with no owner predicate — which answers a question KS-1210 itself listed as not measured, and is why the gate belongs in the route handlers rather than the repository.

18.1 Two gates, two lists, and why they are copied rather than imported

Gate 1 closes both schemas to the nine AVAILABLE_SCOPES (services/auth/src/services/oauth.ts:57-67, blob 8995edec6a43): anything else is 400 for every caller, which alone closes the sev-5.
On top of that, the privileged set {admin:read, admin:write} may only be registered by a caller in the four-role platform list — otherwise 403. Gate 2 makes the four by-id routes (GET, PATCH, DELETE, POST .../rotate-secret) answer 404 unless the caller created the app or is in the six-role admin list — 404 rather than 403, so another user's app is not disclosed by the status code.
Neither list is importable: PLATFORM_ADMIN_ROLES is a module-level const that is not exported (routes/users.ts:192) and ADMIN_ROLES is local to that file's GET '/' handler (routes/users.ts:439), both blob ea9f8da97a04.
They are therefore copied into routes/oauth.ts by name, with a drift cell that reads users.ts as source and fails if either copy stops matching — so the duplication cannot rot silently.
An export edit in users.ts was deliberately not made: that file belongs to other rows this round.

18.3 Figures, measured

Red-first, by assertion, one red arm per conjunct. The same 24 cells against the base product code are 17 failed | 7 passed (24); at head they are 24 passed (24).
Both numbers are non-zero, so the red is a real red and not a load failure — a first attempt with an invalid reporter flag produced neither number and was discarded rather than reported.
The 7 that pass at base are the must-not-break arms: a legal in-vocabulary list, a platform admin registering admin:write, certifications:write for a plain user, the owner's own GET and PATCH, the ORG_ADMIN bypass, and the drift reader's own refusal control.
The services/auth suite is 79 files / 864 tests, 864 passed, 0 failed at head — no new red, and no red at all: the two ks949-platform-admin-seed-identity 5000 ms timeouts seen earlier in the day under heavier concurrency did not recur in this run. tsc 5.9.3 on services/auth is rc 0, 0 errors, with a positive control (a planted type error) at rc 2, 2 errors and the source restored byte-identical.
Two sibling test files had to be corrected, and that is part of this change rather than collateral left for someone else.ks451-oauth-app-nul-scope asserted that analytics:read parses — a scope that was never in the published nine and passed only because the array accepted any string. ks431-oauth-app-update mocked AVAILABLE_SCOPES as [] (which makes z.enum([]) and rejects everything) and mocked getAppById as a bare vi.fn() returning undefined, so the new ownership gate turned five of its cells into 404s.
Both were fixed by moving fixtures into the published vocabulary and giving the stub user an owned app; neither file's subject changed, and KS-451's NUL cells are untouched.

18.4 Not covered

No live sweep (§5f), so KS-1210 does not move to Done here. certifications:write and webhooks:manage are deliberately not privileged — a product choice, tightenable later.
The gateway edge still forwards a valid user token to these routes with no role gate of its own (residue, named not fixed). Existing apps that already carry a now-refused scope are not touched: there is no data migration here, and no audit of what is registered live.
And no stated timing covers a services/auth unit suite — measured at this base across both platform-k docs and the test-discipline skill, services/auth appears 7 times and not once within 120 characters of an explicit duration, where the same instrument on the same three files finds 11 durations beside Akto.
So no tier budget moves with this change.
