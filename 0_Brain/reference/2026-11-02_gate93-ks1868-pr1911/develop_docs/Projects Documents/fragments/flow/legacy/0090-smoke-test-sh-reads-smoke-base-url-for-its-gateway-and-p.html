101. smoke-test.sh reads SMOKE_BASE_URL for its gateway and prints the target it is using (KS-1250)

What this changes. KS-1250: RUNBOOK section 2.2 tells an operator to run SMOKE_BASE_URL=https://<gateway> scripts/smoke-test.sh against an environment, but Blockchain/Dev/scripts/smoke-test.sh set its gateway from a literal and never read the variable, so a run could look like a check of kintsugi or demo while it checked localhost. GATEWAY is now ${SMOKE_BASE_URL:-http://localhost:6882} (unset or empty keeps the old default) and the script prints Smoke target: <gateway>. A local model (the Spark, DeepSeek V4 Flash, pass ks_1250_p1) wrote the patch; its checker passed 7 of 7 and the patch is byte-identical to the drafter’s golden. It was applied here strictly and unchanged.
The script changes +3 / −1 (a comment, the assignment, the echo); its mode stays 100755. The new test is Blockchain/Dev/scripts/__tests__/smoke_test_honours_smoke_base_url.test.sh (5 cells), picked up by the shell-suite runner without any wiring. A remote full run is still not remote-clean: the patch moves only GATEWAY, and 12 live lines in the full run (sections 7 onward) still call hard-coded http://localhost:60xx service ports, so with SMOKE_BASE_URL set to a remote gateway those checks still hit localhost. This closes the gateway half of KS-1250, not the ticket. No tier timing or budget in these documents moves.

101.2 What the cells prove, and what they do not

The gateway variable and the printed target, not a remote run. The cells run the script in --quick mode with a stub curl on a private PATH that records every URL it is given and answers like a healthy gateway, so no network is touched. They prove that with SMOKE_BASE_URL set every URL goes under it and the run prints Smoke target: <base> once (the two RED cells), and that an unset or an empty variable keeps every URL under http://localhost:6882 (two controls) and prints that target once (a third control). Only the quick path is exercised.
Not measured: a run against kintsugi or demo, the full (non-quick) run, the 12 remaining hard-coded service-port checks, a running stack, the four platform suites (Schemathesis, Akto, Playwright, Performance/k6), and any deploy. None of them is claimed as passing.
