91. issuerCerts.ts holds the admin-role test once, in one helper, hasAdminRole (KS-1536, groundwork)

What this changes. KS-1536 hangs this change only because the builder needs an open ticket: it is a behaviour-preserving extraction, groundwork for the role-vocabulary class, not a fix for KS-1536. In services/auth/src/routes/issuerCerts.ts the four gates (isAuthorisedForCertWrite, isAuthorisedForCertRead, isAuthorisedForCertRevoke and isAuthorisedForCertSign) each copied the same two lines, const role = String(user.role ?? '') and the ADMIN_ROLES.includes(role) || ADMIN_ROLES.includes(role.toUpperCase()) test. They now call one exported helper, hasAdminRole(role: unknown), defined after ADMIN_ROLES, whose body is the same two expressions. Every spelling admitted or refused before is admitted or refused now. A local model (the Spark, DeepSeek V4 Flash, pass ks_1536_p1) wrote the patch; its checker passed 7 of 7 and the patch is byte-identical to the drafter’s golden. It was applied here strictly and unchanged.
The product file changes +13 / −8. The new test is services/auth/src/__tests__/ks1536-issuer-certs-admin-role-gate-is-one-helper.test.ts (vitest, 9 cells): R1 to R3 are RED at the pin (the helper is exported; it keeps the truth table of the copied lines; the file holds the role comparison once, which is a source-text check of the file), and C1 to C6 are controls on the four gates that are green before and after. One helper and its four callers, not the role vocabulary.
