69. The two N3 cells now assert that the hash they send is a real one (KS-1634)

What this fixes. In Blockchain/Dev/services/originate/src/__tests__/ks1634-v2-chain-only-match-carries-simulated.test.ts the two N3 cells (simulated as the string "true", and as the number 1) each send a real tx hash on purpose. With a mock_tx_ hash the presenter refuses the reply on the hash alone (FABRICATED_TXHASH_RE in routes/verification.ts), so the cell would pass under the === true mutant and pin nothing. Neither cell checked that the hash it sent was real: it came from chainReply’s default (REAL_TX), implicitly. The review note is AZ1 on the pull request that added the cells (#1639).
Each cell now builds its reply first and asserts expect(reply.txHash).toMatch(REAL_TX_SHAPE) before sending it. REAL_TX_SHAPE is /^[0-9a-f]{64}$/, held apart from REAL_TX so a mock-prefixed value swapped into REAL_TX itself cannot satisfy it. The file goes 249 to 260 lines and keeps its 10 cells; two assertions are added, no cell is added or removed. No product file changes.
