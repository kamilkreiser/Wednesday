What this fixes. Blockchain/Dev/services/originate/src/__tests__/ks1061-shared-mock-completeness.test.ts scans every *.test.ts in the service for a root-module @secuura/shared mock factory and names any file whose factories do not all go through the shared helper. Four cells are added (10 to 14), each written as a fixture the guard must NAME: I1a a wrong helper path (./somewhere/else), I1b a wrong module name under helpers/ (otherMock), I1c a wrong factory name on the right module (makeOtherMock), and I2 a file with two factories, the first compliant and the second partial. The fixture builder viaHelperBody gains an optional factory-name argument whose default leaves every existing call byte-identical. No product file changes.

72.1 Why three wrong-helper fixtures, not one

One cell per kind of looseness. A loosened path and a loosened factory name are different mutants, and one fixture cannot kill both. Measured in 72.2: I1c passes under the loosened path, and I1a and I1b pass under the loosened name. A bare require( is the loosest of the three and is killed by all three cells.
The existing control “exactly the partial fixtures are named, no compliant twin is” also turns red under all four killed mutants, because the new fixtures are partials by name. It could never react before, since no fixture of these shapes existed.
