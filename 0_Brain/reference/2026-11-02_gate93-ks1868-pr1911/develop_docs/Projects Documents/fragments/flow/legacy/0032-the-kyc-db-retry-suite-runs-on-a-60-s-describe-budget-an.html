43. The kyc db-retry suite runs on a 60 s describe budget, and a test now says so (KS-1328)

43.1 What this row is, and what it is not

services/kyc/src/__tests__/db.retry.test.ts exceeded vitest's 5 s default under fleet load: the first cell timed out at 11,498 ms while passing in 675 ms when run alone, so the overrun is scheduling, not work (the KS-1155 class). This row adds no product code. It raises the budget on this describe only, so every other kyc suite keeps the 5 s default, and adds a cell that asserts the budget is actually on every cell in the file. It pins the budget, not the absence of future timeouts — a slower machine can still exceed 60 s. The ticket does not move to Done.

43.2 Red-first by TAMPER, because the load was not reproduced

The original timeout needs fleet load to reproduce, and this seat did not reproduce it: the claim that 60 s absorbs an 11,498 ms overrun is arithmetic on the 2026-09-26 measurement, not a fresh one. So the red proof is a tamper on the one thing the new cell asserts: remove { timeout: 60_000 } from the describe and the suite must go red on an assertion, not a load error. It does — Tests 1 failed | 33 passed (34), Test Files 1 failed | 5 passed (6), rc 1, failing on AssertionError: expected 5000 to be 60000. Restoring the budget: Tests 34 passed (34), Test Files 6 passed (6), rc 0.

43.3 The runner trap this row walked into, recorded because it cost a measurement

Run the suite through kyc's own npm script (npm test = vitest run), never a hand-built vitest invocation. A first red run used npm test -- --reporter=basic. That reporter does not exist in vitest 4.1.11, so vitest exited with a Startup Error and rc 1 having run zero tests. An rc of 1 with no Tests line is a load failure, not a red; reading it as a red would have recorded a tamper that never executed.

43.4 Not covered

Unmeasured here. The four platform suites (Schemathesis, Akto, Playwright, Performance/k6) were not run — no local stack. The timeout under real fleet load is not re-measured. The 6-cell count the new cell asserts will need updating if a cell is added to the file; that is deliberate, so the pin cannot silently decay.
