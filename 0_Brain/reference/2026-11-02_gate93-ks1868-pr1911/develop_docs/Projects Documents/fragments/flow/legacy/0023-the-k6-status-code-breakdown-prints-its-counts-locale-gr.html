26.4 The runner trap this row walked into, recorded because it cost real measurements

This package's vitest config is vitest.unit.config.ts, which vitest does not auto-detect. A bare node_modules/.bin/vitest run <file> therefore runs on vitest's own defaults: a 5000 ms timeout instead of the config's 15,000, different include globs, and — the one that matters — no setupFiles, so tests/unit/support/clearSlotEnv.setup.ts never strips the shell's slot family. Measured consequence: the bare invocation reported 130 files / 456 tests with 1 failure (unitSuiteSlotIndependence.test.ts timing out at 5000 ms), while npm run test:unit on the same tree reports 251 suites / 1363 passed, 0 failed. The failure was the harness, not the repo. Always go through npm run test:unit, which is vitest run --config vitest.unit.config.ts.
