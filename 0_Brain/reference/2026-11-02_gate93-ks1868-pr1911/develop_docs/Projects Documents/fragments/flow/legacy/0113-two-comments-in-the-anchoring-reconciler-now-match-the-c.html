124. Two comments in the anchoring reconciler now match the code, and the did:jwk shape test pins six more refused characters (KS-1816, KS-1830)

What this changes. Comments only in Blockchain/Dev/services/anchoring/src/reconciler.ts (+12 / -4 lines, three hunks). The header property no longer says a chain-provider error always leaves the row untouched: it says so only below the give-up age, and that past it (strictly older than the give-up age) the same error is read as absence and the row is marked failed (KS 1810). The MIN_AGE comment no longer says the live loop touches updated_at as it goes: it says the confirmation poll writes nothing between submitted and confirmed, so a row the live loop is still polling can pass MIN_AGE. No executable line changes. The catch comment inside the loop now says what reaches it: the catch is reached when the chain check or the status write rejects; the production chain check catches a provider error itself and answers not-confirmed, so an outage is decided by the header rule above, not by the catch.
New test ks1816-reconciler-comments-match-the-code.test.ts, 5 cells, reading reconciler.ts as text: R1 and R2 are red until the comments are corrected; C1 to C3 are controls that pin the code lines the comments describe (the select ages rows by updated_at, the give-up test reads created_at, the file was read), so the comments cannot drift again.
KS-1830, second pass, test only: 14 new cells in ks1175-identity-anchoring.test.ts: the did:jwk payload must be refused with an exclamation mark, an asterisk, an at sign, a hash sign or a caret inside it, and with a plus sign at its end, for both actorDid and orgDid (12 rows), plus one control per field that each added row is the realistic did:jwk with exactly one extra character. The product anchorSchema.ts is untouched. The cell titles carry ticket keys and gate finding ids as file content.
