Three passes in Blockchain/Dev/services/originate, one PR. Each turns a malformed input that previously reached a raw 500 INTERNAL_ERROR into the route's existing 400 refusal. No authorisation decision moves in any of the three. 39.3 The share pass registers itself in the hermetic manifest, and the other two must not

The share pass edits KS 1293's SUBJECTS list to add its own new test file. The obvious question is whether the other two new ks593-* files need listing too. They must not, and this was measured rather than assumed. KS 1293's MANIFEST-DRIFT cell requires a file to be a SUBJECT only if its content mentions ENV_KEY (ANCHORING_SERVICE_URL). Counted: the share file mentions it once and is listed; the adminconfig and signatories files mention it zero times and are not listed. Firing control: planting one ANCHORING_SERVICE_URL mention into the unlisted adminconfig file turns MANIFEST-DRIFT red (1 failed / 9 passed, missing non-empty), and restoring the file byte-identical returns it to 10 passed. So the negative answer is one the cell could have contradicted.
