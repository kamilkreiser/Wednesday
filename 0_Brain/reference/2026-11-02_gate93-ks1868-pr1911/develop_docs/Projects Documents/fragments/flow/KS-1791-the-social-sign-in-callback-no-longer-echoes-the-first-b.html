. The social sign-in callback no longer echoes the first bytes of a non-JSON provider answer (KS-1791)

What this changes.Blockchain/Dev/services/auth/src/routes/auth.ts, +4/-3, in the callback’s catch around provider.exchangeCode(code). A provider that answers 200 with a body that is not JSON makes the adapter’s .json() throw a SyntaxError whose message quotes the first 10 characters of that body (V8). The callback echoed that message to the client inside OAuth authentication failed: ..., so those bytes were the provider’s. A SyntaxError now answers 400 BAD_REQUEST OAuth authentication failed: the provider answer could not be read; every other exchange failure keeps its own message, as before. Six adapters parse the token answer with .json() (apple, facebook, github, google, linkedin, microsoft-personal) and the change is in the route, so it covers all of them; the new cell drives GitHub only.
The existing test ks1240b-social-provider-fetches-are-bounded-and-classified.test.ts gains +12/-1: a html200 mode in the provider stub (200 with text/html) and one cell, R1, which asserts the 400, the neutral text, that the first bytes of the provider body are not in the response and that the parser’s own message (is not valid JSON) is not either. The file now has 59 cells.
