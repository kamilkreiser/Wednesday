. Billing’s credit grant and the NFT platform fee admit platform administrators only, not every registered user (KS-1850)

What this changes. POST /billing/admin/credits (adds certification credits, which are money, to any customerId) and PUT /api/nft/admin/platform-fee (sets the platform-wide fee) each answered 403 “Admin access required” unless the role was in ['SYSTEM_ADMIN', 'ORG_ADMIN', 'OWNER']. OWNER is the role every self-registered user gets, so every registered user passed. That list also admitted an array role, through String(), and refused SUPER_ADMIN.
Each route now admits exactly the shared isPlatformRole (SYSTEM_ADMIN or SUPER_ADMIN, ASCII case fold only, a non-string refused), checked before the body is read. ORG_ADMIN loses both routes too. That goes beyond the ticket’s literal “drop OWNER”, by the coordinator’s decision: ORG_ADMIN is a tenant role, the credits route’s customerId crosses customers, and the fee is not a tenant setting.
The 403 body is unchanged byte for byte, and the spec already declared it. Two new test files (ks1850-*.test.ts, 14 cells each). ks591-nft-mint-upload-fee-body-required.test.ts is untouched and green.

.3 What this does not prove

Unit level only. No request was made to a running stack or to Stripe. Whether any caller outside this repository grants credits or sets the fee with an OWNER or ORG_ADMIN token is not measured: an in-repo search found none. Binding customerId to the caller’s own customer is not needed once only platform administrators may call the route, and is not done.
Not run: the four platform suites (Schemathesis, Akto, Playwright, Performance/k6), Node 24, any deploy.
