. The billing webhook replay handler logs a constant reason and answers 500 when the thrown value cannot be read (KS-1868)

What this changes. In Blockchain/Dev/services/billing/src/routes/webhooks.ts, the catch of POST /webhooks/replay read the thrown value with error instanceof Error ? error.message : String(error) inside its logger.error call. A thrown value that cannot be read (a revoked Proxy throws on instanceof; an Error whose message getter throws) made that read throw out of the catch, so the handler rejected and the request was never answered (Express 4 does not see an async handler's rejection). The read now sits in its own try and falls back to the constant unreadable thrown value; the handler logs Replay failed and answers the same constant 500 {success:false,error:{code:'INTERNAL_ERROR',message:'Replay failed'}} that an ordinary error gets. 1 product file, +7/-1.
What does not change: an ordinary Error is logged with its own message and answers the same 500 as before; the replay's 400, 404 and 503 answers; handleWebhookEvent and its order (it grants credits before the status UPDATE, so a throw from that UPDATE leaves the credits granted and the status unchanged, in old and new code alike); the route's guard (authenticate() then requireRole('SYSTEM_ADMIN','SUPER_ADMIN'); the gateway does not route it). No money moves in this change. One new test file, 3 cells (1 control, 2 red). A held Spark pass applied strictly (no fuzz, no 3-way).
