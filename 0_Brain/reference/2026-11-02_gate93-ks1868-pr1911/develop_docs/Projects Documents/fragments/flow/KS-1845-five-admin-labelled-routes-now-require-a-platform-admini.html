. Five admin-labelled routes now require a platform administrator, and a KYC reviewer may not review their own verification (KS-1845)

What this changes. Five routes that their own comments or the published spec call admin-only checked no role, so any signed-in caller could call them:
  • POST /api/kyc/:id/review, which decides a KYC verification and sets its level;
  • POST /api/governance/process-expired;
  • POST /api/delegations/admin/process-expired;
  • GET /api/stake/all;
  • GET /api/wallets/sessions.
Each now refuses, as its first step, any caller whose role does not pass the shared isPlatformRole (SYSTEM_ADMIN or SUPER_ADMIN, ASCII case fold only, a non-string refused). The refusal is the 403 the spec already declares: “Reviewer role required” for the review, “Admin role required” for the other four. Nothing the route does is reached on a refusal.
The review also refuses the verification’s own subject, even a platform administrator. That check refuses on equality, so a strict compare would fail open on any spelling difference: both ids are folded first, and an id that is missing or not a string is refused too (QA gate 42 found the bypass: an upper-case UUID in the row). Its role check runs before the body is parsed or the id is looked up, so a refused caller learns neither (no 400, no 404).
Five new test files (ks1845-*.test.ts, one per service, 72 cells: 24 for kyc and 12 for each of the other four). Three existing fixtures change their test principal only, with no assertion changed:
  • ks849-mock-timer-stale-write.test.ts: ADMIN to SYSTEM_ADMIN;
  • staking.test.ts: the stub role is SYSTEM_ADMIN inside the GET /api/stake/all describe only;
  • ks1410-delegations-process-expired-500.test.ts: role: SYSTEM_ADMIN added.
The spec is unchanged: all five operations already declared the 403.

.3 What this does not prove

Unit level only. No request was made to a running stack, so the gateway’s behaviour in front of these routes is not exercised here (each service mounts its own jwtAuthenticate). Whether any caller outside this repository (a scheduler, Platform S) calls these routes with a non-admin token is not measured: an in-repo search found none. Other KYC routes that read or delete by id with no owner check (GET /api/kyc/:id, GET /api/kyc/user/:userId, DELETE /api/kyc/user/:userId/data) are not changed here.
Not run: the four platform suites (Schemathesis, Akto, Playwright, Performance/k6), Node 24, any deploy.
