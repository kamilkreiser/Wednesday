. demo-service scenario context keeps its 500 when the thrown value is unreadable (KS-1868, demo-service)

What this changes. One catch block in Blockchain/Dev/services/demo-service: the handler of GET /scenario/context (src/routes/scenario.ts) read the thrown value with err instanceof Error ? err.message : 'Unknown error' and no guard. If the thrown value is a revoked Proxy, or an Error whose message getter throws, that read throws inside the catch: the error is never logged and the handler throws instead of answering its generic 500. The read now sits in an inner try with the fallback 'unreadable thrown value'; the 'Unknown error' branch for a non-Error value, the logged key and the generic 500 body are unchanged. Product bytes: +6/-1.
Three new cells in one new test file (ks1868-scenario-context-unreadable-throw.test.ts, +99 lines) that drives the real handler out of scenarioRouter.stack: a control that an ordinary Error still logs its message and answers 500 (C1), and red cells that a revoked Proxy (R1) and an Error with a throwing message getter (R2) log the constant reason and still answer 500. The product edit is one held Spark pass (O37-P2) applied with strict git apply --check -p1 (rc 0, and rc 1 on a copy with one context line's content corrupted); there is no hand edit.
