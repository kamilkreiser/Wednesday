. POST /api/workflows/escalate requires a platform administrator (KS-1881)

What this changes. The transfer service’s POST /api/workflows/escalate (services/transfer/src/routes/workflows.ts) runs processEscalations(), which escalates or times out every overdue approval step in every tenant. Its own comment called it an admin endpoint, but it checked no role and did not read the request, so any signed-in caller could run the sweep. It now answers 403 FORBIDDEN “Admin role required” before the sweep runs, unless the caller’s role passes the shared isPlatformRole (SYSTEM_ADMIN or SUPER_ADMIN, ASCII case fold, a non-string refused). That is the same shape as KS-1845’s /admin/process-expired. The sweep itself is unchanged: an admin sweep over every tenant is the intended shape (Wednesday’s D1 ruling, 2026-10-31).
Who is now refused. Any caller without a platform role. Nothing in the repo calls this route. The gateway proxies only /api/transfers and /api/delegations to transfer (proxy.ts:1106, :1113) and answers its own four /api/workflows paths from Redis (proxy.ts:1124-1149); no nginx or Caddy config routes to transfer, and compose publishes no transfer port. So the route is reachable only service-to-service inside the network (QA gate 53’s reading). Out-of-repo schedulers are not measured.
