. The KS-1851 revoke test pins owner-less refusals as byte-identical to an unknown id and not logged (KS-1898)

What this changes. The refusal cells for owner-less credentials in Blockchain/Dev/services/vc-issuer/src/__tests__/ks1851-credential-revoke-bound-to-the-creator.test.ts (V8b to V8g and the three V9 cells, database path) asserted only a 404 and no UPDATE. Each now also asserts that the refusal body is byte-identical to the answer for an unknown id, and that vc-issuer's own logger received neither the caller's reason nor Credential revoked. Test file only: +31/-4, mode 100644, no product file changes.
Four new cells (V14a to V14d) run an owner-less credential on the memory path (stored with the default OWNERLESS owner, so it records no tenant) against an OWNER, an ORG_ADMIN, a SYSTEM_ADMIN and a SUPER_ADMIN of tenant 1: each is refused with a 404 byte-identical to an unknown id, the stored copy is unchanged and not revoked, and the reason is not logged. Before, no owner-less row ran on the memory path at all. The change is a held Spark pass applied strictly (no fuzz, no 3-way).

.1 What proves it

Each new assertion is killed by a tamper the old cells missed. Red proof. The change is test-only, so the product is tampered, not the test. Five tampers of mine, each diverging only for an owner-less row, each with a unique anchor, parsed before it ran and restored byte-identical (sha256 asserted). Patched test: M1 (the refusal logs the caller's reason) 13 cells red, M2 (an extra field in the refusal body, still 404 with the same code and message) 13, M3 (a platform administrator may act on an owner-less row that records no tenant) 4, M4 (any identified caller may act on an owner-less row) 11, M5 (the refusal still writes before it answers) 13. All red by assertion, every other cell stayed green, and each red set equals the one I predicted before the run. Base test, same tampers: M1 0 red, M2 0, M3 2, M4 7, M5 9. M1 and M2 are the gap the ticket names: they survived every old owner-less cell and now fail all 13.
Suite. vc-issuer before: 710 passed, 0 failed, 0 skipped (23 files). After: 714 passed, 0 failed, 0 skipped (23 files). The ks1851 file alone: 32 cells before, 36 after, 36 of 36 green.

.2 Environment and figures

Measured 2026-11-02 (UTC) on an Apple Silicon (arm64) Mac, Darwin 27.0.0, shared with other seats. Base develop 8afcf256ed5f. Node v26.8.1, the only Node installed on the host; the repository's image line is node:24-alpine, so these runs were NOT measured on Node 24. vitest through npm run test -w services/vc-issuer; no Docker stack is involved, and the cells use the module's database and logger mocks.

.3 What this does not prove

What this does not prove. Not run: the four platform suites (Schemathesis, Akto, Playwright, k6), a real PostgreSQL (the database path models the vc_credentials_store row), a real boot or request, and Node 24.
Scope: the shared error handler writes one error-level line per refusal (the same line an unknown id gets) that vc-issuer's logger mock cannot see, so the logging cells watch vc-issuer's own logger only, as the file header already says. A spy on the shared logger, which the ticket offers "if wanted", is not added.
