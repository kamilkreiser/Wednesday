. mcp-server hash tool keeps its isError result when the thrown value is unreadable (KS-1868, mcp-server)

What this changes. One catch block in Blockchain/Dev/services/mcp-server: the secuura_hash_document tool (src/tools/hash.ts) read the thrown value with err instanceof Error ? err.message : String(err) and no guard. If the thrown value is a revoked Proxy, or an Error whose message getter throws, that read throws inside the catch: the tool handler rejects instead of returning its isError result. The read now sits in an inner try with the fallback 'unreadable thrown value'. Product bytes: +6/-1. The catch still returns the thrown message to the MCP client in {success:false,error:message}; that is unchanged on purpose and is a separate matter (KS 1893, filed 2026-10-31, the same class as KS 1410).
Three new cells in one new test file (ks1868-hash-tool-unreadable-throw.test.ts, +67 lines) that registers the tool on a duck-typed server with hashFile mocked to reject: a control that an ordinary Error still returns its message (C1), and red cells that a revoked Proxy (R1) and an Error with a throwing message getter (R2) return a constant reason with isError true. The product edit is one held Spark pass (O36-P2) applied with strict git apply --check -p1 (rc 0, and rc 1 on a copy with one context line's content corrupted); there is no hand edit.

.3 What this does not prove

One catch block, not the ticket. KS-1868 stays open: it lists 253 catch and log sites that read a thrown value unguarded; this change fixes one of them, in mcp-server. The raw file-system error text that the tool returns to its client is not changed (KS 1893). The tool is registered on the stdio server only (index.ts), and a grep (not a read) finds 9 same-shape reads in src/tools; they are not touched.
Not run: the four platform suites (Schemathesis, Akto, Playwright, Performance/k6), a running stack or an MCP client attached to the tool, Node 24 or any LTS Node, npm ci on the merged lockfile, any deploy.
