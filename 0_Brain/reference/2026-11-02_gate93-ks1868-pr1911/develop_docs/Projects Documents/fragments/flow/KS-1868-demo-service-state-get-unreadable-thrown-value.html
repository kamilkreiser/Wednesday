. demo-service GET /state logs and answers the in-memory state when the thrown value is unreadable (KS-1868, demo-service)

What this changes. The catch of GET /demo-api/state in Blockchain/Dev/services/demo-service/src/routes/state.ts: when the Redis read fails, the handler logs Failed to read demo state and answers the in-memory state. It read the thrown value with err instanceof Error ? err.message : 'Unknown error' and no guard, which itself throws for a revoked Proxy (instanceof throws) or for an Error whose message getter throws; the handler then rejected instead of answering. The read is now in an inner try with the fallback 'unreadable thrown value'. The 'Unknown error' branch for a readable non-Error value, the log message text and the res.json(inMemoryState) answer are unchanged (+6/-1 lines in state.ts).
Three cells in the new ks1868-state-get-unreadable-throw.test.ts (+104 lines): the real GET /state handler is taken out of stateRouter.stack and run against an ioredis stand-in that rejects with the value under test. A control that an ordinary Error still logs its message and answers the in-memory state (C1), and two red cells, a revoked Proxy (R1) and an Error whose message getter throws (R2), that must not throw, must answer the in-memory state and must log the constant reason. Both files are the held Spark pass O41-P2 applied with strict git apply --check -p1 at the base, with no hand edit.
