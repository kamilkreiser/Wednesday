. The api-gateway image keeps only secuura-api.yaml in docs/openapi: the builder removes every other file and folder (KS-1841)

What this changes. Blockchain/Dev/services/api-gateway/Dockerfile line 35 was RUN rm -f ./docs/openapi/*.pre-* ./docs/openapi/*.rollback-* (KS-1823), which removed two backup name shapes. It is now RUN find ./docs/openapi -mindepth 1 -maxdepth 1 ! -name secuura-api.yaml -exec rm -rf {} +: in the builder stage, after COPY docs/openapi/, everything directly inside docs/openapi except secuura-api.yaml is removed, whatever its name and whether it is a file or a folder. That closes the ticket's F1 (backup shapes the two globs missed: a dotfile, an upper-case PRE, a nested file, .bak, .orig, ~) and F3 (a backup-named folder made rm -f fail the build). The Dockerfile change is +2/-2: the RUN line and its comment.
What does not change: the spec the gateway reads (docs/openapi/secuura-api.yaml) is kept byte-identical; the runtime stage still copies the directory from the builder; nothing else in the image. Not addressed: F2 (the backups still enter the build context and the builder layer; that needs a .dockerignore line or an allow-list COPY). The older entries (cheat 0104, flow 0108) still describe the two-glob line; they are history and are not edited here.
The existing test is edited. ks1823-dockerfile-drops-spec-backups.test.ts: R1, R2 and RM_LINE now pin the new line. Its C3 control could not keep its old predicate, because the new line legitimately contains rm -rf and names the spec; the first version of this change narrowed it to physical lines starting RUN rm, which checked zero lines and let a chained RUN npm run build && rm ... and a find ... -delete pass (QA gate 89, G89-1907-F1). C3 is rewritten: over every RUN instruction (backslash continuation lines joined, any letter case) other than the sanctioned find line, it requires that none removes or deletes anything (rm, unlink, -delete) and names docs or the spec. A mv of the spec is still not caught: matching text cannot tell where it goes. The new file carries the other guard: R2 runs the Dockerfile's own command and requires the spec to survive byte-identical. One new test file, 5 cells (3 red, 2 controls).
