. audit-logger flush retries the event when the thrown value is unreadable (KS-1868, packages/shared, SECURITY surface)

What this changes (a SECURITY surface: the audit trail). One catch in Blockchain/Dev/packages/shared/src/security/audit-logger.ts: AuditLogger.flush calls config.onEvent(event) and, on failure, logs Failed to process audit event and re-adds the event with this.eventBuffer.unshift(event). The catch read the thrown value with error instanceof Error ? error.message : String(error) and no guard. If the value is a revoked Proxy, or an Error whose message getter throws, that read throws before the unshift: the retry never runs, the audit event is dropped, and flush() rejects. The read now sits in an inner try with the fallback unreadable thrown value. What does NOT change: the audit record format, the hash chain, the log text, the error key, and the retry for any readable value. Product bytes +7/-1.
Three new cells in ks1868-audit-logger-flush-unreadable-throw.test.ts: a control that an ordinary Error is logged with its message and the event is retried (C1), and red cells for a revoked Proxy (R1) and a throwing message getter (R2), each asserting that flush() resolves, the log carries the constant, and the event is delivered on the next flush. The edit is the held Spark pass O39-P1 applied with strict git apply --check -p1 (rc 0 on both sections, rc 1 on a copy with one context line corrupted); there is no hand edit.

.3 What this does not prove

One catch, and no importer. KS-1868 stays open: it lists 253 catch and log sites that read a thrown value unguarded; this change fixes one. At this base the module has NO importer: it is a published subpath (./security/audit-logger in the exports map of packages/shared) and a census of tracked files (excluding node_modules and dist) finds 8 lines naming it, all in its own file or in package.json; no service imports it, and no existing shared test names audit (0 files), so the new cells are its only coverage. The change protects future and external consumers. A different AuditLogger exists in @secuura/service-utils (services/shared/src/security/audit.ts lines 318 and 461); it is not touched. The other AuditLogger catch sites and api-gateway middleware/audit.ts:334 are not touched, and nothing about what is audited changes.
Not run: the four platform suites (Schemathesis, Akto, Playwright, Performance/k6), a running stack, Node 24 or any LTS Node, npm ci, any deploy.
