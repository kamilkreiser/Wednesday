. The catch of KS-1844 GET /api/certifications/:id answers a thrown value it cannot read instead of leaving the request without a reply

What this changes.The catch of GET /api/certifications/:id in Blockchain/Dev/services/originate/src/routes/certifications.ts (about lines 1063 to 1095) read code, meta.code, error instanceof Error and error.message straight off the thrown value with no try of its own. A thrown value whose property read throws (a revoked Proxy, or an Error whose code or message getter throws) therefore threw inside the catch of an async Express 4 handler, and the request got no answer. The two reads are now each inside a try: a value that cannot be read is not a 22P02 and falls through to the constant 500 envelope, and the log reason is coerced to a string inside its own try (String() of the message, or of the value), with the fixed fallback unreadable thrown value when that cannot be done. +20 -3 in one file (QA gate 36, round 1, added the string coercion and the definite-assignment declaration).
