. package_format_gate.test.sh picks its "dead" pid with ps -p, as the gate does (KS-1926)

What this changes. Cases 20 and 32 of systemTest/__tests__/package_format_gate.test.sh plant a stage directory for a "dead" pid and expect systemTest/scripts/check-package-format.sh to sweep it. The gate decides liveness with ps -p. The test chose the pid with kill -0, which fails with EPERM for a live process owned by another user on macOS, so the test could call that process dead and then fail on the gate's correct refusal to sweep it. At pre-push hook leg 14 that is a random red on an unrelated push. Both pickers now loop on ps -p (a comment line at 654 and 884, the picker on the next line): +4/-2 lines, no change to the gate or to any other cell.
The new suite systemTest/__tests__/package_format_gate_dead_pid.test.sh (5 cells, 71 lines, mode 100644 like its neighbour) pins the picker, not the gate. It takes each of the two picker lines out of the test, forces the line's starting pid to a live process owned by someone else (kill -0 fails, ps -p succeeds), runs the line and requires a pid that ps -p does not see (cells 2 and 3). Cell 1 is a control that the suite holds exactly two picker lines; cells 4 and 5 are controls that a free start pid is kept. If no such live process is visible (for example when run as root) it prints SKIP and expects 3 cells, not 5. The runner (Blockchain/Dev/scripts/run-shell-suites.sh) globs systemTest/__tests__/*.test.sh, so pre-push leg 12 reaches the suite and leg 14 runs it, with no wiring.

.1 What proves it

Red without the change, green with it, and the full suite does not move. Red first, by assertion, develop d7691f35312e: only the new suite applied, pickers still kill -0: 3 passed, 2 failed. Both failures read "start 58433, picked '58433', which ps -p sees": pid 58433 was a live root-owned process (kill -0 as the author: rc 1, EPERM; ps -p: rc 0). With the picker change: 5 passed, 0 failed (start 58433 -> 58434), and the same on three more runs.
Full package_format_gate.test.sh (the case-20 and case-32 host): base 435 passed, 0 failed in 123 s; with the change 435 passed, 0 failed in 121 s. The whole runner (what leg 14 runs): 107 passed, 0 failed, 1 skipped (of 108 suites) in 857 s, rc 0; the one skip is ks949_main_seed_idempotence.test.sh, which the runner counts and attributes to a box with no PostgreSQL. run-shell-suites.sh --check-unreached: rc 0, all 108 reached; a planted suite outside the globbed roots, in a scratch repo, makes it exit 1 and name the file. The new suite takes about 0.13 s.

.2 Environment and figures

Measured 2026-11-01 (UTC) on an Apple Silicon (arm64) Mac, macOS 27.0.1, shared with other seats. Base develop d7691f35312e. System bash 3.2.57 (/bin/bash; no other bash is installed on the host). The suite needs a live process owned by another user, which any macOS login session has (188 root-owned processes were visible when measured).

.3 What this does not prove

What this does not prove. Not run: under bash 5 (the picker uses a quoted-pattern substitution whose behaviour differs between bash 3.2 and 5; only 3.2.57 was available); the SKIP branch (no live other-user process visible, for example a root run); the four platform suites. The live pid is picked before the picker runs: if that process exits in between, the picker keeps its start pid and the cell passes without testing anything, so the race can give a false pass, not a false red.
Scope: the other kill -0 lines under systemTest, Blockchain/Dev/scripts and .githooks (19 lines in 5 other files, and 4 in the gate script) were counted with git grep, not each read in context; the lines read as probes of a pid the script itself started. None is touched. The suite proves the picker, not the gate's sweep, which cases 20 and 32 of the neighbour suite already cover.
