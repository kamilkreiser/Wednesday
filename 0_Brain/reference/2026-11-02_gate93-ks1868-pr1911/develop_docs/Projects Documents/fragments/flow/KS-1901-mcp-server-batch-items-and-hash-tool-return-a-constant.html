. mcp-server’s two batch routes and the hash tool stop returning the thrown error text (KS-1901, KS-1893)

What this changes. Blockchain/Dev/services/mcp-server/src/http-server.ts and src/tools/hash.ts. A client-visible string changes in three places. The per-item catch of POST /register-batch and of POST /verify-batch used to copy the thrown message into results[i].error while the route answered HTTP 200; secuura_hash_document used to return the raw file-system message (ENOENT: no such file or directory, open '<path>', EACCES, EISDIR) in its isError result. Each now logs what was thrown with console.error (the hash tool writes to stderr, because stdout is the stdio JSON-RPC channel) and answers the constant An unexpected error occurred, the one the 500 handlers have answered since KS 1410. success: false, verified: false and the item title stay as they were. A thrown value that cannot be read at all keeps the hash tool’s own reason unreadable thrown value (KS 1868). The cost: an MCP client can no longer tell a missing file from a forbidden one; an allow-listed errno code is a possible follow-up, not part of this change.
A defect fixed on the way. The per-item catch read the thrown value unguarded. An Error whose message getter throws, or a revoked Proxy, threw inside the catch, escaped it, and turned the whole batch into a 500. The read is now inside a try, so one unreadable item answers the constant and the other items keep their results. A non-Error, a thrown string included, is logged by its type and its field names, never its values (Kam’s ruling on KS 1346; the first version logged a string as itself and gate 82 caught it). POST /hash (KS 1214’s route) and the other tools in src/tools are not changed.
