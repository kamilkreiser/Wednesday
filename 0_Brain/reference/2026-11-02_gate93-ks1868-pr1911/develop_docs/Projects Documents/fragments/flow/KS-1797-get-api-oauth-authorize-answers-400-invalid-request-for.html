. GET /api/oauth/authorize answers 400 invalid_request for a repeated state or code_challenge, not 500 (KS-1797, GET half)

What this changes.Blockchain/Dev/services/auth/src/routes/oauth.ts, +5/-1: one early return in the GET /authorize handler. A repeated query parameter (?state=a&state=b) reaches the handler as an array whatever the cast says; generateConsentPage then called escapeHtml on it, an array has no replace, and the catch answered 500 server_error. A state or code_challenge that is not a string now answers 400 { success: false, error: { code: 'BAD_REQUEST', message: 'invalid_request', description: 'state and code_challenge must each be a single string' } }.
The body shape was read against the file’s other 400s: six more invalid_request 400s carry the same envelope (success: false, error.code BAD_REQUEST, error.message invalid_request, an error.description), at lines 537, 707, 762, 879, 1005 and 1027 of the changed file; no published message changes, only the new description text. New test ks1797-authorize-get-refuses-a-repeated-state-or-code-challenge.test.ts, 10 cells: R1 a repeated state and R2 a repeated code_challenge answer 400 not 500; C1 one state, C2 no state and C3 one code_challenge still serve the consent page; C4 a repeated scope is still the 400 of KS 1219. The POST half is not covered (a JSON array state or code_challenge is untouched) and the test header says so. The early return runs before the resolver, so a request with a repeated state and another fault (an unknown client, say) now gets this 400 and not the resolver’s refusal; no cell covers that combination. Merge prep (gate 37, finding F1) added four cells: R3 state[a]=x and R4 code_challenge[a]=x (qs makes an object, not an array) compare the whole 400 envelope; R5 a repeated state of marker values leaves both markers out of the body; C5 an empty state= is still served the consent page.
