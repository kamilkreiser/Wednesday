. analytics dbSaveExport and dbSaveAlertRule log when the thrown value is unreadable (KS-1868, analytics)

What this changes. Two DB-save catches in Blockchain/Dev/services/analytics/: ExportService.dbSaveExport in src/services/exportService.ts (logs DB save export failed) and dbSaveAlertRule in src/services/scheduledJobs.ts (logs DB save alert rule failed). Each catch read the thrown value with err instanceof Error ? err.message : String(err) and no guard, which itself throws for a revoked Proxy (instanceof throws) or for an Error whose message getter throws, so the log line was never written and the exception left the function. Each read is now in an inner try with the fallback 'unreadable thrown value'. The log message text and the log level (info) are unchanged (+7/-1 lines in each file).
Six cells in two new files, ks1868-export-service-db-save-unreadable-throw.test.ts (+69) and ks1868-scheduled-jobs-save-alert-rule-unreadable-throw.test.ts (+82): in each, a control that an ordinary Error still logs its message (C1) and two red cells, a revoked Proxy (R1) and an Error whose message getter throws (R2), that must log the constant reason. The save is reached directly for the export and through the real ScheduledJobs.addAlertRule for the alert rule. All four files are the held Spark passes O42-P1 and O42-P2 applied with strict git apply --check -p1 at the base, with no hand edit.

.3 What this does not prove

Two catches, not the ticket. KS-1868 stays open: it lists 253 catch and log sites that read a thrown value unguarded; this change fixes two, in analytics. Not touched: the line in exportService.ts that stores the thrown message on the export record (its own ticket) and dbSaveAlert in scheduledJobs.ts, which has the same shape and is left for a later pass. Callers (read from the code, not exercised): dbSaveAlertRule is called twice and both calls end in .catch(() => {}), so the visible change there is that the missing log line is now written. dbSaveExport is awaited at four places with no .catch (createExport, no try/catch; processExport, inside its try and again in its catch, and processExport itself is started without an await), so an unreadable value in its catch used to reject the export request or leave an unhandled rejection; it now logs and resolves.
Not run: a real database failure against a booted analytics service, the four platform suites (Schemathesis, Akto, Playwright, Performance/k6), Node 24 or any LTS Node, npm ci, any deploy.
