. analytics loadFromDb catch blocks keep logging when the thrown value is unreadable (KS-1868, analytics)

What this changes. Two catch blocks in Blockchain/Dev/services/analytics: MetricsCollector.loadFromDb (src/services/metricsCollector.ts) and AnalyticsService.loadFromDb (src/services/analyticsService.ts). Each read the thrown value with err instanceof Error ? err.message : String(err) and no guard. If the thrown value is a revoked Proxy, or an Error whose message getter throws, that read throws inside the catch: the WARN is never logged and the rejection carries a TypeError instead. Each read now sits in an inner try with the fallback 'unreadable thrown value'; the WARN texts, the error key and the value logged for any readable thrown value are unchanged. Product bytes: +7/-1 in each file.
Six new cells in two new test files (ks1868-metrics-collector-load-unreadable-throw.test.ts and ks1868-analytics-service-load-unreadable-throw.test.ts, 3 cells and +60 lines each): a control that an ordinary Error still logs its message (C1), and red cells that a revoked Proxy (R1) and an Error with a throwing message getter (R2) log the constant reason. Both product edits are held Spark passes (O36-P1, O37-P1) applied with strict git apply --check -p1 (rc 0 on all four sections, and rc 1 on a copy with one context line's content corrupted); there is no hand edit.
