. The manifest readers-agree test prints a driver’s stderr under a FAIL line (KS-1884)

What this changes. The four driver functions in systemTest/__tests__/manifest_readers_agree.test.sh (writer, playwright, performance, schemathesis) ended in 2>/dev/null | tail -1, so a tool that failed to start left an empty answer and the FAIL line read writer='', as a disagreement between readers, with the reason thrown away. Each driver now writes its stderr to its own file in a temp directory (removed on exit), and a FAIL line is followed by one line per non-empty file with its first 400 bytes. A passing case prints nothing new.
One new suite, systemTest/__tests__/manifest_readers_agree_stderr.test.sh (4 cells), runs the changed test with npx and python3 replaced by stubs on a private PATH that print noise to stderr and nothing to stdout, so no tsx, no Python and no stack is needed. Two cells fail at develop (the noise is not in the output) and two are controls that pass before and after.

.1 What proves it

Red first, then green, and what the cells cannot see. Red first, by assertion: at develop 8126b22bd5aa with only the new suite applied it is 2 passed, 2 failed (the npx and python3 stub noise is missing from the output of a failing run). With the change to the test it is 4 passed, 0 failed.
The changed test itself (manifest_readers_agree.test.sh, the real drivers, tsx and Python): 24 passed, 0 failed before and 24 passed, 0 failed after. The file keeps mode 100755; the new suite is 100644, as R 72nd’s new suite for KS 1926 is.
Mutants (scratch copies of the changed test run through the new suite’s MANIFEST_READERS_AGREE_SH override, each parsed with bash -n, the real file’s sha256 unchanged): 4 of 7 killed — the schemathesis driver back to /dev/null, the whole print loop deleted, the loop cut to the writer. 3 survived: any ONE of the writer, playwright or performance drivers back to /dev/null (the other two still print the stub’s noise, so the cell cannot tell which driver lost its file), and stderr printed for a case that passes (cell 4 looks only at lines that start ok ).
Every shell suite (run-shell-suites.sh): develop 106 passed, 0 failed, 1 skipped of 107 (the skip is ks949_main_seed_idempotence, no PostgreSQL on this host); with the change 107 passed, 0 failed, 1 skipped of 108 (the skip is ks949_main_seed_idempotence.test.sh, no PostgreSQL on this host).

.2 Environment and figures

Measured 2026-11-02 (AEDT) on an Apple Silicon (arm64) Mac, macOS 27.0.1, shared with other seats. Develop 8126b22bd5aa with the change on top. /bin/bash 3.2.57, Node v26.8.1 (not an LTS line). The full test took 42 s before. Machine load average was 9 to 15 during the runs.

.3 What this does not prove

The cause of the 2026-10-30 failure is still unmeasured. This change records the next one; it does not say what the one-off empty answer was. The new suite uses stubs, not a tool that really fails to start. It cannot show that each of the writer, playwright and performance drivers keeps its file (three mutants above). Nothing ran on a GNU/Linux userland or under bash 5. The four platform suites and any deploy were not run.
