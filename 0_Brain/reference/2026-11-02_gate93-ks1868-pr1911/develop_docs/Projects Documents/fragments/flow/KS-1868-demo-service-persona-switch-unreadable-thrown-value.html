. demo-service POST /persona/switch logs and answers its generic 500 when the thrown value is unreadable (KS-1868, demo-service)

What this changes. The catch of POST /demo-api/persona/switch in Blockchain/Dev/services/demo-service/src/routes/persona.ts: when authenticatePersona rejects, the handler logs Persona switch error and answers a generic 500 (INTERNAL_ERROR, Internal server error). It read the thrown value with err instanceof Error ? err.message : 'Unknown error' and no guard, which itself throws for a revoked Proxy (instanceof throws) or for an Error whose message getter throws; the handler then rejected instead of logging and answering. The read is now in an inner try with the fallback 'unreadable thrown value'. The 'Unknown error' branch for a readable non-Error value, the log message text, the log level and the 500 body are unchanged (+6/-1 lines in persona.ts). The route is the demo persona-login path (it calls authenticatePersona and proxies the refresh-token cookie), so it is tier 1 by assignment; only the catch changes.
Three cells in the new ks1868-persona-switch-unreadable-throw.test.ts (+101 lines): the real POST /persona/switch handler is taken out of personaRouter.stack and run against an authenticatePersona stand-in that rejects with the value under test. A control that an ordinary Error still logs its message and answers the generic 500 (C1), and two red cells, a revoked Proxy (R1) and an Error whose message getter throws (R2), that must not throw, must answer the generic 500 and must log the constant reason. Both files are the held Spark pass O43-P1 applied with strict git apply --check -p1 at the base, with no hand edit.

.3 What this does not prove

One catch, not the ticket. KS-1868 stays open: it lists 253 catch and log sites that read a thrown value unguarded; this change fixes one, in demo-service. The guard protects a read that throws, not one that returns a non-string: an Error whose message getter returns an object with a throwing toJSON still reaches the logger as an object (the class KS 1904 tracks for the sites already merged; the same shape applies here and is unchanged). The other demo-service catches are not touched. demo-service is part of the demo stack: nothing deploys from this change, and a later deploy needs its own gate and the owner's word under the demo rules.
Not run: a real authentication failure against a booted demo-service, the four platform suites (Schemathesis, Akto, Playwright, Performance/k6), Node 24 or any LTS Node, any deploy. The 25 existing tsc errors are in other test files and are not touched.
