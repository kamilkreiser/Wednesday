. Every anchor reader decides through one resolver, confirmed is terminal in SQL, and the retry route asks whether the create is already on chain before it pays (KS-1384 R2b)

What this changes.One decision (D1). Before this, which reader ran first decided what a document said: the GET reconcile failed a document on one failed read of its row, while a verify could confirm it from a chain answer naming its id. On kintsugi (31 Oct) a document whose create had landed read anchor_failed, and a retry then paid a second fee. Now the poller, the failure writer, the GET reconcile and both verify heals call one resolver. A confirmed row whose real (64-hex) transaction is bound to the create confirms; otherwise anchoring’s own-create lookup decides (found confirms, none fails a failed row, not answered changes nothing).
One write (D2). Every reader writes through one conditional UPDATE: confirmed is never written over, a failure is pinned to the anchor it fails, and a progress write to the polled anchor.
Own-create (D4). Anchoring’s POST /api/anchors/own-create scans the platform wallet for a transaction bound to the document’s create (its id, its content hash and a recorded create-attempt timestamp to the millisecond), on a 4 s deadline. Only a complete scan answers “none”.
The retry route asks first (D5, D6). After its claim, it asks own-create: found gives 409 naming the transaction, with the document confirmed; a transaction for the document at another time gives 409 for an operator; not answered gives 503 Retry-After 60 with error.kind; only none goes on to pay. Every create and retry records its payload timestamp (createAttempts, the earliest and the 9 newest).
QA gate 65’s wedge (G65-F1). A blob-less document whose next post failed after a marker cycle was left as a bare pending blob, refused for ever; the claim’s re-check now restores the flag that lets the release remove it, but only on a blob that holds nothing else.
QA gate 68’s network leg (G68-F1). R2a’s “already anchored” rule compared the row’s network, which anchoring writes from its OWN CARDANO_NETWORK, with originate’s; where the two services were configured differently every landed anchor read as “another network” and was paid for again. The comparison is dropped (the content hash is still compared), and the deploy hold requires the two values to be equal on each box.
