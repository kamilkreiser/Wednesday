GET /billing/customers/by-email returns the caller’s own customer when two share an email — KS-1911

What to know. A test gap, not a product change. QA gate 62 (finding F3) found that no KS 1888 cell pins GET /billing/customers/by-email when two Stripe customers share one email: its mutant M18, which sends the route back to Stripe’s first match and checks only that one, survived every cell. Four cells now pin it: the caller whose customer is Stripe’s second match gets their own customer, not a 404, and a signed-in user who owns neither gets 404. The route’s code is unchanged; one comment in billing.ts now states the corrected limit (comment lines only).
Green at develop (the route is right). Gate 62’s own M18, applied byte for byte: 1 of 196 cells red, the new cell E1. QA gate 69’s mutant O3 (the first match checked, later ones admitted): 1 of 196 red, the new cell E3. A control mutant (the first match with no owner check): 9 red.
