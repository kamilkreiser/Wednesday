audit-logger flush retries the event when the thrown value is unreadable — KS-1868, packages/shared (security surface)

What to know. AuditLogger.flush read the thrown value from a failing onEvent unguarded; a revoked Proxy or a throwing message getter made the read throw before eventBuffer.unshift(event), so the audit event was dropped. The read is now in an inner try with the fallback unreadable thrown value; the retry, log text and record format are unchanged. 3 new cells; a mutant that removes the unshift line fails all 3.
The module has no importer at this base (published subpath only); a different AuditLogger in @secuura/service-utils is not touched.
Not measured here. KS-1868 stays open (one of its 253 sites). The four platform suites, a running stack, an LTS Node, npm ci and any deploy were not run.
