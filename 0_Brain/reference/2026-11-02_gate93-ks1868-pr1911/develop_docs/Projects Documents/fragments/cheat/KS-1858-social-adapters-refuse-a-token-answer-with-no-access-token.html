The Google, Facebook, LinkedIn and Microsoft sign-in adapters refuse a token answer with no access_token — KS-1858

What to know. The four adapters took access_token from the token answer unchecked; a 200 answer without one reached the profile call as Bearer undefined. Each now refuses a missing, non-string or empty value with <Provider> token exchange failed (no access token) before any profile call, as the GitHub adapter has since KS-1792. 4 new files, 20 cells; the whole auth suite is 117 files / 1385 cells, all pass.
Four held Spark passes applied strictly; no hand edit. Open for the gate: unlike github.ts, these guards do not also refuse a 200 answer carrying an error field. Facebook's token is in the profile URL query (pre-existing, unchanged).
Not measured here. No real provider was called (fetch is a stub). The four platform suites, a running stack, an LTS Node, npm ci on the merged lockfile and any deploy were not run. Two ks949 seed-site cells time out at 5 s on develop itself and a cold-start hook timeout skips a whole file in some runs; both are develop's own and move between runs.
