The Blockchain/Testing entry points aim at the slot that was named — KS-1382

What to know. The audit, ZAP, tenant-isolation and Schemathesis wrappers used to fall back to slot 1’s gateway when TARGET_BASE was not passed, so a run on a slot-N worktree could attack another session’s stack. A local run now names its slot: SECUURA_STACK_SLOT=2 ./run-internal-audit.sh (or STACK_SLOT). With neither a slot nor TARGET_BASE it refuses with rc 2 and prints the command to run.
TARGET_BASE with no slot is used unchanged (CI, remote targets). With a slot named, a local TARGET_BASE that is another slot’s gateway is refused; a remote host, or a local port that is no slot’s gateway, is left alone.
SECUURA_TARGET_RESOLVE_ONLY=1 prints the resolved target and exits 0 without scanning. The ports come from stack_env.sh; check-stack-safety.sh section 3d fails any typed slot port under Blockchain/Testing.
Not measured here. The four platform suites (Schemathesis, Akto, Playwright, Performance/k6), a live stack, pre-push legs 3, 4 and 8 (they skip without the stack) and Node 24. No scan was run: the cells prove which URL each script would aim at and which combinations it refuses.
Blockchain/Dev/deployment/azure/RUNBOOK.md line 56 runs ./run-internal-audit.sh with no TARGET_BASE and will now refuse; it is not changed here.
