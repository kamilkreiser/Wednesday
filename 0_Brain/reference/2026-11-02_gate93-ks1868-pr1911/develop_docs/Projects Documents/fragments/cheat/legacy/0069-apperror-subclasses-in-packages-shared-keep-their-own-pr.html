AppError subclasses in packages/shared keep their own prototype — KS-1467

What to know. Every subclass of AppError in packages/shared (nine, plus DocumentNotFoundError under NotFoundError) used to be reset to the base prototype by the constructor, so err instanceof NotFoundError was always false. The constructor now uses new.target.prototype (one line). Status, code, details and the handler’s answers do not change.
This is the shared half of KS-1467. The services/auth half (its own error classes) is a separate change. A local model wrote the patch; it is applied unchanged.
Not measured here. Other services’ suites (only the packages/shared suite was run), a running stack, and a Node 24 LTS run (the host is Node 26.8.1).
The four platform suites (Schemathesis, Akto, Playwright, Performance/k6) are not claimed as passing. The change is not deployed.
