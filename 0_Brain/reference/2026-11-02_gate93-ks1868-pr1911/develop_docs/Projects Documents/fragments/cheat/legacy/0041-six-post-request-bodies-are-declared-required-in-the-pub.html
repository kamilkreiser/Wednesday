Six POST request bodies are declared required in the published contract — KS-591

What to know. The six operations are POST /api/anchors, POST /api/anchors/thread-mint, POST /api/stake/complete-unstake, POST /api/transfers, POST /api/delegations and POST /api/delegations/validate. Their request bodies now carry required: true in the published contract.
This is a declaration in the contract and nothing else: no handler or route file changes. What each handler does when the body is absent was not measured here.
The change is in three files, anchoring.openapi.ts, staking.openapi.ts and transfer.openapi.ts, and in the regenerated docs/openapi/secuura-api.yaml (6 insertions, 0 removals). Never hand-edit the yaml; run npm run generate-openapi.
Gotcha when you run this locally. A gateway that has already read the old spec keeps serving it until it is restarted.
Not measured here: the spec as served by a running gateway, and any effect on a Schemathesis sweep now that the six bodies read as required.
