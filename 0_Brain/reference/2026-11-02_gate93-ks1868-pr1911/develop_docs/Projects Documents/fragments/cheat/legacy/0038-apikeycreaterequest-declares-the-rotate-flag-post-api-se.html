ApiKeyCreateRequest declares the rotate flag POST /api/security/keys acts on — KS-1434

What to know. rotate is optional and defaults to false. It does nothing without a connectorId: both are needed before any key is retired.
The keys retired are the other active keys for that connector in the same tenant. The query does not look at who created a key.
With API_KEY_ROTATION_GRACE_SECONDS unset or 0 they are deactivated; with a positive value they are given an expiry that many seconds away if that is earlier than their current one.
The 201 response carries priorKeysRevoked only when both rotate and connectorId were sent. null means the retirement was attempted and failed, and the prior key is still valid.
Gotcha when you run this locally. This change is the published contract only. Nothing in the running service changes, and a gateway that has already read the old spec keeps serving it until it is restarted.
Not measured here: the spec as served by a running gateway, and any effect on a Schemathesis sweep now that the field is visible to it.
