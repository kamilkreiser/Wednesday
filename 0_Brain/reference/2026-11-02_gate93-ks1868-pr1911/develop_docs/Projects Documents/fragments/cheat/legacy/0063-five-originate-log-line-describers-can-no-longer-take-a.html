Five originate log-line describers can no longer take a request down — KS-1772

What to know. The log line built from a thrown value at five places in services/originate (the fail500 helper of systemErrors.ts, gdpr.ts, webhooks.ts and adminConfig.ts, and the per-tenant catch of POST /api/admin/migrate-tenant-data) had no try of its own. A thrown value whose description throws (a throwing message getter, a Proxy trap, a revoked Proxy) or a logger that throws left the request with no response in the four helpers, and stopped the migrate loop at the failing tenant, with a 500, in the fifth.
Each site now describes in one try (fallback line thrown value that could not be described) and logs in another. Describable values log exactly what they logged before. The new test has 30 cells: per site four D1 shapes, one L1 throwing-logger cell and one C1 control.
Red-first: 25 failed / 5 passed on the unfixed routes, 30 of 30 fixed. Whole originate suite 140 suites / 1660 tests before, 141 / 1690 after. Each guard is pinned by its own cells: the describe guard removed fails the four D1 cells of that site, the log guard removed fails its L1 cell, at all five sites.
Not measured here. A run on an LTS Node: the host carries only v26.8.1 and nothing was repeated on Node 24. Nothing runs through the gateway or on a deployed box.
The four platform suites (Schemathesis, Akto, Playwright, Performance). The api-gateway half of the same pattern is KS-1771.
