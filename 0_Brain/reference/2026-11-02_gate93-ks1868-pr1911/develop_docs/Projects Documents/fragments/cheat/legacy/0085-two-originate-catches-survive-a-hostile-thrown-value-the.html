Two originate catches survive a hostile thrown value: the system-errors list and extractPgCode — KS-1780

What to know. Some originate catches read the thrown value (an instanceof check, a code or meta read) before answering. A revoked Proxy or an object with a throwing getter made that read throw inside the catch, so the request got no response. This change fixes two sites: the list route in systemErrors.ts (a new isZodError that returns false for a value it cannot inspect) and extractPgCode in pgErrors.ts (returns undefined if its reads throw), which the PATCH /api/webhooks/:id catch calls.
The result is the handler’s constant 500 instead of a hang. The catches in adminConfig.ts are a separate change. Two local-model passes, applied unchanged.
Not measured here. The adminConfig.ts catches, whether a real request can carry such a value (the cells use synthetic Proxies and getters), a running stack, and a Node 24 LTS run (the host is Node 26.8.1).
The four platform suites (Schemathesis, Akto, Playwright, Performance/k6) are not claimed as passing. The change is not deployed.
