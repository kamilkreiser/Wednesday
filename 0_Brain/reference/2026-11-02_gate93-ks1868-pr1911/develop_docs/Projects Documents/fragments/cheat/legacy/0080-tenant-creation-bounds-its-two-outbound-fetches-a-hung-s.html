Tenant creation bounds its two outbound fetches; a hung service ends in the fail-soft path an unreachable one already took — KS-1240 part 4

What to know. POST /api/tenants called the tokenisation service (key generation) and the security service (metering key) with no timeout. Each call now passes AbortSignal.timeout with a 3 s bound (the gateway gives up on this route at 8 s and the two calls run one after the other, so with both services hung the create takes about 6 s plus the route’s own writes). On expiry it fails soft exactly as an unreachable service already did: 201, tenant active, keyFile: null (or meteringApiKey: null), and vault_key_hash stored as NULL when key generation failed.
Only the bounds change. Before, a hung tokenisation service left the request open with the tenant row stuck at provisioning and nothing else written; a hung security service left an active tenant and no answer. What the route should answer when key generation cannot complete is a separate decision: it was decided on 2026-10-28 (option b, an explicit key-pending flag) and is built as a separate PR after this one. A service that answers, but later than the bound, also ends in the fail-soft path: 201 with keyFile (or meteringApiKey) null and vault_key_hash stored as NULL, where the unbounded code waited, returned the key and stored the hash; nothing reads either value.
Scope. The ticket text names only the api-gateway key-validate fetch; this part was added by the coordinator’s brief, not by the ticket.
Not measured here. A real tokenisation or security service, a real database row (the writes are read at a recording stub), a running stack, and the 409 a retry would meet after an unbounded hang (read from the code). The four platform suites (Schemathesis, Akto, Playwright, Performance/k6) are UNMEASURED and not claimed as a pass. The change is not deployed.
Node v26.8.1, not the repository’s stated LTS line of Node 24 (none is installed on this host). The figures are declared as measured on v26.8.1, not claimed as LTS.
