The N3 cells assert that the hash they send is a real one — KS-1634

What to know. In ks1634-v2-chain-only-match-carries-simulated.test.ts the two N3 cells send simulated as the string "true" and as the number 1, each with a real tx hash on purpose: a mock_tx_ hash makes the presenter refuse the reply by itself, which would hide the === true mutant. They took that hash implicitly from chainReply’s default.
Each now asserts expect(reply.txHash).toMatch(REAL_TX_SHAPE) on the reply it sends, with REAL_TX_SHAPE = /^[0-9a-f]{64}$/ kept apart from REAL_TX. Two assertions are added, no cell is added or removed (10 before, 10 after), and no product file changes.
The cell that sends simulated as the number 0 already reds under a mock-prefixed default, so it is left alone. The original RED cell “simulated true with a real hash” has the same dependence and is NOT changed here; it is outside the two cells the ticket names.
Not measured here. A run on an LTS Node: the host carries only v26.8.1 and nothing was repeated on Node 24. Nothing runs through the gateway, and the ticket’s original product defect is not touched.
