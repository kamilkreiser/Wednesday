GET /api/anchors/:documentId answers 500, not 404, on a database fault — KS-1657

What to know. originate’s getAnchorByDocumentId used to catch every error and return null, which the route reads as “no anchor” and answers 404 with anchored: false, so a failed database read looked like a document with no anchor. It now logs the warn line and rethrows: a fault answers the route’s constant 500 INTERNAL_ERROR (no fault text in the body), and zero rows is still the same 404.
500 and not 503 because originate has no infrastructure-fault classifier (auth’s reads pg errors; originate reads through Prisma).
Not measured here. A real database fault: the rejection is a mock on prisma.$queryRaw. How the api-gateway’s /api/anchors proxy relays the 500. Any running stack.
The four platform suites (Schemathesis, Akto, Playwright, Performance/k6) are not claimed as passing. The change is not deployed.
