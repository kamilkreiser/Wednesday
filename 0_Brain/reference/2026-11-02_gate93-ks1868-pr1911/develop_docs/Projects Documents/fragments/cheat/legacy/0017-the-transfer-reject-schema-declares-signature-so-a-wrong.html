The transfer reject schema declares signature, so a wrong-typed one is refused — KS-1435

What to know. rejectTransferSchema in services/transfer/src/index.ts never declared signature, while the published TransferRejectRequest declares it a string.
Zod strips keys a schema does not name, so a wrong-typed signature was discarded rather than refused: the schema then validated and the reject ran with 200.
The caller gets a success for a request the contract calls invalid, and the rejection is recorded without the signature it believed it sent.
The fix is one line, signature: z.string().optional(). The narrowing is the type, never the presence — optional() is what keeps every existing caller that sends no signature green.
Pure declaration; no handler branch, no status-code path and no spec file is touched.
Gotcha when you run this locally. Three of them. (1) --reporter=basic no longer exists in vitest 4. It fails as Failed to load custom Reporter from basic with rc 1 and zero tests run — which reads exactly like a red suite if you only look at the exit code. Use the default reporter.
(2) Re-applying the test section SUCCEEDS. git apply --check -v reports Hunk #1 succeeded at 938 (offset -39 lines), because the hunk's only context is two closing-brace lines that recur all over a test file. Do not use "applied twice refuses" as an idempotence guard on this payload; assert the joined-payload sha and the write-tree result instead.
(3) The runner version is in node_modules, not the manifest. It resolves to vitest 4.1.11 where package.json says ^4.1.9.
