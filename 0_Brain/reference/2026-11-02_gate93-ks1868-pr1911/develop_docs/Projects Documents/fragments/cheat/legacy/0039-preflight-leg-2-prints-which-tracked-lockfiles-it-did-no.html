Preflight leg 2 prints which tracked lockfiles it did not install — KS-1426

What to know. lockfile-cleanroom.sh (preflight leg 2) installs the locks that a find over services packages frontend scripts reaches. At the base that is 35 of the 45 tracked package-lock.json files. The leg used to print All 35 standalone lock(s) pass and say nothing about the other 10.
It now also prints surface: N of M and the paths it did not install, when it is started with no arguments. In scratch pre-push hook runs the count read the same from a main checkout and from a linked worktree: a pre-push hook in a linked worktree has GIT_DIR exported to it, and the function clears git’s own repository-local variables before it asks git anything. It reports; it does not install them, and its exit-code lines are not edited.
The ticket stays open. The install-widening is a later change, and a live run on a developer machine and on CI is owed.
Gotchas when you run this locally. The new suite runs the leg from a scratch copy, and the leg changes into the directory above its own path first (line 35). Run from a non-repo directory and from the worktree, it printed byte-identical output.
The exit code equals the previous head’s in 12 of 12 cases measured. When a git call fails the line says cannot list instead of printing a number (a failing --show-prefix used to print 0 of 6, a failing ls-files 0 of 0). Read the surface line as a report, not as an assertion; a live run is still owed.
On a tree that is develop a78413d3de3e plus this change, the shell-suite count reads 75, not 74.
