The ks1186 test runs every control against every site, and listUsers classifies a DB fault — KS-1484

What to know. The ks1186 test now drives all fifteen cells from one table of the five sites (getUserByIdWithPasswordHash, getUserByIdPreAuth, getUserByEmail hash arm, getUserByEmail legacy arm, getUserBySocialId): an infrastructure fault becomes 503 and is logged; a non-infrastructure fault is rethrown as the very same error (toBe, not a message match) and logged; with no fault the row resolves and nothing is logged as an error.
Blockchain/Dev/services/auth/src/repositories/userRepo.ts:372-373 no longer says the five reads are unawaited. That edit is comment-only, proved by a comment-stripped AST hash equal on both sides, with three controls that fire.
Item 3 is a BEHAVIOUR CHANGE. listUsers now has the lookups’ contract: one try over the SELECT and the per-row fromRow reads; it logs DB listUsers failed; an infrastructure fault is a ServiceUnavailableError (503), anything else is rethrown as the very same error. On GET /api/users and GET /api/users/admin/list that is a 503 where it was a 500 (read, not run). The await on Promise.all is load-bearing: without it the rejection escapes the try, which is the KS 1186 bug class.
Gotchas when you run this locally. getUserByEmail has two arms and the default mock reaches only one. The default query mock answers the hash query with no rows, so a bare call goes to the legacy arm. The hash arm needs the first query answer primed (mockResolvedValueOnce with the row); the table’s prime hook does it. A cell that forgets this tests the legacy arm twice and says nothing about the hash arm.
A mutant of a production file needs both the repo and the test copied. The test imports ../repositories/userRepo by a dynamic import(); a mutant copy sits in the same directory (same relative imports) and each test copy has that one import repointed. Run the OLD test (the base blob) beside the NEW one: a mutant that survives the old and is killed by the new is the proof a control was widened, not merely renamed.
listUsers needs no extra mock. runWithPlatformScope comes from @secuura/shared, which this test mocks with ...actual, so the real one runs. The first query answer is the SELECT; prime it with mockResolvedValueOnce({ rows, rowCount }). A resolved subject DEK must be a Buffer (Buffer.from('test-dek')): getDek returns one, and a string is a TS2345 the type-check ratchet reports as a NEW error.
A mutant that does not parse reds every cell and looks like a spectacular kill. The item-3 driver parses each mutant with the TypeScript compiler API and refuses one that does not. One of mine had a stray closing brace and reded all 23 cells when the code measured directly gave 4.
Not measured here. countUsersInner has the same gap and is not touched (userRepo.ts:1092, one query, no try/catch; both list routes call it right after listUsers), so a fault on the COUNT still answers a raw 500. The route path (catch (error) { next(error); } then the error handler) was read, not run, and every database call in these cells is a mock.
A runtime change that is NOT deployed: under the Done rule the ticket cannot move to Done until auth is. The four platform suites (Schemathesis, Akto, Playwright, Performance) are UNMEASURED; nothing on either box.
