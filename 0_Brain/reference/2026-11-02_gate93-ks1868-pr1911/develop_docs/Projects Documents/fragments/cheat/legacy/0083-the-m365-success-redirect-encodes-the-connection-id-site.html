The m365 success redirect encodes the connection id (site 1) — KS-1670

What to know. GET /api/callback in services/m365-integration redirected to the admin page with connectionId unencoded and tenant encoded. The id is now encoded too. For every id the server issues the redirect is unchanged; the point is that an id format that ever contained &, # or % can no longer change the shape of the query.
Site 1 of KS-1670 only; the other two sites wait for a separate decision. Two new tests: a source-text pin (it reads index.ts) and a behaviour test that drives the real callback and parses the redirect a browser receives. A local model wrote the patch and the pin; the behaviour test was added at prep on the tier-1 gate’s note.
Not measured here. A real Microsoft sign-in or database (both stubbed in the behaviour test), a running stack, and a Node 24 LTS run (the host is Node 26.8.1).
The four platform suites (Schemathesis, Akto, Playwright, Performance/k6) are not claimed as passing. The change is not deployed.
