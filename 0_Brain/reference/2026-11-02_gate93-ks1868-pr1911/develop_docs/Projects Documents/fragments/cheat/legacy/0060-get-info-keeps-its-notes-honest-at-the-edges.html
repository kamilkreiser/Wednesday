What to know. secuura_get_connector_info (mcp-server/src/tools/info.ts) turns the gateway’s answer into a note. Two mutants survived the whole suite: dropping !connectorResult.ok (H1-M3) and loosening typeof ...message === 'string' to != null (H1-M8). Item 1, the 200-character bound, was already on develop; this is items 2 and 3.
Five cells are added to the ks1620 test (4 to 9): a 200 with a JSON null body keeps the not-available note; a non-string message (the number 123) relays no text; and one cell each for 400, 429 and 502 asserting the note still reads “Connector info refused by the gateway (<status>)”. The word “refused” is kept (ruled for this lane); only the code comment at info.ts:129 changed, one line for one line, saying a 403/503 fail-closed is a deliberate refusal and a 400, 429, 500 or proxy 502 is not.
A comment cannot be pinned by a cell; the wording and status it describes can, and now are. Comment-only is proved by emit: both versions of info.ts hash identically with comments removed, and a one-token code change does not.
