generated_guard_restore keeps the suite's exit status when a cleanup is chained in front — KS-1738

What to know. generated_guard_restore() reads the suite’s status as its first statement (local rc=$?). A cleanup chained in FRONT of it runs first and overwrites $?, so a suite that exited 3 was reported as 1. LOW: the failed restore is still loud and still non-zero; only “the suite failed” versus “the restore failed” is lost.
Fix is opt-in: the guard now prefers a status passed as its first argument over $?, so every plain-trap caller (including the two inline copies) is unchanged. The chained call site becomes trap 'rc=$?; stop_stub; generated_guard_restore "$rc"' EXIT. A non-numeric argument is refused by name.
Do NOT put the guard first (generated_guard_restore $?; stop_stub), which is what the ticket literally suggested: on a failed restore the guard exits, so the chained cleanup would never run on exactly the path the guard exists for — it would leak the stub listener.
Gotchas when you run this locally. Drive this in three arms, each a distinct (suite, guard) pair, and fingerprint them. The guard is a sourced file installing an EXIT trap, so a cell cannot test it in-process: build scratch trees of <root>/generated_guard_restore.test.sh + <root>/support/generated_guard.sh, because the suite derives the guard path from its own location and has no override knob. The RED arm is the NEW suite against the ORIGINAL guard.
B stays at 1 after the fix, and that is correct. Shape 1 is opt-in, so a chained call site passing no status still flattens it. If you expect B to flip you will read a correct run as a failure. Each arm points $FIXTURES at its own throwaway directory; no cell touches the repo’s real systemTest/fixtures/generated.
Not measured here. The two INLINE copies (pre_suite.test.sh, quarantine_call_sites.test.sh) are untouched — both use a plain trap, so neither is affected. A grep for generated_guard_restore at this tip finds only the three files this change touches, and nothing wider is claimed.
The four platform suites (Schemathesis, Akto, Playwright, Performance) are UNMEASURED; no service unit suite was run, because no service source is touched. Nothing on either box.
