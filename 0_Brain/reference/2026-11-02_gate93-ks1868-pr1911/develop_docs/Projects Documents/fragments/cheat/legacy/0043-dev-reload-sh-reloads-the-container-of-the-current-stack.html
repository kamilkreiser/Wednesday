dev-reload.sh reloads the container of the current stack slot — KS-1355

What to know. scripts/dev-reload.sh used to look for secuura-<service>, slot 1’s container, whatever slot you named. It now sources stack_env.sh and uses ${STACK_PREFIX}, so SECUURA_STACK_SLOT=2 targets secuura-s2-<service>.
A slot of 5, 0 or abc (the three values run) now stops the script with exit 2 and the stack_env.sh error. With no slot named it still targets secuura-<service>.
Only dev-reload.sh changes, plus the new test and these two documents. This is one of the two scripts in spot 2 of the ticket; the ticket’s other spots are not touched by this commit.
