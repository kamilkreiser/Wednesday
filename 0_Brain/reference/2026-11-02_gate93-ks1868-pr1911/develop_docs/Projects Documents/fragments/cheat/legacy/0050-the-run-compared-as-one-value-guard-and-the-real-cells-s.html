The “run compared as one value” guard and the REAL cell’s summary — KS-1529

What to know. The ks1000 file’s guard against comparing a checker run as ONE value (status and output inside one array or object) used to be a per-line regex on the array form. It missed an object, a reversed array and an array split over several lines; it is now runsComparedAsOneValue, a scan of the joined text bounded by ] or }. A bound of ) would miss a nested call ahead of the first field, so a cell plants that shape.
The REAL cell’s expected summary is a named constant, AUTH_GREEN_SUMMARY. A cell proves it can fail (a red run, a silent run with the right status, a wrong-status run), and a second cell reads the REAL cell off the syntax tree to prove it still passes the constant. Both are needed: with the second cell excluded, the gate’s M3 (the REAL cell cut to a bare status check) leaves the whole file green, 83 passed and 0 red.
Gotchas when you run this locally. Plant a shape by assembly, never literally. The guard scans this file’s whole text, strings and comments included, so a literal expect( followed by [ or { and both fields flags the file itself. The cells build the plants from 'expect' + '('. A permitted shape is the file’s own idiom (expect(r.status, r.out) appears in it already), so those cells count occurrences added, not occurrences present.
A mutant copy must sit beside the test, and under src/__tests__ it is type-checked by the real ratchet. The cells read __filename, so a copy reads itself; but the REAL cell runs the checker over services/auth, copy included, so a mutant that leaves an unused name reds the REAL cell with TS6133 for that reason and not because of the cell’s logic. Delete every copy and check git status.
The -t KS-1529 filter runs only the new describe. The rewritten guard cell is in the KS 1519 describe and the REAL cell in the KS 1000 one, so run the whole file to see them. Under load the full suite also times out ks949 (5 s test timeout) and auth.integration (10 s HOOK timeout): raise --testTimeout AND --hookTimeout, they are different knobs.
Not measured here. A bracket nested ahead of the second field (parts[0], a nested object literal) is NOT caught — measured, 0 hits — and only the REAL cell is protected of the 35 expectRun call sites at base (39 after). The predicate is a substring: 10 new; 0 stale baseline entries contains it, though no run with new errors exits 0.
The four platform suites (Schemathesis, Akto, Playwright, Performance) are UNMEASURED; nothing on either box.
