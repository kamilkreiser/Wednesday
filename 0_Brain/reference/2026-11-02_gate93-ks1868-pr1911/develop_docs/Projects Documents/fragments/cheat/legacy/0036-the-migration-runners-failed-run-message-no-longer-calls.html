The migration runner’s failed-run message no longer calls a closed defect open — KS-1456

What to know. When a migration fails, run-migrations.sh prints why it exits 3. That text used to say a defect about counting skipped migrations as applied was still open.
That defect was closed by commit ae9bf6828f88, so the sentence is gone. The exit code (3), the Summary: line and the clean-run path are asserted by cells that pass at the base and after the change.
One shell comment line after the message carries the ticket key. It prints nothing: the failed-run output with and without it is byte-identical. The ticket does not move to Done; a live run against a database is owed.
Gotcha when you run this locally. The cells use stub psql and pg_isready programs on a private PATH; no database is reached.
On a tree that is develop 76b683c7dcd0 plus this change, the shell-suite count reads 75, not 74.
