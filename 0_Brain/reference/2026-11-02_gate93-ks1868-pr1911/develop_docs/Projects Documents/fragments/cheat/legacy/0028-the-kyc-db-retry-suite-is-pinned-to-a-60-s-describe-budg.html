The kyc db-retry suite is pinned to a 60 s describe budget — KS-1328

What to know. services/kyc/src/__tests__/db.retry.test.ts carries { timeout: 60_000 } on its describe instead of vitest's 5 s default. Under fleet load its first cell timed out at 11,498 ms while passing in 675 ms alone, so the overrun is scheduling, not work.
The budget is on this describe only — every other kyc suite keeps the 5 s default. A new cell asserts all 6 cells in the file carry 60 s, so the budget cannot be removed silently.
Test-only: no product code changes. It pins the budget, not the absence of future timeouts. The ticket does not move to Done.
Gotcha when you run this locally. (1) Use kyc's own npm script. npm test in Blockchain/Dev/services/kyc resolves to vitest run with the package's own config.
(2) Do not pass --reporter=basic. It does not exist in vitest 4.1.11: vitest exits with a Startup Error and rc 1 having run zero tests. An rc of 1 with no Tests line is a load failure, not a red — check for a Tests summary line before calling any run red.
