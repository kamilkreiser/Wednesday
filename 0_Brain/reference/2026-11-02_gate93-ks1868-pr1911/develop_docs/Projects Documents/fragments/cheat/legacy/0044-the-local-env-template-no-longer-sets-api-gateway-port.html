Worth knowing if you go looking: there are two tracked templates whose names differ by one leading dot. bootstrap-env.sh writes .env from env.example and .env.local from the dot-prefixed .env.local.example; it names the undotted env.local.example 0 times, with the dotted name occurring 3 times in that file as the control. The undotted file is reached by its own line 5, cp env.local.example .env, which is a manual step.
Gotchas when you run this locally. The suite runs bootstrap-env.sh once in a scratch tree before any cell, and that tree is built from your worktree’s env.example. Cell 2 reads the generated .env; cells 1 and 4 also read env.example directly; cells 5 and 6 read env.local.example directly; cell 3 plants its own files. So a local edit to either template changes the cells that read it. The suite needs openssl, which bootstrap-env.sh requires.
