The billing webhook replay handler answers 500 when the thrown value cannot be read — KS-1868

What to know. The catch of POST /webhooks/replay read the thrown value unguarded; an unreadable one (a revoked Proxy, an Error whose message getter throws) made the handler reject without answering the request. It now logs the constant reason unreadable thrown value and answers the same constant 500 an ordinary error gets. 1 product file (+7/-1), 3 new cells. No money moves in this change.
Not measured here. Node 24 (the host has v26.8.1 only), a real PostgreSQL, a real Stripe service, the four platform suites. The thrown values are test-authored.
