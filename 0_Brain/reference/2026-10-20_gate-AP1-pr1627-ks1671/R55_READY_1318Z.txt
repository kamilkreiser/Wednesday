## CAUSE

Express 4.22.3 parses queries with `allowPrototypes: true` (`express/lib/utils.js:290`), so `?error[toString]=x`
is an object whose own `toString` is a string, and `String()` on it throws `TypeError` inside the async
`/api/callback`. m365 has no `process.on` handler, so the process exits. The gateway mounts the route with no
`authenticateToken` (`proxy.ts:936-939`). That last point is a static reading; it was not measured through the gateway.

## FIX (+23/-1 product)

`stringParam(value)`: `typeof value === 'string' ? value : undefined`. The four reads at the top of
`/api/callback` (`code`, `state`, `error`, `error_description`) go through it. Anything that is not a string is
treated as absent. No process-wide net (KS-1427), as you ruled.

connection to `status: 'error'` and reflect the `TypeError` text. The filter stays, because your ruling covers
every value the route reads.
