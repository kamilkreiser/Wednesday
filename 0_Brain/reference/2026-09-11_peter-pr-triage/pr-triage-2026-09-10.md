## How priority is set

Four tiers, oldest first within a tier.

| Tier | Rule | Why it outranks the next |
|---|---|---|
| **A — published contract** | diff touches `Blockchain/Dev/docs/openapi/secuura-api.yaml` (⚠ spec) | Schemathesis reads it and Akto imports it — a wrong shape is wrong for every consumer and both suites at once, and it ships to `/api/docs`. |
| **B — runtime behaviour** | diff touches `services/`, `packages/` or `frontend/` outside `__tests__` (⚠ rt) | Live code paths — auth, tenancy, anchoring, persistence. A defect reaches users; tier C/D defects reach only the gate. |
| **C — gate & evidence integrity** | diff touches `.github/`, `scripts/`, `docker`, `compose` (bld) | Decides whether every future PR's evidence is believable. Slower to bite, but it compounds. |
| **D — test-only / docs** | everything else | Real value, no live surface, no effect on what the gate can see. |

Overrides: a **stale approval** rises to the top of its tier (the review is done — a re-check, not a read); a PR that others **hang off** rises above them; a PR that is **blocked** (conflict, or waiting on another PR) sinks below its blocker.
