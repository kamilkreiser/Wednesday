## What is wrong (one paragraph)

In the admin create-user handler (`POST /admin/create`) the success path logs `logger.info('Admin created user', { email, role: user.role, createdBy: req.user!.userId })`: the new user's plaintext email goes to the info log, while `docs/TOKENISATION.md` says logs carry no PII. The service's logger (`services/auth/src/utils/logger.ts`, winston with `errors` and `timestamp` formats only) has NO redaction, measured by a scratch run on the pinned file: in production (json) and development format both, an `email` key is written verbatim. The ruling: the line carries the user id, never the email. `user.id` (the new user's id, a `crypto.randomUUID()` set a few lines above) is in scope at the line; `role` and `createdBy` stay as they are.
