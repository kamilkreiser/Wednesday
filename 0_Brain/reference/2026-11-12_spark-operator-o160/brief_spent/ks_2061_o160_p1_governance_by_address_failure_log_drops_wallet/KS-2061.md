## What is wrong (one paragraph)

In `dbGetParticipantByAddress` (governanceService.ts line 409) the catch block logs `logger.error('DB get participant by address failed', { walletAddress, error: reason })` at line 420: when the database cannot be read, the wallet address the caller sent goes to the service log. KS 1955 treats a wallet address as a data subject's own data and erasure does not reach application logs. The ticket's fix is to drop `walletAddress` from that one log call; `error: reason` stays, and the `throw new ServiceUnavailableError(...)` on the next line stays. Two existing cells assert the wallet is in that line with `toEqual` (ks1940 line 521, ks1942 line 786); they are re-pinned to `{ error: 'unreadable thrown value' }`.
