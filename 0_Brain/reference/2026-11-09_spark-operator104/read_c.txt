**This ticket asks a question rather than answering it: should a webhook payload be**
**scanned at all, or declared out of the class in writing?** Both are defensible. What
is not defensible is the current state, where the doc claims one and the code does
the other.

## Recommendation

Decide first, then implement — the implementation differs completely by answer:

* **(A) Scan raw bodies.** Teach `findControlBytePath` to walk a `Buffer` (a byte
  scan, not `Object.entries`), and mount the guard after `express.raw` on
  `/webhooks`. Cost: a byte walk on every webhook body. Risk: a signed webhook
  payload whose signature covers the raw bytes must not be altered — rejection is
  fine, mutation is not, and the guard only rejects.
* **(B) Declare raw bodies out.** Say so in the guard's doc comment and in
  `mountBodyParsers`'s, and add a leg asserting that no `express.raw`/`express.text`
  mount feeds a handler that persists its body as text. The exclusion becomes a
  **declared set with a reason**, which is the shape the KS-800 gate asked for.

## Detail — measured, not quoted

Against `packages/shared/dist/middleware/index.js` built from this branch's source:

```
Buffer [61 00 62]            findNulBytePath       null
Buffer [61 00 62]            findControlBytePath   null
CONTROL {f: "a"+NUL+"b"}     findNulBytePath       "f"      <- the walker works
CONTROL {a: 0} (a number)    findNulBytePath       null     <- not a numeric artefact
CONTROL {s: buf.toString()}  findNulBytePath       "s"      <- same bytes, as a string
```

Two controls that could have disagreed and did not: the identical bytes presented as
a **string** are found, so the failure is Buffer-specific and not a broken walker;
and a literal number `0` is correctly not a NUL, so the null is not a numeric
artefact either.

**Cause.** The walker recurses with `Object.entries(value)`. On a `Buffer` that
yields numeric indices with **number** values, and no branch of the walker matches a
number — so it returns `null` without ever looking at a byte.

The last two matter beyond this ticket: they are the same two factories recorded as

**differ.** Whatever is decided here should be written into `PARSER_CALL`'s comment so
the next reader does not infer that a detected raw mount is a guarded one.
