##### KS-810 auth.openapi.ts cannot be imported by any test — passwordLoginGate imports z from zod directly, so a module-scope throw there leaves the suite green Done 2026-09-17T06:51:04.385Z
## BLUF

`services/auth/src/auth.openapi.ts` **cannot be imported from a test. It throws on load —** `TypeError: MFA_CODE_ACCEPTED.optional(...).openapi is not a function` **at** `:152` **— because** `services/passwordLoginGate.ts:55` **imports** `z` **from** `'zod'` **directly, which the shared registry explicitly forbids.**

**Consequence, measured by the KS-796 re-gate: a module-scope** `throw` **in** `auth.openapi.ts` **leaves the auth suite fully GREEN.** The file is in no test's import graph, so nothing in it — 300+ schema registrations, the entire published auth contract — is covered by anything that runs.

## Recommendation

Change `passwordLoginGate.ts:55` to `import { z } from '@secuura/shared'`, which is the rule the registry states. **But not casually:** every schema built from `MFA_CODE_ACCEPTED` changes prototype, and `@secuura/shared`'s root barrel pulls a large runtime surface into a module on the auth hot path. Two things to check before merging it:

1. that it does not create an import cycle (`passwordLoginGate` ← `routes/*` ← the service entrypoint, and `@secuura/shared` re-exports a lot);
2. that it does not drag an ESM-only dependency into a CJS require path — this repo has been bitten by `ERR_REQUIRE_ESM` from exactly that shape, and it crash-loops at runtime while tsc and vitest both pass.

**The regression test writes itself and should land in the same PR:** import `auth.openapi.ts` from any test and assert it loads. That single line is worth more than the change, because it converts a whole untested file into one that at least cannot be broken silently.

## Detail

**The rule, stated in the code** — `packages/shared/src/openapi/registry.ts:245`:

> *"Re-export the SHARED zod instance — consumers MUST import* `z` *from '@secuura/shared' (not from 'zod' directly) so the* `.openapi()` *extension applied above by extendZodWithOpenApi is on the same Zod prototype the consumer is using. Otherwise the workspace's hoisted-zod / per-service-zod instances diverge and* `.openapi is not a function` *blows up at the first* `.openapi(...)` *call."*

**The violation** — `services/auth/src/services/passwordLoginGate.ts:55`:

```ts
import { z } from 'zod';
```

`MFA_CODE_ACCEPTED` is built there, then consumed at `auth.openapi.ts:147`, `:449` and `:2474` as `MFA_CODE_ACCEPTED.optional().openapi({...})`. The first of those is line 152 in the compiled position, and it throws.

**Why nobody noticed.** `auth.openapi.ts` is loaded by the spec generator, a single CJS process in which the module resolutions happen to unify, so `npm run generate-openapi` works and the published yaml is correct. It is only under vitest — different resolution, ESM — that the two zod prototypes separate. So the defect is invisible to every path that currently exercises the file, and visible the moment anyone tries to test it.

**Why it matters beyond the inconvenience.** The KS-796 re-gate's canary is the finding: a module-scope `throw` in `auth.openapi.ts` left the auth suite at **441/441 green**. A file that publishes the platform's entire auth wire contract is not merely under-tested — it is un-importable, so it cannot be tested at all without this fix.

## What was done instead, and why it is not a substitute

KS-796's QA2-F4 guard asserts the three `mfaCode` sites against the **generated yaml** rather than the schema objects. That is defensible on its own terms — the yaml is what a client generates from, so it is the artefact that would ship wrong — but it is a text instrument over a build output, and it cannot see anything the generator does not emit. It does not close this.

## Provenance

* The `.openapi is not a function` failure reproduced in this session while writing the KS-796 QA2-F4 guard; the import-order workaround (`import '@secuura/shared'` first) was tried and does **not** fix it, which is what identified the cause as prototype divergence rather than evaluation order.
* The canary (module-scope throw → suite stays green) is the KS-796 re-gate's measurement, not mine.
* Related: **KS-796**, **KS-622** (whose lockstep guard reads the same yaml with occurrence-blind `spec.includes`).
