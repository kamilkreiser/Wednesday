=== KS-1897 | billing: POST /checkout/bundle and /checkout/custom read req.user.stripeCustomerId, which nothing sets, so no checkout is tied to the buyer's Stripe customer | In Progress | kamil.kreiser | prio 3 | archived None | comments 1 | newest 2026-11-15T08:16:57.839Z
DESC: **BLUF:** `POST /billing/checkout/bundle` and `POST /billing/checkout/custom` take the buyer's Stripe customer from `req.user.stripeCustomerId`, and nothing in the repository sets that field. So every checkout session is created without the buyer's customer: with the body's email when it carries one, otherwise with no customer at all. Found while designing KS-1888 and left out of it, as the coordinator ruled: it is a separate defect, not an authorization hole. /  / ## Where (develop df99b04720b8) /  / * `services/billing/src/routes/billing.ts:378` (bundle) and `:422` (custom): `const customerId = (req as any).user?.stripeCustomerId;` / * `services/billing/src/services/stripeService.ts:303-306` and `:356-359`: the session gets `customer` only when that id is set; otherwise `customer_email`, when the body gave one. / * `services/billing/src/services/stripeService.ts:533-537`: the `checkout.session.completed` handler adds the purchased credits to `session.customer`, and only when it is set. /  / ## What was read /  / * `services/` and `packages/`, tests aside, searched for `stripeCustomerId` and `stripe_customer`: the only reads are those two route lines and billing's own OpenAPI schema. Nothing writes the field. The shared `authenticate()` puts `userId`, `email`, `role`, `organizationId` and `tenantId` from the token on `req.user`. / * No migration stores a link from a user or tenant to a Stripe customer. Billing's only owner record is the customer's Stripe `metadata.userId` (the rule KS-1888 builds on). /  / ## Not measured /  / * What Stripe attaches to `session.customer` for a payment-mode session created with no customer, and so where the credits land after such a purchase. / * Whether any purchase has gone through this path. No real or test Stripe account was called. /  / ## Asked for /  / A stated rule for which Stripe customer a checkout belongs to, then both routes use it, with red-first cells. /  / ## Board search before filing /  / Team KS issues, archived included, titles, descriptions and comments: /  / * `stripeCustomerId` 0, `user?.stripeCustomerId` 0, `createBundleCheckoutSession` 0, `createCustomCheckoutSession` 0. / * `checkout/bundle` 4 hits (KS-591, KS-515, KS-501, KS-320) and `checkout/custom` 12: Schemathesis sweeps, schema drift and 500s.
