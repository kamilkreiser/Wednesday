339: ## Data Flow Diagrams
340: 
341: ### Document Certification Lifecycle
342: 
343: ```mermaid
344: sequenceDiagram
345:     participant Issuer as Issuer (Browser)
346:     participant IssuerFE as Issuer Portal
347:     participant APIGW as API Gateway
348:     participant Originate as Originate Service
349:     participant Anchoring as Anchoring Service
350:     participant Cardano as Cardano Network
351: 
352:     Issuer->>IssuerFE: Select document
353:     IssuerFE->>IssuerFE: Hash document (SHA-256, client-side)
354:     IssuerFE->>APIGW: POST /api/documents {hash, metadata}
355:     APIGW->>Originate: Forward request
356:     Originate->>Originate: Store document record
357:     Originate-->>APIGW: Document created
358:     APIGW-->>IssuerFE: {documentId}
359: 
360:     IssuerFE->>APIGW: POST /api/anchors {documentId, hash}
361:     APIGW->>Anchoring: Forward request
362:     Anchoring->>Anchoring: Build Cardano transaction
363:     Anchoring->>Cardano: Submit transaction (via Blockfrost)
364:     Cardano-->>Anchoring: Transaction hash
365:     Anchoring-->>APIGW: {txHash, blockHeight}
366:     APIGW-->>IssuerFE: Anchor confirmed
367: ```

369: ### Verification Flow
370: 
371: ```mermaid
372: sequenceDiagram
373:     participant Verifier as Verifier (Browser)
374:     participant VerifierFE as Verifier Portal
375:     participant APIGW as API Gateway
376:     participant Cardano as Cardano Network
377: 
378:     Verifier->>VerifierFE: Upload document or enter ID

467: ## Authentication Architecture
468: 
469: ### JWT Token Flow
470: 
471: ```mermaid
472: sequenceDiagram
473:     participant Client as Browser
474:     participant APIGW as API Gateway
475:     participant Auth as Auth Service
476: 
477:     Client->>APIGW: POST /api/auth/login {email, password}
478:     APIGW->>Auth: Proxy login request
479:     Auth->>Auth: Verify credentials (bcrypt)
480:     Auth->>Auth: Check MFA requirement
481:     Auth->>Auth: Generate JWT pair (access + refresh)
482:     Auth-->>APIGW: {accessToken, refreshToken, user}
483:     APIGW-->>Client: Set httpOnly refresh cookie + return access token
484: 
485:     Note over Client: Access token stored in memory (not localStorage)
486:     Note over Client: Refresh token in httpOnly cookie
487: 
488:     Client->>APIGW: GET /api/documents (Authorization: Bearer <access>)
489:     APIGW->>APIGW: authenticateToken middleware verifies JWT
490:     APIGW->>APIGW: Attach user payload to request
491:     APIGW->>Auth: Proxy to target service
492: ```
493: 
494: ### Token Configuration
495: 
496: | Parameter | Value |
497: |-----------|-------|
498: | Access token lifetime | Configurable via `JWT_EXPIRES_IN` (default: `1d`) |
499: | Refresh token | Stored in httpOnly cookie |
500: | Algorithm | RS256 (RSA-SHA256, asymmetric) — RS256-only since KS-167/184/302; HS256 dropped |
501: | Keys | `JWT_PRIVATE_KEY` (auth signs) + `JWT_PUBLIC_KEY` (verifiers, fail-closed if missing) + `JWT_KEY_ID`; no shared secret |
502: 
503: ### Authentication Middleware
504: 
505: Two middleware functions in the API gateway:
506: 
507: - **`authenticateToken(required = true)`** -- Verifies JWT from `Authorization: Bearer` header. When `required = false`, allows unauthenticated access with fallback to `x-user-id` header.
508: - **`requireAdmin`** -- Checks that `req.user.role === 'SYSTEM_ADMIN'`. Must be chained after `authenticateToken`.
509: 
510: ### Roles
511: 
512: | Role | Description | Access Level |
513: |------|-------------|--------------|
514: | `SYSTEM_ADMIN` | Platform administrator | Full access, admin portal |
515: | `OWNER` | Document/organisation owner | Issuer portal, own resources |
516: | `VERIFIER` | Third-party verifier | Verifier portal, public verification |
517: | `HOLDER` | Rights holder | Issuer portal, own documents |
518: 
519: ### Wallet Authentication
520: 
521: CIP-30 wallet connection for blockchain operations:
522: 1. User connects wallet via CIP-30 browser extension
523: 2. Server generates a nonce/challenge
524: 3. Wallet signs the challenge (CIP-8 message signing)
525: 4. Server verifies the signature against the wallet address
526: 5. Session is created linking wallet address to user account
527: 
528: > **Note:** CIP-8 signature verification currently uses a development stub. Production requires the `@emurgo/cardano-message-signing` WASM library.
