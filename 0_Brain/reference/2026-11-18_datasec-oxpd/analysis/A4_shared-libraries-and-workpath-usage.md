## 1. BLUF

This lane holds two Datasec-maintained Android libraries and a 661 MB archive that is not source on disk at all: it is 21 complete HP git repositories (the original HP Workpath apps and libraries, 2017 to 2024) packed as git bundles. The five facts that most shape the port:

1. **Token sharing is an Android bound service, not a Workpath feature.** HP Authentication Manager exports an AIDL service; the other apps bind to it through the `usermanagement` library and receive the user's Entra access token as a string, refreshed every 4 minutes. The trust check is "caller is signed with the same APK key". Nothing of this exists on an OXPd device: the server must own the token and the session.
2. **The Workpath identity is display data only.** At sign-in the app pushes a name, e-mail and a fixed placeholder password into the device session (`AccessService.signIn`); every app then reads that Principal back and matches its e-mail to the token. The port needs an equivalent "device session to user" binding obtained from the printer.
3. **All scan and print goes through one library (`commonvaluablelibrary`, Datasec fork 1.09.22) on Workpath SDK 1.6.3**: capability query, job submit with about 20 scan and 13 print attributes, job progress observer, cancel. Files are exchanged through the app's local storage on the printer. On OXPd the server must receive scan data and deliver print data over the network instead.
4. **The suite depends on six more device services beyond scan and print**: USB HID card readers (six vendor/product pairs, owned by HPAM), remote configuration (HP Command Center pushes a JSON document per app), device attributes, job statistics plus supplies (polled each minute and exported to Azure Monitor), app attestation token, and the device's SMTP send helper.
5. **Packaging and deployment are Workpath-specific and simple**: an `.hpk` is a zip of one APK plus `hpk.xml` (platform `LinkForDevice`, `platformVersion` 31.7), all five apps are signed with one keystore that is committed with its passwords, and the `hpk.xml` declares the providers (AUTHN, ACCESSORIES, STATISTICS). None of it carries over; the OXPd bundle and signing process replaces it.

## 4. Findings

### 4.1 Token and identity sharing between the apps: the exact mechanism

The mechanism has three layers. None of them is in CVL; it lives in HPAM and in a small client library, `usermanagement`, that every other app embeds as an `.aar`.

**Layer 1: the device session (Workpath).** HPAM is registered as the printer's authentication agent: its `hpk.xml` declares an `AUTHN` provider whose `authenticationUrl` is the activity `...ui.main.AuthActivity`, with `enablePrePromptCheck` true (`HPAM/app/packaging_contents_release/hpk.xml:28-44`), and its manifest exports `PrinterAuthenticationService` for the action `com.hp.jetadvantage.link.api.action.AUTHENTICATION` (`HPAM/app/src/main/AndroidManifest.xml:101-108`). That service extends the SDK class `AbstractAuthenticationService` and receives `onSignIn(Principal)`, `onSignOut()` and `onPrePrompt()` from the device (`HPAM-J/sdk/PrinterAuthenticationService.kt:81-122`). After a successful Entra sign-in HPAM calls `AccessService.signIn(context, SignInAction(SUCCESS), attributes, result)` (`HPAM-J/sdk/SDKBridgeImpl.kt:68-90`). The attributes are built with `AuthenticationAttributes.WindowsBuilder`: display name (one of first+last name, UPN, display name or e-mail, by configuration), e-mail, a fixed literal password, domain and home folder from string resources, plus `UserPreferencesAttributes` (language code and `setAutoLaunchAppAccessPointId`) (`SDKBridgeImpl.kt:183-258`). So the device session carries **who the user is for display and e-mail defaults**, not a credential. Other calls: `AccessService.initiateSignIn` (ask the device to start the sign-in prompt), `signIn` with `CONTINUE` or `CANCEL`, `signOut`, `getCurrentPrincipal` (`SDKBridgeImpl.kt:52-172`).

**Layer 2: the token service (plain Android IPC).** HPAM exports `TokenManagementService` with the intent action `com.hp.print.hpauthenticationmanager.usermanagement.BIND_SERVICE`, protected by the stock Android permission `GET_PACKAGE_SIZE` (`AndroidManifest.xml:80-87`). The manifest comment says why a stock permission was chosen: a self-defined permission is lost when the defining app is uninstalled (`AndroidManifest.xml:18-22`). The real access control is in code: every AIDL method first calls `enforceSameSignature()`, which resolves the caller's UID to packages and requires `PackageManager.checkSignatures(...) == SIGNATURE_MATCH` (`HPAM-J/tokenmanagement/TokenManagementService.kt:95-109`). The interface (`HPAM/usermanagement/src/main/aidl/.../tokenmanagement/ITokenManagementService.aidl:15-34`):

| AIDL method | Meaning | Source of behaviour |
|---|---|---|
| `setTokens(access, refresh)`, `setRefreshToken(token, cb)` | HPAM's own UI process hands the tokens to the service after sign-in | `TokenManagementService.kt:188-245` |
| `getToken()` | returns the current access token, or null if the token's user does not match the device session | `:247-255` |
| `getNewToken(listener)` | redeems the refresh token now and returns a fresh access token | `:257-270` |
| `registerListener` / `unregisterListener` (`IUserListener`: `onUserSignIn(token)`, `onNewAccessToken(token)`, `onUserSignOut()`) | push channel to every bound app | `:272-297`, `:447-510` |
| `onUserSignIn()` / `onUserSignOut()` | called by HPAM's own authentication service when the device reports the event | `:465-510`; caller `PrinterAuthenticationService.kt:81-117` |
| `setLaunchAppAfterAuthCompleteAndStartAuth(uuid)` | an app that finds no user asks HPAM to start sign-in and to relaunch that app afterwards; HPAM retries `AccessService.initiateSignIn` up to 10 times at 200 ms | `:299-328`; the UUID is handed to the device via `setAutoLaunchAppAccessPointId` (`SDKBridgeImpl.kt:222-229`) |
| `getProperty` / `updateProperty` | per-user key/value stored server-side (Entra back end, or the legacy Keycloak API), cached in `EncryptedSharedPreferences` | `:330-383` |
| `getUserProperty` / `updateUserProperty` | per-user key/value stored through a OneDrive-based store using the user's own token | `:385-422` |
| `getAccessForRefreshToken(token, cb)` | exchange a given refresh token | `:424-445` |

What is shared is the **Entra access token as a JWT string**. HPAM keeps access and refresh token in `UsersTokensStorage`, restarts a loop that redeems the refresh token every 4 minutes and broadcasts each new access token to all listeners (`TokenManagementService.kt:162-185`, `:216-226`). Before any token is returned HPAM decodes it and compares the claims `unique_name`, `upn` and `preferred_username` with the e-mail of the Workpath Principal; on mismatch it wipes the tokens and signs the device session out (`:123-154`). The comment there states the reason: a sign-out event may have been missed.

**Layer 3: the client library `usermanagement` (version 1.06.01, `HPAM/usermanagement/build.gradle.kts:17`).** `UserManagementProxy` binds with that action, scoped to package `com.hp.print.hpauthenticationmanager` (`.../usermanagement/UserManagementProxy.kt:49-51`); `UserManagement` wraps the binder (`.../UserManagement.kt:20-107`); `UserManagementProxyKt.listenForToken()` turns it into a flow with the states `Pending`, `Exists(token)`, `NotExists`, `AuthManagerMissing` (`.../UserManagementProxyKt.kt:16-35`, `:94-106`). The developer note `HPAM/usermanagement/UserManagementHowTo.txt:5-9` describes it as sharing a token "that has openid scope with 2nd party applications".

The same library carries two more cross-app channels:

- **Cloud environment**: HPAM exports `CloudConfigService` (`AndroidManifest.xml:109-113`); `CloudConfigProxy` binds to it after its own `checkSignatures` test and exposes the authority, Graph and Azure Monitor base URLs for Commercial, GCC, GCC High, DoD or Custom (`.../cloudconfig/CloudConfigProxy.kt:86-115`, `.../model/CloudConfig.kt:3-42`). MailFlow, Teams and OneDrive read their Graph endpoint from it (`SC/MailFlow-main/.../microsoft/auth/MSAppAuthHelper.kt:52`, `SC/Teams-main/.../auth/AppAuthManager.kt:57`, `SC/CypherOneDrive-main/.../common/GraphProvider.kt:50`).
- **Pull print**: HPAM binds to a service inside Universal Print, component `com.hp.print.mup.agentas/.directprint.PrintService`, using `bindServiceAsUser` through reflection (`.../asprinterservice/AsPrintServiceProvider.kt:31-34`, `:144-165`), with the interface `fetchJobs(userEmail)`, `releasePullPrintJobs(userEmail)`, `pullPrintTimeoutDuration()`, `cancelPullPrint()` and a callback `onStatusChanged(documentsInQueue)` (`.../aidl/com/hp/print/asprintservice/IPrintService.aidl:5-12`). So release-at-sign-in is HPAM calling Universal Print in-process on the device.

Who consumes it: MailFlow, Teams and OneDrive create a `UserManagementProxy` in their splash and main activities and call `getNewToken` from their HTTP authenticators when Graph returns 401 (`SC/MailFlow-main/.../ui/splash/SplashActivity.kt:66`, `.../HttpClient.kt:58`; `SC/Teams-main/.../auth/SessionAuthenticator.kt:26`; `SC/CypherOneDrive-main/.../auth/SessionAuthenticator.kt:26`); Universal Print uses the flow helper and reads the property `UPAR` (`SC/UniversalPrint-main/.../ui/splash/SplashViewModel.kt:135`, `:184`); all three Microsoft 365 apps keep user preferences through `getUserProperty`/`updateUserProperty` (`SC/MailFlow-main/.../userdata/MailFlowUserDataStore.kt:250-262`, `SC/Teams-main/.../storage/UserPreferencesStore.kt:192-203`, `SC/CypherOneDrive-main/.../storage/UserPreferencesStore.kt:231-242`).

The package list HPAM expects is explicit in its manifest `<queries>`: `com.hp.print.cypher.teams`, `com.hp.print.cypher.sharepoint`, `com.hp.print.cypher.onedriveforbusiness`, `com.hp.print.mailflowas`, `com.hp.print.mup.agentas` (`AndroidManifest.xml:10-16`).

For comparison, HP's original apps (before HPAM existed) each ran their own OAuth sign-in and stored tokens per app through `PersonalizationLibrary` ("Philip"): a `Token` record (access token, refresh token, expiry) (`WP:PersonalizationLibrary/personalizationlib/src/main/java/com/hp/print/lib/personalization/data/model/Token.kt:8-16`), kept locally and, in cloud mode, in an HP vault service reached with an HP "SIO" token (`.../common/Environment.kt:10-41`, `.../data/source/cloud/VaultService.kt:11-45`, `.../TokenProxyService.kt:11-22`), keyed by `deviceUserId` and package (`.../PhilipManager.kt:28`). The Datasec fork switched this off in CVL: `WorkpathAccessService.isHPCloudUser()` and `isSIOEnabled()` both return false unconditionally (`CVL/sdk/WorkpathAccessService.java:108-111`, `:137-140`). MailFlow still imports the Philip model classes `Token` and `UserInfo` as plain data holders (`SC/MailFlow-main/.../userdata/MailFlowUserDataStore.kt:8`).

### 4.4 Android-specific assumptions

- **Process model.** Each app is an APK with activities, long-lived foreground services and broadcast receivers; HPAM starts at boot (`RECEIVE_BOOT_COMPLETED`, `HPAM/app/src/main/AndroidManifest.xml:25`, `:123`) and keeps a card-reader service alive with `START_STICKY` and alarm-based restarts (`HPAM-J/sdk/PrinterAccessoryService.kt:109-123`).
- **SDK levels.** Apps: compile 35 or 36, min 31, target 35 (`SC/MailFlow-main/build.gradle.kts:18-20`, `SC/Teams-main/build.gradle.kts:9-11`, `SC/CypherOneDrive-main/build.gradle.kts:2-4`, `SC/UniversalPrint-main/build.gradle.kts:7-9`, `HPAM/app/build.gradle.kts:22-26`). CVL keeps min 28. The accessory code branches on Android 12 (`HPAM-J/sdk/PrinterAccessoryService.kt:173-177`). The demo app pins ABI `armeabi-v7a` (`SC/CommonValueLibraryCypher-master/app/build.gradle.kts:20-22`).
- **Permissions.** `INTERNET`, `FOREGROUND_SERVICE`, `ACCESS_NETWORK_STATE`, `RECEIVE_BOOT_COMPLETED`, `SCHEDULE_EXACT_ALARM` (UP), `GET_PACKAGE_SIZE` (as the binding token), and the Workpath ones `com.hp.workpath.permission.sdk.ACCESS_STATISTICS_PERMISSION`, `ACCESS_DEVICE_USAGE_PERMISSION`, `ACCESS_SUPPLIES_PERMISSION`, `ACCESS_DEVICE_EVENTS_PERMISSION`; components the device calls are guarded by `com.hp.jetadvantage.link.permission.SERVICES_PERMISSION` (`HPAM/app/src/main/AndroidManifest.xml:22-30`, `:66-70`, `:88-107`, `:115-118`). A custom permission `com.hp.print.hpauthenticationmanager.permissions.TokenLibraryPermission` is marked deprecated but still requested (`HPAM/usermanagement/src/main/AndroidManifest.xml:16-17`).
- **Intents.** Explicit intents and local broadcasts inside each app (CVL scan/print results: `cvs.aar.scan.support.service.event`, `cvs.aar.print.support.service.event`, `CVL/constants/CommonConfigConstants.java:21`, `:101`); bound services across apps (4.1); debug broadcasts in HPAM that emulate a card tap, sign-in and sign-out, registered without a permission (`HPAM-J/sdk/PrinterAccessoryService.kt:126-134`, `HPAM-J/sdk/PrinterAuthenticationService.kt:61-66`).
- **VAV.** `android:useEmbeddedDex="true"` and `allowBackup="false"` are stated as required "for VAV process" (HP's app validation) (`HPAM/app/src/main/AndroidManifest.xml:32-36`).
- **Sign-in UI.** Microsoft sign-in runs in an on-device WebView with an "autoclicker" helper (`HPAM/README.md` section "Microsoft sign-in autoclicker"); detail belongs to the HPAM lane.
- **App signing.** One keystore, `[keystore file name withheld]`, is committed in all five app repositories (the five files are byte-identical) and both build types of every app sign with it; the store and key passwords are written in each `app/build.gradle.kts`. Because cross-app trust is a signature match (4.1), this one key is the security boundary of token sharing.
- **HP packaging.** An `.hpk` is `zip -r <name>.hpk <apk> hpk.xml` (`HPAM/.github/workflows/release.yml:48-67`; the same command by hand in `HPAM/app/notes:34-39`). `hpk.xml` (schema `http://www.hp.com/schemas/jetadvantage/link/hpk/v2.5`): app `uuid`, `name`, `vendorName` "HP Inc", `date`, `platformType` `LinkForDevice`, `platformVersion` 31.7 (31.9 in the simulator variant), `installFile`, empty `defaultConfig`, and `providers`. HPAM declares STATISTICS, AUTHN and six ACCESSORIES entries with `registrationType` OWNED; the four other apps declare no providers (`SC/MailFlow-main/packaging_release/hpk.xml:3-10`, `SC/Teams-main/packaging_release/hpk.xml:3-10`, `SC/UniversalPrint-main/packaging_release/hpk.xml:3-10`, `SC/CypherOneDrive-main/app/packaging_release/hpk.xml:3-10`). A note records that a STATISTICS provider breaks `AccessService` in the Workpath simulator (`HPAM/app/packaging_contents_workpath_simulator_debug/readme`).
- **HP signing (HP's own pipeline, for reference).** `WP:AutoSignToolForJenkins/src/main/java/com/hp/autosign/AutoSignThread.java` automates: copy the unsigned APK, strip `META-INF`, obtain a Kerberos ticket from a keytab, sign the APK with an HP `SecureSign.jar` service, zip-align, insert the `hpk.xml` header (for SecureAccess: replace the APK inside a base `.hpk`), sign the `.hpk` the same way, verify with `jarsigner`, and copy the result to a share (`:64-88`, `:139-143`, `:167-179`, `:339-344`, `:547-555`, `:581-586`, `:604-613`). Whether Datasec's HPKs get an HP signature after the zip step, and by which portal, is not in this lane's material (Question 2).
- **Deployment.** HP Command Center appears as the source of per-app configuration (`unwrapHpcc`, `CVL/config/ConfigHelper.java:201-215`; folder `HPAM/app/how_omni_team_parses_the_config_from_hpcc/`). The installation path itself (Command Center, embedded web server, `HPK-Deployment-Utility-main`) is in other lanes.
- **Client secrets at device level (HP's practice).** `WP:AppAttestation` is a Windows tool that connects to a printer over `adb` and sends a broadcast carrying an app UUID and a block of OAuth client ids and secrets to provision the device-side attestation data (`WP:AppAttestation/AppAttestation/Program.cs:140-152`, `:332-375`; usage in `.../bin/Release/README.txt`). It shows that on Workpath the app's OAuth client credentials were tied to the device through attestation rather than shipped in the APK.

### 4.6 Build system and CI

- **Datasec repositories**: Gradle Kotlin DSL, AGP 8.11 to 8.13, Java 11 bytecode, built on JDK 21 in CI. The apps each have `codeql.yml`, `gitleaks.yml`, `release.yml` (tag `v*` → build APK → zip HPK → upload artifact), some also `build.yml` or `ci.yml`.
- **HP repositories**: Gradle Groovy; older ones keep the Eclipse/Ant layout at the repository root (`WP:HorizontalApps/AndroidManifest.xml`, `src`, `res`, `project.properties`); product flavors build several apps from one tree (HorizontalApps: `.box`, `.dropbox`; ScanApps: `.email`, `.ftp`, `.smb`, `.webdav`; OneDrive: business and personal); `.github` holds only a PR template in the ones checked; signing and HPK assembly were done by the Jenkins tool in 4.4; branch names mention SonarQube (`dev_lim_sq`, `dev_damon_sonar_qube`).

### 5.2 Requirements and constraints

- **R1. One server-side session and token store replaces three IPC channels** (token, cloud environment, pull print) (4.1). The port must keep the behaviours those channels implement: refresh before expiry and on 401, push of sign-out to every module, identity check against the device session, "start sign-in and come back to my app", per-user properties, and selection of the national cloud endpoints.
- **R2. Pull-print release at sign-in is a call from the authentication module into the Universal Print module** (4.1). On the server it is a function call; what it needs from the device is item 16 and 17 above.
- **R3. The scan and print option model is reusable as a specification.** The option keys, defaults handling and conflict rules in CVL (`CVL/constants/CommonConfigConstants.java:47-93`, `CVL/config/SDKOptionDefaultOperator.java`) define what administrators can preset today. The existing `.moc` forms and `.cfg` files define the admin-facing configuration schema that the server's admin UI has to cover for parity.
- **R4. Mixed fleets.** The Workpath apps and an OXPd server will coexist. Shared state that lives outside the device already exists (Entra back end for card mappings and properties, Azure Monitor tables for reporting): the server should read and write the same stores so that a user enrolled on a Workpath device works on an OXPd device. Per-user properties stored through the OneDrive-based store (4.1) are equally reachable from a server.
- **R5. Reporting parity** needs the device attribute set and the job-statistics fields of items 18 and 19, in the same table shapes the Workpath HPAM sends.

### 5.3 Reusable parts

- Card-data decoders for the three reader families (`HPAM-J/sdk/PrinterAccessoryService.kt:282-392`, `:499-518`; HP's `GenericParser` and `RFIDeasParser` in SecureAccess) if OXPd delivers raw HID reports.
- The configuration JSON model (`CVL/config/model/*`) and the HP Command Center unwrap logic, as the import format for existing customer configurations.
- The `TaskConfiguration` and `SensitivityLabel` data classes and the print-option mapping table (`CVL/utils/PrintJobConfigMappingTable.kt`, 35 KB, not read) as the neutral job-ticket model.
- The AIDL interfaces as the contract list for the server's internal session API (4.1 table).
- HP SecureAccess's requirements document and design guides (`WP:SecureAccess/doc/requirements/SecureAccess_SRS_V1.24.docx`, `doc/ui/*.pdf`), as a reference for sign-in flows on small panels. Not read.

### 5.4 Traps

- **T1. The `.aar` copy model has already drifted** (four CVL versions in service, one unversioned `usermanagement` file in Universal Print, 4.5). A shared server core removes this; do not recreate per-app copies of shared code.
- **T2. `isSIOEnabled()` returns false always**, yet the apps still branch on it in more than 40 places (search result in 4.1 consumers; for example `SC/Teams-main/.../ui/main/MainActivity.kt:699-707`). Reading the app code as the behavioural specification without knowing this will overstate what the product does: every `isSIOEnabled` branch is dead.
- **T3. Non-device mode fakes.** CVL returns a canned principal and `isAdmin = true` when not in device mode (`CVL/sdk/WorkpathAccessService.java:61-63`, `:95-105`), and HPAM has emulator branches throughout. These are test scaffolds, not behaviour.
- **T4. The device session carries no secret.** A design that expects to recover a credential from the printer session will find only a display identity (4.1 layer 1).
- **T5. Android 12 changed how accessory events are delivered** (4.3). Expect the OXPd side to have firmware-generation differences of the same kind; the reader path needs testing per platform version (OXPd 1.x and OXPd 2).
- **T6. Destination "ME" hides a storage assumption.** Today a multi-page scan is a set of files on the device that the app can preview, rename and split before upload. With a server, preview and post-processing need the data on the server first; panel responsiveness then depends on network transfer of scans.

## 6. Contradictions and doubts

1. **START-HERE versus the archive.** START-HERE section 3a describes `WorkPathApplicationsAndLibrariesSources-master` as shared libraries plus print/scan code and UI. In fact it contains 21 HP repositories including a full authentication agent (SecureAccess) and eleven apps (3.3, 4.7). It also contains HP originals of `CommonValuableLibrary` and `QuickAccessLibrary`, so the library has two generations of each.
2. **Who owns this code.** The manifests and build files show HP package names and HP-internal hosts; `hpk.xml` of the Datasec apps still says `vendorName` "HP Inc" (`HPAM/app/packaging_contents_release/hpk.xml:5`), while file headers in HPAM say "Copyright (c) 2022. DataSec." The licence under which Datasec holds and may reuse HP's sources (including on a non-Workpath platform) is not stated anywhere I read (Question 3).
3. **`todo.txt` (quoted in START-HERE) says "All the apps share CommonValueLibrary".** True for four apps; HPAM imports one class from it (`commonvaluablelibrary.utils`) and removes its EULA activity from the merged manifest (`HPAM/app/src/main/AndroidManifest.xml:44-48`).
4. **SharePoint package.** HPAM expects `com.hp.print.cypher.sharepoint`; no build in the library produces it (4.7).
5. **`platformVersion`.** Release HPKs say 31.7; the simulator variant says 31.9, and its `authenticationUrl` uses a different spelling (`...ui.main/.AuthActivity`) and turns pre-prompt off (`HPAM/app/packaging_contents_workpath_simulator_debug/hpk.xml` lines 8, 25, 26). I did not find what the numbers map to in firmware terms.
6. **CVL README** is HP's and points to an HP-internal wiki; nothing documents the Datasec fork's additions. The HP bundle's CVL HEAD is a detached 2023 "legacy" commit (version 1.01.22), not `master`; I did not diff HP `master` against the Datasec fork.
7. **SDK 1.6.3 date.** The `.aar` manifest says "1.6.3 (20251111)" while file timestamps inside the archive are 2025-09-04. Harmless, noted only because the SDK version matters for which devices the Workpath apps require.

Weaknesses in the existing product that the port should not carry over:

1. **One signing key guards all token sharing, and that key and its passwords are in every repository** (4.4). Anyone with repository access can build an APK that HPAM will hand the user's Entra token to. On the server, module-to-module trust must not rest on a shared static secret in source control.
2. **Tokens and identities in logs.** HPAM logs the full access token at debug level (`HPAM-J/tokenmanagement/TokenManagementService.kt:172`, `:194`), logs property values (`:358`, `:408`) and card data strings (`HPAM-J/sdk/PrinterAccessoryService.kt:385-387`, `:512`; `HPAM-J/sdk/AccessoryReceiver.kt:132-135`). CVL logs configuration JSON in debug builds (`CVL/config/ConfigHelper.java:264-266`). Card numbers are credentials in this product; the server must never log them or tokens.
3. **Unprotected debug broadcasts in a production service**: any app on the device can emulate a card tap or trigger sign-in and sign-out handlers through plain broadcast actions (`HPAM-J/sdk/PrinterAccessoryService.kt:126-134`, `HPAM-J/sdk/PrinterAuthenticationService.kt:61-66`, usage in `HPAM/app/notes:6-13`). Test hooks must be compiled out of release builds.
4. **A fixed placeholder password is written into the device session** for every user (`HPAM-J/sdk/SDKBridgeImpl.kt:243`). If any device feature uses the session password (for example scan to a network folder "as the user"), it silently gets a wrong value. Check what OXPd does with session credentials before copying the pattern.
5. **Debug and release builds share the release signing configuration** (`HPAM/app/build.gradle.kts:42-50`), so a debuggable build is trusted by the token service exactly like a release build.
6. **Network and e-mail credentials travel in Android intents as a Parcelable** (`CVL/config/NetworkSettingsOption.java:75-82`; passed in the scan start bundle, `CVL/scan/service/ScanSupportService.java:332-334`). In-process today; on a server the equivalent values must stay in a secret store.
7. **Configuration write-back by role only**: an app treats `Principal.isAdmin` as sufficient to overwrite the centrally deployed configuration (`CVL/config/ConfigHelper.java:75-82`). The server should separate device-panel administrators from tenant administrators.
8. **HP SecureAccess precedent to avoid**: user records with a password field, card and PIN hashes and OIDC tokens in a local database on each device, synchronised device-to-device over an HTTP endpoint protected by one static header value (`WP:SecureAccess/.../db/room/entity/UsersEntity.kt:9-21`, `.../services/WebServiceTask.kt:24`, `:46-55`). Datasec's design (mappings in Entra) is already better; the OXPd server should not reintroduce a local credential cache without encryption and an expiry policy.
