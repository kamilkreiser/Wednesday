## Findings

**N1 — Minor — offset paging duplicates rows when the export range includes "now".** `routes/audit-export.ts:196` (`offset: String(entries.length)`) pages over a set the upstream re-sorts newest-first on every call (`services/security/src/index.ts:917-921`). If a row lands in range between two page calls, every later offset moves by one. MEASURED AT RUNTIME (my stub, modelled on index.ts:880-929, cell G-GROW): 1,500 rows, one row added between pages 1 and 2. Result: `200`, 1,501 rows, **1,500 distinct ids** (one row twice), the new row absent, `total: 1501, truncated: false`. No existing row was lost. Only ranges whose `to` day is the current UTC day are affected, which is likely the most common export. Oracle: Purpose (an audit file should not repeat entries) and Product (`totalEntries` counts a duplicate). Fix shape: keyset paging (a createdAt + id cursor), or de-duplicate by id. Regression test: add a row between pages and assert distinct ids == rows. Evidence: `ev_grow.out`.

**N2 — Minor — a later page that answers 200 with no `total` resets the total, and the short file says `truncated: false`.** `routes/audit-export.ts:216` overwrites `upstreamTotal` on every page, and a missing total falls back to `entries.length`. MEASURED AT RUNTIME (stub, cell G-NOTOTAL): page 1 reports total 2,500, then page 2 answers 200 with no total and no rows. Result: `200`, 1,000 rows, `meta.total: 1000, truncated: false`. That is a short 200 that looks complete, the class Q3 asks about. READ ONLY: the real list route always sends `total` (index.ts:923-930), so this needs a degraded upstream or proxy. Fix shape: keep the first (or largest) reported total, and treat a missing total after page 1 as an upstream error. Evidence: `ev_own_head.out`.

**N3 — Minor — the spec now declares `pattern: ^\d{4}-\d{2}-\d{2}$` (required) for `from`/`to`, but the route does not enforce it.** `api-gateway.openapi.ts:630-631` against `routes/audit-export.ts:99-106` (`new Date(x)`). MEASURED AT RUNTIME (stub, G-PATTERN): of 9 values that break the pattern, 7 get **200** at head (`0`, `1`, `-1`, `2026-9-1`, `Sep 1 2026`, `2026-09-01T00:00:00Z`, and also `2026-02-30`, which matches the pattern and rolls over). `20260901` and `x` get 400. Base behaves the same (the base spec said `format: date-time`, which the route did not enforce either), so this is not a regression. But the PR rewrote the declared constraint without making it true. READ ONLY: `negative_data_rejection` is active in `systemTest/schemathesis/config/checks.py`, so a Schemathesis run will probably report it. Fix shape: validate with the same regex in the route (400), or relax the spec to what the route accepts. Evidence: `ev_pattern.out`.

**N4 — Note — CSV formula injection: neutralised at neither base nor head.** `escapeCSVField` (`audit-export.ts:90-97`, unchanged) only quotes values containing `,`, `"` or `\n`. MEASURED (G-CSV, base and head): `+1+1`, `-2` and `@SUM(A1)` go out raw. `=HYPERLINK(...)` is quoted only because it contains a comma and still starts with `=`. A bare `\r` is not quoted at base or head. `userAgent` and `ipAddress` can be set by the caller and were populated at base too. The PR newly fills `action`, `resource` and `timestamp`, which are service-set. Per the commission this is a note, not a hold. Evidence: `ev_own_head.out`, `ev_own_base.out`.

**N5 — Note — the client-visible contract change, stated plainly.** (a) An unknown or repeated `type` used to be 400 BAD_REQUEST and is now 200 with `type` ignored. (b) `meta.type` is removed. (c) The filename loses its `_<type>` suffix. (d) The CSV header goes from 12 to 10 columns: `type` and `email` are dropped and the positions after them shift. (e) An export used to return at most the upstream's default 50 rows and now returns up to 10,000. (f) `to` now includes its whole UTC day. (g) `meta.total`, `meta.truncated` and `X-Audit-Export-Truncated` are new. The READY calls the meta/header changes "additive", but (b), (c) and (d) are removals. **The spec never declared `type`, at base or at head** (base yaml params: format, from, to), so the retired 400 was never in the spec and the spec does not record that it is gone. The PR body and the fragment do state it. Callers: none in frontend, services or systemTest code. The positive control is the same grep at base, which hits the route, its tests and the yaml. The admin portal calls `/api/security/audit/export` (`frontend/admin/src/services/api.ts:927`). `systemTest/schemathesis/docs/known-issues-and-baseline.md:892-900,1232,1239` describes this operation's old spec faults (from/to required ×10, no `entries` key), so that doc will be stale after merge. That is for the systemTest owner. Evidence: `ev_q6_callers.txt`.

**N6 — Note — the seat's cells do not cover per-page auth/tenant forwarding.** I added mutant M4 (Authorization dropped on pages 2 and later).
