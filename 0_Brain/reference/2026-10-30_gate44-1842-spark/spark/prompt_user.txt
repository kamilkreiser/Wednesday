## BLUF

The Sonnet-tier gate on PR #1517 (ticket KS-1232) returned **GO**: 0 Major, 3 Minor notes (verdict sha256/16 `622027fcfb23dab5`). ## Checklist

- [ ] **(a) Stop duplicating the predicate, or pin drift (the gate's Minor 1).** The info reader's guard (`services/api-gateway/src/services/health.ts:77`) is character-identical to the create path's (`routes/verification.ts:1307`): `raw !== undefined && raw !== null && !Array.isArray(raw)`, with the same 403 text. It is **duplicated, not shared**. Drift today is guarded only by the 12-shape AGREEMENT cell in `ks1232-info-reader-refuses-a-non-array-allow-list.test.ts`; the gate's own 30-shape run (`NaN`, `Infinity`, `-0`, array subclasses, a Proxy, an object with a `length`, `new String('')`, `Object.create(Array.prototype)`) found **0 disagreements**. Options: one helper imported by both routes (this edits the create path's allow-list guard, a security surface, so it needs its own gate), or a source-level cell asserting the two guards are the same executable code (a source-text check passes when the guard is commented out, so compare the code, not the text).
- [ ] **(b) Decide whether an array of non-strings is refused, by both read routes together (the gate's Minor 2; a contract question).** Neither route checks array ELEMENTS. The info reader echoes `[1,2]`, `[null]` and `[['a']]` raw (same as before this PR), and the create path accepts the same shape at its guard; reasoned from its code (`allowedTypes.includes(requestedType)`), not run, a non-empty array of non-strings then refuses every create with the "not permitted to register document type" text rather than the list text, so the two routes would answer differently for the same stored value. KS-1230 is where element types are validated on the **write** path; this item is whether the two **reads** should also refuse such an array, and with what text. Out of the ticket's "non-array" wording, so it was not changed in KS-1232.
