## GATE QUESTION 3 — the premise is FALSE. Read this before gating #1603.

You asked to *confirm the error message never reaches the user's browser beyond what it did before*.
**It reaches it.** Chain, read in source:

1. `routes/auth.ts:1032-1035` catches `exchangeCode`'s throw and re-raises
   `new BadRequestError("OAuth authentication failed: " + exchangeErr.message)`.
2. `BadRequestError` extends `AppError` (`errorHandler.ts:30-32`).
3. `errorHandler.ts:293` writes `message: err.message` into the body; `:300` sends it with
   `res.status(err.statusCode)`.

So the adapter's message — now carrying `(HTTP 503)` — is **serialised to the caller in the 400**.
The suite's own docstring says so ("in the log AND in the 400 the callback answers"), so it is the
drafter's intent, not an accident. But **the batch brief describes A.3 as a change to an error
MESSAGE, and it is in practice a change to a RESPONSE BODY.** That is the gate's call, not something
to inherit quietly.

What is disclosed is the status **the provider's** profile endpoint returned — Google's or
Microsoft's, not ours. Low sensitivity, largely inferable by a caller driving the OAuth dance. Still
new information in a response. **The alternative shape, if the gate prefers it: keep the status in
the log line and leave the thrown message alone.** It is in #1603's body in full.

## GATE QUESTION 2 — answered, both halves

**(a) Structured? YES in BOTH modes — and dev is safe for a different reason than production.**
Production is `combine(json())` (`utils/logger.ts:33-34`). Development is a `printf` template, which
would NOT escape a newline — **but the meta object goes through `JSON.stringify` at
`utils/logger.ts:16`**, so the caller-supplied value is escaped there. The unescaped parts of a dev
line are timestamp, service, level and message, none caller-supplied here. So the field cannot forge
a line either way. "It's JSON in production" would have been the wrong answer for the dev path.

**(b) Echoed to a response? Not in auth, deliberately** — `errorHandler.ts:190` says so in terms,
the callback throws the generic `OAuthProviderError`, and cell A2-3 asserts the raw response carries
neither value.
