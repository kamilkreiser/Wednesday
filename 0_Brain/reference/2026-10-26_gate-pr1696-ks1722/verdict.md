## Findings

1. **Minor: a misspelled or unknown filter KEY still returns everyone's proposals.** `ProposalListQuerySchema` is a non-strict `z.object`, so unknown keys are stripped. Measured: `?proposerid=bob`, `?proposer_id=bob` and `?Status=active` all give **200 with every row and no WHERE**. qs's 1000-parameter limit gives the same result: a `proposerId=bob` (or a blank `proposerId=`) placed after 1000 other params is dropped before validation. This is the same "silently unfiltered" trap KS-1722 closes, reached through the key instead of the value. It is outside the PR's stated claim (present-but-unusable *values*), and the one bounding caller (KS-1719) re-checks every row. The fix shape is the owner's call. `.strict()` alone would refuse the SDK's `limit`/`offset` and cache-busters, so a strict schema with an explicit allowance for those, or a refusal of keys that case-fold to a filter name, fits better. Regression cell: `?proposerid=alice` must not answer with bob's rows. **Evidence: MEASURED AT RUNTIME (repo level, gate cells REC "MISSPELLED …" and "after 1000 params").**
2. **Minor: the suite does not pin case, and the S2 agreement oracle cannot see it.** With the runtime status regex made case-insensitive (P3), all 43 builder cells stay green. If that shipped, `?status=ACTIVE` would reach SQL as `ANY(['ACTIVE'])` and answer 200 [], silently: the exact class this PR exists to refuse. Today it is a 400 (measured). Fix shape: add `ACTIVE`, `Active`, `General` and `active ` to R5/R6 and to the S2 corpus. **Evidence: MEASURED AT RUNTIME (plant P3).**
3. **Note: control characters in `proposerId` pass the schema and reach SQL.** NUL, SOH, DEL and U+200B (zero-width space) are not whitespace to `/\S/`, so each gives 200 with the query run. `rejectNulBytes()` (KS-471/472) inspects `req.body` only, never `req.query`. A NUL makes real Postgres reject the parameter. `dbGetAllProposals` catches every error into `[]`, so the caller gets 200 [] plus an error log line (the builder's own "Found, not fixed" note covers the swallow). My mock throws on NUL to imitate that, and the route answered 200 []. Fix shape, if wanted: `regex(/^[^\x00-\x1f\x7f]*\S/)` or an id-charset rule. **Evidence: MEASURED AT RUNTIME (repo level, mocked DB). The real-PG error is READ ONLY.**
4. **Note: the JS SDK's published vocabulary now earns 400s.** `sdk/javascript/src/modules/governance.ts` types `status: 'rejected'` and the categories `platform_fees`, `feature_addition` and `treasury`, none of which governance has. They were a silent 200 []. They are now 400 (measured for `rejected`; the categories fall under the measured unknown-category refusal). No in-repo code consumes the SDK; only `api-gateway/src/docs/developer-portal.html` mentions it. The SDK types predate this PR and are wrong either way, so the 400 is the more honest answer. An external SDK user would see a new error, though. **Evidence: READ ONLY for consumers; MEASURED for the 400.**
5. **Note: the spec's `pattern: \S` has dialect drift.** OpenAPI 3.1 patterns are ECMA-262, and the runtime is JS. Python's `re` (schemathesis / hypothesis-jsonschema) disagrees with JS on 6 code points: U+FEFF (Python valid, JS 400), and U+001C-001F and U+0085 (Python invalid, JS 200). If the sweep fuzzes this parameter it may report a positive/negative mismatch on those code points. That would be an instrument artefact, not a product defect. **Evidence: MEASURED (dialect comparison in python3 and node). No sweep run.**
6. **Note: `proposerId` has no length bound.** 10 KB and 15 KB values give 200 with the query run. 20 KB gets Node's 431 (header limit) before Express runs. This is harmless today. **Evidence: MEASURED AT RUNTIME (repo level).**

Context, not a finding: at develop, the 4 array-`status` shapes leave the request unanswered. Governance's `index.ts` registers no `unhandledRejection` handler (the shared `createUnhandledRejectionHandler` is not used there). So on a real Node 24 process this was probably a crash, not just a hang. This PR removes that path. **READ ONLY for the crash; the no-response is MEASURED.**
