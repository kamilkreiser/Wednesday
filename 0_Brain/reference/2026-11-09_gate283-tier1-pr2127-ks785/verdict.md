## BLUF
The fix does what it says on the path the seat built a harness for, and the evidence reproduces (39/39, the 3 predicted reds on develop, tampers, comment-only, overlap with 2052 clean in both orders). **But it breaks the default start.** The canonical template `Blockchain/Dev/env.example` (the one `bootstrap-env.sh` copies, KS-1081) cannot be sourced by bash: line 236 `ISSUER_NAME=Secuura Platform` runs `Platform` as a command. With the new `source` under `set -e`, `start-environment.sh` on a FRESH clone runs bootstrap, prints a green credential check, then dies at line 144 with `.env: line 236: Platform: command not found`, rc 127, before `docker compose up`. On develop the same run reaches compose. The seat's suite stubs `bootstrap-env.sh` and only feeds two-line .env fixtures, so it cannot see this. **Needs a ruling (Wednesday, and Kam if he wants it):** the obvious repairs leave the ruled scope. Either quote env.example lines 236 and 404 (a third file, and existing clones keep the bad line), or source in a way that does not abort, or go back to shape (b). Kam's KS-762 ruling ("a hard requirement stops every existing local stack") is about the same non-blocking-start property this change breaks.
