===== TICKET =====
KS-1731 — vc-issuer GET /api/credentials pages on ORDER BY created_at DESC alone - rows sharing (or lacking) a created_at repeat or are skipped across pages (gate: 24 of 180 page walks; an id tie-breaker takes it to 0) [In Progress]

## BLUF

`GET /api/credentials` **pages on** `ORDER BY created_at DESC` **alone.** Rows that share a `created_at`, or have none, can be **repeated or skipped** between pages. The tier-1 gate on PR #1691 measured this, rated it **Minor** and found no leak. Only the caller's **own** rows are affected: no foreign row was ever served, and `total` stayed correct. Adding the row id as a tie-breaker took it to 0. **The sort predates PR #1691** — #1691 kept it, and did not introduce it.

## Where (develop `c2505d5c6fe0`)

* `services/vc-issuer/src/repositories/credentialRepo.ts:365` — `ORDER BY created_at DESC LIMIT $n OFFSET $m` in `selectList()`. Both `listReadable()` (what `GET /api/credentials` calls since #1691) and the unbound `list()` use it.
* For contrast, the by-hash read at `:286` already orders `created_at DESC, id DESC`.

## When it came in

`git log -S 'ORDER BY created_at DESC LIMIT' -- services/vc-issuer/src/repositories/credentialRepo.ts` gives one commit: `e50dbde98` (2026-02-18, "Identity verification & SSI integration…"). It is already present on develop `1ae6f17d19a8` at `:227`, before #1691.

## What was measured (by the gate, relayed; not re-measured by the filer)

On PGlite (PostgreSQL 17.5): **24 of 180 page walks** repeated or skipped rows that shared a timestamp or had none. Adding `id` as a tie-breaker took it to **0**. All affected rows were the caller's own. The verdict is on the coordinator's side at `0_Brain/reference/2026-10-26_gate-pr1691-ks1683/verdict.md`.

## Facts that bound it

* `created_at` is `TIMESTAMPTZ DEFAULT NOW()`, nullable (`migrations/001_initial-schema.sql:748`, no `NOT NULL`).
* vc-issuer's own `store()` INSERT (`credentialRepo.ts:84`) does not name `created_at`, so rows it writes get `NOW()`. **A NULL** `created_at` **can only come from another writer.** A shared timestamp is reachable for rows written in the same transaction.
* The in-memory fallback pages a `Map` in insertion order. That order is deterministic, so this ticket is about the DB path.
* Two other `ORDER BY created_at DESC` reads in vc-issuer are boot loads, not paged: `credentialRepo.ts:423` (`loadFromDb`) and `routes/presentations.ts:173`. They are outside this defect.
* `vc_credentials_store` held 0 rows on demo and 0 on kintsugi on 2026-10-20 (from KS-1683's body).

## Fix shape (not chosen here)

`ORDER BY created_at DESC, id DESC`, matching by-hash at `:286`. `id` is the primary key, so that is a total order. Whether NULLs should sort last (`NULLS LAST`; PostgreSQL puts NULLs first under `DESC`) is a choice for whoever fixes it.

## Related, NOT duplicates

* **KS-1544** — `platform_audit_log` paged without a tie-break (`ORDER BY created_at DESC` only). Same class, different table and service.
* **KS-1683** / PR #1691 — the change whose gate found this.

211: // KS-1683: the list and by-hash reads, bound by the KS-1116 rule
212: // ---------------------------------------------------------------------------

214: /**
215:  * The KS-1116 rule (ownership.ts `mayRead`) as a SQL condition on the owner
216:  * columns, for the two reads that return MANY rows or pick ONE of several. There,
217:  * deciding on each record afterwards cannot keep `total`, the page boundaries or
218:  * "the first match" right, so the database has to apply the rule too.
219:  *
220:  * Always parameters $1-$3, in this order:
221:  *   $1  the caller's userId — never null: a caller without one may read nothing,
222:  *       and no query is run for it (readerParams)
223:  *   $2  the caller's tenantId, or null when the token carries none
224:  *   $3  may the caller read an OWNER-LESS row of its own tenant (ruling (a))
225:  *
226:  * Row for row it is mayRead:
227:  *   - `NULLIF(col, '')` is claim(): '' reads as absent, as ownerFromRow reads it.
228:  *   - An owned row: the same userId and the same tenant. IS NOT DISTINCT FROM, so
229:  *     a tenant-less caller matches a tenant-less row — mayRead's
230:  *     `owner.tenantId === claim(user?.tenantId)` with null === null.
231:  *   - An owner-less row: ruling (a) can only ever admit a row whose tenant IS the
232:  *     caller's tenant, so ownerlessRowReadable(req, <the caller's tenant>) decides
233:  *     this branch for every row it could admit, and `= $2` refuses the rest.
234:  *
235:  * mayRead still runs on every row this returns, on both paths — a fail-closed
236:  * backstop. If the SQL and the rule ever disagreed, the row is dropped and never
237:  * served; `total`, counted by the SQL, would then over-claim. It never under-protects.
238:  */
239: const READABLE_BY_CALLER =
240:   `((NULLIF(created_by_user_id, '') = $1::text` +
241:   ` AND NULLIF(created_by_tenant_id, '') IS NOT DISTINCT FROM $2::text)` +
242:   ` OR ($3::boolean AND NULLIF(created_by_user_id, '') IS NULL` +
243:   ` AND NULLIF(created_by_tenant_id, '') = $2::text))`;
244: 
245: /** READABLE_BY_CALLER's $1-$3 for this caller, or null when it may read nothing at all. */
246: function readerParams(reader: Request): [string, string | null, boolean] | null {
247:   // ownerOf reads the caller's claims exactly as mayRead does (claim()).
248:   const { userId, tenantId } = ownerOf(reader);
249:   if (userId === null) return null;
250:   return [userId, tenantId, tenantId !== null && ownerlessRowReadable(reader, tenantId)];
251: }
252:

254:  * GET /api/credentials: the credentials the caller may read (ownership.ts
255:  * `mayRead`), filtered and paginated AFTER the owner bound — so `total` and the
256:  * page are the caller's own, on the DB path and on the in-memory fallback alike.
257:  */

260:   options?: ListOptions,

262:   return selectList(options, reader);

265: /**
266:  * GET /api/credentials/by-hash/:hash: the newest credential with this document
267:  * hash that the caller may read — not the first match. Several callers can hold
268:  * credentials over the same document, and an unbound `LIMIT 1` would let any of
269:  * theirs stand in for (or hide) the caller's own.
270:  */
271: export async function getReadableByHash(reader: Request, hash: string): Promise<SecuuraCredential | undefined> {
272:   const params = readerParams(reader);
273:   if (params === null) return undefined;
274: 
275:   if (isDbAvailable()) {
276:     try {
277:       await ensureTable();
278:       const result = await query<{
279:         credential: SecuuraCredential;
280:         created_by_user_id: string | null;
281:         created_by_tenant_id: string | null;
282:       }>(
283:         `SELECT credential, created_by_user_id, created_by_tenant_id FROM vc_credentials_store
284:          WHERE ${READABLE_BY_CALLER}
285:            AND credential->'credentialSubject'->>'documentHash' = $4
286:          ORDER BY created_at DESC, id DESC
287:          LIMIT 1`,
288:         [...params, hash],
289:       );
290:       if (result.rows.length > 0) {
291:         const row = result.rows[0];
292:         if (mayRead(reader, ownerFromRow(row))) return row.credential;
293:         logger.warn('KS-1683: the by-hash owner filter returned a row mayRead refuses — not served');
294:         return undefined;
295:       }
296:     } catch (err: any) {
297:       logger.warn('DB hash lookup failed — falling back to memory', { error: err?.message });
298:     }
299:   }
300: 
301:   for (const [id, value] of memoryStore.entries()) {
302:     if (value.credentialSubject.documentHash === hash && mayRead(reader, memoryOwners.get(id) ?? OWNERLESS)) {
303:       return value;
304:     }
305:   }
306:   return undefined;
307: }

309: /** The list, bound by `reader` when one is given (listReadable) and unbound when null (list). */
310: async function selectList(
311:   options: ListOptions | undefined,
312:   reader: Request | null,
313: ): Promise<{ credentials: SecuuraCredential[]; total: number }> {
314:   const limit = options?.limit ?? 100;
315:   const offset = options?.offset ?? 0;
316: 
317:   let ownerParams: [string, string | null, boolean] | null = null;
318:   if (reader) {
319:     ownerParams = readerParams(reader);
320:     if (ownerParams === null) return { credentials: [], total: 0 };
321:   }
322: 
323:   if (isDbAvailable()) {
324:     try {
325:       await ensureTable();
326: 
327:       const conditions: string[] = [];
328:       const params: unknown[] = [];
329:       let idx = 1;
330: 
331:       // KS-1683: the owner bound is a WHERE condition, so the COUNT below and the
332:       // page share it — `total` and `hasMore` are counted after the filter.
333:       if (ownerParams) {
334:         conditions.push(READABLE_BY_CALLER);
335:         params.push(...ownerParams);
336:         idx = 4;
337:       }
338: 
339:       if (options?.issuer) {
340:         conditions.push(`credential->'issuer'->>'id' = $${idx++}`);
341:         params.push(options.issuer);
342:       }
343:       if (options?.documentType) {
344:         conditions.push(`credential->'type' @> $${idx++}::jsonb`);
345:         params.push(JSON.stringify([options.documentType]));
346:       }
347: 
348:       const where = conditions.length > 0 ? `WHERE ${conditions.join(' AND ')}` : '';
349: 
350:       const countResult = await query<{ count: string }>(
351:         `SELECT COUNT(*) AS count FROM vc_credentials_store ${where}`,
352:         params,
353:       );
354:       const total = parseInt(countResult.rows[0].count, 10);
355: 
356:       params.push(limit);
357:       params.push(offset);
358:       const columns = reader ? 'credential, created_by_user_id, created_by_tenant_id' : 'credential';
359:       const dataResult = await query<{
360:         credential: SecuuraCredential;
361:         created_by_user_id?: string | null;
362:         created_by_tenant_id?: string | null;
363:       }>(
364:         `SELECT ${columns} FROM vc_credentials_store ${where}
365:          ORDER BY created_at DESC, id DESC LIMIT $${idx++} OFFSET $${idx++}`,
366:         params,
367:       );
368: 
369:       let rows = dataResult.rows;
370:       if (reader) {
371:         // The fail-closed backstop (see READABLE_BY_CALLER).
372:         const readable = rows.filter((r) => mayRead(reader, ownerFromRow(r)));
373:         if (readable.length !== rows.length) {
374:           logger.warn('KS-1683: the list owner filter returned rows mayRead refuses — not served', {
375:             dropped: rows.length - readable.length,
376:           });
377:         }
378:         rows = readable;
379:       }
380: 
381:       return {
382:         credentials: rows.map((r) => r.credential),
383:         total,
384:       };
385:     } catch (err: any) {
386:       logger.warn('DB list failed — falling back to memory', { error: err?.message });
387:     }
388:   }
389: 
390:   // Memory fallback — bound by the same rule, on the record (KS-1683)
391:   let credentials = Array.from(memoryStore.entries())
392:     .filter(([id]) => !reader || mayRead(reader, memoryOwners.get(id) ?? OWNERLESS))
393:     .map(([, credential]) => credential);
394: 
395:   if (options?.issuer) {
396:     credentials = credentials.filter((c) => {
397:       const issuerId = typeof c.issuer === 'string' ? c.issuer : c.issuer.id;
398:       return issuerId === options.issuer;
399:     });
400:   }
401:   if (options?.documentType) {
402:     credentials = credentials.filter((c) => c.type.includes(options.documentType as string));
403:   }
404: 
405:   const total = credentials.length;
406:   const paged = credentials.slice(offset, offset + limit);
407:   return { credentials: paged, total };
408: }
