## What is wrong (one paragraph)

In `index.ts` the catch blocks of GET /api/tenants/:id (line 424), PATCH /api/tenants/:id/status (line 482) and GET /api/audit-log (line 651) each begin `const message = err instanceof Error ? err.message : String(err);`, then `console.error('[provisioning] <route> failed:', message);`, then answer the CONSTANT 500 body `{ success: false, error: { code: 'INTERNAL_ERROR', message: 'An unexpected error occurred' } }`; the message is only logged (KS-1410 made it never reach the response). If the route's database call rejects with a revoked Proxy, `err instanceof Error` itself throws a TypeError inside the catch block; if it rejects with an Error whose `message` getter throws, `err.message` throws. Either way the catch throws before anything is logged and before the 500 is sent; the async handler rejects, Express 4 does not catch that, and the request gets no response (the gateway's upstream timeout answers 504). The fix replaces the ONE `const message` line of each catch with `let message: string;` plus a `try` that runs the SAME expression and a `catch` that sets the constant `'unreadable thrown value'`; every later line (the `console.error` line, the 500) is untouched, and an ordinary Error still logs its own message. This is the inline guard already merged in other services (analytics ExportService.dbSaveExport, nft-certificate minting.service.ts, billing PR 1906); this service has no helper and none is added.
