===== TICKET =====
KS-1701 — Four originate sites hand-write the platform-admin role set and all four omit SUPER_ADMIN (documents.ts:1076 and :299, certifications.ts:959 and :123) - the same omission caused a measured regression under the KS-1695 build [Backlog]

## BLUF

**Four sites in** `services/originate` **answer "is this caller a platform administrator?" with the same hand-written three-spelling literal, and all four omit** `SUPER_ADMIN`**.** A platform administrator whose token carries that casing is treated as an ordinary user by every one of them. This is not hypothetical: the identical omission, copied into a new access check, produced a **measured regression** on `GET /api/certifications/:id` during [KS-1695](https://linear.app/secuura/issue/KS-1695) — a real platform administrator went from 200 to 404 — which its review gate caught and which was fixed by calling `isPlatformRole` instead.

Filed at Wednesday's instruction after the KS-1695 gap-1 merge. **Facts only; no remedy proposed.**

## The four sites (non-test, `git grep` at develop `88933d5c7ebb`)

| file:line | what it gates | text |
| -- | -- | -- |
| `routes/documents.ts:1076` | the `GET /api/documents/:id` ownership cloak | `userRole === 'system_admin' \|\| userRole === 'SYSTEM_ADMIN' \|\| userRole === 'super_admin'` |
| `routes/documents.ts:299` | the documents **list** scoping | identical text |
| `routes/certifications.ts:959` | the certifications **list** scoping + in-memory filter | identical text |
| `routes/certifications.ts:123` | `callerMayCertifyDocument` — the KS 1538 **write**-side access check | `role === 'system_admin' \|\| role === 'SYSTEM_ADMIN' \|\| role === 'super_admin'` |

The repo's own predicate, `isPlatformRole` (`packages/shared/src/security/keyRevokePolicy.ts:140`, exported `index.ts:229`), is `PLATFORM_ROLES.has(String(role||'').toUpperCase())` over `{SYSTEM_ADMIN, SUPER_ADMIN}` — it upper-cases, so all four casings pass. **originate already uses it**, at `routes/adminConfig.ts:26`/`:956` and (since the KS-1695 merge) in the certification by-id read helper. So this is not a missing convention; it is four sites that predate or bypass it.

## A fifth site, different in kind, and the one that includes `platform_admin`

```
routes/adminConfig.ts:60   const SUPER_ADMIN_ROLES = ['super_admin','SUPER_ADMIN','SYSTEM_ADMIN','platform_admin'];
routes/adminConfig.ts:78   if (u?.role && SUPER_ADMIN_ROLES.includes(u.role)) {     // inside resolveTenantId
```

**Used, not dead.** `resolveTenantId` gives a caller in that set cross-tenant tenant resolution (`req.tenantId`, then `?organizationId`, then the user's own org), where a tenant-bound admin gets only its own organisation. So `platform_admin` is a super-admin role **inside originate** for tenant resolution, while being unknown to the four sites above and refused by the certification by-id read. That internal split is the sharpest form of this problem and was not previously recorded.

## NOT measured

* **No live token was decoded,** and no request was issued against any of the five sites. Every row is a source read at one sha. The KS-1695 regression is the only part of this that was executed, and it was executed over the real router with mocked repositories, not through a gateway or a real database.
* **Whether any real principal carries** `SUPER_ADMIN` **or** `platform_admin` is unestablished. Relevant: no in-repo path appears to *mint* upper-case `SUPER_ADMIN` (every occurrence in `services/auth/src` is a comparison list), while `platform_admin` is mintable — auth builds the token with `role: platformAdmin.role` from the `platform_admins` row, whose column permits that value (`docker/init-platform/01-platform-schema.sql`) though it defaults to `super_admin` and the table is created empty on purpose.
* **The consequence of each omission was not traced per site.** Only `certifications.ts` by-id was exercised. What a `SUPER_ADMIN` administrator currently cannot see on the documents cloak, either list, or the certify write path, is unquantified.
* Whether `adminConfig.ts:60`'s breadth is intended, or is itself the defect, is not assessed here.
