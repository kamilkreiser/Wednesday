===== TICKET =====
KS-1591 — Security (nit, pre-existing): isPlatformRole's toUpperCase admits a dotless-i, a long-s and an ARRAY role as SUPER_ADMIN [Backlog]

## BLUF

`String(role).toUpperCase()` **is not an identity test.** `packages/shared/src/security/keyRevokePolicy.ts:139-140` (`isPlatformRole`) and `requireKeyAdmin`'s own `toUpperCase` admit three spellings as `SUPER_ADMIN`:

* `super_admın` — **dotless i** (U+0131), which upper-cases to `I`;
* `ſuper_admin` — **long s** (U+017F), which upper-cases to `S`;
* a role **array** `["SUPER_ADMIN"]`, because `String(["SUPER_ADMIN"])` is `"SUPER_ADMIN"`.

**Measured by the pull request 1539 gate** (verdict sha256/16 `91e8da4021c40661`, finding **n4**): `PUT /api/keys/admin-scopes/:userId` answered **200** and the mint answered **201** for all three.

## Reachability is NOT established, and that is the first thing to settle

This needs a token the auth service **signs** with such a role. **The gate did not test whether any issuer, user-management path or seed can store or sign one**, and nor have I. So the severity here is a nit until someone measures that; if any path can, it is a privilege escalation and should be re-rated immediately.

## Recommendation

Not built. Compare against an exact ASCII-folded string and **reject a non-string role** outright, in the one shared definition so every caller inherits it.

## Where

* `packages/shared/src/security/keyRevokePolicy.ts:139-140` — `isPlatformRole`.
* `services/security/src/index.ts` — `requireKeyAdmin`'s `toUpperCase`.
* Worth a sweep for other `toUpperCase()` role comparisons rather than fixing only these two.

## Dedupe

Linear's `searchIssues` is **fuzzy** — it returned 12 hits for a deliberately nonsensical control term, so it is not a membership test. Deduped with a literal `containsIgnoreCase` filter over title and description, controlled both ways (0 for the nonsense term, non-zero for a real one): `toUpperCase` **0 hits,** `dotless` **0,** `ASCII-folded` **0.** Related but NOT the same: KS-1536 (one role vocabulary, seven divergent lists) is about which role strings each list contains, not about the folding admitting lookalikes.

342: /**
343:  * KS-1584 — may this register-connector caller act on this organisation?
344:  *
345:  * Extracted as a pure function rather than left inline in the gateway route for the reason the rest
346:  * of this file exists: it is an authorisation rule on a path that ends in an irreversible erasure, and
347:  * inline in a 200-line handler it could only ever be pinned by booting the whole app. Here it has a
348:  * truth table.
349:  *
350:  * The rule: a provisioning key that carries an organisation is BOUNDED to it, so at register-connector
351:  * it may do exactly one thing — re-register its OWN organisation. It may not create a new organisation
352:  * (a new one is outside every bound by construction) and it may not act on another organisation, which
353:  * is also what stops it renaming one.
354:  *
355:  * ONE refusal for every case, deliberately. Answering differently for "would be new" and "exists but is
356:  * not yours" would let a bounded key probe which externalRefs exist in its tenant — the same enumeration
357:  * the cross-tenant guardrail refuses. The only outcome a bounded key can tell apart is "my own
358:  * organisation", which it already knows.
359:  *
360:  * An ORG-LESS provisioning key is platform-minted (Platform S's per-instance key) and is UNBOUNDED: it
361:  * registers and creates as before.
362:  *
363:  * @param args.byConnector - true when a connector key authorised the call, not a platform admin.
364:  * @param args.callerScopes - the key's scopes; wildcards count, via `isProvisioningCapable`.
365:  * @param args.callerOrganizationId - the key row's own organisation, or null/absent when org-less.
366:  * @param args.existingOrganizationId - the organisation the externalRef resolved to, or null for none.
367:  * @example decideProvisionerRegistration({byConnector:true,callerScopes:['organizations:register'],callerOrganizationId:'a',existingOrganizationId:'a'}) // allow
368:  * @example decideProvisionerRegistration({byConnector:true,callerScopes:['*'],callerOrganizationId:'a',existingOrganizationId:null}) // deny (would create)
369:  */
370: export function decideProvisionerRegistration(args: {
371:   byConnector: boolean;
372:   callerScopes?: readonly (string | null | undefined)[];
373:   callerOrganizationId?: string | null;
374:   existingOrganizationId?: string | null;
375: }): { allow: true; reason: string } | { allow: false; status: 403; reason: string } {
376:   const ownOrg = normaliseOrgId(args.callerOrganizationId ?? null);
377:   const bounded = args.byConnector && isProvisioningCapable(args.callerScopes) && ownOrg !== null;
378:   if (!bounded) {
379:     return { allow: true, reason: 'not a bounded provisioning key' };
380:   }
381:   const hitOrg = normaliseOrgId(args.existingOrganizationId ?? null);
382:   if (hitOrg === null || hitOrg !== ownOrg) {
383:     return { allow: false, status: 403, reason: 'bounded provisioning key may only re-register its own organisation' };
384:   }
385:   return { allow: true, reason: 'own organisation' };
386: }
