## What you'd be signing

One model for every non-human caller (S connector, MCP AI agents, future OAuth
apps) doing document ops on Platform K:

1. **Agents are connectors, never humans** — machine callers get the connector
   role via `sk_` keys; no human JWTs, no seeded personas, no separate "agent
   role".
2. **Authority = the key's scopes, deny-by-default** — anything without a
   scope in the 32-literal vocabulary is unreachable by agents, by
   construction. Keys are org-bound, minted least-privilege.
3. **Acting for a person requires `onBehalfOf` provenance** — attribution not
   identity; cross-org attribution 403s; stored encrypted off-chain,
   erasure-compatible; autonomous ops honestly attribute to the connector.
4. **Consent chains through the Organisation** that owns the key.
5. **Provenance never reaches the chain** (whitelisted anchor payloads,
   pinned by a test).
6. **Enforcement is server-side and layered** (gateway scopes → service RBAC →
   ownership/tenant checks → 10-min JWTs + instant key revocation).
7. **Every agent op is observable** (metering + provenance rows).

Every enforcement claim carries a file:line reference; the agent hand-verified
the sharpest gap (G-2) against source. The model matches the KS-480 contract
you confirmed 07-29.

## What is genuinely still open (the real decision surface)

The matrix marks share / revoke / transfer-custody / anchor / lifecycle as
**"for sign-off"** — this is contract §6's open point (G-1): which operations
beyond create must carry `onBehalfOf`. Known gaps, none blocking: G-2 MCP
register tool doesn't pass onBehalfOf yet (wired after G-1); G-3 scope-
vocabulary drift already tracked in KS-540; G-4 seventeen services rely on
gateway-level enforcement — fine under this model, flagged for new routes.

## Recommendation

**Sign off the rules as written.** For the G-1 open cells: require `onBehalfOf`
on **share, revoke, transfer-custody** (person-consequential — who did this to
whose document matters); let **anchor + lifecycle** attribute to the connector
(mechanical follow-ons of an already-attributed document). That's the smallest
set that keeps R7's "whose authority" answerable where it counts.

Ruling options: (a) sign off + adopt the G-1 recommendation · (b) sign off the
rules, leave G-1 for Stuart/Peter to propose · (c) request changes (say which).
