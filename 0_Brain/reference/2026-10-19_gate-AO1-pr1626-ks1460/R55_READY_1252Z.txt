## CAUSE

`POST /register`, when it claims an INVITED stub, calls `userRepo.updateUser(...)` and **discards** the result.
`updateUser` returns `null` on a 0-row UPDATE (fail-closed RLS with a mismatched tenant produces exactly that),
so the caller still got 201, a session, a verification token and a mail over a row still INVITED. The fix is
`updateUserOrThrow`, which answers 503 when the update is unconfirmed.

**Static, not measured live:** a normal claim does NOT become a 503. `updateUser` resolves the stub's own tenant
when there is no request context (the QA F-1 fix), so the UPDATE matches one row.
