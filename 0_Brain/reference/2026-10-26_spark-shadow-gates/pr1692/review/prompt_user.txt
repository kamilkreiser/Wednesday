## BLUF

Three findings from the **PR #1528 narrow Sonnet gate** (verdict sha256/16 `244c98cbd4852491`,

false-reds on a host whose `jq` lives outside `/usr/bin`.

## M1 — a fourth suite has the F-4 defect, and nothing stops a fifth

`Blockchain/Dev/scripts/__tests__/tenant_isolation_stderr_own_file.test.sh` checks `jq` on the
**outer** PATH at **:28** and then runs the subject under `PATH="$root/bin:/usr/bin:/bin"` at
**:64** — byte-identical in shape to the three suites #1528 fixed. The gate reproduced the
consequence on a simulated homebrew-only host (`sandbox-exec`): **4 passed, 1 failed**, a false red
blaming the code for the host's layout.

**Confirmed independently** before filing, by a census over every `*.test.sh` in that directory
for suites carrying **both** a `command -v jq` check and a `$root/bin` private PATH:

```
container_trivy_exit_code_env_keeps_findings.test.sh   jq=2 privPATH=1 jqlink=1  (fixed by #1528)
container_trivy_failed_scan_is_loud.test.sh            jq=2 privPATH=1 jqlink=1  (fixed by #1528)
container_trivy_image_filter.test.sh                   jq=2 privPATH=1 jqlink=1  (fixed by #1528)
tenant_isolation_stderr_own_file.test.sh               jq=1 privPATH=1 jqlink=0  (MISSED)
```

**Why #1528 missed it:** that PR's census was scoped to `*trivy*` filenames, because the ticket
names a trivy suite. The defect is not trivy-shaped — it is "any suite that preflights a binary on
one PATH and runs the subject on another". A filename is not a scope.

*Fix:* the same shape as the other three (resolve `JQ_BIN` once, `ln -sf` it into the fixture's stub
dir), **plus a census cell** that enumerates suites with both features and asserts each links `jq`,
so a fifth copy reds instead of being found by the next gate.

## M2 — the KS-1347 probe is brittle to a harmless respelling

`ks1347_proxy_out_dir_spaced_checkout.test.sh` reads the subject's `node:` imports with
`grep -E "^import .* from 'node:[a-z]+';$"`. A harmless respelling in `server.ts` — double quotes,
or `from 'node:url'` written differently — makes the inherited import set incomplete and **reds 4**
**cells while** `server.ts` **still works perfectly**. That is the inverse of the u4 defect the inheritance
was introduced to fix: too loose let the probe supply what the subject lacked; too strict reds on a
subject that is fine.

*Fix shape:* tolerate both quote styles and trailing-semicolon variation, or parse the import list
rather than matching a line shape. Keep the control that the inherited set is non-empty and names
the module the expression needs — that control is what makes the looser match safe.
