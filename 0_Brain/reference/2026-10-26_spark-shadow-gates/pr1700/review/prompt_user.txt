KS-1649 — developer-portal.html:564 says every API key defaults to 1,000 req/hour; Platform S connector keys mint at 3,000 once #1613 lands [In Progress]

**BLUF: the developer portal states one default rate limit for every API key — "1,000 req/hour" — and once #1613 (KS-1195) lands that is no longer true for Platform S connector keys, which mint at 3,000/hour. A one-line doc change, to make AFTER #1613 merges, not before.**

## Where

`Blockchain/Dev/services/api-gateway/src/docs/developer-portal.html:564`, at develop `722e07f19cee`:

```
<tr><td>Per API key / OAuth app</td><td>1,000 req/hour</td><td><code>X-RateLimit-Limit</code>, …</td></tr>
```

## Why it is not simply wrong

1,000/hour **stays true** for every key minted without an explicit `rateLimit` — the security service's own schema default (`services/security/src/index.ts:666`, `.default(1000)`). What changes is one class of key: those `POST /api/platform/organizations/register-connector` mints for Platform S, which take Kam's ruled 3,000/hour (KS-1195, card `secuura-ks1195-s-key-ceiling-1009` = a), tunable by `PLATFORM_S_CONNECTOR_RATE_LIMIT`.

So the fix is a qualification, not a new number:

* the per-key default stays **1,000 req/hour**;
* add that **Platform S connector keys are minted at 3,000 req/hour**; and
* point at `X-RateLimit-Limit`, which already reports the actual ceiling on every response — the page lists the header but does not say it is the authoritative value.

## Timing

Only after #1613 merges. Before then the page is correct, and changing it first would document a ceiling develop does not have. If it lands before a deploy, the text should not imply Kintsugi or demo already run it.
