Opus gate verdict `2026-10-12_gate-pr1499/verdict.md`, sha256/16 `9a9bd1494ca72d12`, GO WITH NOTE at head `8802326a9a54`, 0 Major, 2 Minor. This ticket is Minor 1; Minor 2 (the real push cost) is corrected in the squash body and needs no ticket. Quoted from the gate's reply, not re-measured by me.

## The defect

`Blockchain/Dev/scripts/__tests__/preflight_test_types_ratchet_leg.test.sh` runs the REAL checker (`check.cjs`) over throwaway fixtures, which needs the workspace install (`typescript`). In a tree with no install the suite goes RED, **13 passed, 9 failed**. The leg script itself already handles that tree: it prints `SKIP (advisory)` and exits 0 (leg 1 refuses the push, so the skip lets nothing through), and `run_delegated` counts the leg as skipped. The suite does not mirror it.

## Why it does not bite today, and when it will

Push outcomes do not change: the in-hook run happens in a tree that leg 1 has already refused for the same reason. It will bite a tree that runs the shell suites WITHOUT a push, which is what the dormant CI workflows would do if Actions were ever re-enabled: nine red cells that point at the checker when the cause is a missing install.

## Closing step

At the top of the suite, run the same precondition the leg uses (`bash scripts/preflight/deps-present.sh`, which honours `DEPS_PRESENT_ROOT`). If it fails, print a line the runner recognises, `SKIP — workspace install absent (leg 1 refuses this tree)`, and exit 0. `run-shell-suites.sh` scores that line as a counted skip, not a pass and not a failure (`run-shell-suites.sh`, the `SKIP[[:space:]]*[-—]` branch, KS-1127; ruled 2026-09-13). Two cells to keep it honest: with `DEPS_PRESENT_ROOT` pointed at an empty directory the suite prints the SKIP line and exits 0 without running a single checker cell; and with the real install the suite is unchanged (23/23). A tamper that deletes the precondition must turn the first cell red.

Related: KS-1487 (the leg), KS-1000 (the ratchet), KS-1127 (the runner's skip convention).
