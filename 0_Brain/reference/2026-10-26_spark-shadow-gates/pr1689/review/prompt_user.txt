===== TICKET =====
KS-1716 — systemTest format gate drops packages on large pushes: `grep -q` + `pipefail` turns EPIPE into "unchanged" [In Progress]

**Ask:** make `systemTest/scripts/check-package-format.sh` select packages without a pipe whose reader can exit early, so a large pushed range cannot make the format gate skip a package.

**What goes wrong:** the selection loop (line \~730) runs `printf '%s\n' "$changed_paths" | grep -q "^systemTest/${p}/"` under `set -uo pipefail`. `grep -q` exits at its first match; when the path list is larger than the pipe buffer (64 KiB on macOS) `printf` is still writing, gets EPIPE, and `pipefail` turns the pipeline's status into failure. The `if` reads that as "no changed file under this package", so the package is not checked, and nothing says so: the gate still prints `0 skipped, 0 failed`. The only trace is one stderr line, `check-package-format.sh: line 730: printf: write error: Broken pipe`.

**Measured 2026-10-23 on the push of #989 (head** `eb0f470b685100af865e6c0cb0474a4400c44161`**):**

* the pushed range's path list was **1,736 paths / 116,058 bytes**;
* five packages have a `format:check` script and all five changed in the range (`akto` 196 files, `api-explorer` 33, `oxlint` 48, `performance` 111, `playwright` 68);
* the hook printed `[format-gate] 4 package(s) checked, 0 skipped, 0 failed` and named api-explorer, oxlint, performance and playwright. `akto` **was never judged.**
* **Reproduction** (the selection loop alone, same shell options, the real list; script `5_Project_History/2026-10-23_seatG-18th/evidence/format_gate_select_sim.sh` in the project history): the original form selected `api-explorer oxlint performance playwright` in **3 of 3** runs; the read-to-EOF form (`grep "^systemTest/${p}/" > /dev/null`) selected all five in **3 of 3**. **Control:** with the small list (the 5 files of the PR itself) the original form selects `performance` and loses nothing, so the loss needs a list over the buffer.
* `akto` is the package lost because it sorts first among the five and so matches early, leaving the most unread input when `grep -q` exits.

**Recurrence, counted over the nine push logs the previous seat kept on 2026-10-23:** five carry the `Broken pipe` line (#809, #920, #923, #927, #995) and **all five** report `4 package(s) checked, 0 skipped, 0 failed`. The control is in the same set: the push of #1253 has no `Broken pipe` line and reports `5 package(s) checked`. Three logs (the two #809 follow-ups and one more) ran no format gate at all. I did not measure the size of #1253's list, so I do not know why it escaped; the size of the pushed range decides, and merge-in pushes (which carry develop's whole delta) are the likely exposed shape, though not every one of them was hit.

**Read and not duplicates:** KS-998 (the same gate, In Review) matches this on "format gate", on `grep -qx` (a path read as a regex, an unrelated polish item) and on `akto` (an instance-6 red in akto's tree); none of its items is an early-exiting reader. Its comment records the gate refusing only when `checked == 0 && skipped > 0`, and a package lost to this bug is counted as neither checked nor skipped, which is why the gate still reports `0 skipped` (read from that comment, not re-read in the script).

**Why it matters:** a format regression in `systemTest/akto` passes the pre-push hook. A guard that skips a package silently, on exactly the pushes that bring in the most change, is worse than no guard because the "0 skipped" line reads as full coverage.

**Precedent, and why this is not a duplicate:** PS-1254 (Platform S board, Done 2026-10-15; platform-s pull request 1021) fixed the same mechanism in platform-s's own `.githooks/pre-push`: `printf | grep -q` under `pipefail` skipped a test leg once the changed list passed the pipe buffer, and it was fixed with a pure-bash `case` match on the newline-joined list (no subprocess, nothing to SIGPIPE), moved into a sourced function and covered by contract tests (a list of tens of thousands of lines selects every leg whether the matching line comes first or last; no `| grep -q` pipeline may remain). That repository's fix does not reach this script. Platform K's own `.githooks/pre-push` was checked and has **0** pipes into `grep -q` and no `set -` options, so it is not exposed; this script is. KS-1605 (open) carries other follow-ups for the same script (npmrc, stale tracking refs, two surviving mutants) and none of them is this defect.

**Fix shape, a PROPOSAL (not applied; the script was not changed):** replace the early-exiting reader with one that reads to EOF, e.g. `grep "^systemTest/${p}/" > /dev/null` (the form measured above), or, as PS-1254 did, a pure-bash `case` match on the list (no writer process at all). Add a cell with a path list over 64 KiB that must still select every package which changed, and have the gate fail (not skip) when a package that changed is absent from the checked list.

**Related shape, counted and NOT assessed:** `printf`/`echo ... | grep -q` appears 170 times in shell scripts and hooks, 29 of them outside `__tests__`. It matters only where the input can pass 64 KiB and the script runs under `pipefail`; I did not check each one.

Source: Seat G 18th, from the hook log of the #989 push (`evidence/push_pr989.log`).

131: # look for an existing node_modules is not atomic with the move, and BSD `mv` onto a directory moves the

137: # (measured: the node process that renames) in which another actor can replace node_modules, so a tree

146: # --- KS-998 ITEM 3: WHAT THE INSTALL MAY RUN, AND WHAT IT IS HANDED (gate review of #1532, Minor 3) --------
147: # `npm ci` runs the dependency install scripts from the lockfile, on the developer's push, for a package the developer may not have
148: # touched (a stale base, a merge). The review's fixture: a lock entry whose `resolved` pointed at a local HTTP listener was fetched,
149: # INSTALLED, and its postinstall ran and wrote outside the repository; that script also saw NPM_TOKEN, GH_TOKEN, SSH_AUTH_SOCK and ~/.npmrc.
150: #   * THE LOCKFILE IS CHECKED FIRST (_check_lock_sources; package-lock.json AND npm-shrinkwrap.json): every `resolved` must start with an
151: #     allowed URL prefix (default https://registry.npmjs.org/) and carry an `integrity`; a `link` and a local entry must resolve INSIDE

153: #     (normal mode) / SKIPPED (--all) naming the entry, and NOTHING is fetched or run.

160: #     secret, cert, key). ~/.npmrc is therefore not read: a developer whose registry or proxy lives only there opts back in with
161: #     npm_config_userconfig=<file> (the refusal says so). The developer's default cache (~/.npm) is passed as npm_config_cache unless one
162: #     is set, so a warm cache and an offline push still work.

345: # _check_lock_sources <package dir> <repo root> <allowed URL prefix...>: prints NOTHING and returns 0 if every lockfile `npm ci` could
346: # use here (package-lock.json AND npm-shrinkwrap.json, whichever exist) is installable from the allowed sources; otherwise prints the
347: # first offending entry and why, and returns 1. Rules: an entry's `resolved` must start with an allowed prefix and it must carry an
348: # `integrity`; a `link` (and a local, non-node_modules entry such as its target) must resolve INSIDE the repository; `inBundle` /
349: # `bundled` entries come from their parent's tarball, which is checked; anything else - git+, http:, file:, a missing source, an
350: # unreadable lock, an unknown format - is refused. Nothing is run and nothing is fetched.
351: _check_lock_sources() {
352:     local dir="$1" repo="$2"
353:     shift 2
354:     node -e '
355:         const fs = require("fs"), path = require("path");
356:         const dir = process.argv[1], repo = path.resolve(process.argv[2]), allow = process.argv.slice(3);
357:         const bad = (what, why) => { process.stdout.write(what + ": " + why); process.exit(1); };
358:         const inside = (p) => {
359:             const r = path.relative(repo, path.resolve(p));
360:             return r !== "" && r !== ".." && !r.startsWith(".." + path.sep) && !path.isAbsolute(r);
361:         };
362:         const okSource = (r) => typeof r === "string" && allow.some((p) => p !== "" && r.startsWith(p));
363:         const source = (what, e) => {
364:             if (!okSource(e.resolved)) bad(what, "resolved " + String(e.resolved) + " is not under an allowed source prefix");
365:             if (typeof e.integrity !== "string" || e.integrity === "") bad(what, "has no integrity");
366:         };
367:         for (const name of ["package-lock.json", "npm-shrinkwrap.json"]) {
368:             const f = path.join(dir, name);
369:             if (!fs.existsSync(f)) continue;
370:             let lock;
371:             try { lock = JSON.parse(fs.readFileSync(f, "utf8")); } catch (err) { bad(name, "is not valid JSON"); }
372:             if (!lock || typeof lock !== "object") bad(name, "is not a lockfile object");
373:             if (lock.packages && typeof lock.packages === "object") {
374:                 for (const [key, e] of Object.entries(lock.packages)) {
375:                     if (key === "") continue;
376:                     const what = name + " " + key;
377:                     if (!e || typeof e !== "object") bad(what, "entry is not an object");
378:                     if (e.link === true) {
379:                         if (typeof e.resolved !== "string" || !inside(path.resolve(dir, e.resolved))) {
380:                             bad(what, "link resolves outside the repository (" + String(e.resolved) + ")");
381:                         }
382:                         continue;
383:                     }
384:                     if (e.inBundle === true) continue;
385:                     if (e.resolved === undefined) {
386:                         const local = !/(^|\/)node_modules\//.test(key);
387:                         if (local && inside(path.resolve(dir, key))) continue;
388:                         bad(what, local ? "local entry resolves outside the repository" : "has no resolved source");
389:                     }
390:                     source(what, e);
391:                 }
392:             } else if (lock.dependencies && typeof lock.dependencies === "object") {
393:                 const walk = (deps, trail) => {
394:                     for (const [n, e] of Object.entries(deps)) {
395:                         const what = name + " " + trail + n;
396:                         if (!e || typeof e !== "object") bad(what, "entry is not an object");
397:                         if (e.bundled !== true) {
398:                             if (e.resolved === undefined) bad(what, "has no resolved source (version " + String(e.version) + ")");
399:                             source(what, e);
400:                         }
401:                         if (e.dependencies && typeof e.dependencies === "object") walk(e.dependencies, trail + n + " > ");
402:                     }
403:                 };
404:                 walk(lock.dependencies, "");
405:             } else {
406:                 bad(name, "has neither packages nor dependencies (unknown lockfile format)");
407:             }
408:         }
409:     ' "$dir" "$repo" "$@"
410: }

492:     # swallow the package list this script is looping over (KS-998 robustness note).

497:     # closed so it can never hold a caller's $(...) pipe open.
498:     (

500:         while [ "$_i" -lt "$INSTALL_CEILING" ]; do

507:         sleep 2
508:         _kill_proc KILL "$_FG_NPM_PID"
509:     ) </dev/null >/dev/null 2>&1 &
510:     _FG_WD_PID=$!
511:     wait "$_FG_NPM_PID" 2>/dev/null; INST_RC=$?
512:     kill "$_FG_WD_PID" 2>/dev/null; wait "$_FG_WD_PID" 2>/dev/null
513:     # On the timeout path npm (the leader) may exit on the watchdog's TERM before the watchdog's own KILL, which stopping the
514:     # watchdog above prevents: end the whole group here, so a child that ignores TERM does not outlive the stage.
515:     [ -e "$marker" ] && _kill_proc KILL "$_FG_NPM_PID"
516:     _FG_NPM_PID=""; _FG_WD_PID=""

526:         # Someone made node_modules while we installed: keep the one that arrived.
527:         INST_STATE="raced"
528:     else
529:         # The look above is not atomic with the rename, so the rename must itself refuse a target that appeared in between:
530:         # rename(2) does (a non-empty directory: ENOTEMPTY/EEXIST; a symlink or a file: ENOTDIR), `mv` did not (it moved the
531:         # tree INSIDE the directory, or through the symlink into its target - gate review, Minor 1).
532:         tag=".format-gate-moved.$$"

534:         rn="$(_rename_dir "$stage/node_modules" "$dir/node_modules")"; rrc=$?
535:         if [ "$rrc" -ne 0 ]; then

538:                 *)                        INST_STATE="mvfail" ;;
539:             esac
540:         elif _prettier_ok "$dir"; then

542:             INST_STATE="ok"
543:         elif [ ! -f "$dir/node_modules/$tag" ]; then
544:             # Not our tree any more (another actor replaced it after the rename): it is not ours to move or delete.
545:             INST_STATE="raced"
546:         else
547:             # Prettier ran from the stage and does not run from here: the install embeds its own path (an absolute symlink,
548:             # say). Leaving this node_modules in the package would be the very state staging exists to prevent - "present,
549:             # no prettier" - so rename it BACK into the stage, which is then removed. Not reproduced for any of the four
550:             # lockfiles (0 files embed the stage path).
551:             rn="$(_rename_dir "$dir/node_modules" "$stage/node_modules")"; rrc=$?

561:                 rn="$(_rename_dir "$stage/node_modules" "$dir/node_modules")"; rrc=$?

564:                 else

567:                     # taking it for the garbage of a dead run.

571:                 fi
572:             fi
573:         fi
574:     fi
575:     if [ "$INST_STATE" != "ok" ] && [ "$INST_STATE" != "raced" ] && [ -f "$log" ]; then

577:     fi
578:     if [ "$keep_stage" -ne 1 ]; then _rm_stage "$stage"; fi
579:     _FG_STAGE=""
580:     return 0

593:           .prettierrc.js .prettierrc.cjs .prettierrc.mjs .prettierrc.toml prettier.config.js prettier.config.cjs \

598: # run_check <pkg> <dir>: the package's own `npm run format:check`; sets `out` and `rc`.
599: # Working-tree mode is the original foreground command. With FORMAT_GATE_TREE the pushed commit's package is
600: # archived into a tree dir, the working tree's node_modules is symlinked in, and the same command runs THERE.
601: # That runs as a background job + wait, so a SIGTERM/SIGINT/SIGHUP reaches the trap at once (a foreground
602: # $(...) would defer it until the check returned) and the tree dir is removed.
603: run_check() {
604:     local p="$1" dir="$2" tree anc
605:     if [ -z "$TREE_SHA" ]; then
606:         out="$(cd "$dir" && npm run --silent format:check < /dev/null 2>&1)"
607:         rc=$?
608:         return 0
609:     fi
610:     tree="$(mktemp -d "${TREE_PREFIX}$$.XXXXXX" 2>/dev/null)" || {
611:         out="could not create a tree dir under systemTest/ - is it writable?"; rc=125; return 0
612:     }
613:     _FG_TREE="$tree"
614:     anc="$(git -C "$REPO_ROOT" ls-tree --name-only "$TREE_SHA" -- $ANC_CANDIDATES 2>/dev/null)"
615:     # The commit's files are put on disk with `read-tree` into a PRIVATE index + `checkout-index`, NOT `git archive`: archive honours
616:     # `export-ignore` (a pushed .gitattributes, a developer-local .git/info/attributes, core.attributesFile), which silently dropped
617:     # files from the check - format:check said OK where working-tree mode said FAILED (gate 1540 Minor 2). checkout-index applies the
618:     # same working-tree conversions (eol) as the developer's own checkout and ignores export-ignore. The temp index keeps the real
619:     # index (and its lock) out of it.
620:     # shellcheck disable=SC2086
621:     if ! { GIT_INDEX_FILE="$tree/.idx" git -C "$REPO_ROOT" -c core.sparseCheckout=false read-tree "$TREE_SHA" &&
622:            GIT_INDEX_FILE="$tree/.idx" git -C "$REPO_ROOT" ls-files -z -- "systemTest/$p" $anc |
623:                GIT_INDEX_FILE="$tree/.idx" xargs -0 git -C "$REPO_ROOT" checkout-index -f -q --prefix="$tree/" -- &&
624:            [ -d "$tree/systemTest/$p" ]; } 2>"$tree/.archive.err"; then
625:         out="could not extract systemTest/$p at ${TREE_SHA}: $(cat "$tree/.archive.err" 2>/dev/null)"; rc=125
626:         _rm_stage "$tree"; _FG_TREE=""
627:         return 0
628:     fi
629:     ln -s "$dir/node_modules" "$tree/systemTest/$p/node_modules"
630:     ( cd "$tree/systemTest/$p" && _run_grouped npm run --silent format:check ) </dev/null >"$tree/.check.log" 2>&1 &
631:     _FG_CHK_PID=$!
632:     wait "$_FG_CHK_PID" 2>/dev/null; rc=$?
633:     _FG_CHK_PID=""
634:     out="$(cat "$tree/.check.log" 2>/dev/null)"
635:     _rm_stage "$tree"; _FG_TREE=""
636:     return 0
637: }
