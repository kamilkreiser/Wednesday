## Checklist

- [ ] **(a) Guard the log call (the gate's Minor 1).** The log expression inside the catch at `routes/platform.ts:995` is unguarded. A thrown value that makes `err.message`, `Object.getPrototypeOf`, `.constructor` or `Object.keys` throw (an Error with a throwing `message` getter, a Proxy with a throwing `getPrototypeOf` or `ownKeys` trap, a revoked Proxy), or a `logger.error` that itself throws, leaves the request with **no response** (hung after 2.5 s in the probe) and an unhandled rejection; the base answered the constant 500 for all 15 shapes probed. Not reachable by a caller (the value comes from `pg` or node), and the gateway survives the rejection (`index.ts:1189-1199`), so Minor. It is the same expression as `fail500` in `routes/batch.ts:28`, so the hazard is there too (not measured). Fix shape: wrap the log in try/catch, or build the string in a small non-throwing helper shared with `fail500`. Pin it with a cell that a throwing log call still answers the constant 500: mutant O4 (the log wrapped in try/catch) leaves all 8 cells green today.
- [ ] **(b) Pin the Error branch's exact logged text (Note 2).** Cell L1 asserts only that the text contains `ECONNREFUSED`. Logging `err.stack` (O1) or `String(err)` (O9) leaves L1 and L2 green, and logging the full Error object (O3) reddens only L3 and L4. A logged stack would put multi-line paths in the log unnoticed.
- [ ] **(c) A cell that throws** `null` **(Note 3).** With the `err !== null` guard removed (O11), `Object.getPrototypeOf(null)` throws inside the catch, which is the hang in (a), and every cell stays green. The gate's probe: `null` logs `thrown object` and answers 500.
- [ ] **(d) Cap the line length, or decide not to (Note 4).** The logged line is uncapped: about 15 KB if a database error echoed a maximal caller value, and one huge `fields [...]` string for an object with 100k fields. Same as `fail500`.
- [ ] **(e) Measure the limiter key on the deployed ingress (Note 1), after the deploy.** The bound of 300 log lines per minute per limiter key holds only behind a proxy that **appends** to `X-Forwarded-For` (the compose gateway behind nginx: a spoofed header is ignored, 5 of 40 requests reached the handler at cap 5). Reached directly, a rotating header gave 40 of 40 to the handler. The Azure gateway Container App has `ingress.external: true` (`deployment/azure/services.bicep:582-583`); its live behaviour, and any Front Door or CDN in front of it, is **unmeasured**.
