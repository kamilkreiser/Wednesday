===== TICKET =====
KS-1289 — Blockchain/Dev/.dockerignore excludes `tests`, which does not match `__tests__` - test sources ship into runtime images and one shared test change rebuilt 23 of 29 [In Progress]

## BLUF

`Blockchain/Dev/.dockerignore:13` is the single line `tests`. **That pattern does not match** `__tests__`, so every `__tests__` directory sits inside the build context. Two consequences: **test sources ship inside runtime images**, and **a change to a shared test file invalidates the cache for services that have no runtime change of their own.**

## Measured - the build cost

**2026-09-23 kintsugi deploy (Seat B 23rd).** Two files under `packages/shared/src/__tests__/` were the **only changed input for 23 of the 29 rebuilt images** - roughly **1 h 50 min of a 2 h 10 min build**, for images whose runtime code did not change. Excluding `__tests__` would cut a comparable rebuild to about **6** images.

**At develop** `6ab9d5021` **(Seat B 24th, 2026-09-25):** **471 tracked files** live under `__tests__/` paths beneath `Blockchain/Dev`, and none are excluded by the `tests` line.

## A path correction worth keeping

**There is no repo-root** `.dockerignore`**.** The only two tracked at `6ab9d5021` are `Blockchain/Dev/.dockerignore` and `Blockchain/Dev/services/vc-issuer/.dockerignore`. Because `docker-compose.yml` builds every service with `context: .` = `Blockchain/Dev`, the first **is** the effective one. Earlier notes calling it "the root .dockerignore" mean the build-context root, not the repo root.

## Ask

Add a pattern that matches `__tests__` (and confirm nothing in the build needs those files). **Verify by rebuilding after a shared-test-only change and showing that the set of images which rebuild shrinks** - the measurement above is the before.

+/**
+ * KS-1289 - Blockchain/Dev/.dockerignore keeps every nested __tests__ directory out of the build context.
+ *
+ * A .dockerignore pattern is matched from the build-context root, not at any depth (unlike .gitignore). The line `tests`
+ * therefore matches only a top-level tests/ directory, and every services/<name>/src/__tests__/ directory stayed in the
+ * context: test sources shipped into runtime images, and a change to one shared test file invalidated the cache of services
+ * whose runtime code had not changed. `**` + `/__tests__` is the pattern that matches at any depth.
+ */
+import { describe, it, expect } from 'vitest';
+import { readFileSync } from 'node:fs';
+import { dirname, resolve } from 'node:path';
+import { fileURLToPath } from 'node:url';
+
+const here = dirname(fileURLToPath(import.meta.url));
+// packages/shared/src/__tests__ -> four levels up is Blockchain/Dev, the build-context root
+const lines = readFileSync(resolve(here, '../../../../.dockerignore'), 'utf8').split('\n');
+
+describe('KS-1289 - Blockchain/Dev/.dockerignore excludes nested __tests__ directories', () => {
+  it('RED KS-1289 R1 a line excludes __tests__ at any depth', () => {
+    expect(lines).toContain('**/__tests__');
+  });
+
+  it('CONTROL KS-1289 C1 the original top-level tests line is still there', () => {
+    expect(lines).toContain('tests');
+  });
+
+  it('CONTROL KS-1289 C2 the whatsapp-bot re-include is still there, so its build keeps its sources', () => {
+    expect(lines).toContain('!connectors/whatsapp-bot');
+  });
+
+  it('CONTROL KS-1289 C3 the docs/openapi re-include is still there', () => {
+    expect(lines).toContain('!docs/openapi');
+  });
+});
