This is the product owner's 2026-11-11 ruling: "administrators only; no admin routes in open
(no sign-in) mode; the managed-identity check runs only inside Azure; and no fixed password in
the source for the model switch". The open-mode clause is read so that the first-run open
window is unchanged: every gate uses the project's own requireAdminFor, which lets the open
window and an unfinished first run through exactly as before, so the setup wizard still
works. The admin routes that already answered 403 in open mode keep that answer and are
pinned by a test (RD-966), not changed.

Seventeen gates run as the first line of their handlers. The feedback item writes and the
sustainability config write are checked in server.js ahead of their routers, matched on the
request path case-insensitively with one optional trailing slash, the way Express routes;
backend/routes/ is unchanged. The model switch no longer compares a request field with a
fixed value; the administrator check is its only gate. The managed-identity check dials the
cloud metadata address only in an Azure deployment (AZURE_MANAGED_APP or AZURE_MARKETPLACE);
the App Service branch is unchanged, and anywhere else nothing is dialled.

RD-965's four routes keep their behaviour and get a comment and a pinning test each: the two
reads stay readable by a viewer, the support ticket form stays public, and saving a condition
stays administrator-only while the preview stays open.

rows change (viewer 403), and the fence no longer lists a refused dial. The handler-span pin,
