## The ruling

This is the product owner's 2026-11-11 ruling, which approved all four parts of the proposal: "administrators only; no admin routes in open (no sign-in) mode; the managed-identity check runs only inside Azure; and no fixed password in the source for the model switch".

How the open-mode clause is read here: the first-run open window stays as it is. Every new gate uses the project's existing `requireAdminFor`, which refuses a signed-in non-administrator once sign-in is configured and first run is complete, and lets the open window (no sign-in configured yet) and an unfinished first run through exactly as before, so the setup wizard keeps working. `adminGateRefuses` and `backend/services/authEnforcement.js` are not touched. The admin routes that already answered 403 in open mode (fourteen) and the two that answered 401 keep those answers; a new test pins them (RD-966 stays open as a pin, not done).
