## Runtime behaviour changes (release notes and published code read for every move)
- fast-uri 4.2.3 and 3.1.9 (security release): a percent-encoded scheme is rejected instead of decoded; a domain host holding delimiter or control characters is rejected instead of rewritten; relative-reference dot-segment handling and suffix-reference colons follow RFC 3986. Inputs that were wrong now fail closed. Used through ajv and fast-json-stringify to resolve schema references; this project's references are the fragment form and the relative id "openapi", which resolve identically before and after (checked).
- find-my-way 9.10.0: internal rework of route lookup (faster registration and lookup; an opt-in compiled mode this project does not enable); with ignoreDuplicateSlashes on, a query string is no longer altered. This project sets none of the router options.
- fastify 5.12.6 to 5.12.8 (two security releases): an error status code is limited to 400-599 with 500 as the fallback; string bodies are decoded once; a synchronous throw in a custom content-type parser becomes an error response; the content-type cache is FIFO. The API's own error handler and its upload parsers are unaffected (checked).
- ip-address 10.7.3 to 10.7.6: a bit-test off-by-one used only for Teredo flags is fixed; IPv6 zone parsing, in-addr.arpa length and error-message escaping are hardened. Reached only through the rate limiter's default IP key, which the API replaces with a per-caller key.
- safe-regex2 5.1.2 and ret 0.5.1: no behaviour change for ordinary patterns (typing and build changes; ret no longer rejects an empty capture-group name).
- undici 6.29.1: development only (OpenAPI parser used by the contract package); the services use Node's built-in fetch, not this package.
