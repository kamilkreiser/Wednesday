## What

MPSCALC-170 clause 1, the renumbering row: each fleet line now has a stable,
server-assigned `fleetLineId`, and the price audit pairs fleet lines by it.
Removing a middle fleet line and renumbering the later ones now records only
the removed line's override entries (before: 3 entries for the ticket's case,
now 1). The "Give each line its own number" save of a stored quote with two
lines numbered 1 records 0 override entries.

Product owner's ruling: "fleetLineId, screen unchanged". The audit keeps
naming a line `fleet[<line number>]`; no screen, proposal, export or refusal
carries the id; no web source changes except the three generated contract
copies.

## How

- `FleetLineDto.FleetLineId` (JSON `fleetLineId`, string or null) beside
  `lineNumber`; contract `FleetLineInput.fleetLineId`; `required` unchanged.
- Create assigns every id (`fl_` + 32 lower-hex, `RandomNumberGenerator`).
- Save and duplicate keep a held id, else take the same-number stored line's
  id, else mint one. This runs before the unchanged-draft check, so a draft
  sent back unchanged without ids is still no change. Unknown or repeated ids
  are treated as no id.
- Quotes stored before the id get ids worked out on read (SHA-256 of the
  quote id, line number and occurrence, in the same `fl_` form), the same on
  every read; the stored document is not rewritten until the next save.
  Snapshots are not rewritten.
- `PriceAudit.RentalOverrides` pairs by id when every line on both sides has a
  unique id, else by number as before. The purchase BOM audit is unchanged.
- Allow-list: `FleetLineDto.FleetLineId = N` (never on a proposal or export).
- Quote format string unchanged (`mpscalc-quote/1`).

## Deploy note (rollback)

Nothing is deployed by this merge. Once a build with this change is deployed:
a snapshot written by it carries `fleetLineId` and is read with the API's
strict JSON options, so a build older than this one refuses that snapshot at
load, and refuses every quote that refers to it (measured locally: quote and
snapshot both 404 on the older build; the same snapshot with the field removed
loads). Quote documents written by this build stay readable by an older build,
which skips the field (measured: 200, field absent). A rollback after deploy
therefore needs those snapshots kept readable, or a roll forward.
