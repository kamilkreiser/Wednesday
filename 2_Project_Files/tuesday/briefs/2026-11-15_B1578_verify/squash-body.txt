Each fleet line carries an optional fleetLineId in the API contract, assigned
and kept by the server. Create gives every line a new id; a save keeps an id
the stored version holds, else takes the id of the stored line with the same
number, else a new one, before the unchanged-draft check and the audit; an
unknown or repeated id is treated as no id and nothing new is refused.
Duplicate keeps the source's ids. A quote stored before the id gets ids worked
out on read (the same on every read) and written by its next save; snapshots
are never rewritten.

The rental override audit pairs fleet lines by id when every line carries
one, so removing a line and renumbering the rest records only the removed
line's overrides; entries still name the line by its number. Drafts without
ids pair by number as before. The id is not on the proposal or any export
(allow-list NotShown) and no screen changes. The generated web contract copies
are regenerated by the sync script.

Deploy note: a snapshot written by this build carries fleetLineId and a build
older than this one refuses it at load, together with every quote that refers
to it. Quote documents written by this build stay readable by an older build,
which skips the field. Nothing is deployed by this change.
