## Round 2: the new cells on a hosted Linux runner

**What was wrong.** The first version of this change was green on macOS and read red on the hosted Linux build: two of the new cells failed (the one that checks the boot's data folder is not under `/tmp/`, and the control that the alarm still fires on a volume that lost its sentinel). The product treats any data folder whose path contains `/tmp/` as ephemeral and never raises the wiped-volume alarm there. The new cells meant to boot on a persistent folder, and set `process.env.TMPDIR` to get one. That moved nothing: jest hands each test a copy of `process.env`, while the core `os` module that the harness calls (`os.tmpdir()`, `rd395-server-harness.js` line 85) reads the real environment. On macOS the real `TMPDIR` is already under `/var/folders`, so it went unseen; on a Linux runner every boot landed under `/tmp/`. The cells that assert "no alarm line" also passed there without testing anything, because a `/tmp/` folder gives that for free.

**The fix.** One new commit, one file (`__tests__/rd1037-harness-boots-raise-no-sentinel-alarm.test.js`, +20 -8). `boot()` now reads `persistentTempRoot()` first, replaces `os.tmpdir` with `jest.spyOn(os, 'tmpdir')` for the one `bootServer` call and restores it in a `finally`, and then throws, never skips, if the folder it got still contains `/tmp/`. No cell is added, removed, renamed, skipped or loosened (the count of `expect(` lines, 31, and of indented `test(` and `test.each(` lines, 12, is the same before and after; no removed line in the patch carries an assertion). The harness, the stand script, the counts file and the product are unchanged.

**What was measured.**
- With `TMPDIR=/tmp` and `RUNNER_TEMP` set to a persistent folder (the shape of a runner), the first version of the file fails exactly those two cells, as the hosted build did; with this commit all 14 cells pass in that shape and in the local macOS environment.
- With the replacement removed in a scratch copy, exactly the six cells that boot a server fail, on the helper's own refusal message, so a boot cell can no longer pass on a `/tmp/` folder unseen.
- The spy is restored after a boot that succeeds, after one whose child exits before answering, and after a seed that throws; during a boot `os.tmpdir()` is read once, by the harness. A refused boot's server process is stopped and its folder is cleaned up with the others.
- Hosted, on this commit: every check run is completed and successful (CodeQL, build, scan, audit-production-deps, and the three Analyze jobs). The `build` job's log reads `VERDICT: PASS - 6463/6463 tests passed across 405 suites`, shows the new file passing, and shows its 15 boot folders under `/home/runner/work/_temp/` and none under `/tmp/`.
