**OLDER family** (`PrinterAccessoryService.kt:258-401`; an event whose sequence number equals the previous event's is dropped, `:278`):
- `legacy-elatec`, ids 2520:1040 and 2520:784 (`:282-323`). EVERY byte of every report is read as a signed byte, in order. 0 is skipped. 40 ends the card and ends the reading of THAT report (later reports of the same event are still read). A byte 2, when no marker is pending, sets a marker and adds nothing. Any other byte adds one byte: with a marker pending, the byte plus 61 (and the marker is cleared); without, the byte plus 19, and a result above 57 becomes 48. The marker does not carry from one report to the next. The bytes gathered since the last card are turned into a string when a 40 was seen in the event.
- `legacy-hp`, id 1008:69 (`:324-351`). Every byte of every report is added as a character until a byte 13, which ends the card and the reading of that report (later reports of the same event are still read). Zero bytes are NOT skipped.
- `legacy-rfideas`, id 3111:15354 (`:352-371`, `:499-518`, `Helpers.kt:173-215`). A report of fewer than 2 bytes is skipped. Only byte index 2 of each report is read: usages 0x04 to 0x1D give the UPPER-case letters, 0x1E to 0x26 the digits 1 to 9, 0x27 the digit 0, 0x28 ends the card, anything else adds nothing. The modifier byte and the other key slots are not read; there is no key-down rule. (A report of exactly 2 bytes makes the Workpath code read past its end: Q5.)
- Any other id: the older family adds nothing and logs a line (`:372-375`).
**NEWER family** (`AccessoryReceiver.kt:121-140`, `ReaderDataStore.kt`; a repeat of the last sequence number is dropped, `:124`; ONE buffer per event):
- `hp-text`, vendor 1008 with ANY product id (`ReaderDataStore.kt:43-44`): the whole buffer of the event is the card text. No terminator is looked for: a byte 13 stays in the string. Then the UUID step.
- `keyboard`, every other vendor (`:93-142`): the buffer is read in steps of 8 bytes (a trailing part of fewer than 8 bytes is dropped). In each step byte 0 is the modifier and bytes 2 to 7 the keys; zero keys are empty slots. Only a key that was NOT down in the previous step is typed, in slot order (the previous step's keys are kept from one event to the next). 0x28 ends the card: the rest of that step's new keys are still typed, the steps after it in the same buffer are dropped. Shift is modifier bit 0x02 or 0x20. (RELAYED). **For the newer printers the step is UNMEASURED** (report B2 line 210 says only "monotonically increasing"): the constructor takes an option that switches gap detection off (then only repeats and late copies are dropped); default on.
