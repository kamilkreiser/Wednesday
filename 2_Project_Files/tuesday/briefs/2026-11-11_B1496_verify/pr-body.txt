## What

On the customer roadmap register, a row with nothing stored starts from the action's own owner. When that owner was longer than 100 characters it was shown whole and Save refused it with the bare label "Owner", which the user could not clear without deleting text they did not type.

`startingOwner` (a pure function in `remediation-store.ts`, using the store's own `OWNER_MAX`) now gives the row its starting owner:
- no owner: empty;
- an owner that fits (at most 100 after trimming): returned unchanged, byte for byte, so every default that saves today starts exactly as today;
- a longer owner: trimmed, cut to the longest run of whole code points within 100 UTF-16 units (never a lone surrogate), then end-trimmed.

`RoadmapScreen.tsx` uses it for that one initial value (plus the import line). `checkEntry`, `parseRegister`, the stored shape, `OWNER_MAX` and every `maxLength` are unchanged. No user-facing word is added.

## Scope

This is part (a) of HPSMPOC-408 item 2 only (the code half: cap or truncate the default owner at 100). Part (b), real sentences for the three limits, needs the product owner's words and is held. The ticket stays open; this PR does not close it.
