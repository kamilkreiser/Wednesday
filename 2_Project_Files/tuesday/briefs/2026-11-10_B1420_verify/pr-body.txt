The change report's footer model decides whether the first footer line fits above the manifest hash line, and clips it with dots when it does not. It disagreed with the PDF writer in two ways, and in both the hash line could fall off the page:

1. Tabs. The writer turns each tab into four spaces before it measures, breaks or draws text (6.45 pt a tab at 6.5 pt). The model measured the font's tab glyph (2.88 pt), so it could count one row where the render took two.
2. Line breaks. The writer breaks a line only where the Unicode line-breaking rules allow: never after an opening bracket and its spaces, never before a closing mark across a space. The model broke at every space, so it counted fewer rows than the render.

- Tabs are counted as four spaces.
