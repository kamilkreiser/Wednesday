One workflow with four jobs. linux and windows restore in locked mode, build, test and publish the
server host and run the release guard over the published folder; the linux job also builds the
container image and pushes it nowhere. secret-scan runs a pinned, checksum-verified scanner over the
history and the working tree after a planted control, then over every file the repository stores,
copied under a neutral name behind one plain first line, after six planted files. rules runs the 53
planted controls with a floor of 53, then the repository rules. A test holds the secret-scan job and
the rules job to their reviewed text by a fingerprint. The runtime list of both packagings is declared
once, in Directory.Build.props.

The second scan does not see: text saved as UTF-16, compressed content, a secret split over two lines,
a secret in a commit message, a tag message or a file name, and a secret that lies across a read cut
of a large file. No repository setting requires any of the four checks.

Not in this change, and still open on WP0.3: the bundle tool in the pipeline and a test bundle; the
fingerprint of the real development CA (the deny-list holds comment lines only, and the guard warns
and passes on an empty list); code scanning results. Nothing is deployed or released.
