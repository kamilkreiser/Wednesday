A serial is 1 to 64 characters of `A-Z`, `a-z`, `0-9`, `.`, `_`, `-` (the shape of an HP serial is UNMEASURED; this rule is the lane's); anything else is `InvalidArgument` (holder) or `Unauthorized` (callback). Vault names: `oxpd2/solution-refresh/<h>` and `oxpd2/callback-hash/<h>`, `<h>` = the 64 lower-case hex characters of the SHA-256 of the serial's ASCII bytes, which meets the secret store's name rule ("1 to 200 characters of a to z, 0 to 9, '.', '_', '-' and '/'", `SecretNames.cs:5`) for every serial and never folds two serials that differ by case into one name. Alternative: the serial lower-cased in the name (cost: `SERIAL0001` and `serial0001` share a record). Cell V01.
- **D4 THE TOKEN HOLDER: LAZY REFRESH, ONE REFRESH ON 401, THEN THE REPAIR MARK** (Q4). `DeviceTokenHolder` keeps per serial: the access value in memory only (bytes, cleared with `CryptographicOperations.ZeroMemory` when replaced or forgotten) and a state (`Ready`, `NeedsRepair`). `SolutionTokenHandler` (one per serial, a `DelegatingHandler`): (1) if the serial is `NeedsRepair`, throw `DeviceTokenException(NeedsRepair)` and call nothing; (2) if no access value is held, refresh (D5) first; (3) send the request with `Authorization: Bearer <access value>`; (4) on a `401` answer only: dispose it, refresh ONCE (single-flight per serial: concurrent 401s of one serial cause ONE endpoint call, the others wait for it and reuse its result), send the same request again ONCE (D7); (5) a second `401`: set `NeedsRepair`, clear the access value, and RETURN that `401` answer to the caller (the generated client then returns its status, `Oxpd2ClientCore.cs`, SendForJsonAsync); every later request of that serial is step (1) until `StoreRefreshValue` is called again (after a repair, OUT). Any other status (`403`, `5xx`, `2xx`) passes through with no refresh. **No refresh on a timer and none before expiry** (an expiry is not known: the endpoint's answer shape is UNMEASURED). Alternative: refresh before expiry from an `expires_in` (cost: a field no repository specification states). Cells T01 to T06.
- **D5 THE REFRESH CALL IS AN INTERFACE** (Q5). `ISolutionTokenEndpoint.RefreshAsync(string serial, ReadOnlyMemory<byte> refreshValue, CancellationToken cancellationToken)` returns `Task<SolutionTokenGrant?>`: a grant (the new access value, and a new refresh value or none) on success, **null when the endpoint REFUSES the refresh value** (a dead token: the holder sets `NeedsRepair` at once, no retry), and it THROWS on anything transient (the holder gives `DeviceTokenException(RefreshFailed)`, keeps `Ready`, and the next request refreshes again). Each refresh is bounded by `RefreshTimeout` (default 30 s) on the holder's `TimeProvider`; at the bound the endpoint's token is cancelled and the caller gets `RefreshFailed`. The only implementation in this lane is a FAKE in the test project. The real one (the device's OAuth2 endpoint, `02:251`) is OUT: it is in no specification the repository holds (BLUF 6c). Alternative: a concrete `HttpClient` call (cost: an endpoint shape the repository does not hold, and a request to a host). Cells T05, T06.
- **D6 ROTATION ORDER** (Q6). A grant that carries a new refresh value: the holder writes it to the vault FIRST (`Put` under D3's name); only after the write returns does it keep and use the new access value. A vault write that throws: the new access value is cleared and NOT used, the caller gets `DeviceTokenException(VaultFailed)`, the state stays `Ready` (the old refresh value is still in the vault; whether the endpoint still accepts it after rotating is UNMEASURED). Alternative: use first, store after (cost: a crash between the two loses the only valid refresh value). Cell T07.
- **D7 THE REQUEST AND ITS REPLAY** (Q7). A request that already carries an `Authorization` header is refused with `DeviceTokenException(InvalidArgument)` before anything is sent (never overwritten, never sent twice). Before the first send the handler reads the request content into memory, at most `MaxReplayBodyBytes` (default 1048576, the parse limit of `Oxpd2ParseLimits.cs:10`); a larger body is `InvalidArgument` before anything is sent (the generated clients send JSON bodies only, `Oxpd2ClientCore.cs`, JsonBody). The retry of D4 (4) is a NEW `HttpRequestMessage` with the same method, URI, version, headers but `Authorization`, the same content bytes and content headers. Alternative: no retry, the caller retries (cost: every caller repeats the refresh dance). Cells T08, T09.
- **D8 THE CALLBACK CREDENTIAL** (Q8). `CallbackCredentials.Issue(serial)` draws 32 bytes from `RandomNumberGenerator`, writes them as 43 characters of base64url without padding (`System.Buffers.Text.Base64Url`, MEASURED present in the reference pack), stores ONLY the 32-byte SHA-256 of the 43 ASCII characters through the vault (D3's `callback-hash` name; also cached in memory) and returns the 43 characters ONCE in an `IssuedCallbackCredential` (its `ToString()` a fixed mask), for onboarding to put into the device's context (OUT). Issuing again for a serial replaces the hash (rotation, `02:617`); `Forget(serial)` deletes it from the vault and the cache. The clear value is never stored, so re-writing a device's context always means a new issue. Alternative: store the clear value (cost: a secret at rest that verification does not need). Cells A01, A04.
- **D9 THE CHECK** (Q9). `CallbackCredentials.Verify(string serial, string? presentedHeader)` returns true only when the header is the scheme `Bearer` (any letter case) followed by exactly ONE space and exactly 43 base64url characters, AND the SHA-256 of those 43 characters equals the stored hash under `CryptographicOperations.FixedTimeEquals`. For a serial with no stored hash, or a serial that breaks D3's rule, the presented hash is compared with a random 32-byte value drawn once per instance, so the same work is done; every failure returns the same `false`. A vault read that THROWS is not a `false`: it is reported as `Unavailable` by the dispatcher (D12), so a broken store is never read as a stranger. Alternative: `Basic` (`02:250`; cost: a user name that carries nothing). Cells A02, A03, A05.
