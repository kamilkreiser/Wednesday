### THE RULES (each a DEFAULT of a Question; each has a cell in THE CONTROLS)
**The 401 rule (Q2).** Every logical call (one `SendAsync`, one page of a walk) gets ONE refresh: on a 401 the client calls `GetNewTokenAsync` once; `null` ends the call as `Unauthorized` with no retry; a token is used for ONE more attempt; a second 401 in the same call ends it as `Unauthorized`, with no second refresh. A token source that throws ends the call as `Unauthorized` carrying no part of the source's message (the inner exception is NOT attached: its message is not yours to vet). The refresh is independent of the throttle retries: a 429 after the refresh is still retried within its own bound, and a 401 after a throttle retry still gets the one refresh if it is unused. **No coalescing across concurrent calls**: N calls that all meet a 401 make N refreshes (a NAMED LIMIT: coalescing would need the client to hold a token for other calls, which is the broker's job, lane D, and would make this lane G1). A token source that hands back the SAME token is not detected (named limit; the second 401 ends the call).
**The throttle rule (Q3, Q5).** A response of 429 or 503 (and no other status) is retried, for every method, at most `MaxThrottleRetries` times per logical call. The wait before each retry is the `Retry-After` value read by the grammar of Q4 (block R); when the header is absent or malformed it is the fallback wait (first retry `FallbackFirstWait`, then doubled each time, never above `FallbackMaxWait`; no jitter). A readable wait above `MaxRetryAfter` is NOT waited: the call ends at once as `Throttled` carrying that wait. A wait that would take the call's total of waits above `MaxTotalWait` is not waited either: `Throttled`. Retries exhausted: `Throttled` with the last status. Waits go through `IGraphDelay` only (the tests record them and never sleep).
**`Retry-After` grammar (Q4; frozen as block R).** The raw value is read from `response.Headers.NonValidated` (the framework's own parser is not used: what it accepts for this header is UNMEASURED). Exactly one value, or it is malformed. Spaces and tabs at both ends are trimmed. ONLY ASCII digits `0` to `9`, one or more: seconds; more than 9 digits, or a value above `MaxRetryAfter`, is over the cap (no integer overflow is possible: the length is checked first). Otherwise ONLY the fixed date form `ddd, dd MMM yyyy HH:mm:ss GMT` with English day and month names, a real calendar date and a day name that matches it: the wait is that date minus `TimeProvider.GetUtcNow()`, a date at or before now waits 0. Every other value (a sign, a fraction, a list, an empty value, the two obsolete date forms, a numeric zone, a non-ASCII digit) is malformed and gets the fallback wait.
**The body bound (Q8).** Every body the client reads (a page, a JSON answer, an upload answer, an error body it inspects) is read through a reader that stops at `MaxResponseBytes`: one byte more ends the call as `ResponseTooLarge` and the rest is not read (the response is disposed). Each attempt (send and body read together) runs under `AttemptTimeout` joined with the caller's token; the timeout ends the call as `Timeout` (not retried for `SendAsync` and pages: Q6), the CALLER's cancellation ends it with `OperationCanceledException`. A page or an upload answer that must carry JSON and has no body, or a body that is not a JSON object, is `MalformedResponse`; a `SendAsync` answer with no body is a valid `GraphResponse` with an empty body.
**The paging rule (Q7).** The walk sends the first page's relative address, then follows `@odata.nextLink` while it is present and not null. A next link is followed ONLY if it is a JSON string of at most `MaxNextLinkLength` characters that parses as an absolute URI whose scheme is `https`, whose host equals the base address's host (ordinal, case-insensitive), whose port equals the base address's port, and which holds no user info; otherwise the walk ends as `PagingForeignAddress` and **that link is never requested, so no token is ever sent to it**. A next link equal (as an absolute URI string, ordinal) to any address already requested in the same walk ends it as `PagingLoop`. A walk that would request page `maxPages + 1` ends as `PagingTooManyPages`. A page whose `value` is missing or not an array, or whose `@odata.nextLink` is neither absent, null nor a string, is `MalformedResponse`. Pages yielded before a failure stay yielded; the exception is raised when the caller asks for the next page. `maxPages` must be 1 or more (else `ArgumentOutOfRangeException`); the default the modules will pass is 100 (Q7, a constant `GraphOptions.DefaultMaxPages`).
**The upload rule (Q9).** `uploadUrl` must be an absolute `https` URI with no user info (any host: which hosts Graph returns is UNMEASURED); `content` must be readable and seekable (else `ArgumentException`); `length` must be 1 or more and equal to what the stream holds from position 0 (checked by `content.Length`). Pieces of `UploadPieceBytes` (the last one shorter) go by `PUT` with `Content-Range: bytes <first>-<last>/<length>` and `Content-Length`, and with NO `Authorization` header. A 202 answer must carry `nextExpectedRanges` (a JSON array of strings `<start>-<end>` or `<start>-`); the next piece starts at the FIRST range's start. A 200 or 201 answer ends the upload (its body must be a JSON object, else `MalformedResponse`). A 404 ends it as `UploadSessionGone` (no new session: that is the module's choice). A 408, 429, 500, 502, 503 or 504, a transport error or an attempt timeout is retried: before the retry the client waits (Q4 grammar, the fallback otherwise, the same caps), then reads the session's status by a `GET` of `uploadUrl` (no `Authorization`) and continues from the first start of its `nextExpectedRanges`; a 416 answer goes straight to that status read. At most `MaxPieceRetries` retries per piece; a range start below 0, at or above `length`, or not a decimal number, is `MalformedResponse`; the same start answered `MaxPieceRetries + 1` times in a row, or more than `ceil(length / UploadPieceBytes) * (MaxPieceRetries + 1) * 2` requests in one upload, is `UploadNoProgress`. A 401 or 403 on a piece is `HttpStatus` (no token is involved: no refresh). **No resume across a restart of the process** (it would need the session address persisted: that is persistence, G1, and is not this lane: a NAMED LIMIT).
**Logging (Q11).** The client may log, through the `ILogger` it was given, ONE event per attempt and per final outcome, with exactly these property names: `Method`, `Host` (the base address's host or the upload host), `Status`, `Attempt`, `WaitMilliseconds`, `Outcome` (a `GraphFailure` name or `Success`).
