What this changes (PCOMP-77)

1. A secret field marked "a local value will be required" no longer needs a written justification.
   - API (putControl): a custom decision whose field is a secret and whose custom_value is a value
     reference is accepted with no rationale (null, absent, empty or blank). Every other custom
     decision still answers 422 DECISION_INCOMPLETE with the same message.
   - Storage: no migration. The table refuses a NULL rationale on a custom row, so the empty string
     is stored for this one case. No reader sees it: the decision bodies answer null, and the input
     snapshot carries no justification, so the input hash is the same as for no rationale.
   - Web: the control page raises no justification error for this case and drops "(required)" from
     the label. The hint under the box is unchanged.

2. A "Mark all secret fields local" action on the Controls screen, beside the screen's other actions.
   - It marks each secret field that has no decision yet in the current resolution, one request at a
     time, each with the ETag the previous answer returned.
   - It never overwrites a recorded decision and skips fields of a switched-off item.
   - It stops at the first refusal and says how far it got.
   - It is shown only to a consultant on a draft, and only while something is left to mark.
   - Words: "Mark all secret fields local", "Marked N secret fields as local.",
     "Marked N of M secret fields; the rest were not changed."
