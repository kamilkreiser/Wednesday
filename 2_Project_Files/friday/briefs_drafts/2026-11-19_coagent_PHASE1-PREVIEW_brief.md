**The interface contract (lane B builds against exactly this; changing it is a STOP for both lanes).**

*Daemon flags (`coagentd`, additions):*
- `--gate` — gate mode. Without it the daemon behaves exactly as at `242de86` (M1, ungated), so every existing test and gate file stays green unchanged. `status` gains `"gate": "on" | "off"`.
- `--workspace <dir>` (repeatable; at least one required with `--gate`, else exit 2) → `StateConfig.workspace_roots`.
- `--exclude <glob>` (repeatable) → `StateConfig.exclusions` (policy dialect: `docs/POLICY.md`).
- `--gate-dir <dir>` (repeatable) → `StateConfig.extra_gate_dirs`; the data directory is ALWAYS added by the daemon itself.
- `StateConfig.env.home` = the daemon's `$HOME` at start (refuse to start in gate mode if unset); `host` = `HostOs::Posix`; `approval_timeout_secs` = 300 ([03] §5.2 default).

*IPC command `gate` (version 1, same framing as `docs/DAEMON.md` §3):*
- request `{"v":1,"id":<u64>,"cmd":"gate","args":{"event":<the hook's stdin JSON object, verbatim>}}`; `args` has exactly that one field (unknown fields refused).
- success `{"v":1,"id":…,"ok":true,"result":{"decision":"allow"|"ask"|"deny"|"block","reason":"<text>","halt":<bool>}}`. `reason` is display-safe (built only from policy texts: `AllowWhy::text`, `DenyReason::text`, or the card rendered from `Card` fields that the policy's contract says are display-safe, `engine.rs:242-247`). `"block"` is only for `ConfigChange`. `halt` is true only when `Decision::halts_agent()`.
- errors: `gate_off` (daemon not started with `--gate`), `bad_args`, `too_large`, `malformed`, `internal`. The client treats EVERY error as "blocked".

*Daemon decision for `hook_event_name` = `PreToolUse`:* `HookInput::parse` (failure → `deny`, reason "coagent: the gate could not read this call; not run"); `classify(.., HostOs::Posix, &env, &PosixNormaliser)`; `origin` = `Origin::Member(<peer key id hex>)` while a session exists, else `Origin::Local`; the `State` is per Claude Code `session_id` (created on first sight, at most 64 kept, the oldest unused dropped — a dropped one is simply re-created, never allowed); `link` = `ClosedTainted` if that Claude Code session is tainted (below) and the daemon has no active session, else `Open`; `decide(&action, &state, Surface::TerminalPrompt, now)`. In gate mode there is NO "no decision" path: every call is decided, session or not (the plugin is loaded only in throwaway demo trees, section 6).

*Daemon decision for `ConfigChange`:* in gate mode always `block` with reason "coagent: settings changes are blocked while the CoAgent gate is on" (spike U6: without it a settings write turns the gate off mid-session). Any other event name → `deny` / reason "coagent: event not handled".

*The liveness witness ([03] §3.4: "the daemon releases peer text only if a `PreToolUse` event for that same `coagent` tool in that same Claude Code session arrived within the last few seconds"):*
- When a `PreToolUse` for exactly `mcp__plugin_coagent_link__inbox_read` or `mcp__plugin_coagent_link__wait` is decided `allow` or `ask`, the daemon records a witness `{tool, cc_session_id, at}`, one slot per tool name (a newer one replaces the older).
- TTL `WITNESS_TTL_SECS` = 330: the 300 s approval timeout plus 30 s, because an `ask` waits for the human before the MCP call reaches the daemon (computed, not run).
- In gate mode, `inbox_read` consumes the `inbox_read` witness; `wait` consumes the `wait` witness WHEN THE WAIT IS ACCEPTED and the `Waiter` carries it to `wake_waiter`. No live witness → error `gate_missing`, message "no witnessed tool call: the gate did not see this read", and NOTHING is handed out (the inbox, `handed_out` counts and `ack` unchanged).
- Consuming a witness marks its Claude Code session TAINTED, persisted BEFORE the reply in `<data>/gate.json` (0600, the daemon's existing atomic writer; at most 256 ids, oldest out). An unreadable `gate.json` in gate mode = refuse to start (fail closed, like `session.json`, `docs/DAEMON.md` §2).
- `release.rs` gains a second witness kind made only from a consumed gate witness (constructor `pub(crate)`, in `release.rs`); `ungated_m1()` is still called from exactly one place, and only when `--gate` is off. `release_audit.rs` states both rules and `tests/release_audit.rs` adds mutated copies for the new one.
- Known limit, written in STATUS and `docs/DAEMON.md` §8: the witness is bound by tool name and time, not to the MCP call itself (whether Claude Code passes `tool_use_id` or the session id to an MCP server is UNKNOWN; settled by logging what `coagent-mcp` receives in the live demo — out of scope for the seats).

*Hook client `coagent-hook --data-dir <dir>` (registered for `PreToolUse` and `ConfigChange` only):*
- Reads stdin to EOF, at most 1 MiB; builds the `gate` request; if the request line is over the IPC limit (128 KiB, `limits::MAX_REQUEST_LINE`) it does NOT ask the daemon and answers `deny` with reason "coagent: this call is too large for the gate to check; not run" (BACKLOG item).
- One connection to `<dir>/ipc/daemon.sock`, one request, one response; overall deadline `HOOK_DEADLINE_SECS` = 10.
- Output mapping (exit 0, exactly one JSON object on stdout, nothing else):
  - `allow` / `ask` / `deny` → `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"<same>","permissionDecisionReason":"<reason>"}}` (shape as the M0 stub daemon emitted it, `spikes/lib/stub_daemon.py`, and as G1/U2 observed Claude Code honouring it).
  - `deny` with `halt: true` → the same plus `"continue":false,"stopReason":"<reason>"` ([03] §3.4 row "continue: false").
  - `block` (ConfigChange) → `{"decision":"block","reason":"<reason>"}` (spike U6, from docs re-read there).
- FAIL CLOSED: daemon socket missing, connect refused, deadline passed, connection closed without a line, unparsable response, `ok:false` with ANY code, or a `decision` value not in the list → stderr exactly `coagent gate: daemon unreachable or refused - call blocked` and **exit 2** (spike G2: exit 2 blocks in every mode; `onFailure:"block"` covers a crash or a missing binary). Never exit 0 without a decision on stdout.
- Never prints peer text (it never receives any) and never echoes the tool input.
