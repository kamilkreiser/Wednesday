*What it matches (the grammar; drafter's proposal, OPEN POINT 1 lists the choices):* at each `@` in the text (after `strip_format_chars`, which `PatternRedactor::redact` already applies first, `:48-49`):
- **local part:** the longest run of ASCII `[A-Za-z0-9._%+-]` ending just before the `@` (plus-tags and dotted locals included), with leading `.` trimmed; at least 1 byte. The run stops at any other byte, including `@`, `:`, `/`, `<`, `"`, `'`, whitespace and every non-ASCII byte (the crate's convention).
- **domain:** the longest run of ASCII `[A-Za-z0-9.-]` starting just after the `@`, with trailing `.` and `-` trimmed; it must hold at least two labels separated by `.`, no empty label, and a last label of at least 2 ASCII letters only, or a last label starting `xn--` (punycode).
- **not an address (must NOT be masked by this rule):**
  - an `@` inside a `scheme://` token: from `://` to the end of that token as `url_userinfo` delimits it (`:305-325`: whitespace, `"`, `'`, `<`, `>`, `` ` ``, or a non-ASCII byte). That token belongs to the URL user-info rule, whose answers stay exactly as they are (`https://bob:hunter2pw@example.com/r` → `https://[REDACTED]@example.com/r`, RAN-DRAFTER; the host is kept). Consequence, stated plainly: `https://bob@example.com/r` (a user with no password) is NOT masked by either rule. OPEN POINT 1(c).
  - an scp/ssh target: a domain followed IMMEDIATELY by `:` and then a byte that is not whitespace and not the end (`user@host.example.com:/path`, `git@github.com:org/repo`). A `:` followed by a space or the end (`mail bob@example.com: thanks`) does not stop the match.
  - `@mentions` and decorators (`@alice`, `@Override`, `@app.route`): no local part before the `@`.
  - version pins (`pkg@1.2.3`, `@types/node@18.0.0`): the last label is not letters.
  - a bare `a@b` or `user@localhost`: no dot in the domain.
- **found inside:** angle brackets (`<a@b.co>`), quotes and JSON strings (`"a@b.co"`), `mailto:a@b.co` (the `:` is not a local character, so the local part starts after it; the result is `mailto:[REDACTED]`), a `Signed-off-by:` trailer, an address followed by `.`, `,`, `)` or `: `.
- **NOT caught (stated plainly in the doc comment and in `docs/AUDIT.md`):** quoted local parts (`"john doe"@example.com`); any address with a non-ASCII byte in it (`alice@bücher.de`, internationalised local parts): the domain scan stops at the first non-ASCII byte, so `alice@bücher.de` keeps `alice@b…` unmasked (OPEN POINT 1(b)); percent-encoded `@` (`alice%40example.com`), HTML entities (`&#64;`), spelled-out forms (`alice at example dot com`), an address split across lines or by spaces; a single-label or numeric domain (`a@localhost`, `a@[192.0.2.1]`); an address cut by the 64 KiB window end (finding 2, OPEN POINT 2); addresses inside a `scheme://` token or an scp target (above).
- **Over-masking accepted** (conservative, like the crate's other rules, `redact.rs:10-11`): file-like `name@file.rs`, Python `x@self.weight` (matrix product with an attribute), and anything else of the shape.
