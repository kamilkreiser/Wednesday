## 1. The rule (this is the instruction)

Every Bash or PowerShell command is in exactly one of two states, decided by a small check that cannot be wrong in the dangerous direction:

1. **OPAQUE** — the command text contains ANY construct the shell may rewrite before running, or anything the check does not positively know to be inert: braces, `$` in any form (variables, `$(…)`, `$'…'`, `$"…"`, `${…}`, arithmetic), backticks, glob characters `* ? [ ]`, tilde anywhere except as the first character of a word followed by `/` or end of word, `=` at the start of a word (zsh), history `!`, process substitution, here-documents and here-strings, backslash escapes, quote characters adjoining other text so that words are concatenated (`a"b"c`), any non-ASCII character, any control character other than a single trailing newline, and (PowerShell) backtick, `$`, `@`, `%`, `;`-free checks are not enough: treat ANY PowerShell command as opaque unless every character is in a small plain set you define. An OPAQUE command is **T3**: asked every time, red, never batchable, no "allow for the session", not coverable by a grant, with the card stating in one fixed sentence that the command contains shell expansion, so the gate cannot tell what it will touch. The existing deny scans still run on it and can still turn it into a deny.
2. **PLAIN** — every word is made only of a conservative set of literal characters (ASCII letters, digits, and `/ . _ - : , + @ %` and a leading `~/`), separated by spaces, with the operators `&&`, `||`, `;`, `|`, `>`, `>>`, `<` allowed only as separate tokens. For a PLAIN command the text IS what runs, so the raise-only scans are meaningful, and they must then be done properly: (a) hard-deny, credential, T3-write and exclusion names are matched as SUBSTRINGS of each word after tilde and path normalisation, not only as whole words, so an attached option argument (`-o/Users/x/.zshrc`, `--output=/…`, `-T/…`, `of=/…`) is caught; (b) a redirection target is a write target; (c) command names are compared after the same `fold_name` used for file names (so a folded name equal to a T3 word is T3), though with non-ASCII already OPAQUE this is defence in depth; (d) the first word of each simple command and the word after `sudo`, `env`, `xargs`, `nohup`, `time`, `command`, `exec` are all checked against the T3 word list.

State in `docs/POLICY.md`, in plain words: the gate does not understand shell commands; it asks about all of them; it asks in red, every time, about any command containing expansion; and its warnings on plain commands are a help to the owner, not a guarantee.
