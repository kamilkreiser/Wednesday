### The change, read

`report.ts` gains a `STATUS_CODE_COUNTERS` table (`http_server_error [5xx]`, `http_rate_limited [429/503]`, `http_503 [503]`) kept deliberately apart from the existing `HTTP_CODE_LABELS` table (headline labels by substring vs. the fixed sibling set printed under a failed gate — `http_503` has no headline label, and `http_req_failed` must never join the sibling set since it is the gate itself). `isHttpRateGate(result)` (`report.ts:78`) discriminates on `result.actual.endsWith('%') && /http_|error rate/.test(result.name)` — both rate-gate shapes `evaluate.ts` emits carry a `%` actual; trends carry `… ms`, counters `…/s`. `formatStatusCodeBreakdown(metrics)` (`report.ts:98`) renders the three counters or `absent` (never a fabricated `0`) for one the summary lacks. The per-gate printing moved into a new `printGateLines(r, metrics)` helper (`report.ts:216`) — a structural change (the loop body was at eslint's `complexity` ceiling), same output, same streams (a failed gate + its breakdown both on stderr, directly under the gate's own `actual=/limit=` line). `printReport` (`report.ts:247`) gains an optional 4th parameter `metrics: K6Summary['metrics'] = {}`; `cli.ts:92` becomes `printReport(results, scenarioArg, scenarioCfg.blocking, summary.metrics);` — the ONLY line touched in `cli.ts`. `formatMetricDetail` (inside `printAllMetrics`) relabels the `http_req_failed` row only, to `failed=N  ok=M` (a k6 Rate's `passes` counts evaluations where the metric was TRUE — for `http_req_failed`, `passes` counts FAILURES, which reads backwards as `passes=0 fails=37` on a healthy run); every other Rate metric keeps k6's own `passes=/fails=` words.
