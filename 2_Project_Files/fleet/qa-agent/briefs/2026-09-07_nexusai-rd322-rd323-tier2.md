## SUBJECT 2 — RD-323: `_failed()` and the failure vocabulary
**What it does:** N8-4 replaces an ok-only predicate with a **declarative, overridable** `_failed(result)`
defaulting across `ok===false` / `error` / `errors` / `failures` / `sendError` / `unexpectedError`,
accepting `errors` and `failures` as **either an array or a count**. N8-5 makes `lastError` carry the
failure summary instead of being nulled on every non-throwing tick, and adds `lastOk` to
`getHealthSnapshot`.

**🔴 THE QUESTION: does the new predicate change what counts as a failure ANYWHERE it was not meant to?**
This is a predicate applied across **several schedulers**. The risk is not that it misses a failure —
the round is about catching more — but that it now reports **failures that are not failures**, or
changes an existing scheduler's behaviour silently. **Enumerate every consumer of the predicate and
say, per scheduler, whether its verdict changed.** Name your frame.

**Two shapes the builder measured and corrected in the TICKET's own list — verify both, because a
ticket wrong in its own list produces a fix wrong in the same place:**
- `drDrillScheduler.js:17-19` returns `failures` as a **COUNT**, not the array the finding described.
- `healthSweeperScheduler`'s `p1` is `p1s.length` — a **number**, not `true`.
**Check whether a THIRD shape exists that neither the ticket nor the builder found.** A count of `0`
and an empty array must both read as "no failure"; a count of `0` read as falsy-therefore-absent, or
an empty array read as truthy-therefore-present, is the defect this whole family is about.

**The red-proof to re-run — M3 is the one that matters:**

    M1  _failed reverted to the ok-only predicate ... 11 red — all seven non-erasure vocabularies
    M2  lastError forced back to null ............... 1 red, the N8-5 cell only
    M3  _failed returns true always ................. 13 red, INCLUDING both controls

**M3 is the discriminating mutation** — a predicate that can only say "failed" would pass a suite that
only tests failures. Confirm it reddens the controls too, and that the controls are therefore real.
**M2's isolation (exactly 1 red) is the other thing to verify** — if it reddens more, the cells are
