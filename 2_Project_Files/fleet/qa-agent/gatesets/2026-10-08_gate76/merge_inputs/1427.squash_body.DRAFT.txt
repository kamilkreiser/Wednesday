## What this changes

A trivy that exits **0** and prints a bare `{}` was recorded as a **clean image**. KS 1136 already
covered a non-zero exit and output `jq` could not read; it did not cover a well-formed *empty*
object — the one shape where "no vulnerabilities" and "no scan happened" are indistinguishable from
the artefact.

`Blockchain/Testing/jobs/04-container-trivy.sh:115-120` now records `scan-failed` when trivy's
stdout carries **neither** `Results` **nor** `ArtifactName`.

**Both keys must be absent, and that is deliberate.** The ticket's own suggested fix — fail on a
missing `Results` — over-fires: a genuinely clean image can report `ArtifactName` with no `Results`
array, and failing it would turn every clean scan into an error. So the ticket's suggestion is *not*
what landed. The suite pins the distinction with a control cell that is green in the patched state
and in the reverted state alike.

The three trivy suites stubbed a clean image as `{}`, which under the new guard is precisely the
failure case. The stub moves to `{"Results":[]}` **in this same commit**, and `fail.txt` gains the
`bare` and `nores` vocabulary so each shape can be produced deliberately.

Both platform-k HTML docs are updated in this same commit per SKILL §4: flow block `35.`, cheat
section keyed to this ticket.
