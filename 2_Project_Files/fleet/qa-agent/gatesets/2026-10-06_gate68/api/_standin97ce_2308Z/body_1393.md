## What this changes

`Refs KS-1278` — https://linear.app/secuura/issue/KS-1278

Round 1 of this branch moved the already-revoked decision **into** the `UPDATE`, which is what KS-1278 asked for. It still keyed that `UPDATE` on `external_id`. Round 2 keys the guarded write on **the row the read resolved**.

### The defect round 2 fixes (gate65 N-1393-1, PROBED)

Both reads fall back to the primary key for a UUID-shaped id (`documentRepo.ts:244-251`), and the API hands clients that key as `documentUuid` (`:172`). The guarded `UPDATE` keyed on `external_id`, so a **sequential, non-race** revoke of a live, owned, unrevoked document addressed by its `documentUuid` matched 0 rows.

| addressed by | at the branch base `32e058975d4e` | at round 1 `4a1620588819` | at this head `97ce2f337ae6` |
|---|---|---|---|
| `documentUuid` (the primary key) | 200 + 1 provenance row, but the `UPDATE` matched 0 rows so the status was never written | **400 "Document is already revoked"**, 0 provenance rows, status never written | **200**, status written, exactly 1 provenance row |
| a non-UUID `external_id` | 200, 1 row | 200, 1 row | 200, 1 row (unchanged) |
| a genuine race | both writers passed the read | 400 for the loser | 400 for the loser (unchanged) |

No race is involved in row 1. Round 1 removed the base's false provenance row, which was an improvement; it answered the wrong status code on the way.

### How

The guarded statement keys on `COALESCE` of two tenant-scoped scalar subqueries — `external_id` first, then the primary key — which is the **read's own precedence** (`:238-251`), not a new rule. The status guard stays in the same statement, so of two overlapping writers exactly one still changes the row. Values are bound parameters inside the tagged template: no `Unsafe`, no quoting, no concatenation.

A non-UUID external id never reaches the `::uuid` cast, which would otherwise raise 22P02. The resolver binds `null` instead of casting, mirroring the `isValidUuid` guard the read already uses at `:244`.

### Blast radius: one caller of thirteen

Exactly **one** production caller opts in (`routes/documents.ts:2398`, `POST /:id/revoke`). The other **12** pass no `ifStatusIsNot` and take a **byte-identical** statement. Measured: `git grep -n 'updateDocument(' 4a1620588819 -- Blockchain/Dev` returns 24 lines = 13 production calls + 1 definition + 1 comment + 9 test lines, with a must-hit and a nonsense-token control.

The pre-existing class for those 12 — a UUID-addressed update matches 0 rows and the caller reports success — is filed as **KS 1424** with the full per-caller census. **It is not fixed here.** That census also corrects the figure of **14** used while ruling this fix: 14 counted the 13 calls plus one non-call line.
