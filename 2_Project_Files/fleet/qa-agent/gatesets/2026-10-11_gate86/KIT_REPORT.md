## 4. How the order-independence of the four doc blocks was checked (and what it does and does not say)

`compose` extracts each PR's fragment from its OWN merge-base (exact tail insert), then walks a prefix trie of all 24 orders. At each step it calls `git merge-tree --write-tree --name-only <cur> <head>`; on rc 0 it keeps git's tree; on rc 1 it demands the conflicted set be a subset of the two docs and applies the keep-both ITSELF (insert the PR's fragment before the closing tags of the current doc) into a new tree via a temp index, then `commit-tree`. A conflict outside the docs makes that order UNRESOLVABLE (a positive control proves such a conflict is detectable).
