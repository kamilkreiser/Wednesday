28.1 The mechanism, and what is deliberately NOT changed

The change is a pure insertion of 14 lines (numstat 14 0) after is_baselined() and before ALL_FINDINGS reads $TMP, so the new findings are in the aggregate rather than appended after it. It loops the seven unguarded jobs (01 02 03 05 06 07 08) and calls the file's existing emit. 04 is untouched: its KS 878 guard already fires and a second finding would double-count. No threshold, baseline, exit-code path or report writer is touched, and the finding text carries a filename only — no artefact contents, no environment. jq -e . is the test, so a valid JSON null or false also reads as unreadable; that side effect is named here because -e sets its exit status from the output value, not only from parseability.

28.2 The guard is a two-term conjunction, and each term has its own red arm

It fires only when the artefact [ -f ] and ! jq -e . succeeds on it. Two terms need two arms, or one of them is being asserted by prose rather than by a cell. Each arm was run with bash -n rc 0 first: an arm that does not parse prints no summary line at all, which is a load failure, not an inert tamper.
