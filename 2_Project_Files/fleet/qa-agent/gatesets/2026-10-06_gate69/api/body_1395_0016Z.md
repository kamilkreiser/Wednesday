## What it fixes

A fresh worktree installs `@prisma/client` but never *generates* it — `npm ci` runs with
`--ignore-scripts`, so `prisma generate` does not run. The bare `require('@prisma/client')` inside
`getPrismaClient()` then threw `Cannot find module '.prisma/client/default'`, which reads like a defect in
the originate service. The load now names the cause and the command that fixes it; every other load error
is rethrown as **the same object**.

Pure insertion, `numstat 19 0`, immediately before the existing `require`; on success that `require` reads
the module cache, so the happy path is unchanged. `db.ts` is the tenant-isolation module (`withTenant`, the
GUC wrapper, `getGucPrisma`, `createPoolProxy`) and **no GUC, tenant or RLS line is touched** — the six
KS 458 tenant-GUC cells are green at the head. The new message carries no environment or credential data;
`cause` carries the resolver's error, which holds module paths only.

**Review authority:** `services/originate` is platform-k base code, so Kamil's comments take precedence
(test-discipline skill, review authority). This PR touches no `systemTest/` path.
