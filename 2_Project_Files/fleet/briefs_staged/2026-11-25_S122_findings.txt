1. THE ANSWER, two sentences for Kam
A rotate copies nothing from the old key: it mints a brand-new key from a fixed list in the gateway (nine scopes, subjects:erase is the ninth) at 3,000 requests an hour, so a key rotated on this code carries both, unless the admin's request names its own scopes list (that list is used as given) or the host sets the rate-limit environment variable to another number.
For dev-ps's re-key that means the new key gets erase and 3,000 an hour, but a key minted before KS-869 (6 Sep) has no connector id, so the rotate will not switch it off: that older key stays live with the scopes and the limit it was minted with (by the KS-1195 notes, 1,000 an hour and no erase) until someone revokes it by its id, and the reply says so ("rotated: false" plus a warning) only when none of the connector's older keys carried an id.
