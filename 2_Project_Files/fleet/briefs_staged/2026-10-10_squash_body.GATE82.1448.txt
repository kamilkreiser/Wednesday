Refs KS-1434 — https://linear.app/secuura/issue/KS-1434

The create handler accepts a rotate flag (the create schema in services/security/src/index.ts,
added under KS 577) and, together with a connectorId, retires that connector's other active keys
in the same tenant once the new key is minted. The published request schema listed eight
properties and not rotate, so a contract reader, and a spec-driven caller such as Schemathesis,
could not see the field or send it.

rotate is now declared on ApiKeyCreateRequest in security.openapi.ts as an optional boolean with
default false, and a description whose clauses are traced to index.ts. The yaml is regenerated by
npm run generate-openapi: 10 insertions in one hunk inside ApiKeyCreateRequest, 0 removals.

Spec only. No runtime file is touched, and no service source imports security.openapi.ts.

New test ks1434-api-key-create-spec-declares-rotate.test.ts: at the base rc 1, 3 passed / 4 failed;
with the change 7 passed. Whole security suite 284 -> 291 passed, 0 failed. check:openapi rc 0.
Both platform-k HTML documents carry a new block (flow 54., cheat KS-1434).

Not measured: the four platform suites (no local stack), and any effect on a Schemathesis sweep.
