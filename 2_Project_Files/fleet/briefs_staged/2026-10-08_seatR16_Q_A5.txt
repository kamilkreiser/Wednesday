== THE A5 FINDING, MEASURED ==
The guard's per-line exemption test is `grep -vE 'slot-literal-ok:[[:space:]]*[^[:space:]]'` (:94 at the tip). It asks for one non-whitespace character after the colon. On a `.ts` line the bare marker is at true end-of-line, so nothing follows and the line is correctly REPORTED. **On a JSON line the value's own closing quote follows it**, so ` slot-literal-ok:",` satisfies `[^[:space:]]` and the line is EXEMPTED.

Driven both ways in one call, same filter, same regex:
  `  "reason": "x 6982 slot-literal-ok:",`        -> EXEMPTED   (wrong)
  `const p = 6982; // slot-literal-ok:`           -> reported   (right)

So on a JSON string value, ANY marker exempts, including an empty one. That contradicts the platform rule in `systemTest/CLAUDE.md:1169`, verbatim: *"A deliberate exception carries `slot-literal-ok: <reason>` on the same line; a bare marker exempts nothing."*

**It is not a regression I introduced.** `git show HEAD:systemTest/schemathesis/config/schemathesis-baseline.json | grep -c slot-literal-ok` = **0** — the baseline carried no markers at all before this fix, so mine is the first change that puts a marker inside a JSON string, which is why the gap only becomes load-bearing now. The same `\s*\S`-shaped test exists in at least four other harness implementations (`playwright/tests-unit/no-hardcoded-slot-literals.test.ts:79` `MARKER = /slot-literal-ok:\s*\S/`, `performance/.../noHardcodedSlotLiterals.test.ts:49`, the schemathesis python guard's `_OPT_OUT` at `test_no_hardcoded_slot_numbers.py:50`, and akto's), and the python one even has a cell asserting "the bare marker does not [exempt]" (:263) — which passes only because it tests a `#`-comment line.

== THE DECISION ==
Tightening the shell guard's class to `[^[:space:]",]` makes A5 hold. I measured the blast radius before proposing it: **exactly 2 existing marker lines repo-wide would lose exemption, and NEITHER needs it** — `test_no_hardcoded_slot_numbers.py:50` (`_OPT_OUT = "slot-literal-ok:"`, a constant, no slot literal on the line) and the guard's own bare-marker control line at :191 (its port is computed). So nothing that passes today would go red.
Against it: it changes Peter's marker semantics in ONE of five implementations, so the five guards would then disagree about what a bare marker does — and the other four have the same gap for JSON/quoted lines.
