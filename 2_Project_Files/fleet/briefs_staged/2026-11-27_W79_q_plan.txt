3. CHANGE 2 MECHANISM (one paragraph, proved on psql 15.19)
Reverse reads the WHOLE apply output file (owner-only, in the deploy seat's REC) through ONE stdin stream, in two passes of the same script: script, then base64 of the file, then a line holding only backslash-dot, then the script again. The documented command is

Pass 1 (mode reverse, nothing loaded yet) makes a temp table. Its LAST line is a psql variable holding "COPY ... FROM STDIN" plus an opening if-true, so the base64 lines load as data up to the backslash-dot. Pass 2 sees the loaded flag, decodes, finds EXACTLY ONE line that starts with "KS2366_REPAIR_MANIFEST ", runs the guarded reverse, and its last line closes the if.
Proved in the experiment: (a) the full stream decodes the file byte for byte, a hostile line set included (quotes, backslash, $$, :'manifest', backslash-bang, backticks, $(...), a bare backslash-dot line, a backslash-bang line); none of it executed. (b) With pass 2 missing, or the script sent alone, psql stops with "reached EOF without finding closing \endif(s)", rc 3. (c) Control: the same file sent RAW instead of base64 DID execute the injected backslash-bang line. The file's own backslash-dot ends COPY early, so base64 is what makes the file pure data.
Nothing derived from the file reaches any argv. The path is a redirect, base64 and printf take no content, and docker, sh and psql carry fixed text. No shell ever expands the content.
Why not the others: an env var leaves argv clean, but it cannot cross the D seat's ssh hop without going onto the remote command line, and it has a 128 KB per-string limit. A file copied into the container breaks A3, because the manifest must stay in the REC. psql variables and dollar-quoting let a forged file break out.
