## What is wrong (one paragraph)

Three DB catches of the credential repository pass `err?.message` straight into the logger's meta object, unguarded. `?.` guards a null or undefined value only: a thrown value whose read throws (a revoked Proxy: the `.message` get throws; an Error whose `message` getter throws) makes the catch THROW, so `store`, `list`/`listReadable` and `revoke` REJECT where an ordinary Error gets a logged warning and the in-memory result (store: the credential is already in memory and the call resolves; list: the memory list; revoke: the revoked credential, already written to memory). The fix is the house guard placed before each logger call: read the message once inside a `try` (`?.` kept), keep `undefined`/`null` as they are, coerce anything else with `String(...)`, fall back to the constant `'unreadable thrown value'` when the read or the coercion throws; then `error: reason` (the multi-line `store` log keeps `credentialId`). The hunks are ~290 and ~90 lines apart. The three READ catches (lines 119, 160, 188) are a separate brief (O90-P8).
