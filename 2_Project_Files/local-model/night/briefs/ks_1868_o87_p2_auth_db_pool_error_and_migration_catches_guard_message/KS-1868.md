## What is wrong (one paragraph)

Two places in this module pass the thrown value's message straight into the logger's meta object, unguarded: the pg pool `'error'` listener (`{ error: err.message }`) and the best-effort column-migration catch of `ensureUserColumns` (`error: err?.message`, inside a loop that deliberately swallows every failure). A thrown value whose read throws (a revoked Proxy: the `.message` get throws; an Error whose `message` getter throws) therefore throws INSIDE the listener or the catch: an exception thrown by a listener of the pool's `'error'` event escapes the EventEmitter as an uncaught exception, and a throwing migration catch abandons the loop (the remaining migration statements are never run) and makes `initDb` (and the recovery re-probe) REJECT; an Error whose `message` is readable but not a string (a Symbol) is passed to the logger uncoerced. The fix is the house guard placed before each logger call: read the message once inside a `try`, keep `undefined`/`null` as they are (they were logged as is), coerce anything else with `String(...)`, and fall back to the constant `'unreadable thrown value'` when the read or the coercion throws; then `error: reason`. The probe catch of `probeDb` (`return { ok: false, error: err?.message }`, typed `error?: string`) and the transaction catch (`throw err` after ROLLBACK) are deliberately NOT touched.
