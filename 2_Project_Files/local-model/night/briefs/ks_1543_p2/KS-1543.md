## What is wrong (one paragraph)

At `:1068` the workflow-approve forward collects the originate reply into `body` (`let body = '';` and a `data` listener that appends to it) and never reads it: only the status line decides. The `data` listener must stay, because it keeps the stream flowing so `end` fires; the buffer does not. At `:1187` the `/api/documents` handler declares `let body: Record<string, unknown> = {};`, but every path either assigns `body = parsed` in the try or returns from the catch, so the `{}` is never read (`no-useless-assignment`). The fix drops the buffer (one no-op listener in place of the two lines) and the dead initializer. Behaviour is unchanged.
