## What is wrong (one paragraph)

`mapGdprWriteDbError` (`routes/gdpr.ts:138`) starts with `const pgCode = (err as { pgCode?: string } | null)?.pgCode ?? extractPgCode(err);` (`:139`). `extractPgCode` was made safe against a hostile thrown value by KS-1780, but the property read on `err` before it is not: a revoked Proxy, or an Error whose `pgCode` getter throws, makes that read throw from inside the `catch` of both callers (`POST /api/gdpr/consent` at `:264` and `POST /api/gdpr/dsr` at `:346`, one line before `fail500`). The handlers are `async` on Express 4, so the throw rejects a promise Express never sees and the request gets no response at all (measured by the ticket: no answer in 2500 ms on /dsr, `TypeError: Cannot perform 'get' on a proxy that has been revoked` at `gdpr.ts:139`). Fix: read `pgCode` inside a `try` that falls to `undefined`, then `?? extractPgCode(err)` as before, so a value that cannot be read has no code and the caller keeps its constant 500. Behaviour for every readable value is unchanged.
