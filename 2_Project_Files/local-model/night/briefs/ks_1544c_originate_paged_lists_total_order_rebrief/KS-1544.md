## What is wrong (one paragraph)

In `services/originate`, nine paged reads sort on a column that is not unique and then page with `LIMIT ${limit} OFFSET ${offset}`, so rows that tie on the sort key have no defined order between two queries and a page walk can repeat or skip them. In `src/services/errorTrackingService.ts` (`getRecentErrors`) the five `system_errors` reads each end `ORDER BY created_at DESC LIMIT ${limit} OFFSET ${offset}`. In `src/routes/adminConfig.ts` two `audit_logs` reads (`GET /audit-logs`) end the same way, and two `rights_holders` reads (`GET /rights-holders`) end `ORDER BY display_name ASC, last_name ASC LIMIT ${limit} OFFSET ${offset}`. THE FIX is the same idea in two shapes, at each of the nine: make the primary key the last sort key, changing ONLY the ORDER BY words. Seven `created_at DESC` clauses become `ORDER BY created_at DESC, id DESC LIMIT ${limit} OFFSET ${offset}`; the two `display_name` clauses become `ORDER BY display_name ASC, last_name ASC, id ASC LIMIT ${limit} OFFSET ${offset}`.
