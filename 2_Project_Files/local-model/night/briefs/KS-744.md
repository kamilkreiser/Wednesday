## What is wrong (one paragraph)

without checking they exist: `req.headers['x-user-email'] = decoded.email;` (`:389`) and
`req.headers['x-verification-level'] = decoded.verificationLevel;` (`:394`). A token with a valid signature that lacks
the claim puts `undefined` into the header bag. Express accepts it, then the proxy's outbound `setHeader` throws
`ERR_HTTP_INVALID_HEADER_VALUE`, so every proxied route answers **500** with the internal message
`Invalid value "undefined" for header "x-user-email"` and the upstream is never reached. The line between them already
shows the right pattern: `if (decoded.organizationId) {` (`:391`). **This task:** set `x-user-email` only when the
claim is present, and set `x-verification-level` only when the claim is present, otherwise DELETE it. The delete matters
because `x-verification-level` is NOT in the edge strip pattern in `utils/trustHeaders.ts` (`x-user-*` is), so without
it a client could send its own `x-verification-level` and a token without the claim would forward that value.
