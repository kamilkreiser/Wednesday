## What is wrong (one paragraph)

In `src/index.ts` three catches on the validate path each read `err?.message`: `dbRecordApiKeyUsage` (tip :513-515; the usage write, log-only by Kam's ruling in KS-1370), the stored-state read of a cached key (:1896-1902, answers 503 'Unable to verify key') and the cache-miss lookup (:1919-1921, logs a warning and leaves the key not found). If the database call rejects with a revoked Proxy, or with an Error whose `message` getter throws, that read throws INSIDE the catch. The validate handler takes no `next` (its own comment says so), so the request is never answered and an unhandled rejection is raised. The fix keeps the logged text and replaces only the value: each catch first reads the SAME expression `err?.message` into a local `reason` inside its own `try`, and a `catch` sets the constant `'unreadable thrown value'`; the log then carries `reason`. Nothing else in any catch changes (the 503 body, the not-found answer). This is the inline guard already merged in this file; no helper is added.
