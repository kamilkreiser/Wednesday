## What is wrong (one paragraph)

In `index.ts` the `PUT /api/keys/admin-scopes/:userId` handler runs its DELETE, INSERT and audit statements in one `transaction()` (a failure rolls everything back and rethrows the raw value). Its `catch (error)` first tests `error instanceof z.ZodError` (line 1768) and then `isInfrastructureDbError(error)` (line 1773; that helper reads `err.code` and `err.message`, :1150-1152), and otherwise calls `next(error)`. If the transaction rejects with a revoked Proxy, the `instanceof` test itself throws a TypeError (it reads the prototype of the revoked object); if it rejects with an Error whose `message` getter throws, `isInfrastructureDbError` throws on `e?.message`. Either way the catch throws, in an `async` handler on Express 4, so the throw becomes an unhandled rejection and no answer is sent. The fix reads both classifications inside one inner `try` (`isZod`, starting `false`, and `infra`, starting `false`); when the value cannot be read the catch calls `next(new Error('unreadable thrown value'))`, handing the error handler an ordinary Error. The `badRequestFromZod` branch and the 503 infrastructure branch are unchanged and keep their order, and a readable value takes exactly the paths it takes today.
