## What is wrong (one paragraph)
`services/demo-service/src/app.ts` `createApp()` mounts `express.json()` (line 46), the routers, and a 404 handler
(lines 78–84) — and NO error handler. Any error passed to `next(err)` — a body `express.json()` cannot parse (a raw
NUL byte with `content-type: application/json`, a 400 `entity.parse.failed`), a body over the parser's limit (413
`entity.too.large`), or a thrown route error — falls through to express's DEFAULT handler, which answers an HTML page
carrying the stack trace and absolute filesystem paths whenever `NODE_ENV !== 'production'` (the demo box runs
`development`). Fix: mount a four-argument error handler AFTER the 404 handler that answers JSON in the service's own
`{ success: false, error: { code, message } }` shape, with the error's own `status`/`statusCode` (default 500), a
generic message for 5xx, and never a stack or a path.

```
  // KS-844: a mounted error handler — never express's default HTML page (stack trace + absolute paths).
  app.use((err: Error & { status?: number; statusCode?: number }, _req: Request, res: Response, _next: NextFunction) => {
    const status = err.status ?? err.statusCode ?? 500;
    const code = status === 400 ? 'BAD_REQUEST' : status === 413 ? 'PAYLOAD_TOO_LARGE' : status >= 500 ? 'INTERNAL_ERROR' : 'REQUEST_ERROR';
    res.status(status).json({
      success: false,
      error: { code, message: status >= 500 ? 'Internal server error' : err.message },
    });
  });
```
