## What is wrong (one paragraph)

The `.catch` that closes the subscription logs `{ error: err?.message }` with the read INSIDE the log call's arguments, unguarded. A thrown value whose read throws (a revoked Proxy: the `.message` get throws; an Error whose `message` getter throws) therefore throws INSIDE the catch handler, so the promise it returns rejects with nothing attached (an unhandled rejection, which ends a Node process by default) and the closing line is never logged; an Error whose `message` is readable but not a string (a Symbol) is handed to the log uncoerced. The fix is the house guard placed before the log call: read the message once inside a `try`, keep `undefined`/`null` as they are (they were logged as is), coerce anything else with `String(...)`, and fall back to the constant `'unreadable thrown value'` when the read or the coercion throws; then `error: reason`.
