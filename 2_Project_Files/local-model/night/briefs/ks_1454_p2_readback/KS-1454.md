## What is wrong (one paragraph)

Platform-S anchors the SHA-256 of a detached `.p7s` with a `sign` event (KS-1454 part 1 writes it to `secuura.signatureHash`), and the ticket's item 3 says it must come back on the two reads S and a verifier use. Today neither read returns it. `buildVerifyResponse` (`anchorReadback.ts`) builds `metadata` field by field and has no `signatureHash`; the by-id handler (`index.ts` `app.get('/api/anchors/:id'`) spreads `anchorIdentityView(...)` and nothing for the signature. The change: (1) add an exported pure function `anchorSignatureHashView(secuura)` returning `{ signatureHash: string | null }` (a string value is returned verbatim; a missing key or a non-string value gives `null`); (2) add `signatureHash: anchorSignatureHashView(sec).signatureHash,` to the `metadata` object of `buildVerifyResponse`; (3) extend the `anchorReadback` import in `index.ts` with the new function and spread it in the by-id `res.json` directly after the `anchorIdentityView` spread. The existing `anchorIdentityView` is NOT changed (its cells use an exact `toEqual` on `{ identityCommitment, identity }`, so a new key there would turn them red).
