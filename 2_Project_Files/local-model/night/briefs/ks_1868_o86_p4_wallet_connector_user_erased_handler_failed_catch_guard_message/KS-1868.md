## What is wrong (one paragraph)

The handler-failed catch logs `{ userId, dsrId, error: err?.message }` with the read INSIDE the log call's arguments, unguarded, and then rethrows the original value (`throw err`) so the event bus retries and dead-letters. A thrown value whose read throws (a revoked Proxy: the `.message` get throws; an Error whose `message` getter throws) therefore throws INSIDE the catch, BEFORE the log line is written and before the rethrow, so the bus receives a different error (the one the read threw) and the failure is not logged; an Error whose `message` is readable but not a string (a null-prototype object, a Symbol) is handed to the log uncoerced. The fix is the house guard placed before the log call: read the message once inside a `try`, keep `undefined`/`null` as they are (they were logged as is), coerce anything else with `String(...)`, and fall back to the constant `'unreadable thrown value'` when the read or the coercion throws; then `error: reason`. The `throw err` line is untouched.
