## What is wrong (one paragraph)

`driverRecords` (`:60-83`) walks an error object and collects every record that carries a SQLSTATE. Since KS-1642 it probes each node first (`:69`): `try { void [o.originalCode, o.code, o.constraint, o.originalMessage, o.message, Object.keys(o)]; } catch { return; }`. That `return` abandons the whole node INCLUDING its `cause` chain. So for an error whose OUTER node has a `code` getter that throws, and whose `cause` is a perfectly readable node carrying a genuine 23505 on the `documents_id_namespaces_disjoint` constraint (or the 051 constraint), the walk yields no records, `isIdNamespaceCollision` answers `false`, and the caller maps it to a 500 where the readable inner refusal warrants a 409. The fix: in the probe's `catch`, before returning, visit the node's `cause` (`visit(o.cause, depth + 1)`), inside its own `try` because reading `o.cause` can throw too. The rest of the function is unchanged. `visit` is the inner arrow function defined at `:64` (it is in scope there); `depth` is its second parameter; the node is already in the `seen` set, so a cause cycle cannot loop.
