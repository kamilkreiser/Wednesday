## What is wrong (one paragraph)

Two comparisons in `routes/documents.ts` use the single value `'anchor_failed'` for "nothing is anchored": the GET serve boundary, `anchored: !!document.blockchain && document.blockchain.status !== 'anchor_failed'` (:1200), and the retry route's guard, `if (document.blockchain && document.blockchain.status !== 'anchor_failed')` (:1458). But the blob status `'failed'` also means nothing is anchored: KS-1124 F4 gave the kept certification (KS-1709) `status: 'failed'` because the gateway maps `failed` to off-chain-only, and this file's own retry route writes `status: 'failed'` in its dev fallback (:1538). So a `failed` blob reads `anchored: true` on GET and the retry route refuses it as "already anchored". `verification.ts:100` already has `FAILED_ANCHOR_STATUSES = new Set(['failed', 'anchor_failed'])`. The change: (1) declare a local `FAILED_ANCHOR_STATUSES` (same two values) directly above `export const documentsRouter = Router();` (it is not exported from verification.ts, and importing from there is mocked in the cells and would widen this change); (2) the GET expression becomes `!!document.blockchain && !FAILED_ANCHOR_STATUSES.has(String(document.blockchain.status))` and the one comment line above it is updated; (3) the retry guard becomes `if (document.blockchain && !FAILED_ANCHOR_STATUSES.has(String(document.blockchain.status))) {`. Real anchors (`pending`, `submitted`, `confirmed`) still read anchored and are still refused by the retry route.
