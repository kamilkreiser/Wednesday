## What is wrong (one paragraph)

`blockchain-verifier.service.ts` guards the READ of the thrown value in two places and never coerces it. In `getClient` the init catch assigns `reason = err instanceof Error ? err.message : String(err)` inside a `try` and logs `{ error: reason }`; in `verifyTransaction` the lookup catch first runs a probe `try { void ...status_code; void (err instanceof Error ? err.message : String(err)); void (err as Error).message; } catch { return the constant 'unreadable thrown value' }` and then logs and returns `err.message` unguarded. If the `message` getter SUCCEEDS and returns a hostile NON-string (a revoked Proxy, an object whose `toString` throws, a null-prototype object), no probe read throws, so `reason` holds the hostile value (init) or the probe passes and the hostile value reaches `logger.error` and the returned `error` (lookup); the real winston logger throws while formatting a revoked Proxy, so `POST /api/nft/record` answers 500 and stores nothing (QA gate 109, G109-F1, measured at base and head). The fix wraps each read in `String(...)` so the coercion happens inside the existing `try`: init `reason = String(err instanceof Error ? err.message : err)`, lookup probe `void String(err instanceof Error ? err.message : err)` and `void String((err as Error).message)`. A readable string message is byte-identical; a hostile one now falls to the existing constant `unreadable thrown value`, exactly what PR 1927 does for a message whose getter throws.
