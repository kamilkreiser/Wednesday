## What is wrong (one paragraph)

The pg pool `'error'` listener in `getPool` passes the thrown value's message straight into `dbLog`'s meta object, unguarded: `{ error: err.message }`. A thrown value whose read throws (a revoked Proxy: the `.message` get throws; an Error whose `message` getter throws) therefore throws INSIDE the listener, and an exception thrown by a listener of the pool's `'error'` event escapes the EventEmitter as an uncaught exception; an Error whose `message` is readable but not a string (a Symbol) is handed to `JSON.stringify` uncoerced and silently dropped from the line. The fix is the house guard placed before the `dbLog` call: read the message once inside a `try`, keep `undefined`/`null` as they are (they were logged as is), coerce anything else with `String(...)`, and fall back to the constant `'unreadable thrown value'` when the read or the coercion throws; then `error: reason`. The probe catch of `probeDb` (`return { ok: false, error: err?.message }`, typed `error?: string`) and the transaction catch (`throw err` after ROLLBACK) are deliberately NOT touched.
