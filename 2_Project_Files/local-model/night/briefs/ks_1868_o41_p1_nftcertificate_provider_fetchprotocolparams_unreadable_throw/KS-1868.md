## What is wrong (one paragraph)

In `provider.ts` the catch block of `fetchProtocolParams` (line 65) logs `logger.error('Failed to fetch protocol parameters', { error: err instanceof Error ? err.message : String(err) })` (the read is on line 66). If a Blockfrost call rejects with a revoked Proxy, `err instanceof Error` itself throws a TypeError inside the catch block; if it rejects with an Error whose `message` getter throws, `err.message` throws. Either way the catch throws before the ERROR is logged: `fetchProtocolParams()` rejects instead of returning its documented `null` and the operator sees no log line. The fix reads the thrown value inside its own inner `try` into a local `reason`, falling back to the constant `unreadable thrown value`, and the log call uses `reason`. Nothing else changes: an ordinary Error still logs `{ error: <its message> }`, the log text is unchanged and the function still returns null.
