## What is wrong (one paragraph)

Three catches of `MilestoneService` pass `err?.message` straight into the logger's meta object, unguarded. `?.` guards a null or undefined value only: a thrown value whose read throws (a revoked Proxy: the `.message` get throws; an Error whose `message` getter throws) makes the catch THROW, so `getUserProgress` (via `dbGetUserProgress`), `getPendingRewards` (via `dbGetPendingRewards`) and `verifyDbReady` REJECT, where an ordinary Error gets a logged failure and the documented fallback (`null` -> a fresh default progress, `[]`, a resolved verification). The fix is the house guard placed before each logger call: read the message once inside a `try` (`?.` kept), keep `undefined`/`null` as they are, coerce anything else with `String(...)`, fall back to the constant `'unreadable thrown value'` when the read or the coercion throws; then `error: reason`. The three hunks are ~34 and ~80 lines apart. The two WRITE catches of this file (lines 180 and 194) are a separate brief (O90-P5) and untouched here.
