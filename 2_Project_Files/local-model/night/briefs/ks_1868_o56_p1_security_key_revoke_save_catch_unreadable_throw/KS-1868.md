## What is wrong (one paragraph)

In `index.ts` the `DELETE /api/keys/:id` handler marks the key inactive in memory (`apiKey.isActive = false`), then persists it inside a `try` with `await dbSaveApiKey(apiKey, { rethrow: true })`. Its `catch (saveErr: any)` classifies the failure with `const infra = isInfrastructureDbError(saveErr);` (line 1583; that helper reads `err.code` and `err.message`, :1150-1152) and logs the KS-888 line with `code: saveErr?.code` (line 1584), then answers 503 (infrastructure) or 500 with `The API key revoke could not be saved, so it may not survive a restart`. `dbSaveApiKey`'s own catch reads only `err?.message` before it rethrows the raw value, so a rejection whose `message` is readable but whose `code` getter throws reaches the route catch unchanged, and the read of `.code` throws inside the catch block. The handler is `async` on Express 4, so the throw becomes an unhandled rejection, no answer is sent and the KS-888 line is lost. The fix computes `infra` (starting `false`) and `code` inside an inner `try` and, when the value cannot be read, leaves them at `false` and `undefined`; the log call uses the local `code`. An ordinary Error is unchanged (its `code` is still logged and still classified).
