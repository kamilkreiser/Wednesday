## What is wrong (one paragraph)

In `routes/anchors.ts` three catch blocks read the rejection value with `X instanceof Error ? X.message : String(X)` before logging: `verifyAnchorsDbReady` (line 50: it logs `anchors: database connection FAILED ...` and then throws the constant `Error('Database is required for anchor operations')`), the DB helper `getAnchorByDocumentId` (line 90: it logs the warn `Failed to fetch anchor from DB` and then RETHROWS the caught value `throw err`, KS-1657) and the route catch of `GET /api/anchors/:documentId` (line 202: it logs `Failed to get anchor` and answers the constant 500 INTERNAL_ERROR). If the value is a revoked Proxy, `X instanceof Error` itself throws a TypeError inside the catch block; if it is an Error whose `message` getter throws, `X.message` throws. At the tip that means: at line 50 `verifyAnchorsDbReady` rejects with a TypeError instead of its constant error and no ERROR line is logged; at line 90 the warn is not logged and a TypeError (readable) replaces the thrown value, so the route still answers its constant 500 but only the route's error line is logged. **The three blocks MUST be fixed together:** if line 90 alone were fixed it would rethrow the unreadable value to the route catch at line 202, which would then throw inside the async handler (no response). The fix reads the SAME expression into a local `reason` inside its own `try`, and a `catch` sets the constant `'unreadable thrown value'`; each log call then uses `reason`. This is the inline guard already merged in the same service at `routes/certifications.ts` (KS-1844, line 1086-1094) and in `services/auth` `routes/auth.ts` (PR 1911, lines 308-313); no helper is added. The `throw err` at line 90 and the constant error at line 52 are untouched.
