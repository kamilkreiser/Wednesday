## What is wrong (one paragraph)

`audit-export.ts:115` reads the `type` query parameter as `(req.query.type as AuditType) || 'all'`: a type CAST, not a check. The value is forwarded to the security service verbatim (`type` in the `URLSearchParams`, `:139-143`) and printed into the filename (`:191`) and `meta.type` (`:210`). The gateway filters nothing itself, so an unknown value (`type=bogus`) or a repeated one (`type=auth&type=admin`, which express parses as an array) yields a 200 whose filename and `meta.type` assert a filter nobody applied. An audit artefact that names a filter it did not apply is wrong in the quiet way the ticket calls the defect class. The fix makes the five allowed values a runtime list (`AUDIT_TYPES`) from which `AuditType` is derived, and answers `400 BAD_REQUEST` (the same error shape as the `format` and date refusals) for anything that is not exactly one of them, before the security service is asked.

## Where

- `:51` - **must change**: `type AuditType = 'all' | 'auth' | 'document' | 'admin' | 'billing';` becomes a runtime `const AUDIT_TYPES = [...] as const;` plus `type AuditType = (typeof AUDIT_TYPES)[number];` (hunk 1; the blank lines around it are folded into the hunk as `-`/`+` pairs because the builder refuses a blank context line).
- `:115` - **must change**: `const type: AuditType = (req.query.type as AuditType) || 'all';` becomes the guarded read: `rawType`, the 400 refusal, then `const type = rawType as AuditType;` (hunk 2).
- `:112`, `:113`, `:114` - (correct) `format`, `fromDate`, `toDate` reads stay; `:117` - (correct) the `format` 400 stays as hunk 2's trailing context.
- `:139-143`, `:191`, `:210` - (correct) the `URLSearchParams`, filename and `meta.type` all keep using the variable `type`, now one of the five.
