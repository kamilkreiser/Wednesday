## What is wrong (one paragraph)

Two catches of this module log `{ error: err?.message }` with the read INSIDE the logger call's arguments, unguarded: the handler-failed catch (which then rethrows the original value so the event bus retries and dead-letters) and the `.catch` that closes the subscription. A thrown value whose read throws (a revoked Proxy: the `.message` get throws; an Error whose `message` getter throws) therefore throws INSIDE the handler-failed catch BEFORE the log line is written and before the rethrow, so the bus receives a different error (the one the read threw) and the failure is not logged, and it makes the closing catch handler throw (an unhandled rejection, which ends a Node process by default); an Error whose `message` is readable but not a string (a Symbol) is handed to the logger uncoerced. The fix is the house guard placed before each logger call: read the message once inside a `try`, keep `undefined`/`null` as they are (they were logged as is), coerce anything else with `String(...)`, and fall back to the constant `'unreadable thrown value'` when the read or the coercion throws; then `error: reason`. The `throw err` line is untouched.
