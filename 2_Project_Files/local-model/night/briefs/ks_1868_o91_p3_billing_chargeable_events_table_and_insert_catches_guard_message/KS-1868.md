## What is wrong (one paragraph)

Three catches of this module log `{ error: err?.message }` with the read INSIDE the logger call's arguments, unguarded. A thrown value whose read throws (a revoked Proxy: the `.message` get throws; an Error whose `message` getter throws) therefore throws INSIDE the catch, so the warn line is never written; `loadChargeEventsFromDb` (the billing boot ready hook) REJECTS instead of resolving; and a hostile failure of `ensureTable` escapes into the outer catch of `createChargeEvent`, which skips the INSERT, where an ordinary Error from `ensureTable` is logged and the INSERT still runs; an Error whose `message` is readable but not a string (a Symbol) is handed to the logger uncoerced. The fix is the house guard placed before each logger call: read the message once inside a `try`, keep `undefined`/`null` as they are (they were logged as is), coerce anything else with `String(...)`, and fall back to the constant `'unreadable thrown value'` when the read or the coercion throws; then `error: reason`. Nothing else in the file changes.
