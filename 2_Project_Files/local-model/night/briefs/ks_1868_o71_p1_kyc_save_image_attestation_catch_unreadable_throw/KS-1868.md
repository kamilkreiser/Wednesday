## What is wrong (one paragraph)

In `index.ts` the catch block of `dbSaveImage` (the KS-386 attestation write: it records that a verified image type was submitted, never the image bytes) logs `logger.error('DB save image failed', { error: err instanceof Error ? err.message : String(err) })` (line 353) and then THROWS the authored `new AppError('The verification attestation could not be recorded. No document was accepted.', 500, 'KYC_ATTESTATION_WRITE_FAILED')`. If the INSERT rejects with a revoked Proxy, `err instanceof Error` itself throws a TypeError inside the catch block; if it rejects with an Error whose `message` getter throws, `err.message` throws. Either way the catch throws before the line is logged and before the authored AppError is thrown, so the caller sees the raw TypeError instead. The fix keeps the log line's text and replaces only the value: it first reads the SAME expression into a local `reason` inside its own `try`, and a `catch` sets the constant `'unreadable thrown value'`; the log line then uses `{ error: reason }`. The `throw new AppError(...)` that follows is untouched. This is the inline guard already merged in the same file at the five helpers above it (`dbSaveVerification`, `dbGetVerification`, `dbGetVerificationsByUser`, `dbGetVerificationStats`, `dbSaveConsent`, e.g. lines 191-198); no helper is added.
