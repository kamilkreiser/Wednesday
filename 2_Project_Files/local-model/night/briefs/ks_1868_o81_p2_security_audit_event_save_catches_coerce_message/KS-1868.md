## What is wrong (one paragraph)

In `index.ts` the save catch of `dbSaveAuditLog` and of `dbSaveSecurityEvent` reads the thrown value's message in its own `try` (`reason = err?.message;`, constant `unreadable thrown value` when the read throws) and logs `{ error: reason }`. The guard covers only the READ. If the getter succeeds and returns a hostile NON-string (a revoked Proxy, an object whose `toString` throws, a null-prototype object, a Symbol), the value is passed on uncoerced: the real winston formatter (and `JSON.stringify` in db.ts's `dbLog`) throws on some of them while formatting, INSIDE the catch, outside the guard (QA gate 112, G112-F1, measured). The helper then rejects and `POST /api/audit` or `POST /api/events` answers 500 for a record already kept in memory. The fix wraps the read: `const m = err?.message; reason = m === undefined || m === null ? m : String(m);` inside the same `try`, so a value that cannot be turned into text throws inside the `try` and the existing `catch` gives the constant.
