## What is wrong (one paragraph)

In `governanceService.ts` the catch blocks of `dbGetParticipant` (line 276) and `dbGetParticipantByAddress` (line 286) each log `logger.error('...', { <id|walletAddress>, error: err instanceof Error ? err.message : String(err) })` and then fall out of the catch to `return undefined`. If the database call rejects with a revoked Proxy, `err instanceof Error` itself throws a TypeError inside the catch block; if it rejects with an Error whose `message` getter throws, `err.message` throws. Either way the catch throws before the ERROR line is logged and before the documented `return undefined`: the exported `getParticipant` rejects with the TypeError instead of resolving undefined. The fix reads the SAME expression into a local `reason` inside its own `try`, and a `catch` sets the constant `'unreadable thrown value'`; the log call then uses `reason`. This is the inline guard already merged in the same file at `dbGetProposal` (line 218) and the other readers (lines 255, 313, 342, 448); no helper is added.
