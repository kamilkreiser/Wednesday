## What is wrong (one paragraph)

In production `getCertificationData` fetches the certification from the originate service inside a `try`; its catch block logs `logger.error('Error fetching certification data from originate service', { certificationId, error: err instanceof Error ? err.message : String(err) })` (the read is on line 177) and then `return null`. If the fetch rejects with a revoked Proxy, `err instanceof Error` itself throws a TypeError inside the catch block; if it rejects with an Error whose `message` getter throws, `err.message` throws. Either way the catch throws before the line is logged and before `return null`, so the function rejects with the TypeError. The fix reads the thrown value inside its own inner `try` into a local `reason`, falling back to the constant `unreadable thrown value`, and the log call uses `error: reason`; the `return null` is then reached as for any ordinary fetch failure. An ordinary Error still logs `error: <its message>`.
