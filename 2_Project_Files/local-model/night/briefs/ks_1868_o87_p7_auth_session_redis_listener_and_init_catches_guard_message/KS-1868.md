## What is wrong (one paragraph)

Two places in this module pass the thrown value's message straight into the logger's meta object, unguarded: the Redis client `'error'` listener (`{ error: err.message }`, followed by `redisAvailable = false`) and the catch of `initRedisSession` (`{ error: err?.message }`, followed by `redisAvailable = false`). A thrown value whose read throws (a revoked Proxy: the `.message` get throws; an Error whose `message` getter throws) therefore throws INSIDE the listener or the catch, BEFORE the `redisAvailable = false` line runs: an exception thrown by a listener of the client's `'error'` event escapes the EventEmitter as an uncaught exception and the availability flag stays `true` while the client is down, and a throwing init catch makes `initRedisSession` REJECT instead of falling back to the in-memory sessions with the flag `false`; an Error whose `message` is readable but not a string (a Symbol) is passed to the logger uncoerced. The fix is the house guard placed before each logger call: read the message once inside a `try`, keep `undefined`/`null` as they are (they were logged as is), coerce anything else with `String(...)`, and fall back to the constant `'unreadable thrown value'` when the read or the coercion throws; then `error: reason`. The `redisAvailable = false` lines are unchanged.
