## What is wrong (one paragraph)

`POST /api/users/me/change-password` verifies the current password, checks strength, writes the new hash with `userRepo.updateUserOrThrow(user.id, { passwordHash: newHash }, 'Password change')`, logs `Password changed` and answers 200. It never touches the account's sessions, so every other authenticated session on that account (including one an attacker holds after a compromise) stays live after the password is changed. The fix: directly after the existing `Password changed` log line (which itself follows the write; `updateUserOrThrow` throws if the write did not land), `const sessionsRevoked = await revokeAllUserSessions(user.id);`, and a second `logger.info` that names the count.
