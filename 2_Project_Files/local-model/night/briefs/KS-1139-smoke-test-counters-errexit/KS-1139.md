## What is wrong (one paragraph)

`smoke-test.sh` runs under `set -euo pipefail` (`:13`) and counts its results with three one-line helpers: `pass() { ((PASS++)); ... }` (`:27`), `fail() { ((FAIL++)); ... }` (`:28`), `warn() { ((WARN++)); ... }` (`:29`), each counter starting at 0 (`:22`-`:24`). A post-increment evaluates to the OLD value, so `((PASS++))` at `PASS=0` evaluates to 0 and the arithmetic command returns status 1 (measured on this host's `/bin/bash` 3.2.57: `P=0; ((P++)); echo $?` prints `1`). bash 4.1 and later apply errexit to `(( ))` (KS-1139 BLUF, bash COMPAT 45), so on Linux (CI runner bash 5.2, the Ubuntu 24.04 demo VM) the script exits rc 1 at its FIRST check and prints nothing after it — measured by Peter on bash 5.2 (KS-1148 comment 09:59Z: the `bash -x` trace ends at `+ (( PASS++ ))`). macOS `/bin/bash` 3.2 ignores that status, which is why it passes on a Mac. The script is the deploy check (`deployment/azure/RUNBOOK.md:143`, `Makefile:42`/`:45`, per KS-1139 comment). The fix is KS-1139's own shape: `X=$((X + 1))` — an assignment's status is 0 at every value and the counter's effect is identical. Not `((++X))`, not `((X++)) || true` (KS-1139 "Fix shape").
