## What is wrong (one paragraph)

Two DB catches of the Microsoft 365 OAuth state store pass `err?.message` straight into the logger's meta object, unguarded. `?.` guards a null or undefined value only: a thrown value whose read throws (a revoked Proxy: the `.message` get throws; an Error whose `message` getter throws) makes the catch THROW, so `saveOAuthState` and `consumeOAuthState` REJECT where an ordinary Error gets a logged warning and the documented outcome (save: the state is already in the in-memory map and the call resolves; consume: `null`). The fix is the house guard placed before each logger call: read the message once inside a `try` (`?.` kept), keep `undefined`/`null` as they are, coerce anything else with `String(...)`, fall back to the constant `'unreadable thrown value'` when the read or the coercion throws; then `error: reason`. The two hunks are ~34 lines apart. Nothing else in the file is touched: the token encryption and the binding-hash comparison are not edited.
