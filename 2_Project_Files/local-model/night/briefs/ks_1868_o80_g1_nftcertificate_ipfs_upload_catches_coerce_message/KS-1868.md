## What is wrong (one paragraph)

In `ipfs.service.ts` each provider `upload` method (Pinata, Infura, Web3.Storage) has a catch block that reads the thrown value's message inside its own `try` (`reason = (error as Error).message;`, with the constant `'unreadable thrown value'` when that read throws) and then returns `{ success: false, error: `<Provider> upload error: ${reason}` }`. The guard covers only the READ of `.message`. If the getter succeeds and returns a hostile NON-string (a revoked Proxy, an object whose `toString` throws, a null-prototype object, a Symbol) the template literal `${reason}` throws INSIDE the catch block, outside the guard, so `upload()` rejects instead of answering `{ success: false }` (QA gate 108, G108-F1, measured at base and head). The fix wraps the read in `String(...)` inside the same `try`, so the coercion happens where a throw is already caught: a revoked Proxy, a throwing `toString` and a null-prototype object fall to the constant `unreadable thrown value`; a Symbol becomes its readable text `Symbol(desc)`; every readable string message is byte-identical, and a thrown plain string still reads `undefined` (its `.message`), as before.
