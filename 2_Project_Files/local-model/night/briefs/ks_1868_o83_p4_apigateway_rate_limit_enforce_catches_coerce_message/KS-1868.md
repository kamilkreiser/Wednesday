## What is wrong (one paragraph)

In `middleware/rateLimitEnforce.ts` (1) `logDegraded` reads the Redis error inline when it logs the degradation; it is called inside the try of the catch that degrades to the per-replica in-memory ceiling, so when that read throws (a revoked Proxy; an Error whose `message` getter throws) the catch reports `in-memory fallback ALSO failed`, sets `outcome = null` and the request is let through uncounted, where an ordinary Redis error degrades to the in-memory ceiling; and an Error whose message is a non-string is handed to the logger as is. (2) The `writeErr` catch around the header and 429 write reads the caught value inline in its log argument; a hostile value makes the read throw inside the catch and the middleware rejects instead of letting the request through. The fix reads each value inside a `try` with the coercing form and the constant `unreadable thrown value`: `logDegraded` takes `errorText` from `err instanceof Error ? String(err.message) : err ? String(err) : undefined` (a falsy non-Error stays `undefined` as before) and the `writeErr` catch takes `reason = String(writeErr instanceof Error ? writeErr.message : writeErr)`.
