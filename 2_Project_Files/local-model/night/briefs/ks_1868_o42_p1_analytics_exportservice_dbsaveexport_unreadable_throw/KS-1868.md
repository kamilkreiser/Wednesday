## What is wrong (one paragraph)

In `exportService.ts` the catch block of `dbSaveExport` (line 55) logs `logger.info('DB save export failed', { error: err instanceof Error ? err.message : String(err) })` (the read is on line 56). If the database call rejects with a revoked Proxy, `err instanceof Error` itself throws a TypeError inside the catch block; if it rejects with an Error whose `message` getter throws, `err.message` throws. Either way the catch throws before the INFO line is logged: `dbSaveExport()` rejects, no log line is written, and every caller (`createExport`, `processExport`, in the failure path as well) is cut short instead of continuing with the in-memory copy it already set. The fix reads the thrown value inside its own inner `try` into a local `reason`, falling back to the constant `unreadable thrown value`, and the log call uses `reason`. Nothing else changes: an ordinary Error still logs `{ error: <its message> }` and the log text is unchanged.
