## What is wrong (one paragraph)

In `routes/adminConfig.ts` fifteen `catch (err: any)` blocks read the thrown value before they reach `fail500`: thirteen open with `if (err?.message?.includes('does not exist') || err?.code === '42P01') {` (an empty-list answer when a table is missing), one reads `err?.message?.includes('unique constraint')` (`:227`, a 409), one reads `err?.message?.includes('does not exist')` (`:1568`, no code test). If the thrown value is a revoked Proxy, or an object whose `message` getter throws, THAT read throws from inside the catch, before `fail500` is reached; the async handler's promise rejects and the request gets NO response (the shape KS-1772 closed for the describer, one step earlier; Gate B measured it on `systemErrors.ts:196`, not on these sites). The change adds two small helpers that do the read inside their own `try` and answer false when it throws, and the fifteen conditions call them. A value that cannot be inspected is not a missing-table or unique-constraint error, so it falls through to `fail500` and gets the constant 500. Every value that could be read before gives the same answer as before.
