## What is wrong (one paragraph)

`services/nft-certificate/src/services/ipfs.service.ts` calls `fetch` eight times with no `signal`: Pinata upload / pin / unpin, Infura upload / pin / unpin, Web3.Storage upload, and the gateway read in `IPFSService.fetch`. An endpoint that accepts the connection and never answers holds the caller for as long as the socket lives. Each provider fetch is inside a try whose catch answers a failure value (upload: `{ success: false, error }`; pin and unpin: `false`) and the gateway read's catch throws `ServiceUnavailableError`. The change adds three module constants after the `@secuura/shared` import (`IPFS_UPLOAD_TIMEOUT_MS = 60_000`, `IPFS_PIN_TIMEOUT_MS = 15_000`, `IPFS_GATEWAY_READ_TIMEOUT_MS = 30_000`, with a comment) and `signal: AbortSignal.timeout(<constant>)`: the upload constant on the three uploads, the pin constant on the four pin/unpin calls, and the read constant as a new second argument of the gateway `fetch(url)`. For a healthy endpoint nothing changes.
