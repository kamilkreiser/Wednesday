re-read in the same minutes" was executed as

base parameter on that endpoint.** So the base could move between the assertion and GitHub executing the

```
+**Merge from your own checkout, never through the API's `sha=` pin.**
+`PUT /repos/{o}/{r}/pulls/{n}/merge -f sha=X` pins the pull request's HEAD and
+nothing else — that endpoint has no base parameter — so the base can move
+between the assertion and GitHub executing the merge. On PR #852 (2026-09-06) it
+did, in a nine-second window with the protocol followed exactly: `develop` was
+asserted at 04:27:09Z, the other seat's #848 landed at 04:27:18Z, and #852
+merged at 04:27:20Z onto a parent nobody had approved. Nothing was lost in
+content — the two file sets were disjoint — but the gate's predicted merge-tree
+oid had been computed against the old base, so it did not match the tree that
+exists: a correct merge that could not be checked against its own gate.
+
+1. `git ls-remote origin develop`, then `git fetch origin develop`, then
+   `git merge --no-ff --no-edit <pr-head-sha>` onto `origin/develop` as read,
+   then `git push origin HEAD:develop`.
+2. **No `--force`, no `--force-with-lease`.** A plain push already refuses a
+   non-fast-forward, which turns a base that moved from a silent wrong merge
+   into a refused push. On refusal, re-read, re-merge onto the new tip and push
+   again — the receipt names both attempts.
+3. Every receipt carries the base line: **first parent** beside **asserted**.
+   Equal means the base held. Different means naming what landed, whether the
+   file sets are disjoint, and that the gate's predicted tree does not apply.
+4. A predicted merge-tree oid is carried as "predicted against base <sha>". A
+   differing first parent invalidates the prediction, not the merge — re-derive
+   it against the real first parent and name the new oid.
+5. The server-side `PUT ... sha=` shape is acceptable only for a seat merging
+   alone, which with two parallel seats is never. Serialising the seats was
+   explicitly not ruled: parallel stays, and the rule above is what makes a
+   lost race safe.
+
```
