## What is wrong (one paragraph)

In `minting.service.ts` the catch block of `getWalletNFTCertificates` logs `logger.error('DB get wallet certificates failed', { error: err instanceof Error ? err.message : String(err) })` (the read is on line 688) and then falls through to the sorted `certificates` return. If the database call rejects with a revoked Proxy, `err instanceof Error` itself throws a TypeError inside the catch block; if it rejects with an Error whose `message` getter throws, `err.message` throws. Either way the catch throws before the line is logged and before the normal return, so the function rejects. The fix reads the thrown value inside its own inner `try` into a local `reason`, falling back to the constant `unreadable thrown value`, and the log call uses `reason`. Nothing else changes: an ordinary Error still logs `{ error: <its message> }`.
