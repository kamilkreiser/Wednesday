## What is wrong (one paragraph)

In `signContentHashWithCert` the catch around `crypto.createPrivateKey` (line 345) and the catch around `crypto.sign` (line 359) each throw `new IssuerCertError('SIGN_FAILED', ...)` whose message template (lines 349 and 363) reads the caught value INLINE with `err instanceof Error ? err.message : String(err)`. For a caught value whose read throws (a revoked Proxy throws on `instanceof`; an Error whose `message` getter throws, throws on `.message`) the read throws while the template is built: the caller gets a bare TypeError, not the coded IssuerCertError, so the route layer's SIGN_FAILED mapping does not apply. The fix: lift the read into a local `reason` declared inside the catch, read inside its own try, with the constant `unreadable thrown value` in the inner catch; the IssuerCertError text for an ordinary Error is unchanged (`Could not load decrypted private key: <message>`, `crypto.sign failed: <message>`). Priority Low: nothing known throws such a value from node:crypto (no measurement).
