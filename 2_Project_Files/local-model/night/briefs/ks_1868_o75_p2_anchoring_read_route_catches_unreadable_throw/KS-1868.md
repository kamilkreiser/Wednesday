## What is wrong (one paragraph)

In the anchoring service `index.ts` three catch blocks that only LOG a failed anchor_store SELECT and carry on read the rejection value with `err?.message` inside the log call: the local-DB step of `handleAnchorVerifyByHash` (line 694, `log('warn', 'verify-by-hash: local DB lookup failed', { error: err?.message })`), the content-hash lookup of `POST /api/anchors/verify` (line 1304, `DB lookup anchor by content hash failed`) and `dbGetAnchorByTx` (line 1807, `DB lookup anchor by tx failed`, which then returns undefined). If the query rejects with a revoked Proxy, the property read `err?.message` itself throws a TypeError inside the catch block; if it rejects with an Error whose `message` getter throws, `err?.message` throws. Either way the catch throws before the log line and before its documented fall-through. At the tip: line 694 and line 1304 hand the TypeError to the route's own outer catch (500 for verify-by-hash with `details`, `next(error)` for POST verify) instead of continuing to the chain step / the verified:false answer; line 1807 leaves the async handler of `GET /api/anchors/tx/:txHash` (no try) with a rejection, so Express 4 sends NO response and Node sees an unhandled rejection. The fix reads the SAME expression `err?.message` into a local `reason` inside its own `try`, and a `catch` sets the constant `'unreadable thrown value'`; the log call then uses `reason`. This is the inline guard already merged in `services/auth` `routes/auth.ts` (PR 1911, lines 308-313) and `services/originate` `routes/certifications.ts` (KS-1844); no helper is added.
