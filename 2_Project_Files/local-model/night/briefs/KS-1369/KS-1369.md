## What is wrong (one paragraph)

`createServiceProxy` (`:162`) builds the http-proxy-middleware options for every proxied service. Its `onProxyReq` hook (`:242`) writes headers onto the OUTGOING request: `X-Request-ID` (`:246`), the vouch (`:276`), the policy headers (`:282`, `:286`), `Authorization` (`:296`), and the body re-stream's `Content-Type`/`Content-Length` plus `proxyReq.write` (`:312`-`:316`). None of them checks `proxyReq.headersSent`. Under load (KS-1354 k6 runs, auth DB pool timing out), Node answered the first one, `setHeader('X-Request-ID', ...)`, with `Cannot set headers after they are sent to the client`; the throw escaped as an uncaught exception from http-proxy's event emitter and the gateway process exited, 13 restarts in about five minutes and 11,362 nginx 502s on `POST /api/auth/login` (KS-1369, 31 occurrences in the gateway log, trace `dist/routes/proxy.js:254` = source `:246`). **This task: the hook's FIRST statement returns when `proxyReq.headersSent` is true, so none of the writes runs.** When `headersSent` is false, every line of the hook behaves exactly as today.
