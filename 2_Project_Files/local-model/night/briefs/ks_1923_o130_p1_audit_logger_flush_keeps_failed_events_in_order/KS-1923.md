## What is wrong (one paragraph)

In `Blockchain/Dev/packages/shared/src/security/audit-logger.ts` `AuditLogger.flush` (lines 312-333) copies the buffer, empties it and loops. In the `catch` it calls `logger.error(...)` (line 328) and only THEN puts the event back with `this.eventBuffer.unshift(event)` (line 330). Two defects follow, both read at source in the ticket and again here: (F1) if `logger.error` throws, the `unshift` is skipped, the throw leaves `flush`, and the event (and every later event of that flush) is dropped; (F3) each failure is `unshift`ed to the FRONT, so failures A then B leave the buffer as B, A, and the retry delivers them in reverse order, so the audit hash chain does not verify in delivery order. The fix: collect failed events in a local array in the order they failed; log the failure inside its own try/catch (the event is already kept); after the loop put the whole array back in front of the buffer once, with `this.eventBuffer.unshift(...failed)`.
