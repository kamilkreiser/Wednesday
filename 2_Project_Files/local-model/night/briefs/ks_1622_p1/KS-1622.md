## What is wrong (one paragraph)

`GET /api/platform/audit-log` reads the tenant-provisioning half in windows. At `:491` the route warns when a window answers `!r.ok`, but only while `collected.length === 0`, i.e. the first window. A second window that answers HTTP 500 or 503 with a JSON body such as `{"entries":[...],"total":3}` passes `:491` (something is collected), passes the `:493` list check (the body is a list), and its rows are pushed at `:496`: the caller gets 200 and an operator gets no log line, so a degrading upstream looks healthy from the logs. The fix is one more guard directly after `:493`: `if (!r.ok && collected.length > 0) logger.warn(<same message>, { status: r.status, windowsRead })`. `windowsRead` is the number of windows already read (1 for the second window), the same field the first-window warn and the catch use.
