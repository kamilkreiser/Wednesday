## What is wrong (one paragraph)

`check.cjs` reads each installed `@secuura/*` package's `package.json` in `packageJsonOf` (`:299-304`). When tsc reports TS2307 or TS7016 for a SUBPATH of such a package, the fatal loop (`:316-345`) calls `declTargetsFor(found.pkg, sub)`, which reads `pkg.typesVersions` (`:307`). A manifest that is literally `null` parses to `null` (valid JSON), so `pkg.typesVersions` throws `TypeError: Cannot read properties of null (reading 'typesVersions')`, which is outside any try/catch on the fatal side, and the checker dies with a stack trace instead of printing its verdict. npm would not install such a package, so this is a robustness gap, not a live failure (ticket: "reachable only by hand"). The note side already survives it (`MJ1 ... literally null`, a try/catch). Reading the null as an empty manifest, `JSON.parse(...) || {}`, fixes both sides at the one place the file is read.
