## What is wrong (one paragraph)

`userRepo.updateUser(user.id, updates)` at line 933 and then answers `success: true` unconditionally (line 937),
using `updated?.id` etc. Since KS-943, `updateUser` returns `null` when its UPDATE matched 0 rows (fail-closed RLS
with an unresolved tenant GUC). So a write that never landed is reported to the caller as a successful profile update
with `undefined` fields. The wallet routes already check this return (`routes/wallet.ts:488-495`) and throw an
`AppError(..., 500, 'WALLET_LINK_NOT_PERSISTED')`; this handler does the same, with its own code. (Wednesday's
reading of the ticket's "a 5xx like the wallet paths now do" — the in-file precedent — chosen for consistency.)
