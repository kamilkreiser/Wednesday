## What is wrong (one paragraph)

`UpdateOAuthAppSchema` (`oauth.ts:1299-1306`) declares `redirectUris: z.array(z.string().url()).optional()`. The create schema (`CreateOAuthAppSchema`, `:1179-1181`) declares `z.array(z.string().url()).min(1)`. So an app can be created valid and then patched into the zero-redirect-URI state with `PATCH /api/oauth/apps/:id {"redirectUris": []}`: the schema passes it and the handler calls `updateApp` with an empty list. The fix inserts `.min(1)` before `.optional()` so an empty array is a 400 (the handler's existing `safeParse` failure path) while an omitted key stays legal (a PATCH that changes only the name still works).
