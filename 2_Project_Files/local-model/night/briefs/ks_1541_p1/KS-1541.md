## What is wrong (one paragraph)

`secuura_get_connector_info` drops `connectorResult` to `null` whenever it is not `ok` (`:128`) and then answers the fixed note `Connector info not available (endpoint may not exist yet or no API key set)` (`:148`). `api-client.ts` already returns `{ status, ok, data }`, so the status and the gateway's error body are in hand and thrown away. A 403 or 503 is the gateway refusing on purpose (a malformed or unreadable allow-list), and the note sends an operator to the wrong cause. The fix computes `connectorNote` right after `:128`: for a result that exists, is not ok, and is neither 401 nor 404, it names the status and the gateway's error text (a string `error`, or `error.message`); otherwise it keeps the old note. `:148` then uses `connectorNote`.
