## What is wrong (one paragraph)

`POST /generate-package` in `services/mcp-server/src/http-server.ts` reads `allowedDocumentTypes` from the request body and hands the generator `allowedDocumentTypes || []` (`:258`). A present value that is not a list but is falsy (`""`, `0`, `false`) therefore becomes `[]`, which `MCP Deployment/troubleshooting.md:123` documents as "all types permitted", and the endpoint answers 200: the caller sent something that is not a list and gets back a package that says the connector is unrestricted. The gateway refuses the same stored value with a 403 (KS-1232). The change: directly before the `apiKey` check, answer 400 BAD_REQUEST when `allowedDocumentTypes` is present (not `undefined`) and is not an array, before any response header is set and before the generator runs. An omitted `allowedDocumentTypes` still defaults to `[]` at `:258`, which stays as it is. The existing characterisation pin (`ks1232-generate-package-doctypes-default.test.ts`) asserted today's behaviour and is flipped in place.
