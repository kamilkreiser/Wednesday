## What is wrong (one paragraph)

`chainOnlyMatch` (line 231) answers a hash known only to the chain index. It builds the blob it hands to `presentBlockchainHonestly` (lines 232 to 239) from `anchored: true`, `network`, `txHash`, `blockHeight`, `cardanoScanUrl` and `confirmedAt`, and never `simulated`. `presentBlockchainHonestly` decides on `Boolean(b.simulated)` or a placeholder-looking `txHash`, so with `simulated` dropped a reply that declares itself simulated is judged on the `txHash` prefix alone. Anchoring removes that signal itself (a simulated reply carries `simulated: true, txHash: null`), so the live shape reaches the presenter looking real: `blockchain.anchored` stays `true` with no `simulated` marker and no top-level `simulated: true` on the match. A reply with `simulated: true` beside a real 64-hex `txHash` (not producible by anchoring today, defence in depth) is worse: `checks.isAnchored` reads `true`. The fix is one inserted line, `simulated: chain.simulated,`, after `confirmedAt: chain.confirmedAt,`, so the existing rule decides; the match already surfaces `simulated: true` at the top level from the presenter's answer (line 254). Everything else is unchanged.
