## What is wrong (one paragraph)

`POST /api/auth/reset-password` checks the strength, finds the reset token and the user, writes the new hash with `userRepo.updateUserOrThrow(user.id, { passwordHash: newHash }, 'Password reset')`, burns the token and answers 200. It never touches the account's sessions, so every session the old password minted (including one an attacker holds) stays live after the user has reset the password to get rid of them. The fix: import `revokeAllUserSessions` from `../services/session` (the import line already names four functions from it), and directly after the `updateUserOrThrow` line and before `await userRepo.consumeResetToken(tokenHash);` add `const sessionsRevoked = await revokeAllUserSessions(user.id);` with a log line that names the count.
