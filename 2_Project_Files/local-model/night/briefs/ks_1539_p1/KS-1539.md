## What is wrong (one paragraph)

The info reader (`GET /api/connector/info`, `health.ts`) reads the connector allow-list with `redisService.getNotificationSettings('platform-settings')` inside a `try`. Since KS-1532 a THROWN read answers `503 SERVICE_UNAVAILABLE` ('Connector allow-list configuration could not be read; refusing until it can be read'), but the `catch` (`:77`) binds no error and logs nothing, so an operator who sees connector 503s has no server-side line saying which fault it was. The shapes that reach that catch look identical from outside and need different responses: the Redis client's `MaxRetriesPerRequestError` (an outage) and the `SyntaxError` from `JSON.parse` on malformed stored bytes (`services/redis.ts:675`, corrupted settings). The fix binds the error and logs one warn with the route and the error's class, then keeps the 503 exactly as it is. `utils/logger.ts` exports the module `logger` (winston); `health.ts` does not import it yet.
