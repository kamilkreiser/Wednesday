## What is wrong (one paragraph)

`check-shared-relink.sh` checks that every Dockerfile consuming the `shared-builder` stage re-creates the `node_modules/@secuura/shared` symlink in its final stage, after the last write to `node_modules` and while the effective user can create it. Two of its readings are narrower than the rule they implement, and both produce a FALSE BLOCK with a message that is untrue about the file. (F-C) The re-link test at `:418` accepts a destination path *ending at* `node_modules/@secuura/shared` (F-4's rule, written in the comment at `:411`-`:417`) through the optional prefix group `(\/[^ \t]*\/)?` — which requires the prefix to START with `/`, so `ln -s /shared ./node_modules/@secuura/shared` and `ln -s /shared app/node_modules/@secuura/shared` (the same symlink, written relative) are reported as "final stage has NO `ln -s …`". (F-E) The USER reader at `:435` keeps the whole `USER` value, and `effective_user_is_unprivileged` (`:520`-`:528`) treats only the exact strings `root` and `0` as root, so `USER root:root` and `USER 0:0` — root with an explicit group — are read as a non-root user and the legitimate F-2 shape (root → re-link → drop privileges) is reported as "the re-link runs after a non-root `USER`". The fixes: let the prefix group be any non-space run ending in `/` (`([^ \t]*\/)?`), and drop a `:group` suffix from the USER value before it is stored (`sub(/:.*$/, "", u)`).
