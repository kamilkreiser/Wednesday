## What is wrong (one paragraph)

In `Blockchain/Dev/services/transfer/src/services/approvalWorkflowService.ts`, `processEscalations` (line 605) selects every overdue pending step instance and, per row, looks up the step's workflow with `this.findWorkflowByStepId(instance.stepId)` (line 622). `findWorkflowByStepId` reads the workflows through `dbGetActiveWorkflows` (a bare `catch { return []; }`) and then a second `SELECT * FROM svc_approval_workflows` whose failure is swallowed (`catch { /* fall back to active-only */ }`); if both reads fail it returns `undefined`. Then `stepDef` is `undefined`, the test at line 625 (`stepDef?.autoEscalate && stepDef.escalateTo && !instance.escalatedAt`) is false, and the `else` branch (lines 635-640) sets `status = 'timed_out'` and writes it. `timed_out` is terminal: the sweep selects only `status = 'pending'` rows, and an approval refuses a step that is not pending. So a step configured to auto-escalate loses its escalation silently and a second sweep cannot repair it. The fix (the ticket's): when the workflow cannot be found, skip the row and leave it pending.
