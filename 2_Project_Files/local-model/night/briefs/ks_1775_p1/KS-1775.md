## What is wrong (one paragraph)

`expectRun`'s string branch is `expect(r.out, message).toContain(output)` (`:89`), a substring match. Four ordinary call sites pass the bare string `'0 new'` as their output predicate: `:581`, `:628`, `:915` (each `expectRun(r, 0, '0 new');`) and `:1034` (`expectRun(check(dir, '--baseline', bl(dir)), 0, '0 new', 'the baseline it wrote is trusted');`). The checker prints one summary line, `... N errors: M in the baseline, K new; S stale baseline entries.` (`check.cjs:534-535`), and `'0 new'` is also a substring of `10 new`, `20 new` and so on, so a run that reports ten new errors but still exits 0 would keep these four cells green. The status argument catches that today only because a run with new errors exits 1; the predicate itself pins nothing about the count. The fix is to name the whole tail of the line, the same shape the file already uses at `:934`/`:943` (`'0 new; 0 stale baseline entries'`): `', 0 new; 0 stale baseline entries'`. The leading `, ` is what a `10 new` cannot satisfy, and a run that exits 0 always has zero stale entries, so the longer predicate is true at every one of the four sites.

## Where
