## What is wrong (one paragraph)

In `db.ts` the catch of `runDbReadyHook` and the catch of `probeDb` read the thrown value's message in their own `try` (`reason = err?.message;`, constant `unreadable thrown value` when the read throws). The guard covers only the READ. If the getter succeeds and returns a hostile NON-string (a revoked Proxy, an object whose `toString` throws, a null-prototype object, a Symbol), the value is passed on uncoerced: the real winston formatter (and `JSON.stringify` in db.ts's `dbLog`) throws on some of them while formatting, INSIDE the catch, outside the guard (QA gate 112, G112-F1, measured). For the boot hook `dbLog` builds its line with `JSON.stringify`, which throws on a revoked Proxy, so `initDb` REJECTS instead of resolving true; for the probe the value is returned as `error` and reaches the same `dbLog` in `initDb`, where `initDb` also rejects. The fix wraps the read: `const m = err?.message; reason = m === undefined || m === null ? m : String(m);` inside the same `try`, so a value that cannot be turned into text throws inside the `try` and the existing `catch` gives the constant.
