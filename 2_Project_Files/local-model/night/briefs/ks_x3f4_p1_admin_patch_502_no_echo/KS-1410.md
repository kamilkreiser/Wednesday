## What is wrong (one paragraph)

In `services/api-gateway/src/routes/admin.ts`, `router.patch('/api/users/admin/:id', ...)` forwards the PATCH to the auth service. When that forward throws (a refused connection, a DNS failure, a cut-off body), the `catch (err: any)` answers `502` with the body `{ success: false, error: { code: 'BAD_GATEWAY', message: 'Auth service unavailable', details: { details: err.message } } }`, so the thrown error's own text (a driver message or an internal host:port) reaches the client. The same 502 in `routes/proxy.ts` (:514, :546) carries no `details`. The fix: in that `catch`, log the thrown text server-side with the router's injected `log` function at level `'error'` (a short fixed message that names the route, and the thrown text in the meta object, taken as `err instanceof Error ? err.message : String(err)`), and answer the constant `{ success: false, error: { code: 'BAD_GATEWAY', message: 'Auth service unavailable' } }` with NO `details` key. Nothing else in the handler changes: the status 502, the code and the message stay exactly as they are.
