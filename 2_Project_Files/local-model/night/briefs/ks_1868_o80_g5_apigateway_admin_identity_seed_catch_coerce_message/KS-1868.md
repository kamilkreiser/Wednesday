## What is wrong (one paragraph)

In `routes/admin.ts` the demo-seed catch (`seedIdentityOrgsIfEmpty`, awaited at the start of GET /api/admin/identity/users and /organizations) reads the thrown value's message in its own `try` and logs `'[Identity] Seed skipped: ' + reason`. The guard covers only the READ. If the getter succeeds and returns a hostile NON-string (a revoked Proxy, an object whose `toString` throws, a null-prototype object, a Symbol), the `+` throws INSIDE the catch, so the seed helper rejects and both identity list routes answer 500 instead of carrying on (QA gate 110, G110-F1, measured). The fix wraps the read in `String(...)` inside the same `try`; a Symbol becomes its text `Symbol(desc)`.
