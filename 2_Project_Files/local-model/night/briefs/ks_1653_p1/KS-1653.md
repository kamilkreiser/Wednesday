## What is wrong (one paragraph)

`hasUsersStubScope` (`users.ts:247-259`) decides whether a caller's scopes admit `POST /api/users/stub`. It accepts `*`, `users:*`, `users:read`, `users:create`, and, for KS-564 Option A, `certifications:write`. Platform S's minted connector set carries `documents:transfer-custody` and `certifications:write` but deliberately NOT `users:read`, so S's transfer-custody calls reach `/stub` and are admitted only because S may also write certifications: the scope that admits them has nothing to do with the operation. It works, but the gate is named for the wrong operation and the only thing standing between a scope-set edit and every Platform-S transfer answering a 403-driven 502 is a transcription test in originate. The fix inserts, directly before the final `return scopes.includes('certifications:write');`, a comment line and `if (scopes.includes('documents:transfer-custody')) return true;`. The final `return` is unchanged, so `certifications:write` stays admitted.
