## What is wrong (one paragraph)

The GitHub, Google and LinkedIn adapters (`services/auth/src/providers/social/github.ts`, `google.ts`, `linkedin.ts`) call `fetch` seven times in all (github: token exchange, `/user`, `/user/emails`; google: token exchange, userinfo; linkedin: token exchange, userinfo) with no `signal`. An identity provider that accepts the connection and never answers holds the OAuth callback request open for as long as the socket lives. In each adapter `exchangeCode` already lets a rejected fetch propagate, so a timeout needs no new handling.
