## What is wrong (one paragraph)

In `src/index.ts`, `dbSaveApiKey` ends in `} catch (err: any) { logger.error('DB save API key failed', { error: err?.message }); if (opts.rethrow) throw err; }` (tip lines 474-479). If the save rejects with a revoked Proxy, or with an Error whose `message` getter throws, the `err?.message` read throws INSIDE the catch: the line is never logged, and the caller receives the TypeError the read raised instead of the value (both callers, POST /api/keys and DELETE /api/keys/:id, pass `rethrow: true`). The fix keeps the logged text and replaces only the value: it first reads the SAME expression `err?.message` into a local `reason` inside its own `try`, and a `catch` sets the constant `'unreadable thrown value'`; the log then carries `reason`. The `if (opts.rethrow) throw err;` line is not touched, so the original value now reaches the callers' own catches, which PR 1912 already guards. This is the inline guard already merged in this file; no helper is added.

One narrow difference: an Error whose `message` getter throws but whose `code` is readable and infrastructure-looking (for example ECONNREFUSED) now reaches the caller with its code and is classified 503, which is what an ordinary Error with that code already gets; today the TypeError has no code and answers 500. No key validity or revoke decision is made in this function.
