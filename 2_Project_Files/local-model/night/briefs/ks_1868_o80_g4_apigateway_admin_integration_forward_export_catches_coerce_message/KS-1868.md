## What is wrong (one paragraph)

In `routes/admin.ts` three catches read the thrown value's message in their own `try` (constant `unreadable thrown value` when the read throws) and then use `reason`: the Blockfrost connectivity test answers `Network error: ${reason}`, the PATCH user-update forward answers 502 with `details: { details: reason }`, the audit export logs `{ error: reason }` and answers a constant 500. The guard covers only the READ. If the getter succeeds and returns a hostile NON-string (a revoked Proxy, an object whose `toString` throws, a null-prototype object), the template literal throws inside the catch (integration test: no answer), the forward puts the hostile value into `res.json` (revoked Proxy: no answer; others: 502 carrying a hostile value) and the export passes it to the logger (real winston throws on a revoked Proxy: no answer) (QA gate 110, G110-F1, measured at base and head). The fix wraps each read in `String(...)` inside the same `try`.
