## What is wrong (one paragraph)

`Blockchain/Dev/services/auth/src/services/issuerCertSweep.ts` has three `.catch` handlers that still read the rejection value inside the logger call, unguarded: the `ISSUER_CERT_EXPIRING_SOON` publish (lines 127 to 133: `error: err instanceof Error ? err.message : String(err)`), the startup sweep (lines 171 to 175, message `Initial issuer cert sweep failed`) and the scheduled sweep inside the `setInterval` (lines 179 to 183, message `Scheduled issuer cert sweep failed`). For a value that cannot be read (a revoked Proxy makes `instanceof` throw; an Error whose `message` getter throws) the handler itself throws, which is an unhandled rejection; an Error whose `message` is not a string (a null-prototype object, a Symbol) is handed to the logger as is. The neighbouring handlers (lines 64 to 72, 86 to 95, 105 to 113) were guarded by KS-1868 with exactly this shape: `let reason: string; try { reason = String(err instanceof Error ? err.message : err); } catch { reason = 'unreadable thrown value'; }` and the logger gets `error: reason`. The fix gives the three handlers the same shape. Nothing else changes: the messages, the other fields, the `setInterval`, the sweep body.
