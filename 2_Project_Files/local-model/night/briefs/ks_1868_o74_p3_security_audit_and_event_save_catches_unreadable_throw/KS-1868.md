## What is wrong (one paragraph)

In `src/index.ts`, `dbSaveAuditLog` (tip lines 176-178) and `dbSaveSecurityEvent` (lines 192-194) each end in `} catch (err: any) { logger.error('<message>', { error: err?.message }); }` and swallow the failure (the record is already kept in memory first). If the insert rejects with a revoked Proxy, or with an Error whose `message` getter throws, the `err?.message` read throws INSIDE the catch, so the helper rejects instead of swallowing, nothing is logged, and POST /api/audit / POST /api/events answer 500 (through their own `next(error)`) for a record that is in memory. The fix keeps the logged text and replaces only the value: it first reads the SAME expression `err?.message` into a local `reason` inside its own `try`, and a `catch` sets the constant `'unreadable thrown value'`; the log then carries `reason`. This is the inline guard already merged in this file; no helper is added.
