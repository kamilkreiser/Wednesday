## What is wrong (one paragraph)

The catch of `GET /api/certifications/:id` (`routes/certifications.ts`, handler at :1020, catch at :1065) reads the thrown value without any guard: `(error as { code?: string })?.code ?? (error as { meta?: { code?: string } })?.meta?.code` (:1073), `error instanceof Error && error.message.includes('22P02')` (:1074) and, for the log line, `error instanceof Error ? error.message : String(error)` (:1077). A thrown value whose property read throws (a revoked Proxy: every read AND `instanceof` throw; an Error whose `code` or `message` getter throws) throws inside the catch. The handler is `async` on Express 4, which does not forward a rejected handler promise, so the request gets no answer at all (the same mechanism KS-1798 measured on the gdpr routes). Fix: do the classification reads inside a `try` that falls to `invalidId = false`, and the log-line read inside a second `try` that falls to a fixed text, so a value that cannot be read gets the constant 500 below. Behaviour for every readable thrown value is unchanged.
