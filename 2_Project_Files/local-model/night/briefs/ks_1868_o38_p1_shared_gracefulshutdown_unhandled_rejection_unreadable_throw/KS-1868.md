## What is wrong (one paragraph)

In `gracefulShutdown.ts` the listener returned by `createUnhandledRejectionHandler` (the `unhandledRejection` handler body, starts at line 51) computes `const detail = reason instanceof Error ? `${reason.message}\n${reason.stack ?? ''}` : String(reason);` (lines 52-53) BEFORE it either logs (mode 'survive', the api-gateway) or logs and calls `shutdown('unhandledRejection')` (mode 'exit'). If the rejection reason is a revoked Proxy, `reason instanceof Error` itself throws a TypeError ("Cannot perform 'getPrototypeOf' on a proxy that has been revoked"); if it is an Error whose `message` getter throws, `reason.message` throws. Either way the listener throws before it logs or shuts down: in 'survive' mode that is the front-door outage KS-546 was written to prevent (the survive path was the point), in 'exit' mode the process takes an uncaughtException instead of the orderly shutdown. The fix reads the reason inside its own inner `try` into `let detail: string`, falling back to the constant `unreadable thrown value`. Nothing else changes: an ordinary Error or string reason produces the same log text, the same mode behaviour and the same `survived` counter.

+function run(mode: 'exit' | 'survive', reason: unknown): Outcome {
+  const out: Outcome = { threw: false, logs: [], shutdowns: [] };

+      out.logs.push(m);

+    shutdown: (s: string) => {
+      out.shutdowns.push(s);
+    },
+  });
+  try {
+    handler(reason, Promise.resolve());

+    out.threw = true;
+  }
