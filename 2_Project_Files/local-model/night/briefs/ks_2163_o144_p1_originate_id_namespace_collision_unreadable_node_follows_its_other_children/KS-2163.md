## What is wrong (one paragraph)

In `services/originate/src/utils/idNamespaceCollision.ts` `driverRecords`, the up-front read of a node's fields (line 70) sits in a `try`. When it throws, the `catch` visits only `o.cause` and returns. The normal walk (lines 75-80) that visits every own key runs only for a readable node. So an unreadable outer node (a throwing getter, a Proxy trap) with a readable 050/051 refusal under another child (for example `meta.driverAdapterError.cause` under a Prisma wrapper, or an `errors` array) yields no record, `isIdNamespaceCollision` answers false and the route answers 500 instead of 409. The fix keeps the existing cause visit and also visits the node's own enumerable keys, each in its own try, with the same depth bound and seen-set.
