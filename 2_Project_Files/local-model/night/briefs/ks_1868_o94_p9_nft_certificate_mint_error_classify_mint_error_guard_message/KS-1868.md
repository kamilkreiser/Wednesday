## What is wrong (one paragraph)

`classifyMintError` reads `error instanceof Error ? error.message : String(error)` into `message` with no guard. A thrown value whose read throws (a revoked Proxy: `instanceof` throws on it; an Error whose `message` getter throws) makes `classifyMintError` THROW, from inside the mint route's own catch, where an ordinary Error is classified into `{ message, errorCode }`. The fix is the house guard: read the value inside its own `try` and fall back to the constant `'unreadable thrown value'`, which then takes the same default as any unrecognised failure (`MINT_FAILED`). The classification of every value that can be read is unchanged. FORM OF THIS BRIEF: the probe form. The diff is a pure insertion of one `try` block that reads the same values once before the existing statement and returns `{ message: 'unreadable thrown value', errorCode: 'MINT_FAILED' }` when the read throws; the existing statement is left byte-for-byte untouched (a hunk that ended on it would end before a blank line, which the builder refuses). A Claude seat may prefer the restructured single-read form when raising.
