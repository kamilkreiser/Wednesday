## What is wrong (one paragraph)

`GET /api/callback` (`index.ts:455-518`) is the redirect Microsoft sends the browser to; its own comment says "No auth required". On a provider error (`?error=...`) it logs and redirects at `:465` to `${FRONTEND_URL}/admin/integrations?m365=error&message=${encodeURIComponent(String(error_description || oauthError))}`: the provider-supplied `error_description` goes into the URL with NO length cap. Anyone can send an admin to that callback URL with a long, attacker-chosen `error_description`, which then rides in the redirect to the most privileged UI. `services/auth` caps the same field at `String(...).slice(0, 200)` (measured by the ticket: 1 hit in `routes/auth.ts`, 0 in this file). The fix is the same cap on this one expression: `.slice(0, 200)` on the `String(error_description || oauthError)` value before `encodeURIComponent`. A short description, and the `error` code when there is no description, are reflected exactly as before.
