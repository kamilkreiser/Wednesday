## What is wrong (one paragraph)

`enforceDocumentTypeRules` (`services/enforcement.ts`) reads `const userLevel = user.verificationLevel || 'none';` (`:152`) and calls `meetsVerificationLevel(userLevel, requiredLevel)`, which reads `(userLevel || 'none').toLowerCase()` (`:55`). If the token's `verificationLevel` claim is a truthy NON-string (a number, an array, an object), the `||` keeps it and `.toLowerCase()` throws a TypeError; the 403 text also calls `userLevel.toUpperCase()`. The KS-529 wrapper turns the throw into a 500 on `POST /api/documents`. The change makes both reads treat a non-string (or empty) level as `'none'`: `meetsVerificationLevel` reads `typeof userLevel === 'string' && userLevel ? userLevel : 'none'` and the caller computes `userLevel` the same way, so the 403 text names the level `NONE`. A string level behaves exactly as before.

- `services/enforcement.ts:152` - **must change**: `  const userLevel = user.verificationLevel || 'none';` becomes `  const userLevel = typeof user.verificationLevel === 'string' && user.verificationLevel ? user.verificationLevel : 'none';`.
