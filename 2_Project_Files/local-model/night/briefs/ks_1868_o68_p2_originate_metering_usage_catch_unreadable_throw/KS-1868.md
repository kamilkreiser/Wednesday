## What is wrong (one paragraph)

In `routes/metering.ts` the handler of `GET /usage` (line 108) awaits `getUsageSummary(reqTenantId(req), from, to)` and, in its catch (line 128), logs `logger.error('Failed to read metering usage', { error: error instanceof Error ? error.message : String(error) });` (line 129) and then answers the CONSTANT 500 `{ success: false, error: { code: 'INTERNAL_ERROR', message: 'Failed to read usage' } }`. If the query rejects with a revoked Proxy, `error instanceof Error` itself throws a TypeError inside the catch; if it rejects with an Error whose `message` getter throws, `error.message` throws. Either way the catch throws before anything is logged and before the 500 is sent; the async handler rejects, Express 4 does not catch that, and the request gets no response. The fix keeps the `logger.error` line's text and replaces only the value: it first reads the same expression into a local `reason` inside its own `try`, and a `catch` sets the constant `'unreadable thrown value'`; the log line then uses `{ error: reason }`. This is the inline guard already merged in originate `routes/certifications.ts` (`let reason`, around line 1087); this file has no helper and none is added. The `res.status(500).json(...)` lines are NOT touched.
