## What is wrong (one paragraph)

`requireKeyAdmin` (`services/security/src/index.ts:1100-1107`) is the gate in front of `GET /api/keys` and `DELETE /api/keys/:id`. It computes `String((req as any).user?.role || '').toUpperCase()` and tests membership of `KEY_ADMIN_ROLES` (`SYSTEM_ADMIN`, `SUPER_ADMIN`, `ORG_ADMIN`, `ISSUER_ADMIN`, `ADMIN`). `toUpperCase` is not an identity test: U+0131 (dotless i) upper-cases to `I`, U+017F (long s) upper-cases to `S`, and `String(['ISSUER_ADMIN'])` is `'ISSUER_ADMIN'`, so a role claim spelled `\u0131ssuer_admin` or `\u017fuper_admin`, or carried as an array, is admitted as a key admin (the pull request 1539 gate measured 200/201 on the key routes for these spellings). The change replaces the `role` line with four lines: read the claim, and apply an ASCII-only fold (`claim.replace(/[a-z]/g, (ch) => ch.toUpperCase())`) when it is a string, or `''` when it is not, so a non-string role is refused. Every ASCII spelling admitted before (`ISSUER_ADMIN`, `issuer_admin`, `Issuer_Admin`) is admitted now. Reachability of a token carrying such a role is NOT established (the ticket says so).
