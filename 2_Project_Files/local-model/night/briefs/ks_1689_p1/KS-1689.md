## What is wrong (one paragraph)

`GET /api/connections/:id` (`index.ts:776-797`) answers `status`, `scopes`, `connectedAt`, `lastSyncAt` and `tokenExpired`. A sign-in that fails closed (KS-1682) stores `refreshToken = ''` and the callback still writes `status = 'connected'`; about an hour later the connection is stuck for good (Graph 401, `POST /refresh` answers 400 "No refresh token available") while the status read says `connected`. Nothing on the read tells a caller that the user has to sign in again. The fix is one derived property on the status read's response object, directly after `tokenExpired` (`:794`): `needsReauth: connection.status === 'connected' && !connection.refreshToken`. `connection` is the `M365Connection` the route already holds (`refreshToken?: string`), and the expression is a boolean, so it type-checks. A `disconnected` connection (its token cleared by DELETE), an `error` one and a `pending` one are not flagged, because their status is not `connected`.
