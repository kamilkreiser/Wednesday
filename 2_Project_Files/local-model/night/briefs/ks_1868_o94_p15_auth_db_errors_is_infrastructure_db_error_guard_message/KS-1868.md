## What is wrong (one paragraph)

`isInfrastructureDbError` reads `e.code` and `e.message` of the thrown value with no guard. A revoked Proxy passes the `typeof err === 'object'` test and then throws on both reads, and an object whose `code` or `message` getter throws throws on its read, so the predicate THROWS from inside its caller's catch, where an ordinary error gets true or false. The fix is the house guard: read both once, into a plain object, inside one `try`, and answer false when the read throws (an unreadable value is not known to be an infrastructure failure). The answer for every value that can be read is unchanged. FORM OF THIS BRIEF: the probe form. The diff is a pure insertion of one `try` block that reads the same values once before the existing statement and returns `false` when the read throws; the existing statement is left byte-for-byte untouched (a hunk that ended on it would end before a blank line, which the builder refuses).
