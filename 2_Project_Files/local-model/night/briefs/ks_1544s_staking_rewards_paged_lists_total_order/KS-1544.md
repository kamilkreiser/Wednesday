## What is wrong (one paragraph)

In `services/staking`, two paged reads in `src/routes/rewards.ts` sort on a column that is not unique and then page with `LIMIT ... OFFSET ...`, so rows that tie on the sort key have no defined order between two queries and a page walk can repeat or skip them. `GET /history/:address` (`:315`) reads `SELECT * FROM svc_reward_claims WHERE address = $1 ORDER BY claimed_at LIMIT $2 OFFSET $3`; `GET /distributions` (`:362`) reads `SELECT * FROM svc_revenue_distributions ORDER BY distributed_at LIMIT $1 OFFSET $2`. THE FIX: make the primary key the last sort key, changing ONLY the ORDER BY words: `ORDER BY claimed_at, id LIMIT $2 OFFSET $3` and `ORDER BY distributed_at, id LIMIT $1 OFFSET $2`. Both tables have `id TEXT PRIMARY KEY` (migrations/002_verification-tiers.sql:693 and :703); the sort direction stays ascending, as it is. The rest of each line (the `SELECT`, the `WHERE`, the placeholders and the quotes) stays byte for byte.
