## What is wrong (one paragraph)

In `routes/verification.ts` the outer catch blocks of POST /verify (line 1437), POST /hash (line 1466) and GET /status/:documentId (line 1488) each log `logger.error('<context>', { error: error instanceof Error ? error.message : String(error) })` (lines 1438, 1467, 1489) and then answer the constant 500 (`Verification failed`, `Hash generation failed`, `Status check failed`). If a call in the try throws a revoked Proxy, `error instanceof Error` itself throws a TypeError inside the catch; if it throws an Error whose `message` getter throws, `error.message` throws. Either way the catch throws, nothing is logged and the request gets no answer. The fix keeps each log line's text and replaces only the value: it first reads the same expression into a local `reason` inside its own `try`, and a `catch` sets the constant `'unreadable thrown value'`; the log line then uses `{ error: reason }`. The constant 500 answers are untouched. This is the inline guard already merged in `routes/certifications.ts` (GET /:id catch, lines 1086-1094: `let reason: string; try { ... } catch { reason = 'unreadable thrown value'; }`); no helper is added.
