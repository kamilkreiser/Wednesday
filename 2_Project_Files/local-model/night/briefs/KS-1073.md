## What is wrong (one paragraph)
In `services/api-gateway/src/routes/verification.ts` the verify handler's `persistedAnchored` predicate (lines 681–686)
keeps a legacy carve-out: a blob with NO `status` (`persistedStatus == null`, line 685) is treated like `'confirmed'`.
That carve-out exists for TIER-1 legacy documents (originate's seeded demo documents, KS-1057 — the `REGRESSION: a
legacy statusless blob` cell). But the same predicate is reached by TIER-2 blobs synthesised from the anchor store
(`makeFetchDocFromAnchorStore`, line 264 onward, which marks them `_source: 'anchor_store'` at line 345 and copies
`status: latest.status` at line 312). Tier 2 only carries a status because anchoring happens to emit one — the
gateway itself does not guard it, so an anchor-store row with no `status` reports **on-chain / verified: true**
through the tier a third party reaches. Fix: the carve-out applies to tier 1 ONLY — a statusless TIER-2 blob is not
anchored.


sets on every tier-2 blob; tier-1 blobs never carry it, so the legacy cell keeps passing.
