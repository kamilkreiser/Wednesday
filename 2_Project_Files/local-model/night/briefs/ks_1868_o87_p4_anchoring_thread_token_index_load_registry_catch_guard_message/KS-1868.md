## What is wrong (one paragraph)

The catch of `loadActiveRegistry` passes the thrown value's message straight into the logger's meta object in BOTH of its branches, unguarded: `error: err?.message` (strict: logged at error, then `throw err`) and `error: err?.message` (non-strict: logged at debug, then `return []`, the documented silent degrade to the metadata-label path). A thrown value whose read throws (a revoked Proxy: the `.message` get throws; an Error whose `message` getter throws) therefore throws INSIDE the catch: non-strict, the call REJECTS with that read error instead of resolving `[]`; strict, it rejects with the read error instead of rethrowing the ORIGINAL value; an Error whose `message` is readable but not a string (a Symbol) is passed to the logger uncoerced. The fix is the house guard placed ONCE before the `if (STRICT_MODE)` branch: read the message inside a `try`, keep `undefined`/`null` as they are (they were logged as is), coerce anything else with `String(...)`, and fall back to the constant `'unreadable thrown value'` when the read or the coercion throws; then both calls use `error: reason`. `throw err` and `return []` are unchanged.
