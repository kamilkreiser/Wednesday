## What is wrong (one paragraph)

In `routes/verificationV2.ts` the public, no-login `POST /api/v2/verification/verify` takes a chain-first fallback when the registry holds no row for the hash: `matchesForHash` calls `fetchChainFact(hashNorm)`, whose body is a `try` around a call to the anchoring service ending in `catch (err: any) { logger.warn('v2 verify: chain-fact read failed; matches present stored state', { error: err?.message }); return null; }`. If the thrown value is a revoked Proxy, `err?.message` itself throws inside the catch; if it is an Error whose `message` getter throws, the getter's throw escapes the same way. `fetchChainFact` then REJECTS instead of returning null, `matchesForHash` rejects, and the route's own catch answers the constant 500, where an ordinary Error (a network failure, a timeout) returns null and the route answers `200 { hash, count: 0, matches: [] }`. The fix reads the SAME expression into a local `reason` inside its own `try` and sets the constant `'unreadable thrown value'` when the read throws; the log call then uses `reason`. The `return null`, the message text and the key name are unchanged.
