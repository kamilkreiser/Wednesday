## What is wrong (one paragraph)

The validate handler (`index.ts:1300`, `async (req: Request, res: Response)`, no `next`, no `try` around the save) is the gateway's pre-session check for every `sk_*` key (unauthenticated by design, `:674`-`:684`). For an active, unexpired key it bumps `lastUsedAt` and `usageCount` (`:1352`-`:1353`) and calls `await dbSaveApiKey(apiKey);` at `:1354`. `dbSaveApiKey` (`:292`) catches every INSERT error and re-throws ONLY when the caller passed `{ rethrow: true }` (`:335`, added by #1322 for the mint). Validate does not pass it, so a failed save is swallowed and the handler answers `200 { valid: true }` (`:1356`-`:1372`) on a write that did not land. Kam's default is fail closed: a failed save never answers valid. Passing `{ rethrow: true }` alone is NOT safe: the r2 brief-writer measured (`night/briefs/KS-888-r2/README.md`) that a throw into this handler is an unhandled rejection (no `next`, no `try`), which ends a node 24 process. So the save call goes inside the handler's OWN `try`, and on a failure it logs one line and answers `503 SERVICE_UNAVAILABLE` with `success: false` and no `data`, whatever the fault class (the default says 503, not the mint's 503/500 split). The 200 does not run.
