## What is wrong (one paragraph)

`driverRecords` (`:60-80`) walks an error object and collects every record that carries a SQLSTATE. Its doc comment (`:54-59`) says "Nothing here throws on an unexpected shape". That is untrue: the property reads `o.originalCode`, `o.code`, `o.constraint`, `o.originalMessage`, `o.message` (`:68-70`) and `Object.keys(o)` (`:72`) sit OUTSIDE any `try`, so a getter that throws (gate probes G1 on the outer `code`, G3 on a cause's `originalMessage`) or a Proxy whose `ownKeys` trap throws (G4) makes `isIdNamespaceCollision` / `isLiveAnchorIdClaim` THROW. A throw there escapes the route's catch (`routes/documents.ts`, the `saveErr` block) and becomes the outer 500. No real driver error has a throwing getter, so this is unreachable today. The fix inserts ONE probe line right after `const o = ...` (`:67`): a `try` that touches every field the function reads afterwards (the five property reads and `Object.keys(o)`) and `return`s from `visit` if any of them throws. A node that cannot be read is then skipped (with everything under it), the helper answers `false`, which keeps an unknown error on its current path, exactly as the comment promises. The lines below the probe are NOT edited. The child read at `:74` already has its own `try`; it keeps it, and gains a one-line comment giving the reason it swallows (the workspace rule asks for a written justification on any swallowed exception).
