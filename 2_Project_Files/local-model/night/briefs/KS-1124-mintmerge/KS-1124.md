## What is wrong (one paragraph)

At document create, when `STATE_THREAD_NFT_ENABLED === 'true'` (`documents.ts:761`-`:764`), the route mints a thread token fire-and-forget and, when the mint resolves, caches it on the document with `updateDocument(id, tenantId, { blockchain: { ...(document.blockchain || {}), threadToken: {...} } })` (`:797`-`:807`). `document` is the CREATE-TIME local built at `:683`-`:693`, which has NO `blockchain` key, and `updateDocument` replaces the `blockchain` column wholesale (a top-level spread, `{ ...doc, ...updates }` at `repositories/documentRepo.ts:541`-`:542`, inside `updateDocument` at `:517`). The auto-anchor accept write is also fire-and-forget, so whichever resolves later wins: if the anchor accept lands first, this cache write erases its `txHash`, `status` and `anchorId`. KS-1124's recommendation for O1, verbatim: "merge rather than replace in the mint callback (spread the CURRENT persisted blob, not the create-time local)". Its 2026-09-26 comment re-observed the same write at `documents.ts:797` and says "O1's recommended fix is unchanged". The change: read the document as persisted at write time and spread ITS blob, falling back to the create-time local only when the read returns nothing.
