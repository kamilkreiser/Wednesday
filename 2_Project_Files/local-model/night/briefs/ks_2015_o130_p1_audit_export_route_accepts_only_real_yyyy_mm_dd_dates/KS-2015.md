## What is wrong (one paragraph)

In `Blockchain/Dev/services/api-gateway/src/routes/audit-export.ts` the helper `formatDate` (lines 100-107) validates a `from` or `to` query value by `new Date(dateStr)` and rejecting NaN. The OpenAPI spec declares both as the plain date pattern `^\d{4}-\d{2}-\d{2}$`. On gate 202's stub, seven of nine tried values answered 200: `0`, `1`, `-1`, `2026-9-1`, `Sep 1 2026`, `2026-09-01T00:00:00Z` and `2026-02-30` (which matches the pattern and rolls over to March). The fix: `formatDate` throws unless the value matches that pattern AND names a real calendar day (the parsed date, re-rendered as YYYY-MM-DD, equals the input). The route's existing `catch` already answers such a throw with the 400 `Invalid date format. Use YYYY-MM-DD.`
