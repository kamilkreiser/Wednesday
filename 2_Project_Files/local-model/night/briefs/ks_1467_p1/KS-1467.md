## What is wrong (one paragraph)

The auth `AppError` constructor (`services/auth/src/middleware/errorHandler.ts:25`) ends with `Object.setPrototypeOf(this, AppError.prototype)`. That line runs in the BASE constructor for every subclass instance, so it resets the instance's prototype to the base class: `new ValidationError(...) instanceof ValidationError` is `false` for every subclass. This kills the handler's own branch `if (err instanceof ValidationError && err.details)` (`errorHandler.ts:296`), so the password-strength `feedback` that register, reset-password and change-password pass as `details` is never sent. The fix is the standard one: `Object.setPrototypeOf(this, new.target.prototype)`; the 422 response then carries `details` when the error has them. One comment rides along in `services/passwordLoginGate.ts`: the comment above the `statusCode === 503` check says `instanceof` is always false, which the fix makes untrue; it is reworded (the code stays on `statusCode`).
