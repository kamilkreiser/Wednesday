## What is wrong (one paragraph)

In `routes/verificationV2.ts` the catch blocks of POST /verify (line 440) and POST /verify-file (line 476) each log `logger.error('<context>', { error: error instanceof Error ? error.message : String(error) })` (lines 441 and 477) and then answer the constant 500 `Verification failed` / `File verification failed`. If the database call rejects with a revoked Proxy, `error instanceof Error` itself throws a TypeError inside the catch; if it rejects with an Error whose `message` getter throws, `error.message` throws. Either way the catch throws, nothing is logged and the request gets no answer. The fix keeps each log line's text and replaces only the value: it first reads the same expression into a local `reason` inside its own `try`, and a `catch` sets the constant `'unreadable thrown value'`; the log line then uses `{ error: reason }`. The constant 500 answers are untouched. This is the inline guard already merged in originate `routes/certifications.ts` (`let reason: string; try { ... } catch { reason = 'unreadable thrown value'; }`); this file has no helper and none is added.
