## What is wrong (one paragraph)

In `utils/notificationClient.ts` two catch blocks log the thrown value as `error: String(err)`. (A) `sendNotification` (catch at line 53; the read is line 56): when the `fetch` to the notification service rejects, the catch logs `'Notification service unreachable, falling back to SMTP'` and THEN calls `await sendSmtpFallback(payload)` (line 58). (B) `sendSmtpFallback` (catch at line 107; the read is line 110): when the direct SMTP send rejects, the catch logs `'SMTP fallback also failed (non-blocking)'`. `String(err)` throws a TypeError for a revoked Proxy and also for an Error whose `message` getter throws (Error.prototype.toString reads `message`). In (A) the throw happens BEFORE the `sendSmtpFallback` line, so the SMTP fallback never runs: the notification email is DROPPED, and `sendNotification` rejects although the file header says "failures are logged but never thrown". In (B) the catch throws, so `sendSmtpFallback` rejects. The fix is the inline guard already merged in originate `routes/certifications.ts` (`let reason`, around line 1087): in each catch, `let reason: string; try { reason = String(err); } catch { reason = 'unreadable thrown value'; }`, and the log line uses `error: reason`. The expression `String(err)` is KEPT, so the text logged for an ordinary Error (`Error: <message>`) and for a string does not change. This file has no helper and none is added.
