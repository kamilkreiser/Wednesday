## What is wrong (one paragraph)

In `admin.ts` the catch blocks of GET /api/admin/identity/users (line 1274), GET /api/admin/identity/organizations (line 1296) and PATCH /api/admin/identity/users/:id/level (line 1320) each do one thing with the caught value: `log('error', '[Identity] <what failed>', { error: err instanceof Error ? err.message : String(err) });`, then answer a CONSTANT 500 body `{ success: false, error: { code: 'INTERNAL_ERROR', message: '<fixed text>' } }`; the message is only logged, never returned. If the database call rejects with a revoked Proxy, `err instanceof Error` itself throws a TypeError inside the catch block; if it rejects with an Error whose `message` getter throws, `err.message` throws. Either way the catch throws before anything is logged and before the 500 is sent; the async handler rejects, Express 4 does not catch that, and the request gets no response. The fix puts the SAME expression in a `try` that assigns a local `reason`, with a `catch` that sets the constant `'unreadable thrown value'`, and passes `{ error: reason }` to the same `log` call; every other line (the log message text, the 500) is untouched, and an ordinary Error still logs its own message. This is the inline guard already merged in other services (shared audit-logger and response-cache, analytics exportService/scheduledJobs, billing); api-gateway has no `describeThrown` or other helper at the tip and none is added.
