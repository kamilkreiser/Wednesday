## What is wrong (one paragraph)

In the anchoring `index.ts` three read-side lookup catches read the thrown value's message in their own `try` (`reason = err?.message;`, constant `unreadable thrown value` when the read throws) and log `{ error: reason }` through `log()`, which writes `console.log(JSON.stringify(...))`. The guard covers only the READ. If the getter succeeds and returns a hostile NON-string (a revoked Proxy, an object whose `toString` throws, a null-prototype object, a Symbol), the value is passed on uncoerced and the real logger can throw while formatting it, INSIDE the catch, outside the guard (QA gate 114, G114-F1, measured: `JSON.stringify` throws on a revoked Proxy or a BigInt message inside the catch; the tx route then never answers, verify-by-hash answers 500 with the error text in `details`, POST verify answers 500). The fix takes the read into a local and coerces it: `const m = err?.message; reason = m === undefined || m === null ? m : String(m);` inside the same `try`.
