## What is wrong (one paragraph)

`06-tenant-isolation.sh` runs the TypeScript runner with `> "$OUT" 2>&1` (`:71`), so the runner's stdout AND stderr both go into `$RUN_DIR/06-tenant-isolation.json` (`:30`). The runner prints its result as JSON on stdout (`runner.ts:262`), but its `login()` prints `login failed for <email>: <status> <body>` on STDERR (`runner.ts:74`) whenever a login is refused — and one refused login is DESIGNED: the second principal is `verifier@` OR, failing that, `holder@` (`runner.ts:150`-`:151`). On that legitimate run the artefact is the stderr line followed by the JSON, which no JSON reader parses: the job's own summary (`:74`-`:76`) prints `tested=? cross-tenant_findings=?`, and `09-aggregate-report.sh` (`:168`-`:174`, `jq … 2>/dev/null`) reads no findings at all — a real cross-tenant leak in that JSON included (gate71's `stderr-merged-LEAK`: 0 findings, rc 0). Measured at the tip with the suite below: the fallback run's artefact reads `unparseable`, the summary reads `tested=?`. The fix redirects stderr to its own file beside the artefact, `"$OUT.stderr"` (`06-tenant-isolation.json.stderr`), so the artefact is the runner's stdout alone and the login message is kept, not discarded. The name does not end in `.json`, so `ci/aggregate.ts:237` (`f.endsWith('.json')`) does not pick it up as an artefact.
