## What is wrong (one paragraph)

`certifications.ts` starts the repository at module load: `initRepo().catch((err) => logger.error('Failed to init repo', { error: err instanceof Error ? err.message : String(err) }))`. The read of the rejection value is inside the arrow with no guard: a revoked Proxy (`instanceof` throws), an Error whose `message` getter throws, or an object with a null prototype (`String(...)` throws) makes the arrow throw before the logger runs, so the promise returned by `.catch` rejects with nobody listening: an unhandled rejection (originate's `process.on('unhandledRejection')` handler then runs its error-tracking and shutdown path). The fix is the house guard inline: the same read inside a `try`, the constant `'unreadable thrown value'` when it throws, then the same logger call with `error: reason`. Today's read for readable values is kept exactly (an Error gives its message, anything else `String(value)`). The other `.catch` of this file (provenance record, line ~710) is a separate site and untouched.
