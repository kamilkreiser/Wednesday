## What is wrong (one paragraph)

In `routes/analytics.ts` the catch blocks of GET /realtime (line 245), GET /exports/:id (line 350) and GET /exports (line 372) each have NO ZodError branch and one line that reads the caught value: `logger.error('<text>', { error: error instanceof Error ? error.message : String(error) });`, followed by the CONSTANT 500 body `{ success: false, error: { code: 'INTERNAL_ERROR', message: '<fixed text>' } }`; the message is only logged. If the service call rejects with a revoked Proxy, `error instanceof Error` itself throws a TypeError inside the catch block; if it rejects with an Error whose `message` getter throws, `error.message` throws. Either way the catch throws before anything is logged and before the 500 is sent; the async handler rejects, Express 4 does not catch that, and the request gets no response (the gateway proxy times out). The fix puts a `let reason: string;` plus a `try` that runs the SAME expression and a `catch` that sets the constant `'unreadable thrown value'` just above the `logger.error` line, and changes that line to log `{ error: reason }`; the log text and the 500 are untouched, and an ordinary Error still logs its own message. This is the inline guard (variable `reason`) already merged in this service (exportService.ts dbSaveExport and loadFromDb, analyticsService.ts, metricsCollector.ts, scheduledJobs.ts); no helper is added. The OTHER nine catches of this file open with `instanceof z.ZodError`, which throws first on a revoked Proxy, so a message-line fix would be half a fix there: they are deliberately NOT in this series.
