## What is wrong (one paragraph)

In `index.ts` the DELETE /api/tenants/:id handler archives a tenant inside a transaction. Three catch reads of a caught value are written `x instanceof Error ? x.message : String(x)`: (1) line 603, inside the transaction block's `catch (err)`: `await client.query('ROLLBACK').catch((rollbackErr: unknown) => { console.error('... rollback failed:', rollbackErr instanceof ...) })`, after which the block rethrows the ORIGINAL `err`; (2) line 622, the first line of the outer `catch (err: unknown)`: `const message = err instanceof Error ? err.message : String(err);`, which comes BEFORE the Ruling-1 (KS-1861) `tenant_archive_failed` audit INSERT and the constant 500; (3) line 629, inside that INSERT's `.catch((auditErr: unknown) => { console.error('... could not audit the failure:', auditErr instanceof ...) })`. If the value is a revoked Proxy (`instanceof` throws) or an Error whose `message` getter throws: (1) the `.catch` callback throws, so the ROLLBACK await rejects with a TypeError that REPLACES the original error (the outer catch then reports the TypeError, not the cause); (2) the outer catch throws on its first line: no failed-attempt audit row, no 500, the request gets no response (unhandled rejection); (3) the callback throws, the INSERT's await rejects out of the catch block, and the 500 is never sent. The fix wraps each read in its own try with the constant fallback `'unreadable thrown value'`: (1) and (3) read into a local `reason` used by the existing console.error line, (2) turns the one `const message` line into `let message: string;` + try/catch; every other line is untouched, and ordinary Errors log exactly what they log today. No helper is added (this service has none; this is the inline guard merged in analytics, nft-certificate and billing PR 1906).
