## What is wrong (one paragraph)

In `routes/verification.ts` the lookup block of the public, no-login `POST /api/verification/verify` ends in `catch (dbErr: any) { logger.warn('Verification lookup failed', { documentId, error: dbErr?.message }); return res.json({ verified: false, error: 'Verification lookup failed' }); }`. If the thrown value is a revoked Proxy, `dbErr?.message` itself throws a TypeError inside the catch; if it is an Error whose `message` getter throws, the getter's throw escapes the same way. The new throw reaches the OUTER catch, which answers HTTP 500 'Verification failed' instead of the 200 'Verification lookup failed' that an ordinary Error gets (QA gate 106, G106-F1, measured at base and head). The fix reads the SAME expression into a local `reason` inside its own `try` and sets the constant `'unreadable thrown value'` when the read throws; the log call then uses `reason`. **The `documentId` key and the log message text are NOT changed in this pass** (see the behaviour note).
