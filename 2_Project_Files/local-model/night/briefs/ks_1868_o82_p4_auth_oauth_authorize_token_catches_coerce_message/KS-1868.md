## What is wrong (one paragraph)

In `routes/oauth.ts` the outer catch of POST /api/oauth/authorize and of POST /api/oauth/token reads the thrown value's message in its own `try` (`reason = error.message;`, constant `unreadable thrown value` when the read throws, which also covers a thrown `undefined`), logs `{ error: reason }` and answers the constant 500 `server_error`. The guard covers only the READ. If the getter succeeds and returns a hostile NON-string (a revoked Proxy, an object whose `toString` throws, a null-prototype object, a Symbol), the value is passed on uncoerced and the real logger can throw while formatting it, INSIDE the catch, outside the guard (QA gate 113, G113-F1, measured with the real winston: no response and an unhandled rejection). The fix takes the read into a local and coerces it: `const m = error.message; reason = m === undefined || m === null ? m : String(m);` inside the same `try`.
