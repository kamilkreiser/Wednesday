## What is wrong (one paragraph)

In `governanceService.ts` the catch block of `verifyDbReady` (the boot-time proposal-counter seed) logs `logger.error('Failed to seed proposal counter from DB', { error: err instanceof Error ? err.message : String(err) })` (line 389) and ends; it neither returns a value nor rethrows. If the query rejects with a revoked Proxy, `err instanceof Error` itself throws a TypeError inside the catch block; if it rejects with an Error whose `message` getter throws, `err.message` throws. Either way the catch throws before the ERROR line is logged and `verifyDbReady` rejects instead of resolving. The fix reads the SAME expression into a local `reason` inside its own `try`, and a `catch` sets the constant `'unreadable thrown value'`; the log call then uses `reason`. This is the inline guard already merged in the same file at lines 218, 255, 313, 342 and 448; no helper is added.
