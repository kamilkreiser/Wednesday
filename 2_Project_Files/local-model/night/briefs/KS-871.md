## What is wrong (one paragraph)
`services/api-gateway/src/middleware/audit.ts` records the request path AFTER the response finishes. When an
earlier `router.use(prefix, handler)` gate has already answered (a REFUSED GDPR erasure is the case), Express
has by then trimmed `req.path` to the mount-relative remainder — often `/` — so the audit row carries the wrong
path. The path must be captured ONCE, at entry, and that captured value used everywhere the finish handler
needs a path.

## The exact change — four edits, all in `audit.ts`, nothing elsewhere
E1. Line 210 (`const start = Date.now();`, inside `createAuditMiddleware`'s returned handler): add directly
    AFTER it one line:
    `const auditPath = req.originalUrl.split('?')[0];`
    (Do NOT put this inside `res.on('finish', …)` — that is the defect.)
E2. Line 95 (`function deriveAction(req: Request): {`): give the function a second parameter — change the
    signature to `function deriveAction(req: Request, auditPath: string): {`.
E3. Line 108 (`const segments = req.path.replace(/\/+$/, '').split('/').filter(Boolean);`): replace
    `req.path` with `auditPath` → `const segments = auditPath.replace(/\/+$/, '').split('/').filter(Boolean);`
E4. Line 230 (`… = deriveAction(req);`): pass the captured path → `deriveAction(req, auditPath);`
E5. Line 280 (`path: req.path,` inside the `details` object): → `path: auditPath,`
Every other line stays byte-identical. No new imports. Do not touch lines 206–208 (the entry gates read
`req.path` deliberately and correctly — the ticket says so).
