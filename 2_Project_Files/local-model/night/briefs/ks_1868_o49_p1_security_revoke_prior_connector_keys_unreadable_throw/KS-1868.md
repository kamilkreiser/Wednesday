## What is wrong (one paragraph)

In `index.ts`, `revokePriorConnectorKeys` retires the connector's prior in-memory keys, then (database available) runs the retire UPDATE; its catch logs `log('error', 'KS-577: revoke-on-rotate FAILED ...', { connectorId, tenantId, keepKeyId, error: err instanceof Error ? err.message : String(err) })` (the read is on line 293) and returns `null`, the KS-577 contract for a failed retire. If the UPDATE rejects with a revoked Proxy, `err instanceof Error` itself throws a TypeError inside the catch; if it rejects with an Error whose `message` getter throws, `err.message` throws. Either way the catch throws before the line is logged and before `return null`, so the function rejects with the hostile value. The fix reads the thrown value inside its own inner `try` into a local `reason`, falling back to the constant `unreadable thrown value`, and the log call uses `reason`. Nothing else changes: an ordinary Error still logs `error: <its message>`.
