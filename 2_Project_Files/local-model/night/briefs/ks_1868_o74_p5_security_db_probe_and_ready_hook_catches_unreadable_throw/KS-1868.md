## What is wrong (one paragraph)

In `src/db.ts` two catches read `err?.message`: `runDbReadyHook` (tip :100-103) logs 'DB ready boot work failed' with it, and `probeDb` (:111-114) sets `dbAvailable = false` and returns `{ ok: false, error: err?.message }`. If the call rejects with a revoked Proxy, or with an Error whose `message` getter throws, that read throws INSIDE the catch, so `runDbReadyHook` and `probeDb` reject; `initDb` therefore rejects (at boot) and the background retry timer's callback rejects as an unhandled rejection. The fix keeps the logged and returned text and replaces only the value: each catch first reads the SAME expression `err?.message` into a local `reason` inside its own `try`, and a `catch` sets the constant `'unreadable thrown value'`. In `probeDb` the `dbAvailable = false` line stays first, before the guard. No helper is added.
