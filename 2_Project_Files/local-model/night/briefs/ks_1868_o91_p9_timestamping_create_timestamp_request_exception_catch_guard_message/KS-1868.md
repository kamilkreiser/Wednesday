## What is wrong (one paragraph)

The catch logs `{ error: err?.message }` with the read INSIDE the logger call's arguments, unguarded. A thrown value whose read throws (a revoked Proxy: the `.message` get throws; an Error whose `message` getter throws) therefore throws INSIDE the catch, so `createTimestamp` REJECTS instead of logging and falling through to its documented mock-token fallback ("Falls back to a mock token if no TSA is reachable"), as an ordinary Error does; an Error whose `message` is readable but not a string (a Symbol) is handed to the logger uncoerced. The fix is the house guard placed before the logger call: read the message once inside a `try`, keep `undefined`/`null` as they are (they were logged as is), coerce anything else with `String(...)`, and fall back to the constant `'unreadable thrown value'` when the read or the coercion throws; then `error: reason`. The mock-fallback code after the catch is untouched.
