## What is wrong (one paragraph)

In `POST /seed-demo-users` the loop over the 14 demo users wraps each insert in `try { ... } catch (err: any) { failed++; logger.error('Demo user seed failed', { email: u.email, error: err?.message }); }` (`adminConfig.ts:2107-2113`). `failed++` (:2111) runs first, but the next statement reads `err?.message` from the thrown value itself. If that value is a revoked Proxy, or an object whose `message` getter throws, the read throws from inside the catch, leaves the `for` loop, and is caught by the route's outer `catch` (:2143), which answers `fail500` (the constant 500): the users after the first hostile one are never attempted, and the operator gets no `created / alreadyPresent / failed` report. `fail500` (:110) and the KS-1780 helpers (:133, :141) already survive such values; this is the one catch in the file that still reads the value unguarded. The change: add a helper `readableErrorMessage(err)` that returns `err?.message` inside a `try` and a fixed fallback string in the `catch`, and log `readableErrorMessage(err)` instead of `err?.message`. Every value that could be read before logs the same text as before.
