## What is wrong (one paragraph)

Both catches log `{ error: err?.message }` with the read INSIDE the logger call's arguments, unguarded. A thrown value whose read throws (a revoked Proxy: the `.message` get throws; an Error whose `message` getter throws) therefore throws INSIDE the catch, so a function documented to fail open (or to be non-fatal) REJECTS instead; an Error whose `message` is readable but not a string (a null-prototype object, a Symbol) is handed to the logger uncoerced. The fix is the house guard placed before the logger call: read the message once inside a `try`, keep `undefined`/`null` as they are (they were logged as is), coerce anything else with `String(...)`, and fall back to the constant `'unreadable thrown value'` when the read or the coercion throws; then `error: reason`.
