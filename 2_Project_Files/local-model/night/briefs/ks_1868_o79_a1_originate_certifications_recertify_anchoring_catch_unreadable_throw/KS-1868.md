## What is wrong (one paragraph)

In `routes/certifications.ts` the recertify route posts the new verification certificate's anchor to the anchoring service inside an inner `try`, and the inner `catch (err: any)` is `logger.warn('Anchoring service unreachable for verification cert', { error: err?.message })`; it then continues (outside production) and saves the certificate with `anchoringStatus: 'failed'`, records the charge and answers 201. If the rejection is a revoked Proxy, `err?.message` itself throws inside the catch; if it is an Error whose `message` getter throws, that throw escapes the same way; if the getter RETURNS a hostile non-string (a revoked Proxy, an object whose `toJSON` throws) the real winston logger throws on it (QA gate 105, G105-F1 and G105-F2, measured at base and head). Any of these escapes the inner catch and is answered by the route's OUTER catch as 500 'Failed to issue verification certificate', with NO certificate saved and NO charge recorded. The fix reads the thrown value inside its own `try` with the coercing form PR 1924 merged for the outer catches, sets the constant `'unreadable thrown value'` when the read throws, and the log call uses `reason`.
