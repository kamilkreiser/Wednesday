## What is wrong (one paragraph)

In `services/scheduledJobs.ts` the module-level function `dbSaveAlert` (line 69) pushes the alert into memory, then runs an INSERT ... ON CONFLICT inside a `try`; its catch (line 90) has one line that reads the caught value: `logger.info('DB save alert failed', { error: err instanceof Error ? err.message : String(err) });`. The message is only logged. If the query rejects with a revoked Proxy, `err instanceof Error` itself throws a TypeError inside the catch block; if it rejects with an Error whose `message` getter throws, `err.message` throws. Either way the catch throws before anything is logged and `dbSaveAlert` rejects instead of resolving. The sole caller, `ScheduledJobs.acknowledgeAlert` (line 486), calls `dbSaveAlert(alert).catch(() => {})`, so the rejection is swallowed: today the scheduler loop, the cron jobs and acknowledgeAlert's `return true` are unaffected, and only the INFO line is lost. The fix puts a `let reason: string;` plus a `try` that runs the SAME expression and a `catch` that sets the constant `'unreadable thrown value'` just above the `logger.info` line, and changes that line to log `{ error: reason }`; the log text is untouched and an ordinary Error still logs its own message. This is the inline guard (variable `reason`) already merged at the tip in this same file (dbSaveAlertRule line 58-64, loadScheduledJobsFromDb line 155-161), exportService.ts, analyticsService.ts and metricsCollector.ts; no helper is added.
