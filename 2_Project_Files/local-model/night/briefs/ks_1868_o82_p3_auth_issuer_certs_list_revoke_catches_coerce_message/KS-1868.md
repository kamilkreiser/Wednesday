## What is wrong (one paragraph)

In `routes/issuerCerts.ts` the catch of GET /api/issuer-certs and of POST /api/issuer-certs/:id/revoke reads the thrown value's message in its own `try` (`reason = err instanceof Error ? err.message : String(err);`, constant `unreadable thrown value` when the read throws), logs `{ error: reason }` and answers the constant 500. The guard covers only the READ. For an Error whose message is a hostile NON-string (a revoked Proxy, an object whose `toString` throws, a null-prototype object, a Symbol) the message is passed on uncoerced and the real logger can throw while formatting it, INSIDE the catch (QA gate 113, G113-F1, measured with the real winston: no response and an unhandled rejection). The fix is `reason = String(err instanceof Error ? err.message : err);` inside the same `try`: a non-Error value is stringified exactly as before and a message that cannot be turned into text throws inside the `try`, so the existing `catch` gives the constant.
