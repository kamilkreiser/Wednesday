## What is wrong (one paragraph)

In `POST /api/admin/seed-demo-users` (`routes/adminConfig.ts`), the per-user `catch (err: any)` counts the failure (`failed++`) and then calls `logger.error('Demo user seed failed', { email: u.email, error: readableErrorMessage(err) })` at `:2121`. KS-1802 made the message READ safe (`readableErrorMessage`, `:150-156`) but the `logger.error(...)` call itself sits directly in the catch with no try of its own. A logger that throws (or a serialiser that throws on a value) therefore leaves the per-user catch, ends the `for` loop at that user (the later users are never attempted) and reaches the route's outer catch, which answers the constant 500: the hang class KS-1802 closed. `fail500` (`:110-126`) and migrate-tenant-data (`:2273-2292`) already log in a second `try` with an empty-bodied `catch`. The change: wrap that one call the same way. Nothing else changes: the count, the message text and the report are untouched.
