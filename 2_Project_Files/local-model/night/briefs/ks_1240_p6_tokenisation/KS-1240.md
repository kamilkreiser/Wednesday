## What is wrong (one paragraph)

`tokeniseFields` and `detokeniseValues` in `services/api-gateway/src/services/tokenisation.ts` each `await fetch(...)` the tokenisation service (`/api/tokenise`, `/api/detokenise`) with no `signal`. A tokenisation service that accepts the connection and never answers holds the gateway caller open for as long as the socket lives. Each function already wraps its fetch in a `try` whose `catch` logs a warning and falls through to return the empty map. The change adds one module constant `TOKENISATION_FETCH_TIMEOUT_MS = 10_000` (with a comment) right after the `TOKENISATION_URL` line and `signal: AbortSignal.timeout(TOKENISATION_FETCH_TIMEOUT_MS),` as the last property of each fetch's init object. When the signal fires the fetch rejects into the existing catch. For a healthy service nothing changes.
