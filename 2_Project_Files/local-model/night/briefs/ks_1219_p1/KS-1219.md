## What is wrong (one paragraph)

`GET /api/oauth/authorize` destructures `scope` from `req.query as Record<string, string>` (`routes/oauth.ts:477-482`); the cast is compile-time only, so a repeated parameter (`?scope=openid&scope=profile`) reaches the code as an ARRAY. `POST /api/oauth/authorize` reads `scope` from `req.body` (`:623-640`), so a JSON array body does the same. Both handlers pass it to the one shared resolver `resolveAuthorizeClient` (`:238`), whose RULE 4 calls `parseScopeString(scope)` (`:393`, defined in `services/oauth.ts:357-360` as `if (!scope) return []; return scope.split(...)`). An array has no `split`, the TypeError reaches the handler's catch, and the answer is 500 `server_error`: a malformed client request reported as a server fault. The change is one early refusal in the resolver, placed directly above the line that calls it, `const requestedScopes = parseScopeString(scope);`: if `scope` is neither undefined nor a string, return `{ ok: false, message: 'invalid_request', description: ... }`. `invalid_request` is an existing message (RULE 3 returns it), so no published message changes; `authorizeRefusal` (`:441`) already turns any refusal into a 400 JSON body for GET and POST alike.
