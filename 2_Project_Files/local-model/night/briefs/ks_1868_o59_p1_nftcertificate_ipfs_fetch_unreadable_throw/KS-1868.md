## What is wrong (one paragraph)

In `ipfs.service.ts` the method `IPFSService.fetch` (used when the provider has no native `read`, i.e. every HTTP-gateway provider) has two catch blocks that each map a failure to `throw new ServiceUnavailableError('IPFS gateway')` after a `logger.warn`: (1) line 487, the gateway request `response = await fetch(url, ...)`, logs `'IPFS gateway unreachable'`; (2) line 512, the body read `await response.arrayBuffer()`, logs `'IPFS gateway body read failed'`. Both log `error: error instanceof Error ? error.message : String(error)`. If the awaited call rejects with a revoked Proxy, `error instanceof Error` itself throws a TypeError inside the catch block; if it rejects with an Error whose `message` getter throws, `error.message` throws. Either way the catch throws before the warning is logged and before the `ServiceUnavailableError`, so `fetch` rejects with the TypeError instead of the 503 error. The fix adds, before each `logger.warn`, a `let reason: string;` plus a `try` that runs the SAME expression and a `catch` that sets the constant `'unreadable thrown value'`, and the log call uses `error: reason`; the `throw new ServiceUnavailableError('IPFS gateway')` is then reached as for any ordinary failure. An ordinary Error still logs `error: <its message>`.
