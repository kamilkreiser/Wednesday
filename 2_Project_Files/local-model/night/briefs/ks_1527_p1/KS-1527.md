The fix is (b) log the whole argv: replace `:191` with `fs.appendFileSync('calls.log', process.argv.slice(2).join(' ') + '\n');` (with one argument per call the log is the same as today, so the existing exact-line expectation at `:210` still holds), and (a) add one `expect` right after the api-gateway rc-1 cell (`:212-214`) that asserts `a NEW test-file type error` is in the output of a gateway rc-1 run.
