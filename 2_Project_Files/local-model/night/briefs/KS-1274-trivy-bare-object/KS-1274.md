## What is wrong (one paragraph)

`04-container-trivy.sh` turns each image's trivy JSON into a summary at `:97`-`:113` and, since KS-1136 (#1051), marks the image `scan-failed` when trivy exited non-zero or jq produced nothing (`:115`-`:118`, the guard `if [[ $trc -ne 0 || -z $norm ]]` at `:116`). One shape still slips through as a CLEAN image: trivy exits 0 and prints a bare `{}`. jq reads it happily (`counts: {}`, `vulns: []`), the guard does not fire, and the job prints `CRITICAL=0 HIGH=0 across 1 image(s)` and exits 0 — a scan with nothing in it reads as a scanned, clean image. The fix extends the SAME guard: a report with neither a `Results` key nor an `ArtifactName` key is a failed scan. **Not `Results` alone (measured, see Premises):** trivy 0.71 OMITS `Results` from a clean report and keeps `ArtifactName`, so a `Results`-only guard would turn a genuinely clean scan into `scan-failed`. The three existing trivy suites all stub a clean scan as a bare `{}`; after the fix that stub is (correctly) a failed scan, so each suite's clean stub becomes `{"Results":[]}` — that is why this is four files.
