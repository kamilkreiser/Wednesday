## What is wrong (one paragraph)

The catch logs `error: (err as Error)?.message ?? String(err)` with the read INSIDE `console.error`'s arguments, unguarded. A thrown value whose read throws (a revoked Proxy: the `.message` get throws; an Error whose `message` getter throws; a value with no message whose `String()` conversion throws) therefore throws INSIDE the catch, so the line is never written and `detokenise` REJECTS for the whole batch instead of answering `value: null` for the entry that could not be decrypted, as an ordinary Error does. The fix is the guard already used by the merged KS-1868 passes, with this module's own expression kept as it is: `let reason: string; try { reason = (err as Error)?.message ?? String(err); } catch { reason = 'unreadable thrown value'; }` placed before the `console.error` (after the `tokenHash` line, before the eslint comment), then `error: reason`. The expression is unchanged, so every value that could be read before is logged exactly as before. The `return { token: tok, value: null }` line is untouched.
