## What is wrong (one paragraph)

The login callback of `services/auth/src/routes/auth.ts` wraps every exchange failure as `BadRequestError('OAuth authentication failed: ' + exchangeErr.message)` (`:1077-1081`). When a provider answers HTTP 200 with a body that is not JSON (for example an HTML error page), the adapter's `.json()` throws a `SyntaxError` whose message V8 builds by quoting the first 10 characters of the body (`Unexpected token '<', "<html>PROV"... is not valid JSON`), and that reaches the client in the 400. #1788 already stopped the status-error bodies being echoed; this is the same class on the `.json()` lines. Map a `SyntaxError` to a neutral text; leave every other failure's message alone.
