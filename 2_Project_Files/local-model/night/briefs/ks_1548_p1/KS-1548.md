## What is wrong (one paragraph)

`platform.ts:480-502` pages the platform half of the audit log in windows. Line 482 is the guard `if (remaining <= 0) throw new UpstreamTimeoutError(...)`: when the shared budget is spent no further window starts. Cell `RED KS-1512 M` (test file lines 249-256) makes the FIRST window's body arrive after the budget (`firstBodyDelayMs = BUDGET_MS * 1.1`, line 252) and checks that the page degrades to the audit_logs rows within the time. It never checks how many upstream requests were made. The gate on PR 1522 removed the guard (its mutant) and the whole suite stayed green, because with the guard gone the loop still starts a second window whose timeout is the negative remainder, so it is aborted at once and the page degrades the same way; the only difference is that the stub upstream sees a second request. The stub already records every request in the file-scope `calls` array (declared line 53, pushed at line 67, cleared in `beforeEach` at line 127). So cell M needs one more entry in its `wrong` list: `calls.length !== 1`. The product is right at the tip; this task adds the pin.
