## What is wrong (one paragraph)

Four places in `services/originate` decide 'is this caller a platform administrator?' with the same hand-written literal `role === 'system_admin' || role === 'SYSTEM_ADMIN' || role === 'super_admin'`: the documents LIST scoping (`routes/documents.ts:300`), the `GET /api/documents/:id` cross-tenant fallback (`:1101`), the certifications LIST scoping (`routes/certifications.ts:964`) and `callerMayCertifyDocument` (`:123`). All four omit `SUPER_ADMIN` (the upper-case spelling), so a platform administrator whose token carries it is treated as an ordinary user; the identical omission copied into a new access check caused a measured regression during KS-1695, fixed by calling `isPlatformRole`. The change replaces each literal with `isPlatformRole(<the same role variable>)` and adds `isPlatformRole` to documents.ts's existing `@secuura/shared` import (certifications.ts already imports it). The predicate upper-cases the claim and covers `SYSTEM_ADMIN` and `SUPER_ADMIN`, so every spelling the literal accepted is accepted now, plus `SUPER_ADMIN` and mixed-case spellings.

## Where
