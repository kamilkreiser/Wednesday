## What is wrong (one paragraph)

In `repositories/certificationRepo.ts` the function `verifyDbReady` runs `SELECT 1` and, when it fails, its catch (line 58-61) logs `logger.error('certificationRepo: database connection FAILED ...', { error: err instanceof Error ? err.message : String(err) });` and THEN throws the constant `new Error('Database is required for certification operations')`. If the query rejects with a revoked Proxy, `err instanceof Error` itself throws a TypeError inside the catch; if it rejects with an Error whose `message` getter throws, `err.message` throws. Either way the catch throws before the log line is written and before the constant Error, so the caller receives a TypeError (a different Error, with a different message) and nothing is logged. The fix keeps the log call's text and replaces only the value: it first reads the same expression into a local `reason` inside its own `try`, and a `catch` sets the constant `'unreadable thrown value'`; the log line then uses `error: reason`. This is the inline guard already merged in originate `routes/certifications.ts` (a `let reason: string; try { ... } catch { reason = 'unreadable thrown value'; }`); no helper is added.
