## What is wrong (one paragraph)

The catch around the Prisma connection check in `initDb` (the single-tenant branch, `MULTI_TENANCY_ENABLED` not `true`) passes the thrown value's message straight into `console.error`'s arguments, unguarded: `err.message`. A thrown value whose read throws (a revoked Proxy: the `.message` get throws; an Error whose `message` getter throws) therefore throws INSIDE the catch, so `initDb` REJECTS instead of logging the failure and resolving; an Error whose `message` is readable but not a string (a Symbol) is handed to `console.error` uncoerced. The fix is the house guard placed before the log call: read the message once inside a `try` (`?.` as the merged guards do), keep `undefined`/`null` as they are, coerce anything else with `String(...)`, and fall back to the constant `'unreadable thrown value'` when the read or the coercion throws; then `reason` in the call. The other catch of this module that reads `err?.code` / `err?.message` (the Prisma-client-not-generated check in `getPrismaClient`) is deliberately NOT touched: it rethrows the value and the message test there is a design decision. The ROLLBACK catches read nothing.
