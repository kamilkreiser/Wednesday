## What is wrong (one paragraph)

Three catches of this module log `{ error: err?.message, ... }` with the read INSIDE the logger call's arguments, unguarded. A thrown value whose read throws (a revoked Proxy: the `.message` get throws; an Error whose `message` getter throws) therefore throws INSIDE the catch, so the warn line is never written and the function REJECTS where an ordinary Error makes `processChargeEvent` answer `null` (lookup catch), `processChargeEvent` answer the event (update catch) and `getUsageSummary` answer its empty defaults; an Error whose `message` is readable but not a string (a Symbol) is handed to the logger uncoerced. The fix is the house guard placed before each logger call: read the message once inside a `try`, keep `undefined`/`null` as they are (they were logged as is), coerce anything else with `String(...)`, and fall back to the constant `'unreadable thrown value'` when the read or the coercion throws; then `error: reason`. The other keys of the meta object (`eventId`) and the return statements are untouched. Nothing else in the file changes.
