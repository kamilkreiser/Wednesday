## What is wrong (one paragraph)

The catches of `RedisRateLimitStore.get` (a failed lookup, answered `null`) and `RedisRateLimitStore.increment` (a failed counter, answered a count of 1) log `{ error: String(error) }`; reads the thrown value with `String(...)`, unguarded. A thrown value whose read throws (a revoked Proxy: `String()` throws on it; an Error whose `message` getter throws, since `Error.prototype.toString` reads it) makes the catch itself throw, so the call REJECTS where an ordinary Error gives the fallback. The fix is the house guard placed in the catch: read the value inside its own `try` and fall back to the constant `'unreadable thrown value'` when the read throws. The text of every value that can be read is unchanged.
