## What is wrong (one paragraph)

`markDocumentAnchorFailed` (`:173`) rebuilds the document's blockchain blob when an anchor fails, carrying the chain facts forward from the prior blob. It writes `blockHeight: prior?.blockHeight ?? 0` (`:192`), so a prior blob whose height is `null` (which the four KS-1333 sync writers now store when nothing is known) or absent gets a fabricated `0` back. A stored 0 reads as a claim nobody measured. The fix is `?? null`: a real prior height (including a real 0) is still kept, and only an unknown one stays unknown. The comment above it (`:189-190`) says `?? 0` "reproduce[s] the previous values exactly", which stops being true, so it is reworded in the same hunk.
