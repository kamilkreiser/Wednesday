## What is wrong (one paragraph)

In `routes/systemErrors.ts` the catch blocks of POST /ingest (line 134) and POST /client-errors (line 165) each log `logger.error('<context>', { error: err instanceof Error ? err.message : String(err) });` and then answer the CONSTANT 500 `{ success: false, error: { code: 'INTERNAL_ERROR', message: 'Internal server error' } }`. If the awaited `errorTracking.trackError` call rejects with a revoked Proxy, `err instanceof Error` itself throws a TypeError inside the catch block; if it rejects with an Error whose `message` getter throws, `err.message` throws. Either way the catch throws before anything is logged and before the 500 is sent; the async handler rejects, Express 4 does not catch that, and the request gets no response. The same file already has the guard for exactly this: the module function `fail500(res, context, err)` (KS-730, hardened by KS-1772) describes the value in its own try, logs `{ error: described }` in another, and always sends the same constant 500 body. The four admin routes of the file already use it. The fix replaces the two lines of each catch (the `logger.error` line and the `res.status(500)` line) with ONE call `fail500(res, '<the same context text>', err);`. No helper is added: the existing one is reused.
