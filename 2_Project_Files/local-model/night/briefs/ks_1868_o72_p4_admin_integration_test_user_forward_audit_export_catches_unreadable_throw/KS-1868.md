## What is wrong (one paragraph)

In `routes/admin.ts` three catches read the thrown value with a bare property read: (1) the Blockfrost connectivity test catch (line 1018) answers `res.json({ success: false, message: `Network error: ${err.message}`, ... })`; (2) the PATCH /api/users/admin/:id forward catch (line 1501) answers 502 with `details: { details: err.message }`; (3) the audit-export catch (line 1608) logs `{ error: (err as Error).message }` before a constant 500. If the thrown value is a revoked Proxy, or an Error whose `message` getter throws, that read throws INSIDE the catch block: (1) falls through to the route's outer catch and answers `Test failed unexpectedly`; (2) and (3) reject the async handler, so Express 4 never answers. The fix keeps every text and replaces only the value: it first reads the SAME expression into a local `reason` inside its own `try`, and a `catch` sets the constant `'unreadable thrown value'`; the answer or log then uses `reason`. This is the inline guard already merged in the same file by PR 1916; no helper is added.
