## What is wrong (one paragraph)

In `routes/certifications.ts` the issue route validates an explicit `holderId` with a database read inside a `try`; its `catch (err: any)` computes `const errMsg = err instanceof Error ? err.message : String(err)`, uses it for control flow (`errMsg.includes('invalid input syntax')`, `errMsg.includes('uuid')`) and logs it, then answers 400. Further down, the legacy certify path (a `documentId` without a `parentDocumentId`) rewrites the named document inside a best-effort `try`; its `catch (updateErr: unknown)` logs `error: updateErr instanceof Error ? updateErr.message : String(updateErr)` and the route still answers 201. If the thrown value is a revoked Proxy, `instanceof` itself throws inside the catch; if it is an Error whose `message` getter throws, that throw escapes the same way; if the getter returns a hostile non-string, `errMsg.includes` (site 1) or the real logger (site 2) throws. The throw reaches the route's OUTER catch, which answers 500 'Failed to issue certification' instead of the ordinary 400 (holderId site) or 201 (UPDATE site; the certification is already saved and anchored). The fix reads the thrown value inside its own `try` with the form PR 1924 merged, sets the constant `'unreadable thrown value'` when the read throws, and the code below uses the guarded string. The constant contains neither 'uuid' nor 'invalid input syntax', so an unreadable holderId failure takes the same branch as an ordinary database failure (400 'could not validate'). The log message texts, the other keys and the control flow are unchanged.
