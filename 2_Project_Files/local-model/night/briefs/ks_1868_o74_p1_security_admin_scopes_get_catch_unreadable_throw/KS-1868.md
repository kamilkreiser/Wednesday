## What is wrong (one paragraph)

In `src/index.ts` the GET /api/keys/admin-scopes/:userId handler ends in `} catch (error) { if (error instanceof z.ZodError) return badRequestFromZod(res, error); return next(error); }` (tip line 1825). If the scope query rejects with a revoked Proxy, `instanceof` throws INSIDE the catch, and because Express 4 does not forward an async handler's rejection the request is never answered (and an unhandled rejection is raised). The fix is the one PR 1912 merged for the PUT route in this file: the `instanceof` read goes inside its own `try`; if it throws, the handler calls `next(new Error('unreadable thrown value'))`, which the shared error handler answers as it answers any ordinary non-ZodError Error; a real ZodError still answers the route's 400. The decision order (Zod -> 400, otherwise next) is unchanged. Nothing is written by this read route.
