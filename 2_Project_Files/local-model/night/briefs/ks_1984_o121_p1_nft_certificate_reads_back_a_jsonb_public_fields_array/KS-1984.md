## What is wrong (one paragraph)

`public_fields` is declared `JSONB DEFAULT '[]'` (`migrations/002_verification-tiers.sql` line 796). The Postgres driver therefore returns an already-parsed JS array for it. The service reads it at four sites with `JSON.parse(row.public_fields || '[]')`: line 123 (`loadFromDb`, the startup load), line 505 (`getNFTCertificate`), line 592 (`getUserNFTCertificates`) and line 678 (`getWalletNFTCertificates`). `JSON.parse` of an array coerces it to text first (`['a','b']` becomes `a,b`; `[]` becomes the empty string) and throws a SyntaxError (`Unexpected end of JSON input` for `[]`). Each read is inside a try/catch that logs `DB get ... failed` (or the warning that `loadFromDb` logs) and carries on, so the certificate is never returned: the by-id read answers null, the user and wallet lists come back without the row, and `loadFromDb` stops at the first array row so no later row loads. The write path (line 76) stores `JSON.stringify(cert.publicFields || [])`, a JSON array, so every row the service wrote is affected. The fix at each of the four sites is to take the value as it is when it is an array and to parse it only when it is text (a legacy text value, or NULL, still goes through `JSON.parse(... || '[]')`). Nothing else changes: not the write at line 76, not the row types, not the catches.
