## What is wrong (one paragraph)

In `routes/verification.ts` the public, no-login verification router has three route catches that PR 1925 guarded: the outer catch of `POST /api/verification/verify` (logs 'Verification error', answers 500 'Verification failed'), the catch of `POST /api/verification/hash` (logs 'Hash generation error', answers 500 'Hash generation failed') and the catch of `GET /api/verification/status/:documentId` (logs 'Status check error', answers 500 'Status check failed'). The guard (KS-1868 O66/O70, merged in PR 1925) reads `reason = X instanceof Error ? X.message : String(X);` inside a local `try` and falls back to the constant `'unreadable thrown value'` when that throws. It does NOT coerce `message`: for an Error whose `message` getter RETURNS a hostile non-string (a revoked Proxy, or an object whose `toJSON` throws) `reason` is that object, the guard's try does not throw, and the REAL winston logger (KS-1348 redaction and format) throws on it inside `logger.error`, outside the try: the request gets NO ANSWER (QA gate 105 G105-F1, measured at base and head; PR 1925's own cells use a jest.fn logger, which never formats its arguments and so cannot reproduce it). The fix is one token per site: `reason = String(X instanceof Error ? X.message : X);`, which turns an object into its string form and sends a value String() cannot read to the existing fallback.
