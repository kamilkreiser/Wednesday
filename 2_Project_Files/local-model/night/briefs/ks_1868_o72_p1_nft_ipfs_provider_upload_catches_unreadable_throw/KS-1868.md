## What is wrong (one paragraph)

In `ipfs.service.ts` each HTTP provider's `upload` has a `try { fetch(...) ... } catch (error) { return { success: false, error: `<Provider> upload error: ${(error as Error).message}` }; }` (Pinata line 108-113, Infura line 203-205, Web3.Storage line 280-282). If the provider call rejects with a revoked Proxy, or with an Error whose `message` getter throws, the `.message` read throws INSIDE the catch block, so `upload` rejects instead of resolving the documented `{ success: false, error }` result. The fix keeps the returned text and replaces only the value: it first reads the SAME expression `(error as Error).message` into a local `reason` inside its own `try`, and a `catch` sets the constant `'unreadable thrown value'`; the returned `error` then uses `${reason}`. This is the inline guard already merged in the same file by PR 1915 (`reason` in `fetch`); no helper is added.
