## What is wrong
In the test file, the `get` helper (line 666) resolves its outcome inside `res.on('end', ...)` (line 674), and line 677 reads `hits: seen.filter((s) => s === tag).length` at that moment. The recorder server (line 32 onward) pushes the probe tag into `seen` only when the UPSTREAM request has itself ended. So a gate that sends its 401 and then still forwards the request reaches the recorder AFTER the count was taken: the count stays 0, and the three refusal cells that assert `[401, 'UNAUTHORIZED', 'Authentication required', 0]` stay green. Gate 281 measured it: with `index.ts` line 1132 changed from `return;` to `return next();` (the gate answers 401 and then forwards), the whole file stayed green; the same cells reading the count 500 ms after the response ends went red with hits 1. Not in this task: any product change; the `GREEN control` cell is unchanged (an admitted request waits on the upstream, so its count is already 1 at the end of the response and is still 1 after the delay).
