## What is wrong (one paragraph)

`dbGetAllProposals` in `services/governance/src/services/governanceService.ts` catches every database error, logs it and returns `[]` (`:254-256`). Its callers read that as 'no proposals': `getProposals` (so `GET /api/governance/proposals` and `GET /api/governance/proposals/active` answer `200` with `data: []`, `count: 0`), and `createProposal`'s active-proposal cap (`:495-497`), which therefore fails OPEN when the read fails. The change: the catch still logs, then rethrows (`throw err;`). The two list handlers in `routes/governance.ts` are plain `async` functions with no error path, and Express 4 does not route a rejected async handler to the error middleware, so each is given `next` and adds `.catch(next)` to its `getProposals` call and returns early when the result is falsy (a rejected read resolves to `undefined` after `next(error)` ran) (the POST handlers in the same file reach `next(error)` through try/catch; this form avoids re-indenting the call). The shared `errorHandler` then answers 500. `processExpiredProposals` (`:1013`) already has its own catch returning 0 and is unchanged in behaviour.
