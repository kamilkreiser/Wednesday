## What is wrong (one paragraph)

On the `POST /api/keys/validate` path three catches read the thrown value's message in their own `try` (`reason = err?.message;`, constant `unreadable thrown value` when the read throws) and log `{ error: reason }`: the usage write of `dbRecordApiKeyUsage`, the stored-state read of a cached key (answers 503 `Unable to verify key`) and the cache-miss lookup (falls through to `Key not found`). The guard covers only the READ. If the getter succeeds and returns a hostile NON-string (a revoked Proxy, an object whose `toString` throws, a null-prototype object, a Symbol), the value is passed on uncoerced: the real winston formatter (and `JSON.stringify` in db.ts's `dbLog`) throws on some of them while formatting, INSIDE the catch, outside the guard (QA gate 112, G112-F1, measured). The validate handler takes no `next`, so the request is then never answered and an unhandled rejection is raised. The fix wraps the read: `const m = err?.message; reason = m === undefined || m === null ? m : String(m);` inside the same `try`, so a value that cannot be turned into text throws inside the `try` and the existing `catch` gives the constant.
