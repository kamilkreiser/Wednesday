## What is wrong (one paragraph)

In `exportService.ts` the catch of the private `processExport` (lines 164 to 170 at the tip) calls `logger.warn('Export failed', ...)` at line 167 BEFORE it sets `exportResult.error = 'Export failed'` (line 168) and saves the failed state with `await this.dbSaveExport(exportResult)` (line 169). `createExport` (line 84) calls `this.processExport(exportId, request)` with no `await` and no `.catch`. So if the logger throws (or if reading `error.message` throws, an Error whose `message` getter throws), lines 168 and 169 never run: the database row stays `processing` and the rejection is unhandled. The ticket's fix (the gate's): set the constant text and save first, then log; and guard the log line. This brief does both: the order change, and the log line (message read included) inside its own `try` whose catch holds only a comment (the file already uses `catch {` at line 58).
