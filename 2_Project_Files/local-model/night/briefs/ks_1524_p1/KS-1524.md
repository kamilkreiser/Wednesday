## What is wrong (one paragraph)

The catch of `GET /api/platform/document-lookup` logs the thrown value at `platform.ts:1143`. For an `Error` it logs `err.message`. The gate on PR 1512 (KS-1510) found that cell L1 (test file lines 80-87) only asserts the logged text CONTAINS `ECONNREFUSED`, and cell L2 uses a thrown string, so a mutant that logs `err.stack` (its O1) or `String(err)` (its O9) instead of `err.message` keeps the whole file green. A logged stack would put multi-line file paths into the log unnoticed. The fix is one new cell: reject an `Error` with a fixed message through the file's own helper `stubQueryRejecting` (line 66) and assert the logged calls equal exactly `[[CONTEXT, { error: <that message> }]]`, the same shape cell L2 (lines 89-94) already uses for a thrown string. A stack always starts `Error: ...` and carries `at ` lines, so it can never equal the bare message. The product is right at the tip.
