## What is wrong (one paragraph)

`GET /api/connector/info` in `createHealthRoutes` reads `platform-settings` through `redisService.getNotificationSettings`. In the Redis in-memory fallback mode that read RESOLVES to null (it does not throw), so the handler's catch (KS-1532) never fires and the route answers 200 with `allowedDocumentTypes: []`, which means "all types permitted", for a connector whose allow-list it could not read. The create path refuses that state with a 503 through an explicit `isRedisAvailable()` test before its read. The info reader needs the same early test: add the optional member to `RedisServiceLike`, and right after the `connectorConfig` declaration answer the create path's 503 when `redisService.isRedisAvailable?.() === false`, before the read.
