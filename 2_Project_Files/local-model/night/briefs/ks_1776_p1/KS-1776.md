## What is wrong (one paragraph)

In a test file whose `../repositories/userRepo` mock has no `seedDemoUsers` export, vitest's mock throws SYNCHRONOUSLY on that property read, so the `.catch` is never reached and the error escapes the timer as an uncaught exception that vitest attributes to whichever test is running (seen once, in `ks781-login-authorize-agree.test.ts`, in a loaded run; 49 test files mock `../repositories/userRepo`, 11 of them import `routes/auth`). The change starts the seed inside a `try` whose `catch` and the existing `.catch` share ONE log function, so a synchronous throw and an async rejection both log `Failed to seed demo users` with the same fields. Nothing about when the timer fires, what it calls, or what a healthy repository does changes.
