## What is wrong (one paragraph)

Two places in this module pass the thrown value's message straight into `dbLog`'s meta object, unguarded: the pg pool `'error'` listener (`{ error: err.message }`) and the boot-work catch of `runDbReadyHook` (`{ error: err?.message }`). A thrown value whose read throws (a revoked Proxy: the `.message` get throws; an Error whose `message` getter throws) therefore throws INSIDE the listener or the catch: an exception thrown by a listener of the pool's `'error'` event escapes the EventEmitter as an uncaught exception, and a throwing `runDbReadyHook` makes `initDb` REJECT instead of resolving with the availability flag; an Error whose `message` is readable but not a string (a Symbol) is handed to `JSON.stringify` uncoerced and silently dropped from the line. The fix is the house guard placed before each `dbLog` call: read the message once inside a `try`, keep `undefined`/`null` as they are (they were logged as is), coerce anything else with `String(...)`, and fall back to the constant `'unreadable thrown value'` when the read or the coercion throws; then `error: reason`. The probe catch of `probeDb` (`return { ok: false, error: err?.message }`, typed `error?: string`) is deliberately NOT touched.
