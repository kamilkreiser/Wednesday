## What is wrong (one paragraph)

In `routes/certifications.ts` the issue route has best-effort steps whose failure is logged and then ignored so the 201 still goes out: the KS-1633 pre-anchor reservation (`catch (reserveErr: any)`, line 581, logs a warn), the KS-70 derived-document write (`catch (saveErr: any)`, line 747, logs an error) and the KS-216 charge write (`catch (chargeErr: any)`, line 816, logs an error). Each log object reads `error: X instanceof Error ? X.message : String(X)` unguarded. If the thrown value is a revoked Proxy, `instanceof` itself throws inside the catch; if it is an Error whose `message` getter throws, that throw escapes the same way; if the getter returns a hostile non-string the real winston logger throws on it. The throw reaches the route's OUTER catch, which answers 500 'Failed to issue certification' although the best-effort step is meant to be ignored (for the derived-document and charge steps the certification is already saved, and for the charge step also anchored). The fix reads the thrown value inside its own `try` with the form PR 1924 merged, sets the constant `'unreadable thrown value'` when the read throws, and the log object uses `reason`. The log message texts, the other keys and the control flow are unchanged.
