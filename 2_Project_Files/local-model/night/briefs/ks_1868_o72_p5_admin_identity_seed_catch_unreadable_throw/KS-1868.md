## What is wrong (one paragraph)

In `routes/admin.ts`, `seedIdentityOrgsIfEmpty` (called first by GET /api/admin/identity/users, and only when demo seeding is enabled) wraps its seed queries in `try { ... } catch (err) { log('warn', '[Identity] Seed skipped: ' + (err as Error).message); }` (line 1238). If a seed query rejects with a revoked Proxy, or with an Error whose `message` getter throws, the `.message` read throws INSIDE the catch block, so the seed helper rejects, the route's own catch answers its constant 500 `Failed to fetch identity users`, and the user list is not returned. The fix keeps the log text and replaces only the value: it first reads the SAME expression `(err as Error).message` into a local `reason` inside its own `try`, and a `catch` sets the constant `'unreadable thrown value'`; the log line then concatenates `reason`. This is the inline guard already merged in the same file by PR 1916; no helper is added.
