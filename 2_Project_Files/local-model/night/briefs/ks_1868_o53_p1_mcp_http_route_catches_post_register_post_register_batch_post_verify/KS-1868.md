## What is wrong (one paragraph)

In `http-server.ts` the catch blocks of POST /register, POST /register-batch, POST /verify each contain `const message = err instanceof Error ? err.message : String(err);` (lines 91, 128 and 153) followed by `console.error('[mcp-http] <route> failed:', message);` and then answer a CONSTANT 500 body; the message is only logged. If the route's work rejects with a revoked Proxy, `err instanceof Error` itself throws a TypeError inside the catch block; if it rejects with an Error whose `message` getter throws, `err.message` throws. Either way the catch throws before the line is logged and before the 500 is sent; the async handler rejects, Express 4 does not catch that, and the request gets no response. The fix deletes the `const message` line and logs `describeThrown(err)` instead: `describeThrown` is a function declaration at module level (about line 42, used by the batch per-item catches at :122 and :185), its read is inside its own try, and for an Error it returns the Error's message, so an ordinary Error still logs its own message.

## Where

All three catches only LOG the value and then answer the constant 500 body. **BEHAVIOUR CHANGES the raise PR must state:** (1) unreadable thrown value: today the catch itself throws, the request gets NO response and Node sees an unhandled rejection (process-fatal on Node >= 15); after, the constant reason is logged and the route answers its existing constant 500. No response body changes on any of the three routes.
