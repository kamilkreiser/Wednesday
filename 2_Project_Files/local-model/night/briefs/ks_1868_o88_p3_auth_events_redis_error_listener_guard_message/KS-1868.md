## What is wrong (one paragraph)

The Redis client `'error'` listener in `initEventBus` passes the thrown value's message straight into the logger's meta object, unguarded: `{ error: err.message }`. A thrown value whose read throws (a revoked Proxy: the `.message` get throws; an Error whose `message` getter throws) therefore throws INSIDE the listener, and an exception thrown by a listener of the client's `'error'` event escapes the EventEmitter and is an uncaught exception in the auth process (the very event that says Redis is down turns into a process-level fault); an Error whose `message` is readable but not a string (a Symbol) is passed to the logger uncoerced. The fix is the house guard placed before the logger call: read the message once inside a `try`, keep `undefined`/`null` as they are (they were logged as is), coerce anything else with `String(...)`, and fall back to the constant `'unreadable thrown value'` when the read or the coercion throws; then `error: reason`. The init catch four lines below (line 101) is O88-P1, a separate pass whose hunk is more than 3 lines away; it is NOT part of this pass. The empty catches of `publishEvent` and `shutdownEventBus` read nothing and are untouched.
