## What is wrong (one paragraph)

`executeErasureByExternalRef` answers a connector's (Platform S) erasure request addressed by `external_ref`. When the ref resolves to a K users row it delegates to `executeErasureImpl`, which logs each step. When it resolves to NO users row but `action_provenance` rows still carry identity columns for the ref, it blanks `email_enc`, `display_name_enc` and `email_hash` on those rows, logs one `logger.info` line, and returns `completed`. Nothing is written to `data_deletion_log`, the table that is the accountability record of what was erased, by whom and why. So the one branch where K erased something for a subject it holds no user for leaves no record that it ran. The fix is one INSERT after the blank: `data_type = 'action_provenance'`, `records_affected` = the count the blank reported, `deletion_method = 'anonymize'`, a reason naming the ref and the tenant, `performed_by = connector:<id>`.
