## What is wrong (one paragraph)

Three DB read catches of the credential repository pass `err?.message` straight into the logger's meta object, unguarded. `?.` guards a null or undefined value only: a thrown value whose read throws (a revoked Proxy: the `.message` get throws; an Error whose `message` getter throws) makes the catch THROW, so the read REJECTS where an ordinary Error gets a logged warning and the documented in-memory fallback. The fix is the house guard placed before each logger call: read the message once inside a `try` (`?.` kept), keep `undefined`/`null` as they are, coerce anything else with `String(...)`, fall back to the constant `'unreadable thrown value'` when the read or the coercion throws; then `error: reason`. The three hunks are ~28 and ~41 lines apart. The write/revoke/list catches of this file (lines 96-99, 392, 481) are a separate brief (O90-P9) and untouched here; `getReadableByHash` (line 303) is deliberately not taken (see Skipped).
