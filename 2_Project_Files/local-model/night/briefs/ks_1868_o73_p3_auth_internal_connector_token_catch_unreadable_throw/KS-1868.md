## What is wrong (one paragraph)

In `internal.ts` the catch block of the connector-token exchange route logs `logger.error('connector-token exchange failed', { error: (err as Error).message })` (line 80) and then answers the constant `502 BAD_GATEWAY` 'Key validation unavailable'. If the upstream call (the security service key validation, or the token mint) rejects with a revoked Proxy, the property read `.message` itself throws a TypeError inside the catch block; if it rejects with an Error whose `message` getter throws, `.message` throws. Either way the catch throws before the line is logged and before the 502 is sent. Express 4 does not catch a rejection of an async handler, so the request gets NO response and Node sees an unhandled rejection. The fix reads the SAME expression `(err as Error).message` into a local `reason` inside its own `try`, and a `catch` sets the constant `'unreadable thrown value'`; the log call then uses `reason`. The 502 response is untouched. This is the inline guard already merged in `routes/auth.ts` (PR 1911, e.g. lines 308-313); no helper is added.
