## What is wrong (one paragraph)

The catch of `runAnchorStatusUpdate` passes the thrown value's message straight into the injected log call's meta object, unguarded: `{ anchorId, error: err?.message }`. The function's contract (its own doc comment) is that a statement that threw answers `null`, logged at warn, never rethrown. A thrown value whose read throws (a revoked Proxy: the `.message` get throws; an Error whose `message` getter throws) therefore throws INSIDE the catch, so the function REJECTS instead of answering `null`; an Error whose `message` is readable but not a string (a Symbol) is passed to the log uncoerced. The fix is the house guard placed before the log call: read the message once inside a `try`, keep `undefined`/`null` as they are (they were logged as is), coerce anything else with `String(...)`, and fall back to the constant `'unreadable thrown value'` when the read or the coercion throws; then `error: reason`. `return null` is unchanged.
