## What is wrong (one paragraph)

In `routes/auth.ts` the rehash catch of POST /login (runs only AFTER the whole credential gate passed) and the `.catch` on the refresh-JTI denylist write of POST /logout read the rejection's message in their own `try` (`reason = err?.message;`, constant `unreadable thrown value` when the read throws) and log `{ error: reason }`. The guard covers only the READ. If the getter succeeds and returns a hostile NON-string (a revoked Proxy, an object whose `toString` throws, a null-prototype object, a Symbol), the value is passed on uncoerced and the real logger can throw while formatting it, INSIDE the catch, outside the guard (QA gate 113, G113-F1, measured with the real winston: login answers 500 with no session; logout answers 500 with the cookie kept). The fix takes the read into a local and coerces it: `const m = err?.message; reason = m === undefined || m === null ? m : String(m);` inside the same `try`, so a value that cannot be turned into text throws inside the `try` and the existing `catch` gives the constant.
