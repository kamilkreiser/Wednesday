## What is wrong (one paragraph)

In `resolvePublicAddresses`, the lookup-failure catch reads the message inside a `try` (`reason = (err as Error).message;`, fallback `'unreadable thrown value'`), and the next statement builds `error: \`host "${bare}" could not be resolved (${reason}) - refusing to contact an unverifiable destination\``. When the read RETURNS a value a template literal cannot convert (a Symbol; an object whose `toString` throws; a revoked Proxy) the read passes the guard and the template literal throws outside it, so the function REJECTS instead of returning the refusal; `assertResolvedHostPublic`, `assertSafeOutboundUrl` and `safeOutboundRequest` reject with it. The fix is ONE line: coerce inside the existing `try` with `String(...)`: `reason = String((err as Error).message);`. A Symbol then reads as its text `Symbol(...)`, a value `String()` cannot convert lands in the existing fallback constant, and every string, `undefined` and `null` message reads exactly as it did in the template (`undefined` stays the word `undefined`). The template literal line is NOT touched.
