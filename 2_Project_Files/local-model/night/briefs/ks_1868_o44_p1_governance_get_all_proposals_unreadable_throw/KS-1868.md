## What is wrong (one paragraph)

In `governanceService.ts` the catch block of `dbGetAllProposals` logs `logger.error('DB get all proposals failed', { error: err instanceof Error ? err.message : String(err) })` (the read is on line 255) and then returns []. If the database call rejects with a revoked Proxy, `err instanceof Error` itself throws a TypeError inside the catch block; if it rejects with an Error whose `message` getter throws, `err.message` throws. Either way the catch throws before the ERROR line is logged and before the documented return: `getProposals` rejects with the hostile value instead of treating the list as empty. The fix reads the thrown value inside its own inner `try` into a local `reason`, falling back to the constant `unreadable thrown value`, and the log call uses `reason`. Nothing else changes: an ordinary Error still logs `{ error: <its message> }`.
