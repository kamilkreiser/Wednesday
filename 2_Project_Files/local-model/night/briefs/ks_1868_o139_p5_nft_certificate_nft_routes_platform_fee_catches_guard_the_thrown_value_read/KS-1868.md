## What is wrong (one paragraph)

Each catch below logs `logger.error('<message>', { error: error instanceof Error ? error.message : String(error) })` with the read written inline and unguarded, then answers a 500 envelope. For a caught value whose read throws (a revoked Proxy throws on `instanceof`; an Error whose `message` getter throws, throws on `.message`) the read throws inside the catch: the async Express 4 handler rejects, no reply is sent and the request hangs. The same file already guards its sibling catches with exactly this shape (lines 217 to 223: a local `reason` read inside its own try, the constant `unreadable thrown value` in the catch). The fix repeats it: lift the read into a local `reason` and log `{ error: reason }`; the log line and the 500 answer for an ordinary Error or a thrown string are unchanged. Priority Low: nothing known throws such a value here (no measurement).
