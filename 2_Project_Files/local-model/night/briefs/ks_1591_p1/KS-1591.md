## What is wrong (one paragraph)

`isPlatformRole` (`packages/shared/src/security/keyRevokePolicy.ts:140-142`) decides 'is this caller a platform administrator' with `PLATFORM_ROLES.has(String(role || '').toUpperCase())`. `toUpperCase` is not an identity test: U+0131 (dotless i) upper-cases to `I`, U+017F (long s) upper-cases to `S`, and `String(['SUPER_ADMIN'])` is `'SUPER_ADMIN'`, so `super_admin` spelled with either character and a role ARRAY read as SUPER_ADMIN (the pull request 1539 gate measured 200 and 201 on the key routes for all three). The change replaces the one `return` line with four lines: a refusal of any role that is not a string, then the same set lookup over an ASCII-only fold (`role.replace(/[a-z]/g, (ch) => ch.toUpperCase())`). Every ASCII spelling that was admitted before is admitted now (`SUPER_ADMIN`, `super_admin`, `Super_Admin`, `sYsTeM_aDmIn`); an empty, absent or ordinary role is refused as before. Reachability of such a token is NOT established (the ticket says so); the severity is a nit until measured.
