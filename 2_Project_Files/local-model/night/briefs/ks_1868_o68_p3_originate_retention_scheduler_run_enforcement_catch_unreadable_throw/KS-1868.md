## What is wrong (one paragraph)

In `services/retentionScheduler.ts` the private function `runEnforcement` (line 40) awaits `enforceRetention()` from `gdprService` inside a try; its catch (line 50) logs `logger.error('Scheduled enforcement failed', { error: err instanceof Error ? err.message : String(err) });` (line 51). If `enforceRetention` rejects with a revoked Proxy, `err instanceof Error` itself throws a TypeError inside the catch; if it rejects with an Error whose `message` getter throws, `err.message` throws. Either way the catch throws, nothing is logged, and `runEnforcement` REJECTS; its two callers (`setTimeout` callback line 27 and `setInterval` line 28) neither await nor catch it, so it becomes an unhandled rejection. The fix keeps the `logger.error` line's text and replaces only the value: it first reads the same expression into a local `reason` inside its own `try`, and a `catch` sets the constant `'unreadable thrown value'`; the log line then uses `{ error: reason }`. This is the inline guard already merged in originate `routes/certifications.ts` (`let reason`, around line 1087); this file has no helper and none is added. Nothing else in the function changes: the catch is the LAST statement of `runEnforcement`, it returns nothing and it decides nothing.
