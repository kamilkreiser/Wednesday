## What is wrong (one paragraph)

In `blockchain-verifier.service.ts`, `getClient` (line 66-73) catches a failed `new BlockFrostAPI(...)`, logs `err instanceof Error ? err.message : String(err)` and returns null ("verification disabled"); `verifyTransaction` (line 100-116) catches a failed `client.txs(txHash)`, reads `(err as { status_code?: number }).status_code`, logs the same expression, and returns `error: (err as Error).message ?? 'Unknown error'`. If the thrown value is a revoked Proxy, every one of those reads throws INSIDE the catch block (`instanceof` and property reads on a revoked Proxy throw); if it is an Error whose `message` getter throws, the `.message` reads throw. Either way the catch throws and the call rejects instead of answering. In `getClient` the logged expression is read inside a `try` with the constant fallback (the `let reason` guard). In `verifyTransaction` the catch gets, as its first statement after the comment, a probe `try` that performs every read the handling below it does (`status_code`, the `instanceof`/`message` expression, `.message`); if any of them throws, it logs the constant `'unreadable thrown value'` and returns `{ verified: false, status: 'error', error: 'unreadable thrown value' }`; otherwise the existing code below runs unchanged. Nothing else in the catch changes (the 404 mapping, the message texts, and the reads for readable values). No helper is added.
