## What is wrong (one paragraph)

In `repositories/certificationRepo.ts` `listCertifications` and `getSharesByCertification` each wrap one query in a `try`; the `catch (err: any)` logs a warn line with `error: err instanceof Error ? err.message : String(err)` and then re-throws `err` to the caller. If the thrown value is a revoked Proxy, `instanceof` itself throws inside the catch; if it is an Error whose `message` getter throws, that throw escapes the same way; if the getter returns a hostile non-string the real logger throws on it. In each case the caller receives a TypeError (or the logger's error) in place of the value that was caught, and nothing is logged by the repository (QA gate 105 G105-F3, measured: the route then logs the readable TypeError text). The fix reads the thrown value inside its own `try` with the form PR 1924 merged, sets the constant `'unreadable thrown value'` when the read throws, and the log call uses `reason`; the `throw err;` is unchanged, so the caller gets the original value, exactly as for an ordinary Error.
