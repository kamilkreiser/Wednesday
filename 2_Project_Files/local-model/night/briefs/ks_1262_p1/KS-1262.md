## What is wrong (one paragraph)

`PUT /api/admin/settings` (`requireAdmin`) writes the platform-wide record with `setNotificationSettings('platform-settings', merged)`. `PUT /api/settings/notifications` (`authenticateToken(true)`, any authenticated caller) writes `setNotificationSettings(userId, body)`, and both end up as `notif:<key>`. So a principal whose `userId` is exactly `platform-settings` replaces the platform-wide record, including the connector allow-list KS-1204 and KS-1230 enforce, without passing the admin door. The fix: in the per-user PUT handler, directly after `const userId = req.user!.userId;`, refuse that one id with `403 FORBIDDEN` and return before anything is stored.
