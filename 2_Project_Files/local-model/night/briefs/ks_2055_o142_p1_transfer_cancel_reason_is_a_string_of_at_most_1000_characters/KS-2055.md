## What is wrong (one paragraph)

POST /api/transfers/:id/cancel reads `const { reason } = req.body;` and records `reason || 'Cancelled by user'` in the history: any type (a number, an object) and any length is accepted and stored. The approve and reject routes declare `reason: z.string()...` in zod schemas (approveTransferSchema, rejectTransferSchema) and answer 400 on a bad body; the cancel route has no schema. Kam ruled the bound: 1000 characters.

## Where

`Blockchain/Dev/services/transfer/src/index.ts`: (1) a new module-level `cancelTransferSchema` after `rejectTransferSchema` (`reason: z.string().trim().max(1000).nullish()`); (2) the route head replaces `const { reason } = req.body;` with `safeParse`, a 400 in the file's own shape (`success:false`, `error.code 'BAD_REQUEST'`, `message 'Validation failed'`, `details: zod3Issues(...)`), then `const { reason } = parsed.data;`. The history line `reason: reason || 'Cancelled by user'` is NOT touched, so an absent, null, empty or whitespace-only reason still records the default (`nullish()` takes null as absent). The cancel route has no try/catch (approve and reject `.parse` inside a try), so this brief uses `safeParse` rather than adding a try: a thrown ZodError from an async Express 4 handler would be an unhandled rejection. The 400 is answered before the 404, the entitlement check and any write, as approve and reject do.
