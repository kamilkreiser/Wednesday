## What is wrong (one paragraph)

`fromRow` (`:218`) is async: for a row with an encrypted column it awaits `subjectDeks.getDek(row.id)`, a database read that can fail with an infrastructure error. Five lookups return `fromRow(...)` WITHOUT `await` from inside a `try`. A promise returned from a `try` block is not caught by its own `catch`, so a `getDek` failure skips the `catch` that logs it and maps infrastructure errors to `ServiceUnavailableError`, and the caller sees a raw unclassified error. `getUserById` already reads `return await fromRow(...)` at `:410` (KS-999) and is the positive control. The fix is to add the word `await` at the five sites. Nothing else changes.
