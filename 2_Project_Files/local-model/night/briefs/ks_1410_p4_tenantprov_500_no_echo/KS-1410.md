## What is wrong (one paragraph)

In `services/tenant-provisioning/src/index.ts`, six route handlers end in a `catch` that computes `const message = err instanceof Error ? err.message : String(err);` and answers `res.status(500).json({ success: false, error: { code: 'INTERNAL_ERROR', message: message } })`, so the thrown error's own text (a driver message or an internal host:port) reaches the caller. The fix, at each of the six: keep the `const message = ...` line; immediately after it, log the thrown text server-side with `console.error('[provisioning] <METHOD> <route> failed:', message);` (the text names the route as in the list below; the log text is yours to word, but it must start with `[provisioning]`, be one `console.error(` call and pass `message`); and answer the constant `{ success: false, error: { code: 'INTERNAL_ERROR', message: 'An unexpected error occurred' } }` (that exact string, no `details` key). The status 500, the code `INTERNAL_ERROR` and the envelope shape stay.
