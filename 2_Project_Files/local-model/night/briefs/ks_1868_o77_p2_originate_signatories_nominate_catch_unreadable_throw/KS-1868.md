## What is wrong (one paragraph)

In `routes/signatories.ts` the catch of the nominate route `POST /api/signatories` first reads `error.code === '23505'` (a unique-violation answers 409 CONFLICT) and then logs `Failed to nominate signatory` with `error: String(error)` and answers the constant 500. If the thrown value is a revoked Proxy, the property read `error.code` itself throws a TypeError inside the catch; if it is an Error whose `message` getter throws, `String(error)` throws. Either way the catch throws before it can answer: the async handler rejects and, under Express 4, the request gets NO RESPONSE (gate 104, G104-F3). **Both reads MUST be fixed together:** guarding only `String(error)` would still hang on a revoked Proxy at `error.code`. This is the same inline `let reason` guard that the neighbouring catches of this file already carry (KS-1868 O67, PR 1923: `try { reason = String(error); } catch { reason = 'unreadable thrown value'; }`); the `error.code` read gets the same treatment with an unreadable code treated as NO code, exactly what an ordinary Error without a `code` property gets. No helper is added.
