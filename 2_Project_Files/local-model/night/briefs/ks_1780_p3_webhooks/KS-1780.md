## What is wrong (one paragraph)

`PATCH /api/webhooks/:id` (`routes/webhooks.ts:312-326`) has a catch that begins `const pgCode = extractPgCode(err);` and only then falls through to `fail500`. `extractPgCode` (`utils/pgErrors.ts:51`) reads `e?.code`, `e?.meta?.code` and `e?.message` of the thrown value with no `try`. If the update rejects with a revoked Proxy, or with an object whose `code` (or `meta`, or `message`) getter throws, THAT read throws from inside the catch, before `fail500` is reached; the async handler's promise rejects and the request gets NO response (the KS-1772 shape, one step earlier). The change renames the body of `extractPgCode` to a private `readPgCode` and makes `extractPgCode` a wrapper that calls it inside a `try` and answers `undefined` when it throws: a value that cannot be read has no SQLSTATE, so the caller falls through to `fail500`'s constant 500. Every value that could be read before gives the same answer as before.
