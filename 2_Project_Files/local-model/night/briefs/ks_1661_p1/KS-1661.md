## What is wrong (one paragraph)

When a verify finds a row whose stored blockchain blob is stale (`pending`, with a real transaction hash), both routers ask the anchoring service's chain index and, if the answer attributes a confirmed anchor to the same transaction or document, upgrade the blob to `confirmed` and hand it to `persistHealedAnchor`, which writes it back. Each heal function refuses early when the STORED blob is simulated (`blob.simulated === true`), but neither looks at the INCOMING chain reply's own `simulated` flag. A simulated chain reply that carries a real-looking hash would therefore heal a row to `confirmed` and persist it. v1: in `confirmStalePendingAnchor`, the line `if (chain?.verified !== true || !chainTx || !REAL_TXHASH_RE.test(chainTx)) return blob;` (right after `const chainTx = ...`) gains `|| chain.simulated` after the `chain?.verified !== true` test. v2: in `healBlobWithChainFact`, the first line `if (!blob || blob.simulated === true || !chain) return blob;` gains `|| chain.simulated` after `!chain`. Each is a truthy test, NOT `=== true`. A comment line is added directly above each edited line.
