## What is wrong (one paragraph)

`GET /api/platform/audit-log` (`:359`) reads `limit` as `Math.min(parseInt(req.query.limit as string) || 50, 500)` (`:370`) and `offset` as `Math.min(parseInt(req.query.offset as string) || 0, MAX_AUDIT_OFFSET)` (`:377`). A non-numeric value (`limit=abc`) silently becomes the default, a fraction (`offset=1.5`) is truncated, `limit=0` becomes 50, and a negative value passes straight through (`offset=-1` gives an overfetch of 49), all answering 200. The published operation declares `limit` an integer with `exclusiveMinimum: 0` and `offset` an integer with `minimum: 0`, and declares a 400 (`docs/openapi/secuura-api.yaml`, `/api/platform/audit-log`). The KS-1353 Schemathesis sweeps flag 30 such cases every run (`GET /api/platform/audit-log?offset=-1` as a platform admin -> 200), beyond the KS-518/KS-662 by-design tolerance (KS-1359). **This task: a PRESENT `limit` that is not a whole number from 1, or a PRESENT `offset` that is not a whole number from 0, is refused 400 before any upstream call or query.** An absent value keeps its default; a whole number above the maximum is still clamped exactly as today (KS-5).
