## What is wrong (one paragraph)

In `routes/certifications.ts`, when the anchoring service is unavailable in PRODUCTION (line 634), the issue route compensates the pre-anchor reservation row with `deleteCertification` inside a `try` and then answers 503. The `catch (delErr: any)` (line 655) logs `error: delErr instanceof Error ? delErr.message : String(delErr)` and still falls through to the 503. If the thrown value is a revoked Proxy, `instanceof` itself throws inside the catch; if it is an Error whose `message` getter throws, that throw escapes the same way; if the getter returns a hostile non-string the real winston logger throws on it. The throw reaches the route's OUTER catch, which answers 500 'Failed to issue certification' instead of the 503 that an ordinary delete failure gets, and the 'a certification remains with no anchor' alarm line is not written. The fix reads the thrown value inside its own `try` with the form PR 1924 merged, sets the constant `'unreadable thrown value'` when the read throws, and the log call uses `reason`.
