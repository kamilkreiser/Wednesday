## What is wrong (one paragraph)

In `credentialRepo.ts` the catch block of `credentialRepo.loadFromDb` (starts at line 430) logs `logger.warn(..., { error: err instanceof Error ? err.message : String(err) })` (line 432). If the thrown value is a revoked Proxy, `err instanceof Error` itself throws a TypeError ("Cannot perform 'getPrototypeOf' on a proxy that has been revoked") inside the catch block; if it is an Error whose `message` getter throws, `err.message` throws. Either way the WARN is not logged and the function rejects. The fix reads the thrown value inside its own inner `try` into a local `reason`, falling back to the constant `unreadable thrown value`, and the log line uses `reason`. Nothing else changes: an ordinary Error still logs `{ error: <its message> }`, and the message text of the WARN is unchanged. Note: `ensureTable()` (called first inside the same `try`) has its own `err?.message` catch at :46-48; it is NOT touched and is not reached by the cells, because the stand-in resolves the existence-check query and rejects only the `SELECT ... ORDER BY created_at` query.
