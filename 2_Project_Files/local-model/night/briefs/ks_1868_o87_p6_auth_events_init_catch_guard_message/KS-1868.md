## What is wrong (one paragraph)

The catch of `initEventBus` passes the thrown value's message straight into the logger's meta object, unguarded: `{ error: err?.message }`. A thrown value whose read throws (a revoked Proxy: the `.message` get throws; an Error whose `message` getter throws) therefore throws INSIDE the catch, so `initEventBus` THROWS instead of answering `false` (its contract, in its own doc comment: `true` if the Redis connection was established; on failure the service carries on without events); an Error whose `message` is readable but not a string (a Symbol) is passed to the logger uncoerced. The fix is the house guard placed before the logger call: read the message once inside a `try`, keep `undefined`/`null` as they are (they were logged as is), coerce anything else with `String(...)`, and fall back to the constant `'unreadable thrown value'` when the read or the coercion throws; then `error: reason`; `return false` is unchanged. The Redis client `'error'` listener two lines above (`{ error: err.message }`, line 95) has the same defect but is deliberately NOT part of this pass: the lines between the two sites include a blank line, and a single hunk spanning a blank context line is refused by the harness (the model would not reproduce it); the listener is left for a separate pass or a Claude seat. The empty catches of `publishEvent` and `shutdownEventBus` read nothing and are untouched.
