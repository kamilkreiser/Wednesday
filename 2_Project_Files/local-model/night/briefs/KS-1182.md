## What is wrong (one paragraph)

The #1006 gate (F4) measured the new demo-service `errorHandler` on synthetic errors. It applies `err.status`
unchecked: statuses 200, 302 and 600 go out as they are; a string `'400'` goes out as 400; a status of 99 or NaN makes
`res.status(...).json(...)` throw inside the handler, so the handler never answers (with express's own final handler
behind it, NaN crashed the process). It ignores `res.headersSent`, so an error after the response started makes it
throw `ERR_HTTP_HEADERS_SENT` instead of handing the error on. It drops `err.headers` (the `Allow` of a 405), and it
echoes the message of a 4xx marked `expose: false`. **No current producer sets any of these; this is hardening.**
**This task:** hand an error on with `next(err)` when headers are already sent; treat only an integer from 400 to 599
as a status and answer 500 otherwise; send the error's own headers with its own status; and replace the message of a
4xx marked `expose: false` with the constant `Request error`. Five named lines change; nothing else in the file does.

type Reply = { status: number; allow: string | undefined; backstop: boolean; body: string };

let backstopSaw: unknown = null;
let server: http.Server;
let port = 0;

beforeAll(async () => {

  app.get('/boom', (_req: Request, res: Response, next: NextFunction) => {
    if (startBody) {
      res.writeHead(200, { 'content-type': 'text/plain' });
      res.write('partial');

function drive(err: unknown, beginBody = false): Promise<Reply> {
