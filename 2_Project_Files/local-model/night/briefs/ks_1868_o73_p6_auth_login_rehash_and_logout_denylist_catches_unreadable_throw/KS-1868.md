## What is wrong (one paragraph)

In `auth.ts` two handlers that are meant to be non-fatal read the rejection value with `err?.message`: the catch around the password-hash upgrade in POST /login (line 555: `logger.warn('UPGRADE-ON-VERIFY rehash failed (non-fatal)', { userId: user.id, error: err?.message })`) and the `.catch` on `denylistRefreshJti` in POST /logout (line 784: `logger.warn('Logout denylist failed (non-fatal)', { error: err?.message })`). If the awaited call rejects with a revoked Proxy, the property read `err?.message` itself throws a TypeError inside the handler; if it rejects with an Error whose `message` getter throws, `err?.message` throws. Either way the handler throws before the line is logged: in /login the exception leaves the route's try and ends in the error handler as a 500 with NO tokens (the password was verified and the session was not yet created), in /logout the `await` rejects, the route's catch calls `next(error)` and the client gets a 500, with the refresh cookie NOT cleared (the session revocation above it already ran). The fix reads the SAME expression `err?.message` into a local `reason` inside its own `try`, and a `catch` sets the constant `'unreadable thrown value'`; the log call then uses `reason`. This is the inline guard already merged in the same file (PR 1911, lines 308-313, 622-627, 896-900); no helper is added.
