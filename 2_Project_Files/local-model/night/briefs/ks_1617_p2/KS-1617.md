## What is wrong (one paragraph)

When a provider redirects back with `?error=...`, the callback logs one structured warning (`provider`, `providerError`, the latter `String(req.query.error).slice(0, 200)`) and throws `OAuthProviderError`, a generic 400. The provider's `error_description` query parameter is where it says which thing is wrong (a redirect-URI mismatch, an unauthorised client, an expired secret); it is dropped, so an operator cannot tell a misconfigured provider from a user who pressed Cancel. The warning gains one field, `providerErrorDescription`, trimmed the same way. It is attacker-controllable (it arrives on a browser redirect), which is why it is only LOGGED, trimmed to 200 characters, and never echoed: the existing F-4 cell `does not echo the provider's error text back to the caller` keeps pinning that.
