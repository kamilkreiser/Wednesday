## What is wrong (one paragraph)

In `scheduledJobs.ts` the catch block of `dbSaveAlertRule` (line 58) logs `logger.info('DB save alert rule failed', { error: err instanceof Error ? err.message : String(err) })` (the read is on line 59). If the database call rejects with a revoked Proxy, `err instanceof Error` itself throws a TypeError inside the catch block; if it rejects with an Error whose `message` getter throws, `err.message` throws. Either way the catch throws before the INFO line is logged: the returned promise rejects, the callers' `.catch(() => {})` swallow it, and the operator sees no log line at all. The fix reads the thrown value inside its own inner `try` into a local `reason`, falling back to the constant `unreadable thrown value`, and the log call uses `reason`. Nothing else changes: an ordinary Error still logs `{ error: <its message> }` and the log text is unchanged.
