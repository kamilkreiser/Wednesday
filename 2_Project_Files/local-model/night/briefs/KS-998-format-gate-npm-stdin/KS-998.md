## What is wrong (one paragraph)

The gate's per-package loop reads its selection from a here-string on stdin: `:138` `while IFS= read -r p; do` … `:196` `done <<< "$selected"`. Inside that loop, `:152` runs `out="$(cd "$dir" && npm run --silent format:check 2>&1)"` with NO stdin redirect, so npm, and the package's `format:check` script under it, inherit the loop's stdin, which is the list of packages not yet checked. A `format:check` that reads stdin consumes those names: the loop then ends early, the packages after it are never checked, and **a red package among them passes the gate (exit 0)**. Measured at the tip with the suite below: selection `drain` (format:check `cat >/dev/null; exit 0`) then `red` (a `[warn]` line, exit 1) exits **0**, and `drain` then `green` reports `1 package(s) checked` instead of 2. Each package alone, and two packages with no stdin reader, behave correctly (the CONTROL cells). `< /dev/null` on the npm call gives each format:check an empty stdin, so the loop keeps its own. The defect is latent in the live tree: all 4 real gated packages (akto, api-explorer, performance, playwright) run `prettier --check … .`, which does not read stdin (read from each `package.json` at the tip).
