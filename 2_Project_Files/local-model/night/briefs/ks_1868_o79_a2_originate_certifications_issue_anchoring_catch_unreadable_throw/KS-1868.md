## What is wrong (one paragraph)

In `routes/certifications.ts` the issue route posts the certification's anchor to the anchoring service inside an inner `try`, and the inner `catch (err: any)` is `logger.warn('Anchoring service unreachable for certification', { certId: id, error: err?.message })`; the route then continues (a production anchoring failure answers 503 after compensating the reservation; outside production it saves the certification with `anchoringStatus: 'failed'`, writes the derived document, records the sign and anchor charges and answers 201). If the rejection is a revoked Proxy, `err?.message` itself throws inside the catch; if it is an Error whose `message` getter throws, that throw escapes the same way; if the getter returns a hostile non-string the real winston logger throws on it. Any of these escapes the inner catch and reaches the route's OUTER catch, which answers 500 'Failed to issue certification' BEFORE the save, the charges and the derived document, so no certification is issued and none is charged (and the pre-anchor reservation row, if it landed, is left as it is). The fix reads the thrown value inside its own `try` with the coercing form PR 1924 merged for the outer catches, sets the constant `'unreadable thrown value'` when the read throws, and the log call uses `reason`.
