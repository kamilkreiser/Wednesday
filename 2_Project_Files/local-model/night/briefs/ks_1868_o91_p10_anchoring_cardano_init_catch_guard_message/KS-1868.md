## What is wrong (one paragraph)

The catch interpolates `${err?.message}` into the `logger.error` template literal, unguarded. A thrown value whose read throws (a revoked Proxy: the `.message` get throws; an Error whose `message` getter throws) therefore throws INSIDE the catch, so `initCardano` REJECTS to its boot caller instead of logging and answering `false` (real chain operations unavailable; `cardanoConfigured` was already recorded as true before the `try`, so `/health` can still say configured-but-not-ready); an Error whose `message` is a Symbol makes the template literal itself throw. The fix is the house guard placed before the `logger.error`: read the message once inside a `try`, keep `undefined`/`null` as they are (the template printed them as the words `undefined` / `null`), coerce anything else with `String(...)`, and fall back to the constant `'unreadable thrown value'` when the read or the coercion throws; then `${reason}` in the template. The `return false` line is untouched.
