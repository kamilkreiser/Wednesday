## What is wrong (one paragraph)

Three catches of this module pass `err?.message` straight into `console.error` / `console.warn` as an argument, with the read INSIDE the call's arguments, unguarded. A thrown value whose read throws (a revoked Proxy: the `.message` get throws; an Error whose `message` getter throws) therefore throws INSIDE the catch, so `verifyDbReady` (the boot probe, which documents that a missing table is only a warning) and `processEscalations` (which answers its zero counts) REJECT instead; an Error whose `message` is readable but not a string (a null-prototype object, a Symbol) is handed to the console uncoerced. The fix is the house guard placed before each console call: read the message once inside a `try`, keep `undefined`/`null` as they are (they were logged as is), coerce anything else with `String(...)`, and fall back to the constant `'unreadable thrown value'` when the read or the coercion throws; then `reason` in place of `err?.message`.
