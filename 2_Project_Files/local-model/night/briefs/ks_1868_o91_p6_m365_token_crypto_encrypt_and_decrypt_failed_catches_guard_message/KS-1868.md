## What is wrong (one paragraph)

Both catches log `error: err?.message` with the read INSIDE the logger call's arguments, unguarded. A thrown value whose read throws (a revoked Proxy: the `.message` get throws; an Error whose `message` getter throws) therefore throws INSIDE the catch, so the module's fail-closed answers are lost: `encryptToken` THROWS instead of answering `null` (its own comment: the only caller wraps the whole INSERT in a try/catch that merely logs, so a throw discards the ENTIRE connection row) and `decryptToken` throws instead of answering `undefined` (the caller's re-authenticate path); an Error whose `message` is readable but not a string (a Symbol) is handed to the logger uncoerced. The fix is the house guard placed before each logger call: read the message once inside a `try`, keep `undefined`/`null` as they are (they were logged as is), coerce anything else with `String(...)`, and fall back to the constant `'unreadable thrown value'` when the read or the coercion throws; then `error: reason`. The `return null` and `return undefined` lines are untouched; nothing else in the file changes.
