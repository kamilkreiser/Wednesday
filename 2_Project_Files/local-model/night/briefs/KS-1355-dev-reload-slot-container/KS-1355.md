## What is wrong (one paragraph)

`dev-reload.sh` names the container it hot-swaps into as `CONTAINER="secuura-$SVC"` (`:45`), slot 1's name, and never sources `stack_env.sh`. `stack_env.sh` is where a stack slot becomes a container prefix: slot 1 keeps `STACK_PREFIX=secuura` (`:91`-`:93`), slot N >= 2 gets `STACK_PREFIX=secuura-sN` (`:87`-`:90`). So on a slot-2 worktree (`SECUURA_STACK_SLOT=2`) the script looks for `secuura-<svc>`: if slot 1 is not running it refuses (`:54`-`:58`) although `secuura-s2-<svc>` is up; if slot 1 IS running it builds this worktree's `dist/`, `docker cp`s it into SLOT 1's container and restarts it (`:69`-`:74`) — another stack's service, reported as `reloaded`. Measured at the tip with the suite below: with `secuura-demo` and `secuura-s2-demo` both up and `SECUURA_STACK_SLOT=2`, the tip restarts `secuura-demo`. The fix sources `stack_env.sh` (with `PROJECT_ROOT`, which it requires at `:20`-`:23`, set to the repo root as `stop-secuura.sh` does) and names the container `${STACK_PREFIX}-$SVC`. Slot 1 is unchanged by construction (`STACK_PREFIX` defaults to `secuura`). A malformed or out-of-range slot now exits 2 inside `stack_env.sh` (`:38`-`:53`) instead of silently aiming at slot 1.
