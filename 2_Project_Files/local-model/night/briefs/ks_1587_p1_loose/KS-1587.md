## What is wrong (one paragraph)

`transaction()` in `services/security/src/db.ts:59-72` checks a client out of the pool (`getClient()`), runs BEGIN, the callback and COMMIT, and releases the client in a `finally`. Nothing listens for the client's `'error'` event. When the database kills the backend under a checked-out client (a failover, a terminated session) `pg` emits `'error'` on the client; an EventEmitter with no listener turns that into an uncaught exception, and in production an uncaught exception exits the process (gracefulShutdown). The request itself fails with the query's own rejection and the next request works, so the process exit is the avoidable part. The change: after `getClient()`, attach a named handler `onClientError` that logs through `dbLog('error', 'DB client error while checked out', { error: err.message })`, and in the `finally` call `client.removeListener('error', onClientError)` before `client.release()`. Nothing else in the function changes.
