## What is wrong (one paragraph)

`childSuiteCounts` (`:89`-`:106`) spawns a child vitest over the slot-sensitive files and reads its verdict from TEXT: it joins stdout and stderr (`:100`), takes the FIRST match of `/Tests\s+(?:(\d+) failed \| )?(\d+) passed \((\d+)\)/` (`:101`), and never looks at the spawn's `status`, `signal` or `error`. So (KS-1313) a real fail-only, skip-only or todo-only summary (`Tests  1 failed (1)` etc.) has no `passed` segment and reads NULL, then throws; an earlier `Tests  5 passed (5)` console line wins over the real summary; and (KS-1326) a child KILLED by the 180 s `spawnSync` timeout after printing a summary-shaped pair reads as a clean pass. Measured by this writer with real vitest children (below): a child killed by a 6 s spawn timeout after logging ` Test Files  1 passed (1)` / `      Tests  7 passed (7)` returns `status 143, signal null, error ETIMEDOUT`, writes NO JSON report, and its stdout still carries `Tests  7 passed (7)`. The fix (DECISIONS-24 ruled shape): run the child with `--reporter=default --reporter=json --outputFile.json=<fresh temp file>`; a pure `countsFromSpawn(spawn, reportJson)` refuses FIRST when the child did not end normally (`error` set, `signal` set, or `status` not 0/1), then refuses a missing / unparsable / count-less report, then returns `numPassedTests` / `numFailedTests`. `childSuiteCounts` reads the file (null if absent), removes the temp dir, and returns `countsFromSpawn(result, reportJson)`. Nothing is read from stdout or stderr.
