## What is wrong (one paragraph)

`POST /api/status/:id/unrevoke` (`:304`) unrevokes by `credentialId` and never reads `index`. Since KS-1269 it refuses a present `index` that is not an integer (`:327`-`:330`), but a NEGATIVE integer passes that check, so `{"credentialId": "...", "index": -1}` answers 200 `revoked: false` and the unrevoke runs. The published request schema declares `index` a non-negative integer (`vc-issuer.openapi.ts:979`, `index: z.number().int().nonnegative().optional()`) and declares a 400 for this path (`:1621`). The KS-662 ruling tolerates a below-minimum `index` on `/revoke` only; on `/unrevoke` it tolerates only a non-string `reason`, and its own record lists `POST /api/status/0/unrevoke {index:-1} -> 200` under NON-RULED (read on Linear, KS-662, 2026-09-29). The Schemathesis sweeps catch this case in every run (KS-1371; KS-1269 comment 2026-09-28 12:31). **This task: a present `index` below 0 is refused 400 on `/unrevoke`, exactly like a non-integer one.** An absent `index`, `index: 0` and a positive integer keep today's path. `/revoke` still admits `-1`.
