## What is wrong (one paragraph)

`getConnectorBearer` (`middleware/auth.ts:194`) and `validateApiKey` (`:222`) each `await fetch(...)` an internal upstream (auth's `/internal/connector-token`, security's `/api/keys/validate`) with NO `signal`. An upstream that accepts the connection and never answers, or answers its body seconds late, holds the gateway request open for as long as the socket lives (the gate measured 'never answers: hangs' and 'body 2.5 s late: hangs 2.5 s' on both develop and head). The change adds one module constant `UPSTREAM_AUTH_FETCH_TIMEOUT_MS = 5_000` and passes `signal: AbortSignal.timeout(UPSTREAM_AUTH_FETCH_TIMEOUT_MS)` in both fetches. When the signal fires the fetch rejects, and each function's EXISTING `catch` answers `null` exactly as for an unreachable upstream. Nothing else changes for a healthy upstream.
