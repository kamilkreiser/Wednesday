## What is wrong (one paragraph)

In `routes/signatories.ts` the catch blocks of GET /api/signatories (list, line 180), GET /api/signatories/check (line 235) and GET /api/signatories/:id (line 283) each log `logger.error('<context>', { error: String(error) })` and then answer a constant 500. If the database call rejects with a revoked Proxy, or with an Error whose `message` getter throws, `String(error)` itself throws inside the catch; the catch throws, nothing is logged and the request gets no answer. The fix keeps each log line's text and replaces only the value: it first reads the same expression `String(error)` into a local `reason` inside its own `try`, and a `catch` sets the constant `'unreadable thrown value'`; the log line then uses `{ error: reason }`. The constant 500 answers are untouched. This is the inline guard already merged in originate `routes/certifications.ts` (`let reason: string; try { ... } catch { reason = 'unreadable thrown value'; }`); this file has no helper and none is added.
