## What is wrong (one paragraph)

In the no-upstream branch of `.githooks/pre-push`, line 165 sets `_refs='develop origin/develop refs/remotes/origin/develop'` and the loop at line 175 tries each name with `git rev-parse --verify --quiet`. A bare name such as `develop` is resolved by git in the order exact ref, tags, heads, remotes, so a TAG named `develop` is chosen before the branch, and `--quiet` hides git's "refname is ambiguous" warning. The hook then computes its merge-base against the tag and decides from the wrong changed set whether to run the Blockchain/Dev preflight. The stale-ref guard at lines 166-169 (KS-991) names the bare `develop` three more times, so a tag can fool that guard too. The fix is to spell the local branch as `refs/heads/develop` everywhere the hook means the local branch, and to spell the remote-tracking ref as `refs/remotes/origin/develop` where the list is rebuilt at line 173. No logic changes; only the ref spellings.
