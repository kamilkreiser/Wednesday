## What is wrong (one paragraph)

In `linkedin.ts`, `exchange()` reads the token answer at line 85: `const { access_token } = (await tokenRes.json()) as { access_token: string };` with no check, and the value is used in `Authorization: Bearer ${access_token}`, so an undefined token goes out as `Bearer undefined`. A 200 answer with no `access_token` (empty object, non-string, empty string) therefore reaches the LinkedIn profile endpoint with an undefined token, and the sign-in fails there with a profile-fetch error instead of at the token exchange. The fix reads the answer into `tokenBody` typed `{ access_token?: unknown }`, refuses a missing, non-string or empty `access_token` with a logged warning (provider name only, never the answer) and an Error `LinkedIn token exchange failed (no access token)`, before any profile call, and then binds `const access_token = tokenBody.access_token;` so every later line of the file stays as it is. Nothing else changes: the `!tokenRes.ok` branch above (`LinkedIn token exchange failed (HTTP <status>)`), the profile call, the profile mapping and `exchangeCode`'s timeout/unreachable wrapper stay as they are. A non-timeout Error is rethrown by `exchangeCode` unchanged, so the new message reaches the caller as written.
