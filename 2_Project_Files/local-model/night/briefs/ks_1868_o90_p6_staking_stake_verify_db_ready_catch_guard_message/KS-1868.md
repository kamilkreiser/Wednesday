## What is wrong (one paragraph)

The catch of `verifyDbReady` (`src/routes/stake.ts` line 148) passes `err?.message` straight into the logger's meta object, unguarded. `?.` guards a null or undefined value only: a thrown value whose read throws (a revoked Proxy: the `.message` get throws; an Error whose `message` getter throws) makes the catch THROW, so `verifyDbReady` REJECTS where an ordinary Error gets a logged failure and a resolved call; an Error whose `message` is readable but not a string (a Symbol) is handed to the logger uncoerced. The fix is the house guard placed before the logger call: read the message once inside a `try` (`?.` kept), keep `undefined`/`null` as they are, coerce anything else with `String(...)`, fall back to the constant `'unreadable thrown value'` when the read or the coercion throws; then `error: reason`. The other catches of the file forward to `next(error)` and are untouched.
