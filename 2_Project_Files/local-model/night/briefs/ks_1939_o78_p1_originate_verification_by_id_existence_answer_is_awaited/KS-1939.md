## What is wrong (one paragraph)

In `routes/verification.ts` the public, no-login `POST /api/verification/verify` has a lookup block `try { ... } catch (dbErr) { logger.warn('Verification lookup failed', ...); return res.json({ verified: false, error: 'Verification lookup failed' }); }`. Strategy 2 (a body with a `documentId`) answers a found row with `return respondExistenceOnly(rows[0], '...')`. `respondExistenceOnly` is an `async` function, and the call is NOT awaited: a throw inside it (a field read of the row, `buildCertification`, the response write) is a rejected promise that is returned out of the `try`, so the lookup catch never sees it, and the outer catch never sees it either. The handler's promise rejects and, under Express 4, the request gets NO RESPONSE, even for an ordinary Error (QA gate 106, G106-F2, measured at base and head). Every other throw inside that `try` (the lookup query, the strategy-1 branches, which are awaited or synchronous) is caught and answered 200 'Verification lookup failed'. The fix is `return await respondExistenceOnly(`: the one line changes and nothing else; the success path returns the same value.
