## What is wrong (one paragraph)

In `parseCert` the catch around `new crypto.X509Certificate(trimmed)` (line 113) and in `verifyKeyMatchesCert` the catches around `crypto.createPrivateKey` (line 198) and `crypto.sign` (line 218) each begin with `const msg = err instanceof Error ? err.message : String(err);` (lines 114, 199, 219) and then throw an `IssuerCertError` with a stable code (`INVALID_CERT_PEM`, `KEY_PARSE_ERROR`, `KEY_MISMATCH`) that the route layer maps to a 4xx answer. For a caught value whose read throws (a revoked Proxy throws on `instanceof`; an Error whose `message` getter throws, throws on `.message`) the read itself throws first: the caller gets a bare TypeError, not the coded IssuerCertError, so the route's code mapping does not apply and the upload answers an unmapped 500. The fix: read into a local `msg` inside its own try, with the constant `unreadable thrown value` in the catch; the IssuerCertError text for an ordinary Error is unchanged (`Could not parse cert: <message>` and so on). Priority Low: nothing known throws such a value from node:crypto (no measurement).
