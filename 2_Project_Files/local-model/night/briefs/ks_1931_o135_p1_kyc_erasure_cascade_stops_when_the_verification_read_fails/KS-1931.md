## What is wrong (one paragraph)

In `Blockchain/Dev/services/kyc/src/index.ts`, `dbGetVerificationsByUser` (line 223) catches every database or decrypt error, logs it and returns `[]` (line 240). `dbDeleteUserData` (the GDPR erasure cascade, line 372) calls it at line 390 to collect legacy image ids, then deletes images, consents and verification rows by `user_id` regardless. So when the read fails the cascade goes on with an empty list: the verification rows are deleted and the legacy images only they pointed to survive, and the route `DELETE /api/kyc/user/:userId/data` (line 1224) answers that all data was deleted. The comment at lines 380 to 383 of the same function says the opposite: "failures THROW so the event bus retries and dead-letters". The fix: the cascade asks for a throwing form of the read; every other caller keeps the empty list.
