## What is wrong (one paragraph)

`refuseConnectorBearer` (`auth.ts:267-283`) logs one structured warning, `CONNECTOR_JWT_AS_BEARER_REFUSED`, whenever a verified connector JWT is presented as a Bearer. Its `path` field is `req.path`. Inside a router mounted with `app.use('/api/credentials', router)`, express rewrites `req.path` to the mount-relative remainder, so a refused `GET /api/credentials/abc` logs `"path":"/abc"` and the log no longer says which route it was; the warning exists precisely so the first Kintsugi cycle shows WHICH call presented a connector Bearer. `req.baseUrl` holds the mount prefix (`/api/credentials`), so `req.baseUrl + req.path` is the full path without a query string. `req.originalUrl` is deliberately NOT used: it carries the query string, which can hold a token.

## Where

- `:274` - (correct) stays, hunk context (`    method: req.method,`).
- `:275` - **must change**: `    path: req.path,` becomes `    path: req.baseUrl + req.path,`.
- `:276` - (correct) stays, hunk context (`    requestId: req.requestId,`).
