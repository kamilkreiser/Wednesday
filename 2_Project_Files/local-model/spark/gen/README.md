# spark/gen - the brief generator (rescued into the tree 2026-10-28, extended by Spark operator 4)

Batches 1-5 briefs were generated by script, never typed; goldens come from difflib. The scripts used to live in a session scratchpad and died with it three
times. They live here now and derive every path from `__file__` (no scratchpad path anywhere: `grep -rn /private/tmp gen/` finds nothing).

| file | what |
|---|---|
| `mk.py` | `python3 -I gen/mk.py gen/specX.py` - reads spec `S`, builds products/tests, writes `night/briefs/<dir>/{KS-n.md,golden.diff,spark.pins}`. REFUSES to overwrite an existing brief dir unless `GEN_OVERWRITE=1` (it once overwrote a tracked ks_1515_p1 on 2026-10-28; git `show HEAD:` restored it) |
| `mk2.py` | mk.py + LOOSE briefs (`S['loose']` text replaces the dictated product diff; `S['rung_raw']`) |
| `loosegen.py <spec> [suffix]` | builds the LOOSE (rung 4) TWIN of any existing spec: the product diff is not given, every hunk header and its unchanged context lines are dictated FROM THE GOLDEN (p9b shape). A twin is a calibration, not a second candidate. Caveat: it reuses the spec's `wrong`/`where` prose, which often names the literal lines, so it is looser in format than in semantics |
| `mk_testonly.py <spec>` | builds a `test_only` brief (ONE existing test modified in place + a planted tamper in the product, `## Tamper`/`## Red cells`); see `specY.py`/`specZ.py` |
| `specA..AA.py` | one spec per brief. A-T = batches 1-4 (ks_1780_p2 ... ks_1240_p9_internal_loose; `specL` chains onto `specI`). U = ks_1515 (QUARANTINED: timestamping tsc baseline red, see below), V = ks_1732_p1, W = ks_1684_p1, X = ks_1240_p10_demo_auth, Y/Z = ks_1588_p1_header/_error (test_only), AA = ks_1579_p1_wording |
| `chk.sh <dir-name>` | lint + dry-run + control for `night/briefs/<dir-name>`, waiting out BUSY (control cannot run while a round holds round.lock) |
| `overlap.py <dir-name>...` | golden.diff file set vs (a) the files of today's READY_* passes (`HELD_SINCE=YYYY-MM-DD` to change) and (b) every OPEN Secuura PR's files (gh with the Secuura `GH_TOKEN` from its .env in a scratch `GH_CONFIG_DIR`; token never printed) |
| `ticket.py KS-n...` | prints Linear ticket text (read only; needs `LINEAR_API_KEY` in the env: `set -a; . <Secuura 4_Credentials/.env>; set +a`) |
| `keepdraining.sh` | re-runs `queue.sh` whenever `queue.md` has an entry (queue.sh exits when empty, so a brief appended afterwards idled the Spark). Stop: create `state/keepdraining.stop` or kill the pid in `state/keepdraining.pid` |

Env overrides: `GEN_BRIEFS` (output dir, default `night/briefs/`), `GEN_TIP` (default `65bc2823...`, the base the batch 1-4 briefs were built at; SET IT to the current
develop sha for a new brief: `git -C spark/cache/src ls-remote origin refs/heads/develop`), `GEN_SRC` (read files from a checked-out tree instead of
`git show $GEN_TIP:<path>` in `spark/cache/src`), `GEN_OVERWRITE=1`.

Proof (2026-10-28): `GEN_BRIEFS=<scratch> python3 -I gen/mk.py gen/specS.py`, `mk.py specL.py` and `mk2.py specT.py` each reproduced the queued brief dir
(ks_1240_p8_provisioning, ks_1240_p3_batch_audit, ks_1240_p9_internal_loose) with `diff -r` empty. `ks_1240_p9b_internal_loose` was hand-edited from specT output
and has no spec. Always set `GEN_BRIEFS` to a scratch dir when regenerating an OLD brief.

Builder rules met while drafting (each cost a control round): a `+` line equal (after strip) to a `-` line in the same fence is refused as CONTEXT (do not re-indent
a block); a red cell must fail by ASSERTION, not by a TypeError (use `?.`); `test_file=`/the first `## The test` File must not equal `ref=`, and in code_patch2 the
NEW test goes FIRST in the tests list; the timestamping service cannot pass A7 here (tsc baseline red: asn1js/pkijs not installed).
