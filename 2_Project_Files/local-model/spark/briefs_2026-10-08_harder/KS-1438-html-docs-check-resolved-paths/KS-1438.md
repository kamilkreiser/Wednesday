## What is wrong (one paragraph)

`html_docs_check.mjs` is both a library (`export function check`, `export function checkMermaid`) and a command (`node html_docs_check.mjs <file.html>...`, `:17`). Its command block runs only when its main-module guard at `:120` holds: `if (import.meta.url === \`file://${process.argv[1]}\`) {`. `import.meta.url` is the module's RESOLVED real path written as a file URL (symlinks resolved, every space percent-encoded as `%20`); `process.argv[1]` is the path exactly as the caller typed it. So through a symlinked spelling, or from a directory whose name contains a space, the two strings differ, the block never runs, and `node` exits 0 having printed nothing — on every input, a broken page included. A guard that cannot fail reads exactly like a guard that passed. Measured at this tip (Premises): through a symlink and from a spaced directory, a page with an unbalanced Mermaid bracket exits 0 with no output, while the same page through the real path exits 1 and names the finding. The fix is the ticket's: compare resolved paths on both sides, `fileURLToPath(import.meta.url) === realpathSync(process.argv[1])` (with a guard for a missing `argv[1]`), which needs `realpathSync` from `node:fs` and `fileURLToPath` from `node:url`.
