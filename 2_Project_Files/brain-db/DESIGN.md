# brain-db: design

First written 2026-11-27 11:55 AEDT by the WED build seat "brain-db", before any code. Revised the same day for round 2 (`ANSWER-1.md`), round 3 (`ANSWER-3.md`, after the first checker's NO GO) and round 4 (`ANSWER-6.md`, after the second checker's NO GO, by a fresh seat). Points changed in round 3 are marked **R3**, in round 4 **R4**. Where an R4 point and an older one disagree, R4 stands. Brief: `BRIEF.md` in this directory.

## What it is
A local Postgres 15 cluster whose data directory sits on the drive (`pgdata-<seat>/` in this lane), holding a full-text index of the seat's markdown brain. The files stay the master. The index can be thrown away and rebuilt at any time; nothing is ever written back to the brain.

## The boundary (Wednesday's ruling, in her words)
**The index holds only files this seat is already allowed to read at boot; no file that belongs to another seat or another client's project enters it.** Rows inside this seat's own files that NAME the other client stay, because shared rules name both clients. Nothing is dropped by client name. The boundary is drawn on files, by path and by tier, not on words.

**R4: QUALIFY OR STAY OUT.** Rounds 2 and 3 tried to recognise every bad shape of a lesson file and keep those out; two independent checks showed that list cannot be finished. Round 4 turns it round. The code states the ONE shape that is in, clause by clause, each read strictly; a lesson is indexed only when it positively meets every clause, and whatever does not is left out and named with the clause it failed. There is no "untagged, so W", no "no row, so the tier decides", no dropping of marked sections and no parsing of fences or section spans. The cost of a wrong "out" is one missing lesson that three commands point at; the cost of a wrong "in" is another client's or another seat's text in this seat's index.

**What keeps another client's material out, said plainly (round 4b, `ANSWER-7.md`).** Three things, each DECLARED BY A PERSON: the lesson's row in the rules index (which seat it is for), its `tier:` line (whose it is), and a section marker (this part is another client's). The tool reads those three strictly and reads nothing else. Nothing reads meaning, and there is no list of client names: one was built in round 4, it left out 55 of the Wednesday seat's own lessons for mentioning the other client in passing, and it still could not see a project named without its client or an abbreviation. So a lesson about another client's work that is tagged `W` or `M`, scoped to this seat and carries no marker WILL be indexed. The remedy is to tag it with its project tier or mark the section, in the lesson file; it is not a word list, and one should not be put back.

## Pieces
| File | Job |
|---|---|
| `braindb.sh` | The one tool. Decides the seat from the tree, owns the cluster life cycle (`init`, `start`, `stop`, `status`, `up`, `doctor`) and hands `rebuild`, `check`, `search`, `at` to the indexer. |
| `braindb_index.py` | Standard-library Python. Reads the scope file, walks the allow-list, parses, and talks to the database through `psql` only. |
| `braindb_lock.py` | R3. Runs one command while holding the cluster's lock, so two commands cannot both initialise or start one data directory. |
| `scope/<seat>.scope` | The allow-list for one seat, as a plain reviewable text file. A seat with no scope file is refused before anything is created. Only `scope/wednesday.scope` ships live; the other two seats' files sit in `proposed/scope/` until their own coordinator confirms or changes them. |
| `tests/run.sh` | Copies the tool into a scratch tree named WEDNESDAY and proves the behaviours on a fixture brain and scratch clusters. |
| `tests/mutants.sh` | R3. Breaks the tool in a copy, one thing at a time, and requires the suite to go red on the matching assertion. |
| `tests/attack_tree.sh` | R3. Re-runs the independent checker's own attack tree against this tool. |

## Choices, one line of why each

**The server**
1. **Unix socket only, no TCP port.** `listen_addresses = ''` is written into `postgresql.conf` at `init`. No `PORTS.md` line is needed.
2. **Socket directory `/tmp/wed-braindb-<uid>-<seat>`, mode 0700.** The macOS socket path limit is 104 bytes; one short rule serves every seat. A symlink, another owner or another mode is refused. It holds no state.
3. **Peer authentication, host connections rejected.** No password or key exists anywhere.
4. **Unlogged tables.** After an unclean stop Postgres empties them; `check` says so and `search` rebuilds.
5. **`rebuild` is one transaction.** A failed rebuild leaves the previous index intact.
6. **On demand, stopped at wrap.** `rebuild`, `check`, `search` and `at` bring the server up themselves (and create the cluster when there is none); `search` and `at` build a missing index but not a stale one. `BRAINDB_NO_AUTOSTART=1` turns the self-start off.
7. **R3: a command acts only on the cluster it is addressed to.** A socket directory does not identify a cluster. Before anything else, every command that talks to the server asks it for its data directory and refuses with exit code 4 unless that equals the data directory the command was given. `check`, `status` and `rebuild` print the data directory they report on.
8. **R3: init, start and stop run one at a time per cluster**, under `flock` on `pgdata-<seat>.lock` (never deleted; the kernel frees it when the holder ends, so it cannot go stale). A second command waits, then finds the server running. Rebuilds take the same lock, so two first builds cannot both create the database. After a failed `pg_ctl start` the tool re-tests "running" and carries on if another command won the race.
9. **R3: a stale pid file naming a live process that is not ours is never moved by the tool.** `start` says so in one line and prints the exact `mv -n` command for a person or the coordinator. A wrong guess there would touch a live process that is not ours.
10. **`stop` stops only the process started with this data directory**, read from the process's own command line, never by name.
11. **Version guard.** `start` compares `PG_VERSION` with the binaries' major version and refuses with the word "rebuild".
12. **R3: the seat is the tree's folder name** (WEDNESDAY, TUESDAY, FRIDAY), through the fleet's own `tools/seat_note.sh`. `WED_AGENT` may only agree with it; a disagreement, or a folder with another name, is refused. Before round 3 the variable won, so a pane carrying the wrong variable would have built another seat's index from this tree.
13. **R3: the scope file is tested before anything is created.** A seat with no scope file gets no cluster and no server.

**What enters the index (R4: points 14 to 21 are rewritten)**
14. **R4: what a scope file may ask for is a closed table in the code.** For each kind there is one folder, and for ledgers, pickup files, the rules index and the rules files one list of exact names, PER SEAT (`SEAT_DAILY`, `SEAT_LEDGERS`, `SEAT_PICKUP`, `ROOT_RULES`, `SHARED_DIRS` in `braindb_index.py`). A scope line inside the table is honoured; any other line is REFUSED when the scope is loaded. The daily folder is also taken from `tools/seat_note.sh` and the two must agree. So a Tuesday or Friday tree cannot index the Wednesday seat's ledger, daily notes or pickup file by any allow line, and the reverse: it is not an instruction to the seat, it is not expressible. `4_Credentials/`, `3_Access_Keys/`, `0_Brain/dashboard/`, `0_Brain/reference/` and chat stores stay refused by their own tests as well.
15. **R4: the scope is validated before anything exists.** `braindb.sh` runs the indexer's `validate` (which only reads the scope file) before it creates a cluster, takes the lock or starts a server. A scope file that is missing OR refused leaves no directory, no lock file and no process.
16. **R4: a file is judged on the descriptor it is read from.** Every file is opened once, inside its already-open folder, with `O_NOFOLLOW`; `fstat` on that descriptor must say regular file with link count 1; the bytes are read from the same descriptor. Nothing is tested by name and opened later, so a file swapped for a symlink mid-rebuild is either refused or read as the regular file it was. **What this cannot do:** a hard link and a copy are indistinguishable once the original is gone; a secret pasted into a lesson is not a path problem; and the FOLDERS above a file are checked by `realpath` once, not held open, so a process that can replace a whole brain folder with a symlink mid-rebuild is outside this guard.
17. **A file is taken only under the kind its name says it is.** A lesson's name starts with its date; a daily note's name is a plain date and nothing else; a name starting with `_` is never a lesson, skill or document. `(conflict_on_` copies and `.pre-` backups are left out by the code itself.
18. **R4: which lessons. The qualify rule** (`qualify_lesson()`), in this order; the first clause not met is the one named:
    - **(t) plain text.** Valid UTF-8 (an optional BOM first); no control, format or line-separator character other than LF and TAB; every letter an ASCII letter once accents are removed. This is what makes the word tests of (c) and (d) mean what they say: without it a look-alike letter, a zero-width character or a line break only some readers honour walks round them.
    - **(a) exactly one row.** Exactly one row of the rules index has a key that EQUALS the file's name (both sides NFC, format characters removed; no case folding, no stripping, no path). Further `#n` rows are fine when each is read and no `#n` repeats. And no line of the index that could NOT be read as a row holds the file's name anywhere in it.
    - **(b) that row names this seat.** Its seats cell is `all` (the spec's word: "`all`, or a comma list of `wednesday`, `tuesday`, `friday`") or holds this seat. A `#n` row naming this seat does not rescue a lesson whose plain row names another; a `#n` row naming another seat keeps its rule line out of an indexed lesson.
    - **(c) frontmatter and tier.** Line 1 is exactly `---`; a later line is exactly `---`; every line between is a plain `key: value` with a lower-case ASCII key; no key twice; exactly one key `tier`, and no other key that folds to something holding "tier"; no other value carries a tier assignment; the block is not followed by a second one. The tier VALUE is on a closed list: `W`, `M`, or `P-<Client>/<Project>` whose client is one of the seat's own. Measured on the real lessons before it was written (table in `STATUS.md`): the only values in use are `W`, `M`, `MIXED`, `P-General/...`, `P-Datasec/...` and `P (Datasec/...)`.
    - **(d) no tier marker, in any spelling, anywhere.** No `<!--` or `-->` at all (a section marker in any spelling is an HTML comment); no line that starts with the word tier or assigns one, outside the one frontmatter line; no numeric character reference (it can spell the word where the line test cannot see it). A lesson with a marked section is out WHOLE. **Round 4b: there is no client-name test** (see "What keeps another client's material out" above); the `deny_clients` directive is gone and a scope file that still carries it is refused, so no file can promise a protection that does not exist.
    - **(f) file-level**, from point 16: reported as a clause so a lesson lost to it is named like the others.
    - **No usable rules index, no lessons.** Missing, not a plain regular file, not UTF-8, or with no row that could be read: `rebuild` and `check` REFUSE.
19. **R4: a rules-index ROW is read only in the spec's shape:** seven TAB-separated fields, none empty or with outer white space, no control character; a key `<file>.md` or `<file>.md#n` (n at least 2); status `live`, `dead` or `superseded`; seats `all` or a comma list of distinct seat words. Any other non-blank line, a comment line below line 1 included, is kept as "could not be read" and counts against every lesson it names (clause a).
20. **R4: what is left out is visible.** `rebuild` names every left-out lesson under its clause and its LAST line gives the count per clause; `check` prints the same count with up to five names per clause; `doctor` carries the count in its one line; `search`, when it finds nothing, says how many lessons are left out. `search` does NOT look inside left-out files to say "your word is in one": a search must not read what did not qualify, so that part of N8 is not done.
21. **One bad file does not lose the rebuild**; rows over 80,000 characters are cut and listed; the two bytes the tool splits `psql` output on (0x1E, 0x1F) and NUL are stripped from the files that are not lessons (a lesson holding them fails clause t).

**R4: the right database, inside the same session (replaces point 7)**
7a. Every `psql` session the tool opens begins with the same two statements: it stores the data directory the command is addressed to in a session setting, and a `DO` block raises unless the server's own `data_directory` equals it. For a rebuild they are the first statements inside the one transaction that drops and reloads the index; for `check`, `search` and `at` they are the first statements of the transaction that reads. The server that answers the assertion is the server that does the work, so there is no moment between "which cluster is this" and the write. Exit code 4 and "Nothing was read or changed" when it fails; exit code 3 when nothing answers.
7b. **How "the same directory" is decided.** `braindb.sh` resolves the data directory to its real path once, at the top, and uses that one spelling for the pid-file test, `-D`, the lock file and the assertion. A trailing or doubled slash, or a symlink to the directory, is therefore the same cluster. The server's side is the spelling it was started with, which is always that real path when this tool started it. A server someone started by hand through another spelling is refused: that is the safe side, and the message names both directories.
7c. The indexer's own lock wait has the same limit (150 s, `BRAINDB_LOCK_WAIT`) and the same sentence as `braindb_lock.py`, exit code 75.

**Search**
22. **Units.** Lessons, skills, identity, people and architecture files are split at headings and the best section per file is shown. Ledger rows and daily-note lines are one unit each. A rules file gives one row per numbered rule and one per heading section's other text.
23. **Ranking.** The query is split into its lexemes; each is weighted by a rarity score computed at rebuild, summed over `ts_rank`, multiplied by the square of the share of the query's rarity mass the row matched, and divided by the query's total rarity mass. Title and file slug weigh most, then the heading and the lesson's rules-index line, then the body. Dead or superseded rules are halved and labelled.
24. **What a search shows.** With no `--kind`: knowledge first (rules files, lessons, skills and the like, by score), then up to two incident rows from the ledger and daily notes under their own heading. `--all` gives one mixed order; `--kind K` gives one kind. Every result line carries its kind.
25. **R3: no WEAK MATCH line. The last line states a fact instead.** In round 2 the tool called a result weak under a score of 0.035. The checker showed that figure mostly measures the length of the question. Its fix (measure on the question's rarest three or four words) was built and tried on 36 questions, 34 of them judged: at its best single threshold it was wrong on 5 of 34, the same as the old measure, and the gap it sat in was 0.0006 wide (`evidence/threshold_study_round3_confidence_measure.txt`). No threshold separates right from wrong honestly, so the line was removed, as `ANSWER-3.md` item 11 directs. The last line now reads, for example, `first result: score 0.0172; of the question's 4 rarest words it holds 2 [skip move] and lacks 2 [deploy fail]`. That is a fact the reader can weigh; it is not a verdict, and it is not a safe one either: 4 of 13 wrong first results held every rare word of their question (`evidence/threshold_study_round3_neutral_line.txt`).
26. **R3: a rules-file row goes ahead of the lessons only when it holds every one of the question's rarest words** (up to four). **R4:** such rows are selected in SQL before the top-N cut, so result 1 no longer depends on `--limit`. Otherwise it competes on score like any other row. This replaces round 2's "when its match is not weak", which depended on the removed threshold; the purpose is the same: one shared word must not put the rules file first.
27. **`at <trigger>` weights come from this seat's indexed ledgers only.** The set of rules matches `rules_card.py`; the order may differ.
28. **`check` also compares the indexer's and the scope file's own hashes** with those stored at rebuild.

## Not built
Vectors, any extension, any network call, any service or launchd job, any file outside the WEDNESDAY tree, any write outside this lane (other than the socket directory and the session scratchpad).
